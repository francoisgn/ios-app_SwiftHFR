### Problem
In the reader, a horizontal scroll inside a sideways-scrolling block (`[fixed]`, `[code]`: `table.code td, table.fixed td { overflow-x: auto }`, `reader.css:196`) also turned the page when the drag was long enough (the pure `PageSwipe` rule only looks at the drag).

### Cause
`TopicReaderView.pageSwipe` (a `simultaneousGesture` `DragGesture`) calls `PageSwipe.of(translation:predictedEnd:page:maxPage:)` (`ReaderPageSwipe.swift:24`), which has no idea where the touch started; the web view never tells the app. Legacy fixed this on #372 (`b16eb82d`, `5f6c411c`): `MessagesView.swift:1102-1142` (touchstart script) and `:5398-5428` (drag guard) @ 87fe0d1c.

### Change
- `reader.js`: capture-phase `touchstart` walks up from the target to an element with `overflow-x` auto/scroll and `scrollWidth > clientWidth + 1`; posts `{type: "scroller", inside}` on change only (as legacy).
- `ReaderBridgeMessage.scroller(inside:)`, strict boolean decoding (shared helper `flagMessage` with `edge`), not a tap action.
- `ReaderWebController.touchStartedInScroller` (set through `flagReported`): reset by the next touch the page reports (not on `touchend`, legacy's reason: an async `touchend` message could beat `DragGesture.onEnded`) and by a new document, so the first swipe after a page change works.
- `PageSwipe.of(... startedInHorizontalScroller:)` (required, no default) returns nil when true; `TopicReaderView` passes it. The "Swipe changement de page" setting check is unchanged.
- **Deliberate difference from legacy**: `[code]` is covered too. `table.code td` scrolls sideways in SwiftHFR (`reader.css:196`), whereas legacy's `[code]` lines do not scroll (measured, #372 check 4a'), so a fling on one still turned the page there. Stated in the `ReaderPageSwipe.swift` header and in the `gap-edit` below.
- Reused from the stale mac/M1 worktree (`fix/672-fixed-scroll-no-page-swipe`, base 10286cf1, uncommitted): the design, the Swift pieces and the tests. It had no `reader.js` part; re-applied on current dev-swift (one conflict, `isTapAction`, resolved) and the JS written from legacy.

### Tests (iOS 27.2 simulator, unsigned)

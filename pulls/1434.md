### Cause
- **The CI failures** (2026-11-18/19) ran the file as it was before #1127: a stale merge ref (analysis on #1201). There the Messages list was built logged out, and its load when the list appears closed the open conversation (`MessageListModel.load`, `.signedOut`). Since #1127 the hosted list is logged in.
- **Since then on CI**: in the last 100 failed `ci.yml` runs (2026-11-24 → 2026-11-28), `DuoLayoutHostedTests` ran in 11 and passed all 11 (the Messages case in 2.5–4.1 s). The runs failed on other suites.
- **Locally on `dev-swift` `ffa9418d`** (iPhone Duo, iOS 27.2 clone): 10/10 green, 5 alone and 5 under 4 × `yes`, with a Mac load average of 45–126 from the other sessions.
- **The timing guess that is left** is after the fold, `DuoLayoutTests.swift:314-316` on `dev-swift`: the test waited for `loader.isLoading` to drop, then slept a fixed 500 ms and checked that the cover screen's list load had kept the conversation. `ContentLoader.finish` drops `isLoading` one main-actor hop before `MessageListModel.load` resumes and keeps or closes the selection (`MessageListModel.swift:378-393`). So the check ran at "500 ms later", not "after the decision". If the decision came later than that, the test passed whatever the decision was (shown below with a 5 s mutation).

### Change (test only)
- The hosted `MessageListModel` gets a `ledgerSeen` closure that counts calls (`ReaderCallCounter`). `recordReadState` calls `ledgerSeen` last in a page-1 load, after the selection has been kept or closed (`MessageListModel+Notifications.swift:30-33`). So the count is an observable "this `load()` has run to its end".
- Before the fold, the test waits until the split's own load has ended (count > 0 and not loading), not only until a request was sent. After the fold, it waits until a new request was sent **and** the count has moved past its pre-fold value. Both waits use the suite's `settle` (30 s deadline, a layout pass each poll), and each fails with a message that names the requests and the count. The `Task.sleep(for: .milliseconds(500))` is gone.
- No app code changes. The Categories case is unchanged.

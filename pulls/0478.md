Closes #477
Claim: cloud/orch

**Problem.** All of 2026-11-05, the required check "Analyze (swift)" (CodeQL on `macos-26`, about 15 min) was cancelled on every PR before any macOS runner picked it up. That blocked every merge for hours. Meanwhile "App build + tests (iOS 27 simulator)", the check that caught the day's real bugs (compile errors after merges, main-actor isolation in tests, flaky tests), is not required: a PR could merge with the app red.

**Cause.** CodeQL Swift is required on every PR that touches Swift, although ADR 0012 says it only analyses HFRKit. Every push to an app PR therefore started 2 or 3 macOS jobs, intermediate pushes included.

**Change (operator decision, #477 items 1–3; child parallelism unchanged):**
1. `codeql.yml`: "Analyze (swift)" runs on every push to `dev-swift`. On a PR it runs only when the PR carries the `codeql` label. Adding the label triggers it (`labeled` event), and the existing Swift-diff detection still applies. The label is meant for session, cookie, token and posting changes.
2. `.github/rulesets/dev-swift.json`: the required check "Analyze (swift)" is replaced by "App build + tests (iOS 27 simulator)". There are still 9 checks, so the CONTRIBUTING diagram stays right. A PR that does not touch the app still passes, because the skipped job counts as passed.
3. `ci.yml`: the two macOS jobs, "HFRKit tests (macOS) + iOS 27 build" and "App build + tests", skip draft PRs and run on `ready_for_review`. Linux jobs keep running on every push. GitHub refuses to merge a draft, so the skip never lets a PR through untested.
4. Docs: CONTRIBUTING merge criteria, an amendment to ADR 0005, an AGENTS.md learning, and the `codeql` label in `.github/labels.yml`.

Why no wider: the path-based change detection already existed and is kept, and the number of parallel children stays as the operator decided.

**For the maintainer (ezzz):** the ruleset change takes effect only after a re-import (`scripts/configure-repo.sh`). The `codeql` label is created when the label sync runs, or by hand. Until the re-import nothing blocks, because a job skipped by its `if` counts as passed for a required check:
- "Analyze (swift)" stays required but is skipped on PRs without the label;
- "App build + tests" is not yet enforced, so cloud/orch keeps checking it by hand until then.

**Tests.** The workflow and ruleset changes can only be exercised on GitHub. Checked locally: the YAML and JSON parse, and `scripts/check-lot-deps.py` passes. This PR touches no Swift, so "Analyze (swift)" is skipped on it. It changes `ci.yml` and is not a draft, so both macOS CI jobs run and exercise the new conditions. The draft path still has to be seen on the next draft PR.

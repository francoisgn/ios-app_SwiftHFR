LOT-036

**Problem.** HFRParsing could not read the composer pages (reply, quote, edit, new topic, MP, moderator alert). The posting flow (LOT-048) and the moderator alert (LOT-050) need the form's fields, selects, prefill and action as a `ForumForm`.

**Cause.** The only readers were in the legacy view controllers (`QuoteMessageViewController.m`, `AlerteModoViewController.m`) and the live Swift service, which differ (LOT-004 quirks 1-5, 10).

**What changed, and why this wide.** `HopFormParser` (`parse` for `<form name="hop">`, `parseModerationForm` for the `modo.php` form), one file in `HFRParsing/Forms`. It reports every named input and select in page order, the `content_form` prefill (entities decoded, CRLF read as LF, `[quotemsg]` blocks untouched) and `#dynamic_smilies`. It decides nothing about what is sent and has no login flag: `hash_check` is on anonymous pages too (quirk 10), the anonymous composer shows it empty (`R40b`). Spec `docs/lots/LOT-036-hop-form-parser.md` (legacy sources, edge cases, 7 intentional differences, pending capture), HFR-PROTOCOL §6c `### LOT-036`, AGENTS.md §11 learning, LOTS row set to done.

**Tests** (Swift Testing, 28 tests over all 16 captures R40a-R47u1; whole HFRKit suite green locally):
- `HopFormOracleTests` (differential vs the LOT-004 oracle, coverage test over the oracle map): action, legacy value map rebuilt from the parsed fields, field/select order, prefill (raw and CRLF-normalised), derived flags and sub-categories, favourite smileys, R46 moderation form.
- `HopFormParserTests`: facts per capture (R40a 43 inputs and 16 radios, R40b empty token, R41b prefill, R42/R47c two quote blocks, R43a `/bdd.php` and delete box, R45a 16 sub-categories, R47u1 8 smileys, R46) and rules on small inline pages (entities, bare `checked`, selects, option groups, textarea normalisation, scope, smiley filtering).
- Shown to fail without the change (reverted one line at a time): no CRLF normalisation (14 issues), absent `value` read as non-empty (2), selected ignored (2), first-`selected` rule replaced by last (1, after adding its test), any-tag match for the form (3).

**Pending capture** (none blocks this lot): public-topic edit form action, new-topic form with a preselected sub-category, a prefill starting with a newline, the reply form of a locked topic. Listed in the spec.

## Problem
The app has one look (LOT-121/122: hue slider, dark styles). THEMES.md asks for themes that are a token file plus optional art, picked in a gallery of Réglages › Thème, with Legacy = today's app, unchanged. LOT-191/192/193 and Noël abusé (LOT-166) need that engine and a stable token model.

## Cause
No theme model, no setting, no path from tokens to screens or the reader.

## Change
- **HFRModels `Theme/`** (pure, tested on Linux): `ThemeRGB` (`#RRGGBB[AA]`, WCAG luminance), `ThemeTokens` (the 21 required tokens of THEMES.md §3, the 5 optional table tokens with their fallbacks, unknown names refused, contrast rules), `ThemeDefinition` (strict decoding: kebab-case id, `light`+`dark` or `any`, only Legacy without variants), `ThemeCatalog` (Legacy first, family order, unknown id → Legacy, bad files left out).
- **HFRStorage**: `SettingKey.themeID` (`theme_id`, device-only; ADR 0013 matrix E row).
- **App**: `ThemeCatalog.bundled` reads `Themes/<id>/<id>.theme.json` — **not `theme.json`**: synchronized folders are copied flat into the bundle, so a second `theme.json` would collide (THEMES.md §3 updated; *Mac check*: two theme folders build). `ThemeSettingsModel` stores and resolves the theme; `ThemeAppearance` carries its variants: tint = `accentText`, `appScreenBackground()` paints `background` with one dynamic colour (structure chosen by `screenFill`: Legacy's two paths untouched, a flip changes values only), `.fontDesign`, a single-variant theme imposes its appearance, `BadgeCapsule` fills with `unread`/`onUnread`. Reader: `--app-theme-{light,dark}-*` variables, read by `reader.css` only under `:root[data-app-theme]` (Legacy removes the attribute, so its page is today's); the page is `surface`.
- **Gallery**: `ThemeGallery` (own view, so LOT-180/#420 moves it into its sub-menu instead of building a second): families, light + dark swatches (or one and « clair = sombre »), name, « par <auteur> », check mark, footer. The hue, dark style and brightness show while Legacy is the theme (operator note 2026-11-11).
- **Not here**: native rows and text keep the system colours of the appearance in force (#572, #651 unchanged); the contrast test therefore also checks the system text on `background` and `surface`. Spec: `docs/lots/LOT-188-theme-engine.md`.

Why this wide: the engine needs the setting, the model, the reader and the screen fill to be usable by a theme lot; no theme beyond Legacy, no seasonal behaviour, no accent presets.

## Tests
- HFRKit (`swift test`, 1950 tests green here): `ThemeDefinitionTests` — colours, WCAG reference values, decoding rules, the test fixture meets every rule, **the broken fixture fails `dark link/surface` (1.64:1)**, every bundled theme decodes and passes, a broken file added to the bundled set fails, catalog order and unknown id; `SettingKeyTests.theThemeIDIsReadAsStored`, `SettingScopeTests` (device scope). Shown to fail without the change: removing the `link`/`surface` rule turns `theBrokenThemeFailsTheContrastRuleItBreaks`, `theBundledCheckFailsWhenABrokenThemeIsAdded` and `aMissingTokenAnUnknownTokenOrAnOpaqueRuleBreakIsRefused` red.
- App (not runnable in the cloud; CI and the Mac run them): `ThemeEngineTests` (empty store is Legacy and writes nothing; selection survives a relaunch; unknown id is Legacy and stays stored; Legacy changes nothing; a theme reaches tint, fill, font, reader variables; every reader variable is read by `reader.css`; a single variant imposes its appearance; #651 tones in every bundled theme), `ThemeEngineWindowTests` (real windows: list light/dark and back to Legacy, pushed screen, sheet, three split columns, a dark/light/dark flip makes the counted view once), `ReaderThemeTests.aThemeRecoloursThePageAndLegacyRestoresIt`, `ThemeAppearanceTests` (Legacy's script with its fixed attribute removal). LOT-122's `AppThemeTests` are unchanged.

## What and why
The previous hero (the forum page pulled into an iPhone with a genie effect) was judged too conventional. Three concepts were posted on #1380; the operator chose **A « the lens » for the README hero** and **B « `:o` » for the GitHub social preview**, with one condition: the phone must show the real app.

- `docs/assets/hero.jpg` (2400×1200, about 410 KB): the forum's home page as a printed sheet on an orange table, a phone lying on it showing the same categories in the app. Built from `docs/assets/source/hero.html`.
- `docs/assets/social-preview.png` (1280×640, about 70 KB): the forum's smiley code as a two-ink typographic poster with the wordmark. Built from `docs/assets/source/social.html`.
- `node render.js` writes both in place, lowers the JPEG quality until the hero is at most 500 KB, and fails on a missing font or an image that did not load.
- **The phone screen is an image slot.** `render.js` uses the simulator capture `docs/assets/source/app-forums.png` when it exists. **It does not exist yet: the committed `hero.jpg` is built with a stand-in** (`app-screen.html`, drawn from the app's list code, sources listed at the top of the file; not a screenshot). When the Mac session pushes the capture, `node render.js` is run again and `hero.jpg` replaced, on this PR or a follow-up.
- `hfr.webp` keeps only the category, sub-category and counter columns.
- README alt text and `docs/assets/source/README.md` (recipe, licences, the source of « 1997 ») updated; the old `scene.html` and the concept folder are removed.

**For the operator after the merge:** upload `docs/assets/social-preview.png` in the repository's Settings › Social preview (a repository setting, not done by this PR).

Why no wider: docs and images only; no `App/` or `Packages/` file.

### Problem
Item 4 of #1073 (operator): in an iPad split under the classic look, the selected topic / MP / category row is filled with the system's solid accent colour (« gros bloc de couleur »). mac/M1's `/release` left this and a toolbar check.

### Cause
`ListLookRow` returned `listRowBackground(nil)` for the classic look, so the system's selection fill showed; only the dense look and gallery themes drew their own.

### Change
- `ListLook.rowBackground(isSelected:scheme:contrast:)` (pure): a selected row is the accent at `selectedStrength` = twice `RowTint.strength`, capped at 0.30 (0.20 light; 0.30 dark and Increase Contrast), so it stays above every state pill (max 0.24) and stays a tint. Unselected classic → nil (card kept); dense → clear. Mechanism: a custom `listRowBackground` on the selected row (Apple list API), not a custom selection appearance. Gallery themes keep `themedListRow`.
- The selected row resets `backgroundProminence` to `.standard`: the system turns the primary text white on a prominent (selected) background, which was for the solid fill (LOT-126, `ReadTitleStyle`). On the tint the text keeps its normal colours.
- The selected row keeps its pill (super favourite, flag, unread MP) over the tint: the `isSelected` parameter is removed from `TopicRowCues.accent`, `TopicListView.rowTint` and `MessageRowView.rowTint` (and the dead `MessageRowView.isSelected`).
- `BookmarksView` uses the shared `listLookRow` instead of its own hard-coded 0.15; `DenseListLook.selectedRowBackground` is deleted. **The dense look's selection also changes**: 0.15 → 0.20 (light) / 0.30 (dark, Increase Contrast).
- Legacy: the split-view topic row is a solid `actionTintColor` rounded rectangle with white text (`Common.swift:3669-3676`, `:3372-3392` @ 87fe0d1c). The light tint is the operator's decision, not a port (Ledger below).
- Item 2 (toolbar overlap with the « Sous-forum » picker): not changed. The picker is a `LabeledContent` row of the list (`ForumScopeBar.swift:32`), the buttons are nav-bar `ToolbarItem`s (`TopicListView.swift:102-106`); no code path overlays them; seen only in the pre-#955 split. Left to the Mac check.

### Tests
`ListLookSelectionTests` (4 tests): selected tint for every scheme × contrast, strengths pinned (0.20 / 0.30), selection stronger than a state pill, unselected rows unchanged, the pill kept. Updated `TopicRowCuesTests`, `MessageRowCuesTests` for the removed parameter. Not run: Linux, the app target cannot build here; Compile check will. The modifier wiring and the text contrast are **device-checked, not tested** (a hosted pixel test cannot be written or run from Linux); estimate from review: ReadTitleStyle in light on the 0.20 tint about 4.8:1, thin margin, so the probe below matters.

### Mac / device check owed (iPad Pro 13, landscape, light, dark, Increase Contrast, classic look)
1. Catégories with a category selected; a category's topic list and Favoris with a topic open; Messages with a conversation open; Bookmarks with one open.
2. Selected row: tinted, not solid; text not white, readable; repeat the LOT-126 pixel probe and record the ratios (title, secondary text) with a super-favourite pill, a flag pill and an unread MP pill under the selection.
3. « Lignes denses » on: selection now 0.20 / 0.30, still subtle?
4. Item 2: « + » / refresh / « … » vs the « Sous-forum » picker in a split column, no overlap.

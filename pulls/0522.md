# PR #522: Reader: message header wraps at accessibility text sizes

Refs #499

Claim: mac/m2-lead

**Problem.** At Dynamic Type accessibility-extra-large the reader's message header rendered the pseudo one character per line (header 150-215 pt, "⋯" button 125x112).

**Cause.** `body` sets `overflow-wrap: anywhere`, which makes the min-content of every flex item one character. The header row (`display: flex`, no wrap) therefore shrank the pseudo and the date to columns instead of wrapping. The "⋯" button grew with its em-sized font and padding.

**Change** (`reader.css`, 7 lines): header `flex-wrap: wrap`; avatar, date and button `flex: none`; pseudo `flex: 1 1 auto; min-width: 0; overflow-wrap: break-word` (breaks at word boundaries, a very long one still breaks); button glyph `min(1.4em, 32px)`.

**Test.** `ReaderTextScaleTests.theMessageHeaderWrapsItsAuthorSensiblyAtALargeTextSize` in the real web view. System Dynamic Type does not reach a WKWebView in a test host, so `--text-scale` (as the visibility web tests do) stands for it. Default: pseudo on one line, header 37 pt (unchanged). At 300 %: before the fix the pseudo takes 6 lines and the button is 143 pt tall (fails); after, at most 2 lines and the button 64 pt (passes).

**Not verified**: the real app at `content_size accessibility-extra-large` on iPhone/iPad (XCUITest never reached idle at that size on this Mac; see the lead's report).

## What and why

- **Problem**: #1202 refused any account-sync state this version cannot read and never wrote over it, so a state a later version wrote stays readable for that version. But damaged bytes, which no version wrote as they are, then locked the sync for good: no operation worked, and « Mettez l'app à jour » could not help (Fable round 1 on #1202, finding 3).
- **Decision**: the operator chose option (b) (#1200, 2026-11-18). An **explicit switch-off by the user** resets a damaged state. It is never reset silently, and a later-version state stays locked. Design approved by cloud/orch: a « Réinitialiser » button shown only for a damaged state, behind a destructive confirmation; a fresh off state; no tombstone.
- **Change**:
  - `AccountSyncState.decoded` now tells three cases apart:
    - readable: absent means off with nothing known, as before;
    - **later version**: valid JSON whose integer `version` is above this one's;
    - **damaged**: not JSON, no integer `version`, or this version without its required fields.
  - `AccountSyncError.unreadableState` splits into `stateFromLaterVersion` and `damagedState`. Every operation still throws on both, and nothing is written over either.
  - `switchOff()` on damaged bytes writes a fresh off state with `hadLocalAccounts = true`, so the device never bootstraps by itself again. The **accounts and the synchronizable iCloud item are untouched**: whether this device was sharing is unknown, so the other devices are left alone (no tombstone). A later-version state still throws on `switchOff()`.
  - App:
    - `AccountsModel.isAccountSyncDamaged` is refreshed after every sync operation.
    - Under the notice, the settings show « Réinitialiser » (destructive) only for a damaged state, since the switch already reads off. It opens a `confirmationDialog` before `resetAccountSync()`, the explicit switch-off.
    - The two cases now have their own messages; until now one sentence covered both.
- **Why no wider**: no other path writes a fresh state over unreadable bytes. A later-version state keeps the strict #1202 behaviour (ESSENTIEL persistence rule).

3. **Low** — `AccountSyncUnreadableStateTests.swift:78-81`. The "never imports" assertions are vacuous: the device holds `user-a`. Without `hadLocalAccounts = true`, only line 74 fails. Fix: add a case with no local account and a live envelope.

5. **Detail** — `AccountSyncState.swift:92-97`. `{"version":"2"}`, a version above `Int.max`, or a non-JSON later format classify as damaged, so resettable. Write in the spec that every later version keeps a top-level integer `version`.

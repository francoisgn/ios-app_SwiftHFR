## What and why
**Problem.** A small-store file that is damaged, or was written by a newer build (TestFlight rollback, restored backup), makes reads answer empty and every write throw, at every launch. The pseudo-list editor showed "illisible" with a "Réessayer" that re-read the same bytes; the only exit was a reinstall. The engine has `discardUnreadableData()` ("the single way out of a failed load") and no screen called it. An undecodable drafts file was moved to `.corrupt` silently.

**Change.**
- `App/SwiftHFR/Common/UnreadableDataRecovery.swift` (new): one « Repartir de zéro… » button with a confirmation saying the file is kept aside, not deleted, and the data start again from zero on this device; the action runs only after the confirmation.
- Wired on every screen that shows a store load failure:

  | Screen | Store(s) | Model entry |
  |---|---|---|
  | Réglages › list editors | `PseudoListStore` | `PseudoListEditorModel.discardUnreadable()` (via `PseudoListManager`) |
  | Favoris list banner | `FavoritesLayoutStore`, `SuperFavoritesStore` | `FavoritesOptionsModel.discardUnreadable()`, `canDiscardUnreadable` (read failures only); clears the write problems on success |
  | Smiley picker, « Favoris de l'app » | `AppSmileyFavoritesStore` | the section turns `failed` with the button; `discardUnreadableFavorites()` |
  | Image panel | `RehostUploadHistoryStore` | `ImageUploadHistoryStoring.discardUnreadable()`, `ImageUploadModel.discardUnreadableHistory()` |
  | Réglages › Stockage MP | `MPStorageCopyStore` | `MPStorageSyncModel.discardUnreadableCopy()`, `copyIsUnreadable`; then `start()` again (an `on` account syncs) |
  | Réglages › account deletion | `ReadingPositionStore` | `AccountDeletionModel.discardUnreadablePositions()` when a wipe met unreadable positions |

- Engine (`HFRStorage`):
  - `MPStorageCopyStore.discardUnreadableData()`, as its sibling stores.
  - `DraftStore.takeRecoveredCorruptDataNotice()`: true once after a load set undecodable drafts aside.
  - **Every `discardUnreadableData()` reads the data again first** (`SmallStoreState`, `PseudoListStore`, `ReadingPositionStore`): a read that failed once (I/O) and works now is never set aside.
- Composer: `draftsNotice`, its own banner, announced by VoiceOver. It is not a failure: no « Fermer sans enregistrer », and a working save keeps it. The first sheet shows it.
- Persistence: nothing is deleted; the `.corrupt` copy keeps the old bytes.
- Docs: LOT-063, LOT-102, LOT-118, LOT-130, LOT-157.

Not wider: smiley search history and the notification ledger show their failure on no screen. **iCloud lists:** `SyncedListsStore` is not run by the app yet. Once it is, a discard must drop that slot's digests, or `reconcile` would push the emptied list: noted on #447.

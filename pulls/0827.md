Closes #826
Claim: cloud/i826-sonnet

**Problem.** Docs consistency failed four times on a mismatch between the `### Ledger` section and the `ledger` label (#757, #759, #795 twice); issues stayed `status: ready` under an open PR.

**Cause.** The check required the label and read it only on a push; `fold` selected PRs by label; nothing set `status: claimed` from an open PR.

**Change.**
- `ledger.py`: `check-body` validates the section only (`--labels` accepted and ignored so old workflow files run); `fold` selects merged PRs with a section and no `ledger: done`; the legacy `ledger` label is inert; only `done` writes labels. CI step, AGENTS.md §8 (bullet, learnings, overrides row), PR template, README, CONTRIBUTING, tooling READMEs, REVIEW-ROUNDS, ORCHESTRATION updated.
- `hygiene.py`: new `claim` action: an open issue cited by `Closes/Refs #N` of an open dev-swift PR (draft or not; `type: roadmap` trackers excepted) gets `status: claimed` first, then its other `status:` labels are dropped. `Refs` of a merged PR never closes (only `Closes`, unchanged). Stale-claim report now only for claims with no open PR; never released. Dry-run stays default.
- Uncited issues carrying several `status:` labels are still only reported (no rule says which wins).

**Tests** (`scripts/tests/test_docs_ledger.py`, `test_roadmap.py`; 155 pass). Without the change: 5 fail/error in test_docs_ledger (section alone decides, CLI ignores labels, pending by section, fetch has no label filter, CRLF) and 4 fail in test_roadmap (claim from open PR, blocked lot claimed not unblocked, stale-claim report, apply order). `test_refs_of_a_merged_pr_never_close_an_issue` is a regression guard that already passed.

**Dry-run on the live tracker** (`hygiene.py`, no `--apply`): 3 routine actions: unlabel #138 (closed, `status: ready`); claim #634 (PR #712, drops `status: ready`); claim #731 (PR #805, drops `status: blocked`). No `Refs` issue closed; `ledger: none pending`.

Linux-only change (Python, docs, one CI step).

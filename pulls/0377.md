Claim: mac/verify-merges

**Problem.** Mac check of #344 row 2 (iPhone 18 Pro, iOS 27.0, build of dev-swift `34c4e556`): Plus > Réglages > Icône highlights the row and opens nothing; Thème does the same. On iPad Pro 13-inch (M5) both rows open their screen.

**Cause.** #303 (LOT-170) made the iPhone Plus stack push Réglages with `navigationDestination(item: $model.plusEntry)`. The settings rows of #292 (LOT-119) are value-based `NavigationLink(value:)` resolved by a `navigationDestination(for: SettingsDestination.self)` on the settings screen. A value pushed from a screen that `navigationDestination(item:)` presented never appears. Moving the `navigationDestination(for:)` to the stack root did not help either (tried on the simulator). On iPad, Réglages is the root of its own stack, so the value link resolves. The code is the same at #303's merge (`d25de46d`), so #303 introduced it.

**Change.** Each row links to its destination view directly (`NavigationLink { SettingsDestinationView(destination:) }`), which works in both layouts. `SettingsDestination` stays the list of rows, and later lots (LOT-121 theme, LOT-123 icon) still replace their case's screen in one place (`SettingsDestinationView`). Nothing else changes: the Plus selection model (`plusEntry`) stays as #303 designed it.

**Tests.** There is no UI test target in the repo, so no committed test can drive a push. Checked on the simulator with a local XCUITest driver (not committed) on iPhone 18 Pro and iPad Pro 13-inch (M5), iOS 27.0:
- Plus > Réglages > Icône, back, twice; Thème; switch to Catégories and back to Plus (Réglages is still shown); back to Plus; push again. **Fails on `34c4e556`** (no "Icône" navigation bar after 3 s, row stays selected) and **passes with this change** on both devices.
- Settings in light, dark, XL and AX5 (#322) and the rotation lock still pass with this change.

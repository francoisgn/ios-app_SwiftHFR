**Problem.** The Messages badge showed 7 where HFR and legacy showed 6, on the same account at the same moment.

**Cause.** The badge read only the home page loaded at launch (`forums.loader.value`), reloaded only by a pull-to-refresh of the Forums tab, and nothing moved it when a conversation was read here. The 2026-11-10 captures give 6 with every SwiftHFR reader and with legacy's `extractMPCount` (issue comment), so the count was stale, not misparsed. This is inferred from the code, not observed on the device (see "Device check"). Legacy keeps `nb_mp` current in two ways (all @ 87fe0d1c, through `HFRplusAppDelegate.m:704-706`):
- it rewrites the count from every home page (`ObjCForumsParser.m:516-525`) and every favourites/flags page (`ObjCFavoritesLoaderWorker.m:91-98`);
- it moves the count locally: -1 when an unread conversation is opened (`MPListView.swift:497-502`), +1 when one is marked unread (`:536-540`).

Legacy also rewrites the count from the 3-cell header of every topic page (`MessagesTableViewController.m:931-944`, `OnlineMessagesTableViewController.m:442-453`). The captured MP thread pages (R123b, RA1, RU2) have a 2-cell header, so reading an MP does not refresh the count that way: the immediate drop is the local -1.

**Change.**
- `PrivateMessageCountingSource` wraps the root's `ForumDataSource`, so every home, topic-list, favourites and flags load hands its count to one `PrivateMessageCount`. The badge reads that count.
- Each load takes a ticket when it starts; the newest load to start wins, so a slow answer never puts back an older count.
- A page without the entry (nil) keeps the count. A logged-out home page sets 0: an expired session that keeps its root (same generation) still clears the badge, as before.
- `MessageListModel` takes one off when an unread conversation's last page is shown (the row's existing read rule), and adds one when HFR confirms a read conversation marked unread. Both decide from the row the list holds now for that conversation, not from the reader's value of the tap, which a later load can make stale. A conversation the list no longer shows (another page, deleted) keeps its "read here" mark through the load, so the tap's value is not taken for the row there either. A local change takes a ticket too, so a load already in flight cannot undo it (LESSONS 57).

What is counted, and what is not:
- **Counted, beyond legacy:** topic lists. Legacy's Swift layer parses their header (`ObjCTopicListParser.m:83-92`) without applying it; only the ObjC `TopicsTableViewController.m:426-427` applies it.
- **Not counted:** topic pages. `TopicPage` does not expose the count; the logged-in public topic captures R21 and R63a carry it.
- **Not counted:** the background check (LOT-140, #230).
- **Timing of the -1:** it comes when the last page is shown, not on the tap. Like legacy, it can drift until the next list load if HFR still holds the thread unread.

**Why this wide.** Every list load already goes through the one data source the tabs share, so no list model changed. The engine is untouched (its parsers already expose the count).

**Tests.** `PrivateMessageBadgeTests`; each test fails without its part of the change (seen through the gate, one mutation per part):
- `aLaterFavouritesPageReplacesTheCountOfTheHomePage`: home 7, then favourites 6, and the badge shows 6.
- `aTopicListHeaderUpdatesTheCountAndAPageWithoutTheEntryKeepsIt`: a header saying 0 updates the badge; a later page without the entry keeps it.
- `aLoadThatStartedEarlierNeverOverwritesANewerCount`: covers both orders of answers, a failed newer load, and a load in flight across a local -1.
- `aLoggedOutHomePageClearsTheCount`: 7, then a logged-out home page gives 0.
- `readingAnUnreadConversationToItsLastPageTakesOneOffOnce`: 7 to 6 only on the last page, once; a conversation already read takes nothing off.
- `markingAReadConversationUnreadAddsOne`: 6 to 7; a row already marked unread adds nothing.
- `aStaleThreadValueAfterAReloadTakesNothingMoreOff`: open (7 to 6), reload with the row read, the last page shown again with the tap's value: still 6.
- `aStaleThreadValueAfterAReloadStillAddsOneOnMarkUnread`: same setup, then a confirmed mark unread with the tap's value: 7.
- `aThreadOffThePageTakesNothingMoreOff` / `aThreadOffThePageStillAddsOneOnMarkUnread`: the same two cases after a load whose page no longer lists the conversation: still 6, then 7.

`RootModelTests` builds its root through the counting source; its badge test is renamed `theMessagesBadgeShowsTheCountTheCountingSourceRecorded`. Gate: full suite green on iPhone and iPad (1485 tests).

**Problem.** #904's last acceptance item: "With the switch off, no code path of this folder runs (a test)." No test covered it end to end. The existing ones check one entry point each: the reader's presentation (#985) and the control row and title (#903, #972).

**Change.** Tests only: a new hosted suite, `App/SwiftHFRTests/Experimental/ModernComposerOffHostedTests.swift`.

`ComposerPlacement.reader` runs on both paths, since it is the split itself. So "no code path runs" is checked through every modern-only behaviour the folder brings:
- the floating close, drafts and send buttons and the close glyph (`FloatingComposerButtons`), and the docked bar's fill (`DockedComposerBar`): their `ComposerLayoutProbe` parts must never report;
- the controls inside the card (`ComposerChrome`): the row must sit under the card;
- the partial height (`ComposerHeight`): the card must be at least half the window;
- the docked placement (`ComposerPlacement`): the reader's page must see no docked composer, and the reader must show legacy's cover on an iPhone and a sheet on an iPad (`coversTheScreen`, #985).

It runs on every composer entry point: a list's sheet (reply or new topic), a new MP's sheet (with its recipient and subject fields), and the reader's presenter.

**Control twin.** The same test runs with the switch on. On an iPhone the probes then see the floating parts, the controls inside the card, the partial height and, in the reader, the docked fill. So the off case cannot pass because a probe went blind. On an iPad the modern composer never runs, and the on case expects the off result.

**Tests.** `ModernComposerOffHostedTests.theOptionsFolderRunsOnlyWithTheSwitchOnAnIPhone(entry:modernComposer:)`: 3 entry points × 2 switch states. Every case checks the switch (`isPhone && modernComposer`), so a regression that runs a modern part with the switch off fails the off case, and a broken probe fails the on case.

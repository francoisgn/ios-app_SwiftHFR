## What and why
**Problem.** Under a gallery theme, native lists still show system grey rows, system separators and selection, and system label text on the themed background, so strong themes (Rétro 5250, OG) cannot look whole (#842, LOT-188 decision (a)).

**Cause.** LOT-188 drew only the tint, screens, prominent buttons, the unread capsule and the reader; rows need a per-row `listRowBackground`, left to #842. Operator decision of 2026-11-18 (option B): do it now through one shared modifier, ahead of #836.

**Change.**
- `App/SwiftHFR/Common/ThemedList.swift`, the one place the rule lives, colours only through `ThemeAppearance.themeColor(_:)`:
  - `ThemeAppearance.listColors`: nil for Legacy; otherwise row `surface`, `selection`, `separator`, `textPrimary`, `textSecondary`, `sectionHeader`, `title`, and `background` for sheets.
  - `.themedListRow(isSelected:legacySelection:)`: `listRowBackground` (surface or selection) and the row and section separator tint. It sets no text style, so `Button` rows keep the tint (Fable round 1).
  - `.themedRowText()`: `foregroundStyle(textPrimary, textSecondary)`, so `.primary` and `.secondary` text follow. It is applied only to a row's own content: forum, topic, search-result, MP, offline and draft rows. Other rows keep the system label, which `systemText/surface` checks.
  - `.themedSectionHeader()` (headers and footers), `.themedTitle()` (`ScreenLargeTitle`), and `.themedListScreen()` (the theme's `background` behind the four sheets on a plain `NavigationStack`).
  - `ThemedSection("…")`: `Section("…")` with those applied. It is sugar over the modifiers, not a list component.
  - `ThemedErrorStyle` (`.themedError`): row error text, at the former `.foregroundStyle(.red)` sites. It is `Color.red` for Legacy (unchanged) and `AccessibleColors.errorText` under a theme: the system red measures 3.75:1 on Noël abusé's rows.
  - Legacy: every modifier keeps `content` as is. Bookmarks keeps its accent selection through `legacySelection`.
- #651's read MP title (`ReadTitleStyle`) takes `textSecondary` under a theme. Sidebar and Plus labels that forced `Color.primary` take `textPrimary` under a theme, with the same code path as before on Legacy.
- Contrast rules (HFRKit `ThemeTokens.contrastRules`, a public `HFRModels` type, so the core orchestrator or the maintainer merges this PR per AGENTS.md §8):
  - `textPrimary`, `textSecondary`, `accentText` and `errorText` on `selection`;
  - `errorText` and `badgeOutline` on `surface`.

  `errorText` and `badgeOutline` are derived names for the app's `AccessibleColors` colours.
- Docs: THEMES.md §3 (where each token is drawn now, the new rules, why the system secondary label has no rule), LOT-188 spec notes, `AccessibleColors` comment.

**Rows use `surface`**, as THEMES.md §3 says; `surfaceRaised` stays for raised elements (orchestrator decision on #842).

**Out of scope:** destructive row buttons keep the system red, exactly as on `dev-swift`. Theming them is tracked in #1121, which needs a Legacy no-op modifier and rendered tests (Fable round 4).

**Width.** The change is wide (every list) but shallow. Each `Section` body is wrapped in `Group { … }.themedListRow()`, so the header is never touched by a row modifier and no row trait is stacked on a row that sets its own. Use `git diff -w`: most lines are re-indentation. No list was merged or refactored (#836).

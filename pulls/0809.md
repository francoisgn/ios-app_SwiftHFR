## Problem
The « Icône » screen listed nine names in one list: no packs, no dates, no Noël icons, and no way to see an icon before choosing it (operator, 2026-11-11: the picker must show a preview of every icon).

## Cause
`AppIconOption` had no pack and no window, the view was a plain `Form` of text rows, and the system gives no API to read an alternate icon's image at runtime.

## Change
- `AppIconOption` (now in `AppIconOption.swift`) gains `pack` (`AppIconPack`: Legacy, Beta, X-face, Saisons) and an optional `window` (`IconWindow`, month/day, both ends included, year-wrapping allowed). Raw values and `alternateIconName`s of the 9 shipped options are unchanged (legacy key `icon`). Two cases added: `noel-redface` (`Icon-NOEL-REDFACE`) and `noel-hfr` (`Icon-NOEL-HFR`), window 01/12 to 26/12.
- `AppIconSettingsModel` takes an injected `calendar` and `now`; `sections` lists the options offered today by pack (the active dated icon stays listed after its window so the ring shows where the user is); a dated icon outside its window cannot be chosen. Choosing a dated icon from a plain one stores the plain one under the new key `icon_previous`.
- `AppIconSeasonModel` + `appIconSeasonAlert`: on launch, a dated icon active after its window triggers « Revenir à l'icône précédente ? » [Oui] [Garder] once per season (`icon_revert_asked` = `<icon>:<year the window ended>`); Oui applies the previous icon (user answer, system call), a refused switch asks again next launch. Both keys are new, device-local, in the `SettingKey` catalogue.
- `AppIconSettingsView` is a grid per pack: preview, name, selection ring (VoiceOver: name and selected trait).
- Noël icons: Icon Composer bundles in the same layout as #731's (full-art PNG layers with Default, Dark and Tinted via `hidden-specializations`, `Icon-<RAW VALUE UPPERCASE>.icon`), registered in `ASSETCATALOG_COMPILER_ALTERNATE_APPICON_NAMES` in both configurations. Default layers: `noel-redface.jpg` converted to PNG; `noel-hfr.svg` rendered at 1024 px by headless Chrome (the redface SVG cannot be regenerated: the Blender renders `icons.py` needs are not in the repository, README of `tooling/illustrations`). Dark and Tinted derived by `tooling/icons/make-variants.swift` (dimmed / greyscale).

## Thumbnails: approach and why
No public API reads an alternate icon (`UIApplication` only returns its name), and `UIImage(named:)` cannot load an app icon set. So the previews are **image sets in the app's asset catalogue rendered from the same `.icon` files** with Xcode's `ictool` (`scripts/icon-previews.sh`): the thumbnail is the real masked icon, the Dark rendition goes in the image set's dark appearance so the grid follows light and dark, and no art is duplicated by hand. Cost: 3.7 MB of 360 px PNGs for 11 icons (about 340 KB each). Kept in sync by the script (rerun after a redraw) and by `everyOptionHasAPreviewImageInTheAppCatalogue`, which fails when an option has no image set.

**Convention for #731 (data-only addition of an icon):**
1. `App/SwiftHFR/Icon-<RAW-VALUE-UPPERCASE>.icon` (as the 20 bundles of #805).
2. A new `case` in `AppIconOption.swift`: raw value, `title`, `alternateIconName` (the bundle name), `pack` (`.beta`, `.xface`, `.season`, existing enum), `window` (nil = all year).
3. `scripts/icon-previews.sh Icon-<NAME>` renders `Assets.xcassets/IconPreviews/IconPreview-Icon-<NAME>.imageset` (name = `IconPreview-` + bundle name); commit it. Run without argument to render every icon.
4. The name in `ASSETCATALOG_COMPILER_ALTERNATE_APPICON_NAMES` in both configurations.
No view or model change. Merge order: whichever lands second resolves the one `AppIconOption` enum and the build-setting string; CREDITS rows are one per PR.

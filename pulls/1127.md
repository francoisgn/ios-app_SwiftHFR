### Problem
`DuoLayoutHostedTests/aFoldShowsTheTopicOpenInTheTab(tab: .messages)` (#1115) went red at `DuoLayoutTests.swift:294` (before the fold), then `:298`, locally and in CI (#1122, run 44306381806: stacks `[["Messages"], [""]]`, then `[["Messages"]]` once folded).

### Cause
Test setup, not app code. `host()` built the Messages list with the default `isLoggedIn: { false }` (`MessageListModel.swift:75`), while Favoris is built logged in. `MessageListView` loads the list each time it appears (`.task { await model.onAppear() }`), and a logged-out load answers `.signedOut`, which closes the open conversation (`MessageListModel.swift:357`, `if loader.value == .signedOut { selected = nil }`). So the case raced the reader's title against that load: it passed only when the reader showed `Sujet 7 p1` first.

Evidence (temporary prints, not committed, iPhone 18 Pro simulator): every red run logs `load signedOut clears selected=topic:prive-7` after the test set the selection, and at `:294` `selected=nil signedOut=true`. `rootSwapped` (the suspect in #1115's Fable round 2) is not involved: in the Messages case it is not called before the fold, and every call ran with `messages.selected=nil`. The same log also explains the R1 mutation note of that review: its red at `:294` came from this load, not from the mutated `rootSwapped`.

App behaviour is right: a logged-out list must not keep a conversation open, and a logged-in reload (the fold's new list) keeps it. That is the LOT-126 spec (`docs/lots/LOT-126-mp-list.md`, rows "Logged out" and "Session refused": the open conversation is closed), and legacy drops the selections when the account goes (`handleCurrentAccountChange` calls `clearTopicSelections()`, `MainWindow.swift:2521-2531` @ 87fe0d1c) and empties the MP list logged out (`MPListViewModel.clearForLoggedOut`, `MPListView.swift:327-334` @ 87fe0d1c).

### Change
`App/SwiftHFRTests/Root/DuoLayoutTests.swift` only:
- the Messages model is logged in (`isLoggedIn: { true }`), as Favoris;
- the Messages case waits for the split list's first load to end before the fold, so the load counted afterwards is the cover screen's own;
- it then waits for that load (`FakePrivateMessages.requests` grows, loader idle), gives `load()` the main-actor hop it takes after `isLoading` drops plus a layout pass (500 ms, as `aTopicClosedOnTheCoverScreenDoesNotComeBackUnfolded`), and checks both `messages.selected` is still conversation 7 and its title is still shown, so a loss at that reload cannot hide behind the frames before it (round 1, Fable).
Nothing wider: no other hosted test selects a conversation on a logged-out list (`grep messages.selected =` in `App/SwiftHFRTests`).

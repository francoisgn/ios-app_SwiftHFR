**Problem.** Below 100 % the reader's text goes under 11 px (HIG minimum, floor applied to the lists since #1157/#1236). At 70 % and the default Dynamic Type size, measured in the real reader: body 10.5 px, date 10.1, quote header and signature 8.9, "Nouveau" badge 8.3, quoted bubble 9.1, trailer 10.1.

**Cause.** `ReaderWebController+Scripts.swift:88` only sets `--text-scale`; `reader.css` multiplies every size by it (`body` `font-size`, `--content-em`, and `em` ratios of 0.85, 0.765, 0.7) with no floor.

**Change.** `reader.css`: one floored variable per ratio (`--fs-body`, `--fs-content`, `--fs-85`, `--fs-765`, `--fs-70`, `--fs-85-content`), each `max(scaled, min(unscaled, 11px))`, the rule of `TextScale.pointSize`. The `min(unscaled, …)` keeps 100 % and above unchanged, including at small Dynamic Type sizes. Floored per element because an `em` chain would floor only the parent. `ReaderTextScaleTests` now uses 80 % (its 70 % factor check no longer holds under the floor). Legacy never goes below 100 % (`Common.swift:314-322` @ 87fe0d1c): the range is SwiftHFR's, no ledger entry (per the issue).

**Tests.** New app-hosted WebKit suite `ReaderTextFloorWebTests` (iPhone Duo, iOS 27.2 simulator): reads computed font sizes of content, date, quote header, bubble, badge, signature, trailer.
- `at70PercentEveryTextIsAtLeast11Px`: red before the CSS change (7 issues, values above), green after.
- `at100AndAboveTheSizesAreTheUnscaledOnesTimesThePercentage`: green before and after (100 % and 130 % unchanged).
- Also green: `ReaderTextScaleTests`, `ReaderMarginsWebTests`, `ReaderLegacyStyleWebTests`, `ReaderPlusButtonWebTests`.

Not covered: elements not named by the issue that keep an `em` of a floored parent (avatar, paddings) grow slightly at the floor; the floor ignores Dynamic Type sizes below the default beyond the `min(unscaled, 11px)` rule.

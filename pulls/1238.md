## What and why
**Problem.** `MessageBlockParser.extract` threw `missingElement` for the whole page as soon as one `messagetable` block lacked its `s2` cell, its `t<n>` anchor or its `para` element: the reader (and `MessageActionsParser`, `MPStoragePageParser`, `FilteredPostsFlow` through it) turned one odd block into an error page. Legacy read each message on its own with nil fields (`HFRswift/Wrapped/ParseMessagesOperation.m:139-177` @ `87fe0d1c`); our list parsers already skip an unreadable row and fail only when every row fails (LESSONS 44).

**Change** (`HFRParsing` only).
- `MessageBlockParser`: the block reading moves to `block(in:isFirst:)`; `extraction(from:)` (internal) skips a block that throws, counts it (`Extraction.skipped`) and keeps the failure of a block skipped before any readable one (`leadingFailure`). The page throws its first block failure only when it has message blocks and none is readable. Advertisement blocks are skipped as before and not counted. Only the page's first message block, readable or not, can be the continuation copy. `extract` and `blocks(in:)` keep their signatures.
- `MessageActionsParser` uses the same `extract`, so the action sets stay aligned with the blocks (the reader pairs them by position).
- `MPStoragePageParser.firstMessage` refuses a page whose first block was skipped (`unreadablePage`): it edits that message, so the next one must never pass for the document.
- `docs/lots/LOT-030-message-blocks.md`: the API rows (incl. `extraction(from:)`, its count internal until a consumer shows it) and difference 7.
- No hand-built deleted-post block: #123 captures `messagetabledel`.

## How it was verified
`swift test` on HFRKit (Linux): **2172 tests green**. Suite `MessageBlockUnreadableTests`, captures broken in memory inside one block only:
- `skipsUnreadableBlock` × 3 on `R20` (anchor / `s2` / `para` renamed on message 2666682): the other blocks in order, `skipped == 1`, actions aligned. **Fails on the base.**
- `aBlockAfterASkippedFirstOneIsNotTheContinuation` on `R22a` (continuation block broken, its own lead moved to the next message): not a continuation. **Fails with the first-readable rule.**
- `storageRefusesAnUnreadableFirstBlock`: **fails with the skip but without the MPStorage guard.**
- `everyBlockBrokenThrows`: the rule kept (passes on the base too; a mutation removing the none-readable throw fails it).

No GAP row for LOT-030 and no legacy-app fix: no `### Ledger` section.

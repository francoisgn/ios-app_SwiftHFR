Closes #756
Claim: cloud/i756-sonnet

**Problem.** HFR refuses an edit POST of another account's message (`W440c`) with a link-less `.hop` ("Vous n'avez pas les droits pour éditer ce message !") that refreshes to the thread after 3 s. The app reported `unconfirmed(.unrecognizedAnswer)` instead of a refusal.

**Cause.** `HopResponseParser.classify` (LOT-037) calls a `.hop` a refusal only with a link or input, and a success only with "avec succès": this one has neither.

**Change.** Under `.write` only, a `.hop` whose sentence contains "pas les droits pour éditer" is `rejected`, with its sentence. Sentence, not shape: a sweep of the 282 HTML captures found `W440c` to be the only link-less `.hop` that is a write refusal (the others are lists R08, search wait R50a, login/stale-session/profile pages R70/R71/W01/W03, poll W42/W45). Not widened: a negation rule would also catch login pages and has no second capture behind it. `W17c` handling and the success sweep are unchanged. Docs updated: HFR-PROTOCOL bullet, LOT-037 table row, LOT-052 outcome.

**Tests** (`swift test` in `Packages/HFRKit`; SwiftLint strict clean on the touched files). Both fail without the source change (shown: `unrecognized` / `unconfirmed` instead of `rejected`):
- `HopResponseEditRefusalTests.rejectedUnderWrite`: `W440c` is `rejected` with its sentence under `.write`; `otherContextsUnchanged`: still `unrecognized` under `.alertPrepare`.
- `MPStorageTransportWriteTests.anotherAccountsMessageIsNotASuccess`: now expects `.posting(.rejected(message:))`, one POST, no retry.

Review: Opus round 1 REQUEST CHANGES (lint `type_body_length`, stale docs), fixed in ac428ca; round 2 APPROVE on ac428ca (verdicts posted).

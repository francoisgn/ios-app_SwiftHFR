## What and why

**Problem.** After a confirmed edit in an MP, the reader kept the text from before the edit; only the round arrow showed it (#908).

**MP path vs topic path: one path, nothing to merge.** Topics and MPs use the same `TopicReaderView` (`MessagesRootView` → `MessageReaderColumn`), which installs the same `MessageWriteModel` (`TopicReaderView.swift:372-375`).
- Edit: `ReaderEditFlow` → `MessageWriteModel.editorDidClose` → `TopicReaderModel.reloadPage(at:)`.
- Reply: `ReaderReplyFlow` → `composerDidClose` → `showLatestPost()`.

The only MP difference is the pager follow (LOT-128), which is deliberate.

**Ruled out.**
- `reader` is the same weak reference, to the model the view holds.
- No page cache: `urlCache = nil` (`HFRSession.swift:60`, `AnonymousTransport.swift:36`) and `.reloadIgnoringLocalCacheData` (`URLSessionTransport.swift:51`).
- A delivered reload is a new document token.
- Since #750, a web view that is in a window is never left stopped. A resume added in round 1 was removed in round 3 because it could only act off screen.

**Cause addressed (not reproduced on a device).** `viewDidDisappear` → `cancel()` stops the reload a send starts, and `onAppear` loads again only when no page is shown, so the edited page never comes. That gives the reported symptom: old text, no error, and the round arrow fixes it.

**Change.** `TopicReaderModel.owedFollowUp` records the reload a write owes: `.page(message:)` for an edit or a delete, `.latestPost` for a reply.
- **Settled:** in the load task's own main-actor turn, once a load delivers a page or a failure ("Réessayer" asks the same page). A conversation's first pager step (`settles: false`) does not settle it.
- **Kept:** a cancel leaves it in place.
- **Run once:** at the next `onAppear`, never while a composer is open (#653), or when the last composer closes while the reader is on screen (`owedTask`).
- **Unchanged:** closing without a send reloads nothing. An unconfirmed send keeps its single reload and shows no success. Nothing is sent again.
- **Docs:** LOT-083's edge case names the exception.

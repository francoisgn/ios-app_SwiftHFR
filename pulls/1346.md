## Problem
After LOT-140, reading or marking unread an MP from a list older than a background check replaced the whole ledger set with the stale one: a thread could be notified twice (a), or a reply to a conversation the stale list showed read went unnotified (b).

## Cause
`MessageListModel.markOpened` / `markUnreadEnded` called `recordReadState`, which records the whole page-1 unread set (replace), and `markOpened` recorded nothing when the list showed the row read.

## Change
- `NotificationLedger.setThread(_:unread:)` + `NotificationLedgerStore.setThread(_:unread:account:)`: one-step removal (read) or insertion with the highest mark (mark unread) of one conversation; no change without a recorded set (first check stays the baseline).
- `MessageListModel` gets `ledgerThread`; `markOpened` always removes the conversation (whether or not the list showed it unread), `markUnreadEnded` inserts it (page 1 only). The whole set is still replaced only after a list load (`recordReadState`).
- Same ledger key: both go through `NotificationLedgerStore.update` / `AccountKey.make`.

## Tests
- `NotificationLedgerSetThreadTests` (engine, run here: 6 pass).
- `MPNotificationOpenTests.readFromAStaleListKeepsTheCheckSLedger` (a) and `readFromAListShowingItReadStillClearsTheLedger` (b): drive the model and the real background check; with the old `recordReadState` path (a) renotifies 12 and (b) never renotifies 11. Not runnable on Linux: red/green to be confirmed by the Compile check / Mac run.
- Adjusted `aCancelledReloadKeepsTheMarkedUnreadConversation` and the two ledger-wired open tests.

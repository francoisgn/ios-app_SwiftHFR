## What and why
**Problem.** The transport maps every `URLError.cancelled` to `.cancelled` (`URLSessionTransport.swift:166-171`), also one nobody asked for (#566). Only the reader retried it. Elsewhere `.cancelled` meant "the user went away": blank Messages list / endless profile spinner (`ContentLoader.finish` set neither value nor error), "Chargement…" for ever in Alertes Qualitay (`hasLoaded` stayed false), a filter banner that vanished with no result, an in-topic search sheet that went back to the form silently (#1191). And `MessageListModel.load(page:)` dropped the Bool of `loader.load`, so after a load that applied nothing it cleared `openedThreads` / `markedUnread` and handed the old page to the ledger (#1192).

**Change.**
- `App/SwiftHFR/Navigation/UnrequestedCancellation.swift` (new): `retryingUnrequestedCancellation(cancelledAs:_:)`, the reader's rule as one helper: a cancellation while the calling task is **not** cancelled is asked once more; a second one is thrown. Runs on the caller's actor (`#isolation`). For reads only.
- `ContentLoader.load(retriesUnrequestedCancellation: = true, …)` uses it; `finish` turns a `.cancelled` that still holds the current generation (neither `cancel()` nor a newer load asked for it) into `.other`. Every `ContentLoader` screen gets "Réessayer" instead of a blank.
- `ForumSearchModel.search()` passes `false`: the search starts with a POST that LOT-046 never sends twice, so the failure shows at once; its pager GETs keep the retry.
- `FilteredPostsModel.read`, `QualityAlertsModel.load`: same helper; `.network(.cancelled)` is "stopped" only when `Task.isCancelled`, else a failure (filter: "Une page n'a pas pu être lue.", AQ: `.other` with `hasLoaded`).
- `TopicSearchModel.submit` (a POST, no retry): an unrequested cancellation shows "Impossible de joindre le forum."; `cancel()` stays silent.
- `TopicReaderModel.fetch` uses the helper instead of its own copy (same behaviour, covered by `anUnrequestedCancellationIsAskedAgainOnce` / `aRepeatedUnrequestedCancellationIsAnError`).
- `MessageListModel.load(page:)`: `let applied = await loader.load {…}`, the `.notAuthenticated` branch unchanged, then `guard applied else { return }` before the marks, `recordReadState()` and the segment advance (as `TopicListModel`). Defensive after the `ContentLoader` change (a double unrequested cancel now ends on the error branch), but it closes the class.

## How it was verified
- `ContentLoaderTests` built and run on Linux in a scratch package (ContentLoader + ListLoadError + helper over HFRKit): the two #1191 tests **fail without the change**; all 10 pass with it, incl. `aRequestedCancellationIsNotRetried` and `anOperationThatMustNotBeSentTwiceFailsAtOnce`. The old `aCancelledLoadIsNotAnError` encoded the bug and is replaced.
- Read, not run here (app target; Mac/CI): `QualityAlertsModelTests.aCancellationNobodyAskedForIsRetriedOnce` / `aCancellationNobodyAskedForEndsTheLoad`, and `aCancelledFirstLoadIsNeitherAFailureNorAnEmptyList` now really cancels the visit's task; `FilteredPostsModelTests.aCancellationNobodyAskedForIsRetriedOnce` / `aCancellationNobodyAskedForIsAFailure`; `ForumSearchModelTests.anUnrequestedCancellationOfTheSearchIsAFailureAndSendsItOnce`; `TopicSearchModelTests.anUnrequestedCancellationIsAFailureAndSendsTheSearchOnce` (replaces `aCancelledSearchIsNotAFailure`); `MessageListReadStateTests.aCancelledReloadKeepsTheLocalMarks`, `aCancelledReloadKeepsTheMarkedUnreadConversation`, `aReloadTheTransportCancelsKeepsTheLocalMarks`. Each fails on the base for the reason named.
- SwiftLint 0.65.1 `--strict` on every changed file: clean. The helper's call shapes compile in Swift 6 mode with `-warnings-as-errors`.

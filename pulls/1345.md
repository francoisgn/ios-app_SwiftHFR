### Problem
The three Réglages sliders (text size, accent hue, dark brightness) lag.

### Cause (from the code; not measured)
Each tick set the model property directly: hue wrote two store keys and rebuilt both accents (up to 1,000 steps), brightness and text size wrote one key each. Every model change also invalidates the app root (`appTheme`, `textScale`). Instruments is not available from a Linux session, so the per-tick cost is not measured here (see below).

### Change
- New `SliderDraft`: while a drag is on, the value lives in a `@State` draft; the model/store get the final value once on `onEditingChanged(false)`. A change outside a drag (VoiceOver increment/decrement) is saved at once, each step.
- `ThemeSettingsView`: hue and brightness sliders, their readouts, and the mode tiles / light / dark previews follow the draft live; the app root follows on release.
- `SettingsView`: text size slider extracted to `TextSizeRow` (re-render scoped to the row); percentage follows the finger, the app-wide scale changes on release.
- Hue step left at 0.001: not changed without a measurement.
- No coalescing timer: release-only is the simpler of the two options in the issue.

### Tests
`SliderDraftTests` (app tests, cannot run on Linux): 200 drag ticks → 0 store writes, exactly 1 on release; tap without movement → none; steps outside a drag → saved each. Red on today's code: `SliderDraft` does not exist, and a direct model assignment writes per tick.

### Measure on a Mac (owed, #893)
Time Profiler + SwiftUI instrument, 3 s drag per slider, before/after: main-thread ms/s, root `body` evaluations, store writes, reader script injections. Device check: the three sliders follow the finger.

**REQUEST CHANGES**, head ae8d89ca5a89bc176128d96815c4a503d4f469b3

1. **Medium**, `App/SwiftHFR/Settings/ThemeSettingsView.swift:21-28` (`previewAppearance`). With the Legacy theme selected, the previews replace the stored accents and brightness even when no drag is in progress. `ThemeSettingsModel.init` keeps `theme_day_color_action` / `theme_night_color_action` as stored (an older version may have set any colour; the night accent is a key of its own). A user with a day accent of saturation 0.3, or a night accent of another hue, sees `dayTint`/`nightTint` of `accentHue` in `ThemeModeTiles`, `LightStylePreview` and `DarkStylePreview` instead of the colours the app uses. Breaks "behaviour unchanged". Fix: override accents only when `hueDraft.draft != nil`, and `darkBrightness` only when `brightnessDraft.draft != nil`.

2. **Low**, `SliderDraftTests.swift`. The tests cover only `SliderDraft`; removing the wiring from the three views leaves every test green, so "a drag writes once" is never tested on the shipped path. Fix: move the save/`editingChanged` glue into a testable helper shared by the views and test it with `CountingStore`; otherwise say the wiring is checked by hand and add it to #893.

3. **Detail.** If the row disappears while a finger is down (e.g. theme switches away from Legacy), `onEditingChanged(false)` may never fire and the dragged value is dropped silently. Acceptable, but the code should say so.

Checked, nothing to report: `@State` mutation via `mutating` calls in the `Binding`/`onEditingChanged` closures; local `@Bindable` capture in `Binding(set:)` (same pattern as `SecuritySettingsSections.swift:51`); `CountingStore` vs `SettingsStore: Sendable`; test initial state. `swiftlint lint --strict` clean on the 4 files; no build or test run (Linux).

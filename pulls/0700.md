**Problem.** The LOT-118 review left five small findings: a swipe-delete turned offsets into pseudos inside its background task (two quick swipes could remove the wrong member or flash a row back), a weak-capture rule broken by the profile hook, footers reworded against legacy, an outdated spec paragraph, and silent profile list buttons for VoiceOver.

**Change.**
1. `PseudoListEditorModel.remove(at:)` is synchronous up to the write: it resolves the pseudos and drops them from the list at swipe time, then chains the writes in one task; the list is read again only when the last pending removal is done. The view calls it directly.
2. `TopicReaderView.makeController` builds one `[weak model]` closure for the profile hook.
3. Footers are legacy's words again (`AppSettingsView.swift:671-678` @ 2fe43da3).
4. LOT-118 spec: avatar menu paragraph updated (#638 merged).
5. Profile list feedback is announced to VoiceOver (`AccessibilityNotification.Announcement`).

**Tests.** `twoQuickSwipesRemoveTheTwoSwipedMembers` (PseudoListTests.swift); on the old code `remove(at:)` was `async` and resolved offsets in the task, so the second swipe hit the wrong row. Reviewed by Opus 5.5, APPROVE on f32fa36 (3 rounds). Not run: the cloud cannot build the app; CI will.

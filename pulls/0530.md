**Problem**: some app tests wait on timing (an unbounded `Task.yield` spin, 100 ms sleeps), which is flaky on a loaded simulator (#366, #468, #517).

**Changes** (tests only, no app code)
- `ContentLoaderTests`: private `Gate` with an unbounded `while !arrived { await Task.yield() }` replaced by `CheckGate` (`run` / `entered`); suite gets the 5 min hang backstop (#366).
- `PseudoListsSnapshotTests`: `while model.isRunning { await Task.yield() }` replaced by `await model.settle()` (resumed by the run's own task).
- `ReplyComposerDraftTests` (2 sites) and `ReplyComposerSendTests` (1 site): the 100 ms sleeps before an "absence" assertion replaced by `await composer.waitForAutosave()`: it returns at once when the operation settled the autosave, and waits for a pending write otherwise, so a late write still fails the unchanged assertion. No clock needed.

**Grep of `App/SwiftHFRTests`** (`Task.sleep`, `Task.yield`, `.timeLimit`), found and left, with reason:
- `AccountsModelTests:129`: bounded (200) yield loop; a second restore must NOT reach the checker, so this is a bounded negative wait that no signal can report. It cannot fail a correct build.
- `AppThemeTests:31`, `ListDensityLayoutTests:47`: bounded polls of SwiftUI render/layout, no completion signal exists.
- `ReaderWebSecurityTests:72,114`, `ReaderWebControllerTests:65,80,116`, `ReaderWebTestSupport:82,92`, `ConnectionCounter:40`: real WKWebView / loopback polling or absence waits (comments cite why).
- These stay outside the issue's "no yield loop used to wait" criterion; the maintainer may narrow it on #521.
- `.timeLimit(.minutes(5))` already on Message*/FilteredPosts* suites (now ContentLoaderTests too); no `.minutes(1)` found.

**Run**: SwiftLint `--strict` on the changed files: 0 violations. Not run: app build and tests (Linux); CI is the arbiter.

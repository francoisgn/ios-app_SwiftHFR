**Change.**
- `PostCharacterCheck` (HFRModels): per character, `.truncates` (a scalar above U+FFFF: Q-3, `W12`) or `.untested` (U+FE0F, or an emoji scalar above U+00FF: CAP-N3 #171 not captured, never refused); `riskyCharacters(in:)`, `truncatingCharacters(in:)`.

- `EmojiSmileyTable` + `Resources/EmojiSmileys.json`: 49 emoji → codes of the bundled catalogue (LOT-012), best first, only smileys whose file name says what they show; lookups ignore U+FE0E/U+FE0F and skin tones.

**Merge.** Adds HFRModels public types: for the steward or the maintainer (AGENTS §8). It also touches `PostingFlow.checkInput`, which #359 changes too; coordination note posted there.

**Tests.** `EmojiSmileyTableTests` (every code in the catalogue; keys normalised; lookups with selectors and skin tones; no entry), `PostCharacterCheckTests` (truncating, untested and plain characters; order and uniqueness), `PostCharacterAgreementTests` (the posting flow refuses exactly `truncatingCharacters` and sends untested emoji); `PostingInputTests` unchanged and green.

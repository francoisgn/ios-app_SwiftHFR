**Problem.** At the first launch, iOS's notification prompt appears before any login (`SwiftHFRApp.swift:104-105` → `MPNotificationCenter.prepare()` → `requestAuthorization`). For a logged-out user it means nothing: MP notifications and the badge concern a logged-in account. HIG › Privacy, « Requesting permission »: "Avoid requesting permission at launch unless the data or resource is required for your app to function" and "wait to request permission until people actually use an app feature that requires access".

**Cause.** A port of legacy's launch request (`HFRswift/Swift/HFRswiftApp.swift:27-29` @ `87fe0d1c`, LOT-140).

**Change.**
- At launch, `MPNotificationCenter.registerCategory()` only registers the `mp` category. No prompt.
- `MPNotificationPrompt` asks when an account becomes current, through `AppLifecycle.currentAccountChanged`: a stored account restored at launch, a login, or a switch. This runs once per change, whatever the number of windows.
- It asks only when all of these hold: iOS never asked (`.notDetermined`), and « Notifications » or « Badge messages non lus » is on.
- Logged out, it never asks. After any answer, it never asks again (iOS would not show the prompt anyway).
- Réglages › Notifications MP asks when either switch is turned on: « Notifications » as before (#1060), and « Badge messages non lus » too now (an account can be current while iOS never asked, when both switches were off at the login).
- When an account becomes current, the prompt comes before the account's legacy import step, so it never lands over the import summary.
- `LiveNotificationPermission` is now the only caller of `requestAuthorization(options:)`.
- LOT-140 §Permission and §Tests are updated.

**Tests** (app-hosted; not run here, since Linux cannot build the app):
- `MPNotificationPromptTests`:
  - logged out → no request;
  - an account becoming current → one request, and none for a second account once iOS answered;
  - already allowed, denied or badge-off → none;
  - both switches off → none;
  - the pure rule `asks(account:notifications:badge:authorization:)`;
  - `onlyThePermissionSeamAsksIOS`: red before the change, because `MPNotificationCenter.swift` called `requestAuthorization(options:)`.
- `MPNotificationPermissionTests.turningBadgeOnWhileNeverAsked`: turning the badge on while iOS never asked shows the prompt, with no alert (red on the old `badgeTurnedOn`).
- `MultiWindowTests.theNotificationPromptComesBeforeTheAccountsImportStep`: the whole log of an account change is `ask`, then `importForAccount`.
- `MultiWindowTests.everyWindowSeeingAChangeRunsItsReactionOnce`: the prompt step runs once for the account change. The launch test's exact step list shows the launch never asks. Both are red before the change: `Steps` had no such step.

SwiftLint 0.65.1 `--strict` clean. `ledger.py check-body`: 2 blocks ok.

Device check (#893):
- Fresh install, logged out: no system prompt.
- Log in: the prompt shows once.
- Relaunch: no prompt.
- After a launch whose account restore ran while no window was active, the first activation still shows the prompt, and the account's legacy import step still runs.

## What and why
Adds `docs/ux/questionnaire/cadrage-construction.md` (French): the framing for building the survey, complementing the per-lot briefs of `docs/ux/cadrage-agents-questionnaire.md`. The issues stay the source of truth.

It adds what the briefs lack:
- the flow screen by screen, with a stable ID per question (`E0`, `P1`–`P3`, `O1`, `L1`–`L2`, `D1`–`D2`, `C01`–`C11`, `M1`, `F1`, `I1`, `E1`) and a time budget;
- contracts between lots: stable answer codes, a fixed block format for `questions.md` checked by a test against the form's content file, naming and size rules for visuals;
- constraints for the form spec (#633): no third-party requests, accessible card sort, single submission, threshold before live stats, closing date and removal;
- theme 1: capture SwiftHFR where an improvement already exists instead of drawing mock-ups (#632);
- six PO decisions still open (D1–D6), none blocking wave 1;
- known gaps between the archive and the issues, and three follow-up lots without an issue (trial, opening, analysis), to create only with the PO's agreement.

`docs/ux/README.md` gets a one-line pointer to it.

This is a framing document, not a decision to implement: it changes neither `LOTS.md` nor `FEATURES.md`.

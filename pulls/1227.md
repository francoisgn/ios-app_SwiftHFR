### Problem
The seasonal arrival alert is informative, shown at app start, with a title (« Oh Oh Oh ! ») that says nothing, and neither button has the cancel role, so Esc / ⌘. on a hardware keyboard has nothing to trigger (HIG › Alerts: a title that describes the situation; avoid alerts that only inform). Legacy has the same class of alert, simpler (`Classes/HFRplusAppDelegate.m:665-676` @ 87fe0d1c, GAP-147).

### Cause
`SeasonalArrivalAlert` used the greeting as title and plain buttons; its binding setter ignores dismissal, so only a button can answer.

### Change
This is the **smallest step** of the issue; the larger one (no alert, a note in Réglages › Thème) remains the operator's call. **The title wording is mine to confirm.**
- `SeasonalThemeModel.title(for:)` names the situation **from the model's state** (review round 1: the alert is also pending when nothing was switched on, on 25–26/12, with automatic themes off, or after the user picked another theme first): « Thème de Noël activé » when a theme is active, « Thème de Noël » otherwise. `Alert.message` keeps « Thème disponible dans les réglages ».
- `SeasonalArrivalAlert` uses them and gives « OK » `role: .cancel`, so Esc answers « OK » (keeps whatever is on) through the existing `answer(disable: false)`.
- Docs that quoted the old title: `docs/THEMES.md` (Noël row, and a note on the Samain row: LOT-191's title must name the situation and be true when nothing is switched on), `docs/lots/LOT-166-seasonal-noel.md`, the mockup note in `docs/assets/themes/tokens/themes.json`, the mockup generator `tooling/illustrations/build.py`; code comments. The Samain alert itself is not implemented (`Alert` has only `noelArrival`); its wording stays for LOT-191.

### Tests
`SeasonalArrivalAlertTextTests` (model-backed): on 01/12 Noël soft is on and the title is « Thème de Noël activé »; on 25 and 26/12 and with automatic themes off nothing is on and the title is « Thème de Noël » (these fail with the first version's constant); no title greets. The cancel role and Esc are SwiftUI wiring: Mac check on #893 (iPad with a keyboard: Esc dismisses it keeping the theme). Not run here (Linux); `compile-check` runs on the head.

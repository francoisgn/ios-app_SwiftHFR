**Merge:** by the core orchestrator or the maintainer (AGENTS.md §8): the PR adds a public `HFRModels` type (`SubforumTarget`).

**Problem.** Inside a sub-forum there is no Tous / Favoris / Suivis / Lus filter. #427 only did categories, because the app knows a sub-forum by its path only.

**Cause.** HFR filters a sub-forum with the category list URL plus `subcat=<s>` (`R603d`), and the home links give no id. The sub-forum's page names its category and subcat in the `md_btn_new_topic` link (`R06`: own page, logged out; `R603d`: filtered page, logged in). A category page does not (`R09`).

**Change.**
- `SubforumTarget` (HFRModels) reads cat and subcat from `newTopicPath`.
- `topicList` takes an optional `subcategory`. With it, the request is `R603d`'s exact query; a category keeps its short form.
- `TopicListModel` loads the sub-forum page, learns the target, then asks for the stored choice with `subcat=<s>&owntopic=<n>`.
- The filter is offered only once the id is known. Logged out stays on Tous.
- No REST dependency (#873).
- `docs/HFR-PROTOCOL.md`: the R2 row and the §6c bullet.

**Tests.**
- `SubforumTargetTests`: fixtures `R603d`, `R06`, `R09`, plus malformed paths.
- `HFREndpointReadTests`: `topicListOfASubforumIsTheCapturedR603dUrl` (exact string) and `topicListOfASubforum` (long-form variants).
- Four `TopicFilterTests` cases: filtered at first load; reload and paging with subcat; page names none; logged out.
- Full iPhone and iPad suites pass.

**Pending capture.**
- The sub-forum's own page, logged in.
- A page where the viewer may not post.
- An empty sub-forum.
- The filtered URL with an expired cookie.

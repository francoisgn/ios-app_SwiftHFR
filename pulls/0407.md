Closes #342
Claim: cloud/i342

**Problem.** A `PostingForm` loaded before a logout, or before a login of another account in the same `HFRSession`, still carries the old page's `hash_check` and `pseudo`. Submitting it sends them with the new cookies: HFR refuses it (`W17b`), so nothing crosses accounts, but the user sees HFR's bad-token sentence instead of a clear local error.

**Cause.** `PostingFlow.loadForm` took a `HashCheckSeed` (#308) but dropped it; `submit` never compared the session's identity with the one the form was fetched under.

**Change.**
- `PostingForm` keeps the `HashCheckSeed` taken before the form's GET.
- `PostingFlow.submit` throws the new `PostingError.sessionChanged` before any request when the session's `userKey` is not the seed's identity (logout → nil, other account → another key; a nil seed identity fails closed). It sits after the local input checks and the cancellation check, right before the POST, so every write (reply, new topic, new MP, edit, delete) gets it.
- Same-account re-login still sends: the refreshed token is HFR's to judge (#315).
- App: `ComposerMessages` says the account changed and nothing was sent (exhaustive switch); `ReplyEntryTests` lists it among "not posted".
- Optional nits from the issue: `HashCheckSeed` doc cross-references `RefreshSeed`; `ScriptedFlagSession` doc comment fixed. The shared adoption code of the two scripted sessions is left as is (no behaviour, not worth the churn).
- LOT-048 spec, step 1, updated.

Narrow on purpose: the check reads `userKey` in its own actor turn, not atomically with the send; a switch in that window is still caught by HFR (`W17b`), as before.

**Tests** (`PostingSessionChangeTests`, Swift Testing):
- `changeAfterLoad`: login of another account or logout after the load × the 5 write entry points → `sessionChanged`, only the GET was sent.
- `switchDuringLoad`: account switch during the form's GET (R40a) → `sessionChanged`, no POST.
- `sameAccountRelogin`: same-account re-login after or during the load → POST sent, HFR's `W17b` → `rejected`.
- `noChange`: the POST is sent.
Shown to fail without the guard (`unconfirmed(.transport(.unscripted))`, 2 requests). Full `swift test`: 1278 tests pass; SwiftLint clean on the touched files. App target not built here (Linux): CI is the judge.

### Problem
Operator feedback of 2026-11-17: in the reader the signature text starts at the screen edge, the text has no legacy right padding, quotes are framed by full-width rules (#1038), and smileys and inline images are centred on the text line instead of resting on it (#1049).

### Cause
- (A) `.signature` is a sibling of `.content`: it got the article's 1em padding only, not the body indent (`--indent`, modern style).
- (B) legacy `div[id^=para] { padding-right: 10px }` (`style-liste-light.css:505-509`, `style-liste-dark.css:506-509`, `style-liste-oled.css:502-505` @ 87fe0d1c) was never ported.
- (D) HFR writes `<hr size="1" />` after the header and text of an `oldcitation` / `oldquote` (R33b, R47u1, R95f, R443l); the normalizer keeps `hr` and `reader.css` had no rule, so the browser drew its inset rule. Legacy: `hr { visibility: hidden; height: 12px }` and `hr:last-child { display: none }` (`style-liste-light.css:393-400`, `style-liste-dark.css:302-309`, `style-liste-oled.css:298-305` @ 87fe0d1c; margins are zero through `* { margin: 0 }`, `style-liste.css:39-46`). **Option 1 (parity: no rules) taken.** Plain `citation` markup carries no `hr` in the captures; if the device still shows a rule around those, that needs a capture on #893.
- (#1049) `reader.css` set `vertical-align: middle` on message and signature images (LOT-083). The legacy `style-liste*.css` @ 87fe0d1c set no `vertical-align` on message images (`git grep vertical-align 87fe0d1c -- 'SuperHFRplus/Assets/HTML/style-liste*.css'` finds nothing), so they keep `baseline`; the `middle` rules of `style-smile.css` belong to the smiley picker.

### Change (`reader.css` only)
- Signature: box spans the article (negative margins = `--edge`), so the dashed rule starts at the edge; padding puts the text at `--text-inset` (indent in modern, 0 in classic, plus bar and padding for my/whitelisted messages) and `--text-right`. Blocked posts keep their own margins, in the content's em.
- `.content` gets `padding-right: 10px` (legacy value) **on top of** the article's 1em: the total right margin is wider than legacy's, as an earlier operator ask for wider margins wanted. Operator to confirm on #893 whether exactly legacy's total is wanted.
- Legacy `hr` rules ported; quote tables set `border: none; border-left` (`style-liste-dark.css:296-300`).
- Smileys and inline images: `vertical-align: baseline` (posted pictures, `.hfrplusimg`, unchanged: the rule still excludes them).
- `SignatureLineWebTests` compares the rule's width with the article's, since it starts at the edge.

### Tests
- New app-hosted WebKit `ReaderMarginsWebTests` (modern/classic × light/dark) on an `oldcitation` with HFR's real `<hr>` markup: signature text left == message text left, rule left == article left, right paddings 10 px, signature text right edge == message text right edge, rule right == article right, quote borders and visible `hr` == 0.
- New `ReaderImageBaselineWebTests`: a 40 px smiley taller than the text, in the message and in the signature: computed `vertical-align` is `baseline` and the image bottom is within 1 px of the line's baseline (measured with a zero-size inline-block on the baseline).
- Not covered: the blocked post and my/whitelisted insets; no string test on the CSS (the WebKit tests assert computed styles).
- **Not run here** (Linux, no Xcode), so not shown red without the change; the Compile check and the Mac/CI run decide. `swiftlint --strict` is clean.

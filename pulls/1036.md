### Problem
A rehosted image posted as a `.th.` / `.md.` rendition (img3.super-h.fr) showed small inline, and « Copier le lien » on a long press copied the posted address. The viewer and the long-press save already used the full-size file on dev-swift (#923).

### Cause
`ImageHostTable.fullSizeURL` was only applied by `ImageGallery.build`; the reader's `hfrreader:` image handler and the menu's copy used the posted URL.

### Change
- `ImageGallery.fullSize(of:)`: the single resolver (host table rewrite, ignored if it changes host or origin), reused by the viewer.
- `ReaderImageFetcher.imagePreferringFullSize`: full-size first, posted URL on any failure (404, non-image), no second request if cancelled. Same policy C, cookie-less client and limits for both. Used by the page's images (the load decision is taken before the fetch, unchanged, so « Jamais (au toucher) » still fetches nothing before a tap) and by long-press save.
- Long-press « Copier le lien » on an image link copies the full-size URL; other links unchanged.
- Inline page images send no `Referer` (LOT-071 R3) and `reho.st` answers 403 without one (T30-T33): a host whose rule has a `Referer` keeps its posted address inline (no wasted request). The viewer, save and copy still use the full-size address for it.
- No new host or marker. Specs updated: LOT-137 (copy), LOT-056 (inline).

### Open point for the operator
Issue scope 1 says the layout width stays the same. The reader CSS only sets `max-width: 100%; height: auto` and the markup has no width, so a rendition narrower than the column now shows at the full file's natural width (up to the column). Keeping the old width would need the rendition's size, which is unknown without fetching it. Left as is, stated in the spec and the ledger; confirm or ask for a constraint.

### Tests
Fetcher: full-size address requested; 404 and non-image fall back; policy refusal requests nothing; host without rule fetched once; a Referer host keeps its address. Gallery: resolver rewrite. Link menu: copy gives the full-size URL. Web controller: inline full-size request, fallback on 404, nothing fetched without a tap. App tests cannot run on Linux: written with compiler rigour, CI to confirm. Device check listed for #893.

Three Opus rounds done (cap). Round 3 findings (a compile warning treated as error in a test helper, a wrong legacy citation in the ledger row) are fixed in the head; no APPROVE yet, orchestrator decides.

### Problem
A reader pushed from a link shows no hint of how many readers are stacked behind it; legacy shows a capsule with the depth before the title (`MessagesView.swift:3476-3488` @ 87fe0d1c; `3410-3440` @ 2fe43da3, `602b900e`).

### Cause
`TopicReaderModel.linkedReader` (LOT-137) pushes a reader but keeps no depth.

### Change
- `TopicReaderModel.depth`: 0 from a list, opener's depth + 1 for the reader a link pushes (legacy `navigationDepth + 1`, `:4021, :4720` @ 87fe0d1c; `follow` is the only place a reader pushes another one, the in-topic search result goes through it); a negative value is raised to 0.
- `ReaderTitleWithDepth` / `ReaderStackDepthCapsule` / `ReaderDepthTitleToolbar` (new file): « ‹ N » capsule, then the title, as the principal toolbar item with no glass capsule behind it (as `ScreenTitle`). VoiceOver « N affichage de messages empilé » (legacy string). Shown from depth 1 only: at depth 0 the system title stays.
- Differences from legacy: the capsule uses the app's badge colours (`AccessibleColors` badge fill/text, a theme's `unread`/`onUnread`, as `BadgeCapsule`) instead of legacy's palette tint with white text, and its sizes follow the app's type scale (`scaledFont`); the title keeps the system inline title's size at depth ≥ 1 (legacy sets it in caption2 bold); no loading spinner in the title (the reader has its state overlay); no « back to root » button (dropped by legacy at `602b900e`).
- LOT-137's spec line now says the count is ported by #682.
- Not checked here (Linux session): light, dark and Dynamic Type XL, and whether the bar's title slot shows the capsule without clipping on a narrow iPhone: device check on #893.

At depth 1 and more the title becomes `.caption2` bold, so following a link shrinks it. It also skips the app's type scale: TextScale.swift:73 says to use `scaledFont`, not `.font(...)` or fixed sizes. Fix: `scaledFont(.headline)` (the inline title's style), or record the change as a difference.
4. **Low**, `TopicReaderView.swift:121`. The `.principal` item does not call `.sharedBackgroundVisibility(.hidden)`, which ScreenTitle.swift:82 uses so the bar does not draw a glass capsule behind a custom title. 6. **Detail**: the capsule's fixed 7/9 pt sizes do not scale with Dynamic Type. Legacy does the same and the PR says so; `@ScaledMetric` would fix it.

Paths that create readers: `follow` is the only place a reader pushes another one. The in-topic search result goes through `follow` too (ReaderSearchFlow.swift:54), which matches legacy's +1 at :4720.

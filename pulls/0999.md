### Problem
Réglages > Maintenance has no cache figures; legacy at `2fe43da3` shows them (`AppSettingsView.swift:547-577`, identical at `87fe0d1c`). Clearing is LOT-187 (M5), not here.

### Cause
LOT-120 left `cacheRows` empty for this lot.

### Change
- `CacheStorageSnapshot` (pure; takes the `CacheDirectory`): total = allocated size of every non-hidden regular file under `Library/Caches` (legacy `directoryAllocatedSize`); "Pages HTML" = allocated size and count of the pages saved for offline reading, with the names `OfflineTopicStore` gives them: regular `<n>.json` files (decimal, no sign or leading zero) in `<category>-<topic>` folders of the `offline` area (`Caches/cache/offline`). Operator decision of 2026-11-17 (comment on this PR): LOT-066's `pages` area has no writer, so it is not the source; the row stays. Symlinks are not followed; missing or linked folders count as empty.
- `CacheStorageText`: sizes via `.byteCount(style: .file)`, "N fichier(s)", footer derived from `CacheEvictionPolicy.offlineTopics` ("Les pages HTML enregistrées sont conservées quel que soit leur âge. Leur cache est limité à 200 Mo.").
- `MaintenanceModel.refreshCacheStorage()` measures off the main actor (last started measure wins); `MaintenanceSection` shows a spinner until measured, the two rows and the footer; `SettingsView`'s `.task` starts one measure per appearance (as legacy `:606-607`).
- Spec `docs/lots/LOT-179-cache-sizes.md` completed.

### Tests
`CacheStorageSnapshotTests` (11) and 2 `MaintenanceModelTests`, Swift Testing. One test saves pages through `OfflineTopicStore(cache:)` in a temporary root and expects them counted (it fails if the snapshot reads another area, e.g. `.topicPages`); another covers names (`abc-def`, `13-1-2`, `013-1`, `abc.json`, `01.json`, `7.JSON`, strays, deeper folders, hidden entries). The stale-measure test holds the first measure so it ends last and fails without the ticket guard. Run on Linux in a scratch package (Foundation + HFRStorage + HFRModels): all pass; mutations (`.topicPages`, folder-name filter, file-name filter, leading zero, any file counted, symlinked page, footer without the age sentence, ticket guard, hidden files, singular rule) each fail the matching test. The App build + tests job is green on the head and covers the app target (it caught a case-insensitive-volume collision in my name test, fixed in 948099a).

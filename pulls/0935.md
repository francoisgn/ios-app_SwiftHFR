### Summary
As a member, I want one switch per MPStorage function, each with an info popover, so that I turn on only what I want. Operator decision 2026-11-15 (comment on #859): these switches are **behind Réglages › Expérimental** (#903), off by default; with it off, Réglages › Stockage MP keeps legacy's single switch.

**Problem.** Réglages › Stockage MP had one switch for everything MPStorage does, and no explanation of what each function does.

**Cause.** Legacy's single `mpstorage_active` (`AppSettingsView.swift:112`, `:534-545` @ 87fe0d1c) was ported as one per-account state (LOT-130).

**Change.**
- **Stored record.** The per-account record `mpstorage.<account>` gains an optional `disabled` list.
  - Absent or empty means every function is on (legacy parity). Older records read unchanged, and unknown names are kept.
  - No new settings key. The scope stays ADR 0013 §7: iCloud KVS, per account, like the master state.
  - ADR 0013 §7 and its matrix row, the store header and the LOT-130 spec document the field.
- **Forward-compatibility limit** (stated in the ADR). A build without this change ignores `disabled` and keeps syncing every function. Its master toggle rewrites `{state, decidedAt}`, which erases the list on every device. Builds already released cannot be fixed.
- **`MPStorageSyncModel`.**
  - New `isEnabled` and `setFunction`.
  - `edit(_ function:)`, `writeConsent(for:)`, `flag(for:)` and the new `document(for:)` (the gated read accessor for LOT-131/132) all check the function's switch.
  - A function that is off stops this app reading and writing its section. Nothing is deleted, and other clients' data is untouched.
  - An edit queued before the switch-off is still written at the next sync, so the member's earlier intent is not lost.
- **Behind Expérimental.** New `ExperimentalFeature.mpStorageSwitches` (« Stockage MP détaillé », sub-menu Messages, now listed). `MPStorageSyncModel.experimental` is set by `RootNavigationView` from the app's `ExperimentalSettings`. Off (default), `isEnabled` is true for every function, so the single master switch governs everything as in legacy, and the stored `disabled` list is ignored, not deleted (it applies again when the option is turned on). Gate points are marked `EXPERIMENTAL(mpStorageSwitches, #859)` (the model's input and `isEnabled`, the section's footer and rows, the root's wiring). The gate is inline in `MPStorage/` (a two-line branch at each point) rather than an `Experimental/<Option>/` folder: there is no separate modern path to move, the option only decides whether the existing per-function code is reached, so a folder would hold nothing. Removing the option means deleting the case and these marked lines. The legacy section has no footer, so it shows only with the option on. ADR 0013 §7 says `disabled` applies only while the option is on.
- **Réglages** (option on only).
  - A footer explains what MPStorage is, without any pseudo or MP id.
  - Each shipped function gets a switch and an info popover (VoiceOver: "Plus d'infos sur …").
  - Only the group-MP read position (« MP multiples → dark topic », #858) is shown. Its popover says this app shows what other HFR+ clients stored and does not write it yet.
  - Blacklist (#221) and bookmarks (#222) join `shippedFunctions` when their lots ship, so there is no dead switch, as the issue asks.

**Tests** (`MPStorageSyncStateStoreTests`, `MPStorageSyncModelTests`):
- option off: every function is on whatever `disabled` holds, nothing gated, nothing deleted, back to today's behaviour when turned on; no environment reads off; the option is listed under Messages and off by default;
- option on: every function is on by default;
- the switches are per account (Bob's record is stored first);
- a state change keeps the switches off;
- a function that is off gives no edit, no consent for sync, no flag shown and no gated document;
- a resync leaves the section intact and saves nothing;
- master off then on keeps the switches;
- an edit queued before the switch-off is still written.

Red was seen by temporarily removing the guards (earlier rounds: 5 app tests and 1 engine test), and, for the option gate, by removing it: `withTheOptionOffEveryFunctionIsOnWhateverTheStoredListHolds` failed on iPhone and iPad. Full gate (tag f859): iPhone and iPad, 1567 tests, green.

**Not checked.** Dynamic Type AX, VoiceOver and the popover's look on a device: only the unit tests ran.

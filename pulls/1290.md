**Problem.** The App Store update must pass guideline 1.2 (user-generated content: filter, report, block, contact) and keep the Q-7 App Review rules; nothing tied each rule to its code and a test, and no App Review notes existed.

**Cause.** The rules were built piecemeal by LOT-082, 115, 118, 133 and 135. Checking every one against the code found two gaps: the filtered posts sheet (LOT-114) renders messages without any menu, so a post read there can be neither reported nor its author blocked (legacy showed the filtered posts in `MessagesView` with every menu, `MessagesView.swift:4767-4791`, `:2011-2030` @ `87fe0d1c`); and Crédits had lost legacy's contact block (`credits.html:7-14`).

**Change.**
- `docs/lots/LOT-159-app-review-ugc.md`: legacy sources (file:line @ `87fe0d1c`), the checklist R1-R15 (one line per Q-7 / guideline 1.2 rule, with its code and test), the operator's decisions of 2026-11-24 (D1, D2, D5), the open ones (D3, D4), the pending capture of an accented `md_user`, and the App Review notes draft (no credential).

Confirmations use the reader's banner (`MenuFeedbackShowing`) and VoiceOver announcement.

- `ReviewAccountConfigurationTests`: the root the app builds hands one `ForumVisibility` to the forum list, the search picker and the AQ list (R1).
- `docs/HFR-PROTOCOL.md`: the AQ row said category 25 was hidden "unless pseudo `applereview`"; legacy hides it for that account and when logged out (`AQTableViewController.m:332-347`, `AQPlusView.swift:52-57`).
- Why no wider: every other rule was already implemented and tested by its lot (the checklist names those tests); the filtered sheet stays read-only (LOT-114) apart from the UGC entries. `VisibilityPolicy.ownKey` has the same encoded-key class but is another helper: left to a follow-up issue.

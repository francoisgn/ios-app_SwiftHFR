**Problem.** These are the round-3 residuals of #1248 (#1193):
1. `ReplyComposerView.init` evaluates `State(initialValue: ImageUploadModel(…))` each time SwiftUI builds the view, and keeps only the first model. `ImageUploadModel.init` built `services.thumbnails()`, which is a `ReaderImageFetcher()` with its `AnonymousTransport` and two `URLSession`s. So every discarded model created a pair of sessions.
2. No test read the loader the views use (`ImageUploadModel.thumbnails`). Replacing it with `.gif()` kept the suite green.

**Change.**
- `ImageUploadModel.thumbnails` is now `@ObservationIgnored private(set) lazy var`, built from `services.thumbnails()` on first use.
- A model SwiftUI discards never reads it, so it builds nothing. The model kept in `@State` builds the loader once, and both the history rows and the composer's chips read that one.
- No other change.

**Tests** (app-hosted; not run here, since Linux cannot build the app):
- `RehostThumbnailTests.thePanelsLoaderFiltersOnTheRehostHost` reads the model's `thumbnails.hostFilter`. It accepts the rehost host and refuses another host and Giphy's CDN.
- That test is red if the model's loader drops the filter or becomes `.gif()`.
- The laziness itself has no test seam. It is checked by reading: the only reads are `ReplyComposerView` (`imageUpload.thumbnails`, the `@State` instance) and `ImageUploadView` (`model.thumbnails`).

SwiftLint 0.65.1 `--strict` clean.

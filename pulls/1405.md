**Problem.** Audit #1388 / #1397: each smiley or GIF cell built its own `ReaderImageFetcher` → `AnonymousTransport` → 2 `URLSession`s (35 cells = 70 sessions, 35 handshakes), identical URLs were fetched once per cell, every picker opening re-read the reply form and the own-smileys page, and every launch re-looked-up each avatar-less MP correspondent (2 GETs each).

**Cause.** No shared transport, no in-flight map, picker state per opening, "no avatar" kept in memory only.

**Change** (no wider):
- `HFRNetwork.CoalescingTransport` (new): identical GETs in flight share one exchange; nothing is remembered once it ends (a failure is never replayed); writes and any non-equal request are never merged. A cancelled caller leaves at once; the exchange is cancelled when its last waiter leaves.
- `ReaderImageFetcher.sharedTransport`: the default fetcher uses one cookie-less `AnonymousTransport` behind it (policy C, cookie-less, hop-by-hop redirects untouched) → one `URLSession` pair for the app's images instead of one per cell/reader.
- `SmileyListMemo`, held by `ComposerServices` (a fresh one per composer, `withFreshSmileyMemos`): the forum favourites and own smileys are kept for the composer's life; a failure is not kept, so « Réessayer » still reaches the forum.
- `MemberAvatarPrefetcher.Misses`: a "no avatar / unknown member" answer is remembered 24 h across launches, through the `Sendable` `SettingsStore` (one device-only JSON setting, pruned on write); failures and refusals are not remembered. No `nonisolated(unsafe)`.

**Left, tracked in #1415:** finding 3 (avatar store and web view fetch each avatar twice) and a bounded memory cache for forum-host images across readers (finding 5; this PR only removes the per-reader `URLSession` and merges concurrent GETs).

**Tests.**
- `CoalescingTransportTests` (engine, run here, 7 tests, no wall-clock: callers are awaited by condition, the exchange is held by a signal): 35 concurrent calls with the same URL → 1 request (before: 35); requests differing by URL, headers or redirect policy → not merged; a write is never merged; a failure is not replayed; a cancelled waiter returns while the base is still blocked and the others are served; the last waiter leaving cancels the exchange; a caller cancelled before joining starts nothing. Each shown red under mutation by the reviewer.
- App tests, written but not runnable on Linux (compiler-reviewed, Compile check green): `SmileyListMemoTests` (3 reads → 1; failure not kept), `MemberAvatarPrefetcherTests` (no-avatar answer holds across a second "launch", expires after 24 h; failure not remembered).

No legacy behaviour changes (legacy sends no MP-row lookup, GAP-230), so no `### Ledger`. Device check owed: open the smiley picker twice in one composer and read an MP list with an avatar-less correspondent over two launches (counts in the trace).

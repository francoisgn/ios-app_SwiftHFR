### Problem
Mac check of 2026-11-10 on #499: the YouTube player sheet shows "Erreur 153 – Erreur de configuration du lecteur vidéo"; a Vimeo player that answers 401 leaves a blank sheet.

### Cause (traced, not guessed)
`PlayerWebView` loaded `URLRequest(url:)` with no `Referer` (LOT-071 R3). YouTube documents error 153 as "The request does not include the HTTP Referer header or equivalent API Client identification" (IFrame Player API reference, developers.google.com/youtube/iframe_api_reference, read 2026-11-10) and requires identification through the `HTTP Referer`, protocol HTTPS, domain = the app ID (YouTube API Services, Required Minimum Functionality, "API Client Identity and Credentials", developers.google.com/youtube/terms/required-minimum-functionality, read 2026-11-10).
Trace on an iOS 27.0 simulator, the real player web view loading `https://www.youtube.com/embed/<public video>` (a throwaway app-hosted test, not committed; no HFR page loaded): without Referer the page renders "Erreur de configuration du lecteur vidéo"; with `Referer: https://hfrplus.red.super/` it renders the player (title, "Regarder sur YouTube"). The Referer on the wire is proved by a loopback server in the committed tests. The Vimeo 401 is a main-frame HTTP 401 the web view displayed as an empty page.

### Change
- `VideoPlayerSheet.playerRequest(for:)`: `Referer: https://<bundle id>/` for `www.youtube.com`, `youtube.com`, `www.youtube-nocookie.com` only (the existing allow-list, no wildcard); no other provider or host. No cookie, no forum URL: R1 holds.
- The player web view reports a main-frame status >= 400 or a failed load; the sheet then shows the existing "Vidéo indisponible" view with "Ouvrir le lien". A YouTube error drawn inside a 200 page is not detected (the player's own "Regarder la vidéo sur YouTube" stays).
- Specs: LOT-071 R3 exception with its sources; LOT-108 section.
Why this wide: the request builder and the failure report, nothing in the reader's web view or in R3's other cases.

### Tests (`VideoPlayerSheetTests`, shown failing with the Referer, status and failure code mutated out: 7 cases red, then green)
- request carries the Referer for YouTube; none for Vimeo, Streamable or a non-YouTube host with the YouTube provider;
- a real `WKWebView` against a loopback server: the Referer is on the wire for YouTube, absent for Vimeo;
- a 401 answer and an unreachable host report a failure, a 200 does not; status rule table; after a failure the sheet shows the unavailable view.

Mac check still wanted on a device: real playback (tap play), Vimeo live video.

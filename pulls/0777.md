**Problem.** Every capture PR appends its rows at the end of `tooling/fixtures/corpus.json`, so each merge conflicts with the next PR (seven times on 2026-11-10, each costing a merge of `dev-swift` and a macOS CI run).

**Cause.** One shared file, appended at the same place by every PR. (The issue says `anonymize.py` reads it; it is `publish.py` that does. `anonymize.py` is not touched, so there is no overlap with #771.)

**Change.** Same fix as #612/#620 for the ledger: one file per batch.
- `tooling/fixtures/corpus.d/<batch>.json` (`{"captures": [...]}`), read by `publish.py` in file name order. `load_manifest` takes a folder or a single file, refuses a raw id or corpus id declared twice (naming both files), a fragment without `captures`, invalid JSON, an entry missing a key, and an empty folder.
- One-time migration: `corpus.json` becomes `corpus.d/00-base.json`, same entries in the same order (checked equal with a script before deleting the old file; #764's `R267a` landed in it through the merge of `dev-swift`); only its `note` is reworded.
- `anonymize.py check --corpus` is unchanged and stays the arbiter on the files; `manifest_check.py` (#776) follows the layout through `publish.DEFAULT_MANIFEST`.
- Docs: `tooling/fixtures/README.md` (new "Adding a capture batch" section, file table), `docs/FIXTURES.md`, `LOT-001` spec line.

**Open capture PRs.** Only #766 (`capture/333-storage-page-2`) is open and touches `corpus.json` (plus the README). After this merges: merge `dev-swift` into the branch (no rebase). Git sees `corpus.json` as renamed to `corpus.d/00-base.json`, so the conflict is inside `00-base.json`: `git checkout --theirs tooling/fixtures/corpus.d/00-base.json` (theirs = `dev-swift`), put the rows the branch added (`git diff $(git merge-base HEAD origin/dev-swift) HEAD -- tooling/fixtures/corpus.json`) into `tooling/fixtures/corpus.d/333-storage-page-2.json`, `git add` both, then `python3 -m unittest discover tooling/fixtures/tests` and `anonymize.py check --corpus`. Any `capture/*` PR opened later does the same or starts from the new layout. #771 touches neither `corpus.json` nor `publish.py`: no conflict expected (if it merges first, I merge `dev-swift` here). #776 and this PR both edit the README file table: whoever merges second resolves that text conflict.

**Tests** (`tooling/fixtures/tests/test_corpus_fragments.py`, written first, 11 of 14 failing before the change; round 1 added shape and encoding cases): ordering, ignored non-JSON files, single file, duplicate raw / id across and inside fragments, malformed fragments, empty and missing folder, the committed folder loads with unique ids and `corpus.json` is gone. The whole suite (357 tests, with `dev-swift` merged in) and `anonymize.py check --corpus` (675 files) pass.

Linux-only (no `App/` or `Packages/` change): no macOS job.

## Problem
The reader and composer had labels for most controls but no structure for VoiceOver: no heading per message (rotor), quotes, code and spoilers were bare tables, the avatar and author buttons duplicated each other, posted pictures were read as their URL, announcements were inconsistent (a page change and the reply confirmation were silent), and the dismiss target of the confirmation was small.

## Change
Spec: `docs/lots/LOT-163-a11y-reader.md`. Only HTML from the builder and attributes set by the adapter: the reader's security (CSP `script-src 'none'`, no page script) is untouched.
- Author = level-2 heading per message; avatar button hidden from assistive technologies; `aria-haspopup` on the menu buttons.
- Adapter: quotes, code, spoilers as named groups; spoiler and collapsed blocklisted-quote headers as buttons with `aria-expanded` and Enter/Space; a blocklisted quote never names the pseudo it hides; pictures with no real alt read "Image".
- One place (`ReaderAnnouncements`) announces the feedback toast and page changes (not while a confirmation is shown); reply confirmation and composer banners announced.
- 44 pt dismiss target (banner grows ~20 pt: the one visible change), "Mise en forme" container, "Image n sur m" in the viewer, focus ring and a Reduce Motion guard in the CSS.

## Tests
`ReaderAccessibilityTests` (wording; the adapter in a real `WKWebView`), `TopicHTMLBuilderTests` (heading, haspopup, escaping). Not built or run here (Linux): CI is the first build. SwiftLint clean on the touched files.

### Problem
`MessageTitleToneTests` (`drawnColour(dark:)`, both appearances) fails now and then on CI with `Self.centre(of: readSwatch, …) → nil` at `MessageTitleToneTests.swift:91`, after three `#704 blank render redone` lines. That was 3 times on 2026-11-24 alone, and each one costs a macOS re-run.

### Cause
`ImageRenderer.cgImage` rasterizes through a GPU (Metal) pipeline and waits **2 s** for it. The first render in a test process has to compile that pipeline first (`plane_color`). On a loaded CI runner the compile is slower than the three 2 s tries. From CI job 138840678795 (PR #1322, attempt 1), thread 69891 is the pipeline build and thread 48294 is the main thread:

```
23:16:52.599 [69891] fopen failed for data file: errno = 2            <- pipeline cache miss, build starts
23:16:54.579 [48294] image provider … timed out while waiting for phase 6 (1)
23:16:54.593 #704 blank render redone (try 1, corner 0.0 0.0 0.0)
23:16:56.583 … timed out … / try 2
23:16:58.587 … timed out … / try 3  -> ✘ dark → false
23:17:03.727 [69891] [error] building pipeline plane_color-cea14ge2ba4 took 11.135042 seconds
```

Once the pipeline was built, the next render (`dark → true`, try 3) and `rowDrawsTheTitleTone` passed. In a green CI run (job 138815183187) the same build took 0.902 s. On this Mac (iOS 27.2 simulator, a fresh erase before each run, 8 × `yes` load) it takes 0.30 to 0.49 s, measured between the two `fopen` lines in 7 runs. That is why it never reproduced locally (#704's 60 + 20 runs), and why the #1110 retry only made the window 6 s wide. So the cause is the timing of a cold GPU pipeline build that `ImageRenderer.cgImage` waits on. It is not appearance or trait state.

### Change
`render(_:background:)` (test helper only) now calls `ImageRenderer.render(rasterizationScale: 1)` and draws the same display list into a Core Graphics sRGB bitmap that the test owns. This draw is synchronous and runs on the CPU: no image provider, no GPU pipeline, nothing to wait for. The retry loop and its `print` are gone. The corner check stays as one sanity check (one render, no redo), and its `#require` messages now say `no render of the background, #1283`. Tolerances are unchanged (0.02). App code is not touched. `ImageRenderer` has no other user in the test target (`git grep ImageRenderer App/`): the other pixel tests use `UIGraphicsImageRenderer` on a hosted window.

### Tests
Run on the iPhone 18 Pro iOS 27.2 simulator (own clone), `-parallel-testing-enabled NO` as in CI, `-only-testing:SwiftHFRTests/MessageTitleToneTests` (9 tests, 23 cases):
- Before the change: 7/7 green (1 warm, 6 cold under load). Every run builds the GPU pipeline (`fopen`/`IOSurfaceClientSetSurfaceNotify` lines, 0.30 to 0.49 s).
- After the change: **20/20 green**. 10 runs on a freshly erased simulator with 8 × `yes` CPU load, 10 runs alone. **No run shows any `fopen`, `IOSurface`, `image provider` or `building pipeline` line**, so the GPU path is no longer touched.
- Red mutation: `MessageTitleTone.style`'s `.secondary` set to `AnyShapeStyle(.primary)`. It fails `drawnColour(dark:)` at :93 (both cases) and `rowDrawsTheTitleTone(dark:)` at :113 (both cases), 4 issues. The renders succeed and the colour check is what catches the mutation.

## What and why
**Problem.** In the legacy app, jumping 10 pages ahead in a topic list crashed it (`NSInvalidArgumentException`, `initWithString:` on `nil`) when a pager entry had no `href`. The same pattern sits on every link the list parsers read: `ObjCTopicListParser.m:195,214` (pager), `:323` (title), `:342` (flag), `:417` (last post), `:455` (last page), plus `ObjCForumsParser.m:67,108` and `Favorite.m:101,115,154,169,176`. Found and fixed in legacy by Bybifok (`237db70`, ezzz/HFRnow#3).

**Does SwiftHFR have it? No.** `TopicListPager` classifies entries by their text and `linkTarget(of:)` returns nil when there is neither an obfuscated class nor an `href` (`TopicListPager.swift:17-36,53-64`). `TopicListRowParser` skips a row without a title path and turns any other missing link into nil (`TopicListRowParser.swift:15-19,23-30,73,142-148`). The page fails only when *every* row is unreadable (`TopicListParser.swift:54-57`). The home page and the favourites were already tested (`ForumListRobustnessTests.unreadableRowSkipped`, `.subforumWithoutHref`; `FavoritesParserTests.lastPageLinkWithoutHref`). The topic list, the pager and the MP list were not.

**Change.** Tests only, plus the legacy fix recorded in `docs/CHANGELOG-LEGACY.md`. No code change, since there is nothing to fix.

## How it was verified
New suite `ListLinksWithoutHrefTests` ("List links without href (#102)"). Every test uses an in-memory edit of a committed capture (no hand-built page) and compares it with the unedited capture:
- `pagerWithoutTargets`, on R04, R05a, R05b and R13u1: every top-pager link (obfuscated spans, `a.cHeader`, arrows) becomes an `<a>` without `href`. Rows and page numbers are kept; `firstPath`, `lastPath`, `nextPath` and `previousPath` become nil, except a current page's own path.
- `titleLinkWithoutHref` (R04): that row is dropped and the 54 others are identical.
- `lastPageLinkWithoutHref` (R04): the row is kept on 1 page, with `lastPagePath == path`.
- `lastPostLinkWithoutHref` (R04): the row is kept with `lastPost == nil`.
- `flagLinkWithoutHref` (R08-2): the row is kept with no `flagPath` and no `currentPage`.
- `privateMessageTitleWithoutHref` (R13u1): that thread is dropped and the others are identical.

**The tests fail when the code regresses** (each mutation applied, then reverted):
- An unreadable row loses the page, as in legacy (`TopicListParser.parseRows` throws): `titleLinkWithoutHref` and `privateMessageTitleWithoutHref` fail.
- A pager entry without target drops the whole pager: `pagerWithoutTargets` fails on all 4 captures.
- A row with a dead last-page, flag or last-post link is dropped: `lastPageLinkWithoutHref`, `lastPostLinkWithoutHref` and `flagLinkWithoutHref` fail.
- Note: removing the `hasAttr("href")` guards is an equivalent mutant. SwiftSoup returns `""` for a missing attribute, and `HFRURL.forumRelativePath("")` is nil.

Other checks:
- `swift test` in `Packages/HFRKit` on macOS: 966 tests pass.
- `python3 scripts/check-lot-deps.py`: 0 violations.
- SwiftLint is not installed here, so LESSONS 21 was checked by hand (lines ≤ 140, no force unwrap, type body < 250).

### Problem
The ledger kept only `unreadThreads: Set<Int>`, so a reply in an MP conversation that is already unread was never news.

### Cause
That reply changes only the row's `repliesCount` and last-post date (HFR-PROTOCOL §6c LOT-140, `R336`→`R338`: icon unchanged, row position not reliable).

### Change
- `NotificationSummary.unreadThreadMarks` and `UnreadThreadMark` (topic, `repliesCount`, `lastPost?`); `NotificationLedger.unreadThreadMarks` (optional, so older documents decode as before).
- `diff`: `newThreads` = newly unread ∪ still-unread with a count or date that grew (highest mark per topic). No recorded mark (old ledger, first check) is a silent baseline.
- `record`: marks follow the unread set (read conversations dropped); highest count and latest date win, so a stale list shown in the app cannot lower the baseline; a summary without marks keeps the existing ones.
- App: `MPNotificationLedger.seenSummary` and `MessageListModel.recordReadState` feed marks, so a reply seen in the list is not notified. `MPBackgroundCheck` is unchanged (it already notifies `newThreads`).
- Specs LOT-091 / LOT-140 updated. No new HFR fact: only captured fields are used.

### Tests
- `NotificationLedgerThreadMarkTests` (Linux, 13 tests): reply in unread, count/date alone, no change, stale/lower value keeps the baseline, two marks of one topic, newly unread + moved, read then unread again, old record/old JSON baseline, summary without marks, mark of a read thread ignored by `diff`, read conversations dropped on record, missing date, invalid mark. `swift test --filter NotificationLedger`: 34 pass. Red before the change (types absent); mutations (no diff filter, record replaces, no drop) each fail a named test.
- App `MPBackgroundCheckTests/replyInAnUnreadConversation` and `MPNotificationOpenTests` (marks carried by the foreground record): not runnable here, need CI.

### Ledger

```gap-edit
GAP-191
SwiftHFR final: One notification per conversation that became unread, or that received a reply while already unread (reply count or last post moved forward), interlocutor and title (or a group's title), `mp-<topic>` identifier and thread, a summary past 5; the legacy text only when the list could not be read and the count rose.
```

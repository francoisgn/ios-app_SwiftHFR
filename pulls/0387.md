**Problem.** #306 (PR #332) reads the topic flag from the function bar. A differential test on the overlap with legacy needs legacy's `isFavoritesOrRead` and `isRedFlagged` (`HFRswift/Wrapped/MessagesTableViewController.m:1556-1583` at `2440d79`), which the LOT-003 oracle did not export. #268 also asks for the other settings values.

**Cause.** `-[MessagesTableViewController setupFastAnswer:]` sets them. That controller is compiled into the `SuperHFRplus` target only, not into the `HFRswift` test host (the export first tried to call it through the runtime: "not in the test host").

**What changed.**
- `hfrnow.patch` (superset of the previous one): `OracleObjCSafe.m` transliterates lines 1556-1583 on the real `HTMLParser`/`HTMLNode` calls, after `ParseMessagesOperation` ran on the same parser, as `startParseDataHtml:` does. Exported as `result.fastAnswer` `{isFavoritesOrRead, isRedFlagged, isUnreadable}`; documented in the LOT-003 spec.
- `Fixtures/LOT-003/`: the 21 oracles re-exported. Each one only gains `fastAnswer` (5 lines); the rest is byte-identical, and the map is unchanged.
- `Fixtures/LOT-003-flag/`: R33b, R61d, R61e, R63a, R63e, the logged-in captures with the bar link that `LOT-003/` lacked.
- `Fixtures/LOT-003-settings/`: R21 with `display_sig: yes`, `display_images: no`, `embedded_videos: no`; R26 with `display_sig: yes`; R28 with `display_images: no`, `embedded_videos: no`.
- Why separate folders: adding these cases to `LOT-003/` changes the case lists and corpus totals of the LOT-030..034 differential tests (seen: `MessageContentOracleTests` totals and `MessageQuoteOracleTests` fail). Those suites stay as they are.

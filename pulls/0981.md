**Problem.** `host: mac` sits on 153 open issues. Most of them only need a device check, which since 2026-11-16 goes to the general review (no merge waits on it). Cloud sessions skip these issues, so M4 lots stay idle.

**Change.**
- `.github/labels.yml` and AGENTS §7: `host: mac` now means only what cannot be done without the Mac: live captures, the legacy app or oracle, signing, TestFlight and the App Store, and a measurement or hand check that is itself the deliverable.
- New `host: mac-helps`: the cloud can do the work, but a free Mac session takes it first to spare macOS CI runs (heavy visual iteration, app-hosted WebKit or UI tests, simulator screenshots, flaky app tests).
- ORCHESTRATION's pick rule now says the cloud may take `host: mac-helps`.

The live labels are already created and updated by hand (the sync runs only from `master`, ADR 0010). The 153 open `host: mac` issues were relabelled on 2026-11-16 (63 keep it, 32 move to `host: mac-helps`, 58 lose the host label), reported on #893 (https://github.com/ezzz/HFRnow/issues/893#issuecomment-6931831052).
- Review round 1: `MAC-SESSIONS.md` now sends a check owed by a merge to #893 and picks `host: mac` then `host: mac-helps`; `EXTERNAL-AGENTS.md` and the README name the new label.

**Tests.** Docs and labels only; the Docs consistency check covers the links.

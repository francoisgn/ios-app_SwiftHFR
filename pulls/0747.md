## What and why
Operator device feedback: an MP row shows initials when the cache has no avatar, even for a correspondent who has one. Parts 1, 2, 4 of #714.

- **Cause:** `AvatarCache` names files by the hex of the pseudo; the legacy app's files sit in the same folder as `MD5(lowercased pseudo)` (`MPListView.swift:911-917`, writer `ParseMessagesOperation.m:340-347` @ `87fe0d1c`), so after the update from legacy every cached avatar was ignored.
- **Part 1:** `AvatarCache.entryAdoptingLegacy(forPseudo:accepting:)`: no entry → read the legacy file (read-only; regular file by `attributesOfItem`, which does not follow a link; ≤ 256 KiB; the app's `accepting` closure checks it decodes as an image), copy it under the SwiftHFR name keeping its date. MD5 is a small RFC 1321 function in the engine (`LegacyAvatarName`: Foundation-only, no CryptoKit on Linux, no dependency). A pseudo with U+200B is tried as printed (legacy) and stripped (ours).
- **Part 2:** `MessageRowView.avatarSubject(of:)`: one-to-one → the interlocutor (the list's starter cell, never the account's pseudo), trimmed as legacy; group → icon. Difference from legacy: only the whole label "Interlocuteurs multiples" counts as a group, not any pseudo containing "multiples".
- **Part 4:** unchanged fallback: no entry or a failed read → monogram.
- Spec: LOT-066 updated.

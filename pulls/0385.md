Closes #366
Claim: mac/lot-366

**Problem.** `ForumSessionCheckTests` failed at random on the simulator CI, never the same test twice: `loginSavedWhileACheckWritesBackWinsOverItsCookies` (run 41232795746) and `loginDuringARecheckWinsOverItsResult` (run 41323654034). Reruns passed.

**Cause.** Five tests ran under `.timeLimit(.minutes(1))`. Swift Testing starts that clock before the test gets the main actor, and every app test shares the main actor. On the `xcode-27` runner, untimed tests that do milliseconds of work report 30–40 s in a normal run and up to 120 s in the failing runs (run 41232795746: `TopicReaderModelTests` and others passed at 119.9 s, while the timed test failed at exactly 60.000 s). So the limit measured the main-actor queue, not the test. When it fires, Xcode treats the test as hung and kills the runner process. That is why the second failure has no `Test case` line in the log, and only 155 of the 349 results were printed.
Reproduced locally: run next to a throwaway test that holds the main actor for 65 s, `recheckWhileTheLaunchCheckWaitsOnAnotherAccountSendsNothing` failed with "Test exceeded execution time allowance of 1 minute" at 60.000 s. Run in isolation, the suite passed 50 iterations under full CPU load (500/500): the model has no race.

**Change.** `CheckGate.entered()` now also returns when the gated work calls `finish()` without reaching the gate. It returns whether the gate was reached, and the tests `#require` that. A guard that skips the gated call now fails at once. That hang was the only reason for the time limits, so the limits are removed. The two other `CheckGate` users (`AccountsModelTests`, `AccountsModelLoginTests`) had the same possible hang and now use the same pattern. No app code changes.

**Tests.**
- Same 65 s main-actor hog with the fix: all 10 `ForumSessionCheckTests` pass, at about 65.5 s each.
- A gate that is never reached (gated call moved to 9, temporarily) fails in 0.026 s with "the re-check never reached the gate", where it used to hang until the limit.
- `ForumSessionCheckTests` + `AccountsModelTests` + `AccountsModelLoginTests`: 100 iterations under CPU load (20 `yes` processes), 2100 passed, 0 failed.
- Full app suite: 3 iterations, 1047 passed, 0 failed (iPhone 18 Pro, iOS 27.0 simulator clone).

Note: the main actor is held for long stretches on the CI runner, which is visible in the durations of every suite. Any future wall-clock limit on an app test would be flaky in the same way.

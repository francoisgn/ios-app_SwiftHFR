Not a lot: CI change, operator go (2026-10-27) to remove CI bottlenecks within our rights.

**Problem.** The macOS runners (`xcode-27`, `macos-26`) are saturated: jobs wait for tens of minutes and `Analyze (swift)` repeatedly fails with "The job was not acquired by Runner … capacity constraints". The ruleset requires branches to be up to date, so every merge re-runs full CI on the next PR.

**Change.**
- `ci.yml`: `HFRKit tests (macOS) + iOS 27 build` now needs the existing change-detection job and runs only when the PR touches `Packages/` or `ci.yml` (pushes to dev-swift always run it). A job skipped by `if:` reports "skipped", which satisfies the required check — the same mechanism the CodeQL Swift gate already relies on (CONTRIBUTING §2). Claim and docs PRs stop using a macOS runner.
- `codeql.yml`: `concurrency` with `cancel-in-progress` for pull requests only (group by ref); pushes to dev-swift and the schedule are grouped by SHA and never cancelled, so post-merge analysis always completes.
- CONTRIBUTING §2 table updated.

Not changed (owner's settings, asked to ezzz separately): the up-to-date requirement, auto-merge, required checks.

**Checks.** actionlint (v1.7.7) clean apart from the pre-existing custom runner labels; markdownlint clean. This PR touches `ci.yml`, so its own engine job runs.

# PR #517: #514: MessageListSplitTests gate tests no longer measured by a 60 s limit

**Problem.** `MessageListSplitTests/switchingSegmentDuringASearchStopsIt` and `aCancelledSearchDoesNotUndoWhatWasReadMeanwhile` failed 4 times on 2026-11-06 on PRs that touch no MP code.

**Cause.** Read from the code (the app cannot be built or run on Linux; I did not read the three job logs). The split tests' private `Gate` was already continuation-based and could not hang: `select(.group)` always reaches page 2 with the fixture. What failed was `.timeLimit(.minutes(1))` on the two tests. App tests share the main actor, so on a loaded simulator the limit measures that queue, not the test (same lesson as #366, documented on `CheckGate`; neighbouring `PollModelTests`/`TopicSearchModelTests` cases took 60–100 s in the failing runs; #468 hit the same limit). The change that matters is therefore removing the per-test limit. The Opus reviewer reached the same reading independently.

A second, real race sat in the neighbouring file: `MessageListReadStateTests.waitForRequests` polled with a bounded `Task.sleep` (500 × 5 ms = 2.5 s). On a slow simulator it gave up and the test went on before the load had started.

**Changes**
- `MessageListSplitTests`: both tests drop `.timeLimit` and use `CheckGate` (`gate.run { … }`, `entered()`), which records an issue and stops instead of hanging if the search never reaches page 2. The private `Gate` is removed. Assertions unchanged.
- `MessageListReadStateTests` (`aThreadOpenedWhileTheNewestLoadRunsStaysReadWhenItLands`, `aSupersededLoadLandingLateChangesNothing`): the sleep poll and the private `Gate` are replaced by `CheckGate` signals; on the failure path the first gate is released. Assertions unchanged.
- Both suites get `@Suite(.timeLimit(.minutes(5)))`, a hang backstop only (#468 precedent; review finding 1), since the app job has no `timeout-minutes`.

**Class checked (LESSONS 9).** `.timeLimit` in app tests: only the FilteredPosts suites (5 min, #468) and these. `Task.sleep` / private `Gate` in `App/SwiftHFRTests/Messages/`: none left. The reviewer also listed other suites that still spin or sleep (`ContentLoaderTests:12`, `PseudoListsSnapshotTests:118`, `ReplyComposerDraftTests:99,215`, `ReplyComposerSendTests:133`): outside this issue, left for a follow-up.

**Tests.** Not run (Linux, no app build); CI "App build + tests (iOS 27 simulator)" is the arbiter. SwiftLint not run; LESSONS 21 checked by hand (line length, trailing newline, no stray blank lines).

**What actually caused the failures.** The old private `Gate` in `MessageListSplitTests.swift` was already deadlock-free:
- `waitUntilWaiting()` returned as soon as a waiter was registered.
- `wait()` resumed the observers inside the continuation closure.
- `select(.group)` always reaches page 2 with this fixture: page 1 holds a one-to-one row, `last: 4`, and `onAppear` does not advance because its segment is not empty.

So no test hung. What failed was the per-test `.timeLimit(.minutes(1))`. On a loaded simulator the main actor is shared by every app test, so the limit measured that queue, not this test. The issue comment shows neighbouring tests taking 60–100 s, and `CheckGate`'s own doc comment (`App/SwiftHFRTests/Accounts/AccountTestSupport.swift:27-30`, #366) records the same lesson.

The change that fixes the flake is therefore removing the two `.timeLimit` traits. Switching to `CheckGate` adds a clean exit when page 2 is never asked for, which is good to have, but it is not the fix. The PR text should say this plainly (see finding 4).

**What I checked and found correct**
- **Assertions:** none were weakened. Every `#expect` is kept, and each early `return` follows an `Issue.record`, so the test still fails.
- **`CheckGate` behaviour:** `wait()` sets `arrived` before it parks, and `entered()` resolves on arrival or on `finish()`. `run` calls `finish()` once the work returns. With one gate per test there is no lost wake-up.
- **Main-actor re-entrancy:** the test hops to the `CheckGate` actor, which frees the main actor so the `run` task can start. In both split tests, `select(.oneToOne)` cancels the loader while `isSearchingSegment` is true, and the follow-up search exits because page 1 has a one-to-one row. The late page-2 answer is then dropped (`mine != loadCount`). The asserted outcomes hold.
- **Two-gate test (`aSupersededLoadLandingLateChangesNothing`):** picking the gate by `source.requests.count == 2` works. The test waits on `slow.entered()` before starting the second refresh, so the first handler has already read the count, which is 2: one request from `onAppear`, then this one. When the second load starts, `ContentLoader.load` cancels the first task, but its handler stays parked on a continuation that ignores cancellation until `slow.open()`. The intended order holds.
- **Rest of the class:** `MessageListReadStateTests` (the `Gate` and the 500×5 ms sleep poll) is converted too.
- **SwiftLint (LESSONS 21):** no line is over 140, the files end with a single newline, there are no stray blank lines, and the type body got shorter.
- **Rules:** no `Task.sleep`, no GCD, Swift Testing only. The closures captured by `run` are `@MainActor @Sendable`, the same pattern `AccountsModelTests` uses.

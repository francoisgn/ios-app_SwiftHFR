Claim: mac/w6-167-sonnet (2026-10-28)

**Problem.** A forum-list pager is a window (`1 … 10 20 … 100 500`); its last link was taken as the page count, so a list could offer a fake last page.

**Cause.** `PageNavigation` had `last` only, with no way to say whether it is exact.

**What changed, and why this wide.**
- `PageNavigation.isExact` (HFRModels): default `false`, `Codable` with `decodeIfPresent`, so older records decode as lower bound.
- `TopicListPager` (HFRParsing, the only builder of list navigation): exact only when entries are `1…N` with `N < 10` (HFR shows 1-10 then tens, so nothing hides) or when there is no pager. Anything else is a lower bound. The `N < 10` inference is documented as pending capture in the spec.
- Docs: LOT-167 spec, new FEAT-003 spec, HFR-PROTOCOL §6c LOT-167, FEATURES.md status, CHANGELOG-LEGACY row 22. Not in scope: the app disabling "Dernière page".
- `docs/LOTS.md` has no status cell any more (state lives on the issues), so no row edit.

**Tests** (Swift Testing; all fail to compile without the change, `isExact` does not exist, and the parser ones also fail on behaviour):
- `recordWrittenBeforeTheFlagDecodesAsLowerBound`, `paginationIsALowerBoundUnlessSaidExact` (model, Codable round trip, default).
- `windowedPagerIsLowerBound` (R04, R05a, R05b), `shortPagerIsExact` (R08-2, R50b), `exactnessRule` (shapes), `rowCountBeatsThePagerWindow` (R04 row count 84 / 35634 vs last link 500, per the legacy oracle), MP list R13u1 exact; R13c (no pager) exact.
- `swift test` green locally (372 + others); `check-lot-deps.py` 0 violations; markdownlint passes.

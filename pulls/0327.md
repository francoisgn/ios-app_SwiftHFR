**Problem.** 23 lot issues stayed `status: blocked` after their last dependency merged. Six of them are M2 lots for the Mac, and eight are engine lots for outside contributors. Work that was ready looked blocked.

**Cause.**
- The label and the `### Blocked by` section were generated once, when the issues were created on 2026-10-27, and nothing updates them.
- The label and claim workflows only run from `master` (the legacy app).
- `LOTS.md` no longer has a status column.
- So the transition from blocked to ready had no owner.

**What changed.** `docs/agents/ORCHESTRATION.md` only:
- **Shared state:** the tracker row names the milestone boards #166 (M1) and #324 (M2–M4).
- **Still manual until the workflows are on `master`:** a new step for whoever merges, done in the same work unit as closing the issue:
  1. list the dependents of the closed lot;
  2. check that nothing else blocks them (a capture, an ADR, an operator decision);
  3. swap the label and rewrite `Blocked by`, or name the real blocker;
  4. update the board line, and add a line to the audit list #326 for a PR delivered by an outside contributor.

There is no LESSONS row, because two open PRs already add row 54. The 23 issues themselves are being fixed on GitHub right now; that is not part of this PR.

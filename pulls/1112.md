### Problem
The line between the last read message and the first new one (`div.separator1`, `TopicHTMLBuilder.swift:64-97`) was drawn like any quiet separator (`1px dashed var(--separator)`), unlike legacy, and nothing says where reading resumes.

### Cause
`reader.css` had no rule for legacy's `--color-separator-new-message`.

### Change (CSS only: the markup, the builder and the CSP are unchanged)
- Parity @ 87fe0d1c: modern style `2px solid` (`style-liste-light.css:27, 134-136`), classic `1px dashed` (`style-liste.css:24, 124-126`), colour = legacy's `rgba(0,0,0,0.4)`, expressed as 40 % of `--text` so it follows dark and the themes. The legacy dark sheet (`style-liste-dark.css`) has no `.separator1` rule and no such variable (grep), so there is no dark value to port: this is the choice made for it.
- Deliberate gap (operator, 2026-11-11): a « Nouveau » chip, `::after` generated content centred on the line, accent background. Only the line carries it, so it never shows after the last message of a page (the builder writes no line there) nor without a flag. VoiceOver reads generated content where the line sits. A vertical margin (none in legacy) makes room for the chip.
- MP threads use the same builder and sheet.
- Not settled here: screenshots (light/dark, both styles, densities) and the VoiceOver/Dynamic Type check; the issue asks for them and for the operator's device check, so #807 should stay open for that: this PR is `Closes` only if the operator accepts the CSS as is.

### Tests
`ReaderSeparatorStyleTests` (new): per-style rule, stronger than `--separator`, one chip rule on the line only, the word « Nouveau » never in the generated page. Existing `TopicHTMLBuilderTests.theFlagMessageIsFollowedByTheLegacySeparatorUnlessLast` keeps covering « never after the last message / no flag ». Not run (Linux session).

### Problem
MPStorage (bookmarks, synced blacklist, MP flags in a private thread) had a transport (LOT-052) and a merge (LOT-062) but nothing that decides when to sync, for which account, or shows it. ADR 0013 §7 replaces the legacy app-wide `mpstorage_active` with a per-account state, on by itself when the account already has a storage thread, never creating one without asking.

### Cause
Legacy (`Classes/MPStorage.m`, `AppSettingsView.swift:233-270, 534-545`, `MPListView.swift:354-373, 775-786` @ `87fe0d1c`) keeps one global switch, asks at switch-on, aborts local edits on a failed sync, skips every reload after one failed save, and loses "Dernier accès" at relaunch.

### Change
Spec: [docs/lots/LOT-130-mpstorage-sync.md](docs/lots/LOT-130-mpstorage-sync.md).
- **HFRStorage**: `MPStorageSyncStateStore` (record `mpstorage.<account key>` = `{decidedAt, state}` JSON in the settings store; unreadable values never overwritten automatically; `applyLegacySwitch` for LOT-067), `MPStorageCopyStore` (device-only `post`, `base`, `pending`, `lastSync`, `lastSearch` per account), `SyncedSettingsStore.syncKeys(_:)` so #447 can sync the per-account records (accounts change at run time).
- **HFRClient**: `MPStorageSync`, a per-account loop over LOT-052 (`LiveMPStorageRemote`): `detect` (read-only), `sync` (local edits written on their own base, kept on any failure, one more merge on a concurrent write), `create`, `edit` (local first). Calls are queued, so an edit never lands inside a sync's read-merge-write.
- **App**: `MPStorageSyncModel` per account session (built by `RootModel`), the "Stockage MP" Réglages section (toggle, state in words, Dernier accès, Resynchroniser, creation question), MP group rows showing `⚑ page / max` while sync is on (opening at the flag waits for the reader's flag write, Fable round 1); `writeConsent()` / `edit(_:)` for LOT-131/132.
- Why no wider: blacklist and bookmark edits are LOT-131/132; the reader's flag write is a follow-up (spec "Out of scope"); the app still uses `UserDefaultsSettingsStore` until #447 wires `SyncedSettingsStore` (it then calls `syncKeys(MPStorageSyncStateStore.keys(for:))`).

**Count each successful label deletion.**

If an issue has two status labels and the second DELETE fails, `drop_status` has already removed the first label. The exception skips this increment, so the final count omits that deletion. The close-action count has the same failure path. A concurrent removal can cause the later DELETE to return 404. Update `dropped` after each successful DELETE so a partial failure does not erase completed work from the report. ([docs.github.com](https://docs.github.com/en/rest/issues/labels))

**Problem.** #532 shipped the AQ feed, per-topic check and new-since count; the create was left until its answer was captured (#558, `T50`, `T51`).

**Cause.** No client call for `addAlerte.php`, and #611 showed the AQ database refuses or silently changes some values depending on an unknown `sql_mode`.

**Change.** `AQClient.create(_:)` (HFRClient only, no new dependency): one POST through the cookie-less transport, no redirect followed, no retry, 5 s, legacy field order plus `from=SwiftHFR` (decided on #573). Success only on status 200 with body `1`; everything else (redirect, transport failure, other status or body) is `AQCreateError.unconfirmed`, never a success; refusals are not captured on the live host, so none is read as one. Cancelled before sending is `cancelled` (nothing sent). The report is validated before sending (required fields, column sizes, BMP only, `int(11)` ids, `https://forum.hardware.fr` permalink with no port or userinfo). Spec `docs/lots/LOT-055-aq-client.md` updated, with the differences from legacy.

**Tests** (`AQCreateTests`, shown to fail without the change; mutations checked). `swift test` on HFRKit and `swiftlint --strict` pass locally.

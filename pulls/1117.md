### Problem
The operator wants one look for every list (#1107, consistency rule): the Favoris card by default, and the edge-to-edge look of a category's topic list as the « Lignes denses » view, so a list never mixes the two.

### Cause (facts at `12fdd8bf`)
- On the iPhone, on current `dev-swift`, every list already draws the Favoris card: Catégories (`ForumListView.swift:24`), the topic lists (`TopicListView.swift:61`, explicit since #1081 / `e1e945d9`, 2026-11-18 06:48), Messages (`MessageListView.swift:35`), Profile (`UserProfileView.swift:64`), all `.insetGrouped` + `densityListMargins()`. Simulator renders of the real `RootTabsView` with fixture data show the category topic list on the same card as Favoris (`before-iphone-classic-dark-2-category-topics.png` vs `-3-favoris.png`), dense rows on or off.
- The edge-to-edge look of the operator's screenshot is the **automatic** list style the topic list had before #1081: a plain list in a split view's content column (#1081's own measurement), where the category topic list lives (`RootTabsView.swift`, `CategoriesTabView` `content:` column), while Favoris sits in the sidebar column. Rows on the screen's background, flagged rows as `RowTint` pills 4 pt from the edge (`RowTint.edgeGap`). The operator's build (08:51) most likely predates #1081 or showed the column layout: to confirm on the device. This inference contradicts #1081's commit text (« iPhone unchanged », not measured on the iPhone): either the automatic style was already the block on the iPhone and the operator's screenshot comes from another layout, or #1081 did change the iPhone's category topic list. Not settled here (no pre-#1081 build measured).
- Search, Bookmarks and Accounts set no style (automatic). Nothing drove the list look from « Lignes denses »: only the rows (`TopicRowStyle.current`, `MessageRowView.usesDenseRows`).

### What changed
- `ListLook` (`Common/ListLook.swift`): one switch, read from the same flag as the rows (`ExperimentalFeature.denseRows`), and `listLook()` (on the list), `listLookRows()` (once around the whole content of each list, `List { Group { … }.listLookRows() }`, so no row keeps the card), `listLookRow(isSelected:)` (rows of lists with a selection). The style is always `.insetGrouped` and the look only changes values (outer margin, background visibility, row background nil, clear or selected), so switching keeps the list's identity: no reload, no lost scroll position (Favoris re-runs `refresh()` on a new identity).
- Classic (off, default): unchanged on the iPhone, the Favoris card everywhere; Search, Bookmarks and Accounts now say `.insetGrouped` explicitly (the card on the iPhone already; in an iPad column the automatic style was plain).
- Dense (on), `Experimental/DenseRows/DenseListLook.swift` with `EXPERIMENTAL(denseRows, #1107)` markers (decisions by mac/M1 under the operator's go, round 1): no card, outer margin 0 (the rows from one side to the other, safe area kept), clear row backgrounds on the **plain list's background** (white in light, black in dark: the grouped background is hidden, `systemBackground` behind), or on the theme's fill where a theme or dark style paints the screen (`AppScreenBackground` now says so in `screenPaintsLists`, so the classic value of every list stays what it was). #817's flag pills show as strips 4 pt from the edge, as in the operator's screenshot. A selected row (iPad columns) gets an accent background (`DenseListLook.selectedRowBackground`, as `BookmarksView`), since the clear row hides the list's own selection. The large-title row has no band in dense (`listLookTitleRow()` in `ScreenLargeTitle`); classic keeps today's row unchanged (identical classic renders before/after). Catégories keeps its icons, loses height (vertical inset 5 pt, title/sub-forum spacing 1 pt: 58 → 44 pt, 70 → 47 pt) and gets 16 pt between icon and title (12 classic).
- `densityListMargins`, `densityRowMargin`, `densityHeaderMargin` read the look as well as « Mode compact » (`ListDensity`), so headers and scope rows stay on the rows' margin in both looks.
- Lists: Catégories, the topic lists (category, Favoris, Drapeaux, with the scope bar), Messages (segment switch included), Search, Bookmarks (error and empty rows included), Accounts (« Ajouter un compte » and the store-problem section included), Profile, archived drafts, Plus (#572's definition plus the drafts list and the Plus menu, mac/M1's decision). Not changed: the iPad root's navigation sidebar (`RootSidebarView`), a sidebar of destinations rather than a content list, and a file LOT-147 (#237) rewrites in parallel; it can follow in a later PR if the operator wants it.
- Bookmarks keeps its own background switch (`BookmarksView`) instead of `listLookRow(isSelected:)`: its selected row already had an accent in the classic look (it opens the message beside the list, #1089), which the other lists leave to the system's selection; the shared modifier gives no accent in classic.
- `ScreenLargeTitle`: a row trait set below `onScrollVisibilityChange` is not honoured (the row's own clear background, hidden separator and 4 pt insets were ignored, so the title sits on the card in classic). Those dead traits are dropped (classic renders unchanged) and a comment says why the look's background must stay above that modifier. Offline is not reachable (`DISABLED(offline, #822)`) and untouched. No root or column layout file touched (LOT-147).
- #817's row tint is kept as it was: pills on flagged rows in category lists, only super favourites in Favoris and Drapeaux; in the classic card it is the same as today, so no conflict with the card look.

Why this wide and no wider: the switch, its two value sets, and one call per list; no row content changes (the dense rows are #905/#973's).

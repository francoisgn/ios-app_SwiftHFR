## What and why
**Problem.** A tap on a member's avatar or pseudo in the reader opened an anchored author menu (#595). Legacy opens the member's profile directly when the message has a profile link, with MP / Whitelist / Blacklist on it. Operator decision (2026-11-16, option A on #652): do as legacy, and keep the author menu only for a message with no profile link.

**Cause.** `requestMenu` always presented the author menu. The reader also built the profile sheet without `onPrivateMessage`, so MP never showed on a profile. The profile stayed open after a list toggle.

**Change.**
- **Routing** (`TopicReaderModel+Menu.requestMenu`, `openMenu`): for `source: .avatar`, when "Profil" is offered, no menu is presented and `openMenu` runs `.profile` straight away. Otherwise the author menu opens as before. Legacy `presentAvatarActionSheet`, `MessagesView.swift:4415-4420` @ 87fe0d1c.
- **`ProfileActionHandler`** is offered only for a link the router reads as a profile (`HFRLinkRoute.profile`). Any other link falls back to the menu, as legacy's sheet does.
- **`AuthorMenuFlow`** now owns the profile sheet (`profile`, `showProfile(_:from:composer:confirm:)`, `closeProfile(then:)`, `profileDidClose()`), so the flow is tested without a view. A profile opened from a message gets legacy's quick actions (`userProfileQuickActions`, `:4387-4412`):
  - MP, from the message's private-message link, when the post is not the user's own and a composer exists;
  - the lists on the message's author, when the post is not the user's own and the pseudo is not empty.
- **After a quick action**, "MP" or a toggle closes the profile first. The composer opens, or the result shows as the reader's toast (which announces itself), in the sheet's `onDismiss` (legacy `dismissUserProfile(then:)`, `:4422-4490`). The page is rebuilt with the lists. The profile then shows no sentence of its own, so VoiceOver hears the result once.
- **A profile opened from a link** in a message body is unchanged (LOT-118: it stays open and shows the sentence).
- **Docs:** the legacy pointer of `AuthorActionHandlers.swift`, the `UserProfileModel` header, LOT-087 difference 5 and the LOT-118 profile difference.

Why this wide and no wider: the policy, the menu UI and the bridge are untouched. Only the avatar route and the profile hooks change.

**Problem.** Favoris has no way to see only the favourites with something new. Legacy has none either (`Favorites.swift:581-594` @ 87fe0d1c filters by collapse state and the empty-sections setting only): a deliberate gap, asked by the operator.

**What « unread » means here.** Favourites rows carry no `sujetCase1` marker (`readState` is `.unknown`). The row's state is the badge it draws: pages between the flag and the end of the topic, `TopicRowCues.unreadPages` (legacy `unreadCount = maxTopicPage - curTopicPage`, `Favorites.swift:1096-1100`; badge only above 0, `:1130-1131` @ 87fe0d1c). A row with no flag link, or flagged on its last page, is read. Limit: new messages on the very page of the flag show no badge, so « Non lus » does not list them either, as the list does not.

**Change.**
- `FavoritesLayoutOptions.unreadOnly` and `FavoritesPresentation.isUnread`: « Non lus » keeps the rows with that badge, in the grouped and the flat list. A section it empties is dropped, unless the empty-sections setting shows it; super-favourites follow the same rule (no empty « Super favoris » section).
- New device-only setting `favorites_unread_only` (`SettingKey.favoritesUnreadOnly`, default « Tous », not synced; ADR 0013 row added), read and written by `FavoritesOptionsModel.unreadOnly`.
- `FavoritesUnreadFilterButton`: one tap, no menu, trailing in the Favoris top bar before refresh (`TopicListView` toolbar, only where `model.favorites` exists), `line.3.horizontal.decrease.circle` / `.fill`, accessibility label « Afficher : non lus / tous ».
- Empty state (`NoUnreadTopicsView`, in `FavoritesUnreadFilterButton.swift` since `TopicListView.swift` hit the 400-line limit after the #1056 merge): with « Non lus » on and no unread row at all (`TopicListModel.showsNoUnreadFavorites`, rows whose flag was removed excluded), « Aucun sujet non lu » with a « Afficher tous les sujets » action, and no empty headers whatever the empty-sections setting. Unread rows hidden inside folded sections are not « nothing unread »: the folded-sections screen shows then.
- « Tout replier » folds only the sections the list shows (under « Non lus », those with an unread row).
- Not changed: the pushed category lists have no button; no Duo cover-screen layout exists in SwiftHFR, and overlap with the title pill (#1012) is for the device check (#893). « Tout replier » ignores removed flags, as under « Tous ».

**Tests.** `FavoritesUnreadFilterTests`: the unread rule; « Tous » unchanged; filtering and dropping emptied sections; the empty-sections setting; super-favourites; the flat list; the default « Tous » and the key written, surviving a relaunch; the model grouping under the choice; fold-all under the filter; three `TopicListModel` cases (nothing unread with empty headers enabled, unread only in folded sections, last unread flag removed); the button's state, icon and label; the model toggle; and a hosted test that puts the button in a top bar and sends `.primaryActionTriggered` to the control on the right of the bar, expecting the choice to flip: it ran and passed on the Mac runner on `636fe4a` (job 134569153985; the one red test there was `FavorisScrollHostedTests`, the `AccountsModel` trap #1085 fixed). `SettingKeyTests`, `SettingScopeTests` updated and run on Linux: green (30 tests). `swiftlint --strict` clean.

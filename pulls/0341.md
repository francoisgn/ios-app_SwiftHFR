**Problem.** Legacy rewrote a topic-list URL for page N by appending `?page=N` to `liste_sujet-1.htm` (`TopicPageURLRouting.replacingPage`, `HFRswift/Swift/Common.swift:2750-2759` on `master`: the path has no `page=` and no `_N.htm`, so it falls through to adding a query item). HFR ignores that query: the header said "page 11" and page 1 was shown. Found and fixed in legacy by Bybifok (`a817498`, ezzz/HFRnow#3).

**Does SwiftHFR have it? No.**
- `ForumCatalogue.topicListPath` (`Packages/HFRKit/Sources/HFRModels/Catalogue/ForumCatalogue+TopicListPath.swift:6-9`), used by `HFREndpoint.topicList`, always builds `forum1.php?config=hfr.inc&cat=C&page=N&subcat=&owntopic=F`.
- `HFRLinkRoute` reads the page from the path for canonical lists (`liste_sujet-N.htm`) and from `page=` for `forum1.php` (`HFRLinkRoute+Routing.swift:52-68, 93-105`).
- No code builds `liste_sujet-1.htm?page=N`. The app pages sub-forums with `SubforumPath`, already tested by `SubforumPathTests.replacesThePageOfAListPath`.

**Change.** Tests only, as the issue's scope asks (step 2), plus a CHANGELOG-LEGACY row.

- `endpointRequestsTheCapturedPage`: `HFREndpoint.topicList(category: .forum(13), page: N).url` equals the capture's requested URL (meta `url`) and has no `liste_sujet`. - `routerKeepsThePage`: `HFRLinkRoute.route(for:)` gives the same `.topicList(page: N)` for the `forum1.php` request and for the canonical final URL.

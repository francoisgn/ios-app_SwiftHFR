### Problem
Messages splits into « MP » / « MP multiples » only when the setting « Réglages › Messages › Affichage des MP » is « Deux listes », the position is not remembered, and there is no way to see both at once in the split view (#899; operator decisions of 2026-11-14 and 2026-11-15).

### Cause
LOT-171 (#297) made the split an opt-in setting and kept the position in memory only (`MessageListModel.segment`, set to `.oneToOne` at start).

### Change
- `MPSegment` now lives in `HFRStorage/Settings` (next to `TopicListFlag`; no new public `HFRModels` type, no `Codable`), with a first case `all` (« Tous »); `contains` is true for every row on `all`. Unread count of « Tous » is the sum of the two others (same `unreadCount(in:)`).
- New `MPListSegmentStore` (`HFRStorage`): the last position per account under `mp_list_segment.<account key>` (`AccountKey`, as `mpstorage.<account key>`), device-only, never in `syncKeys(_:)`, same `SettingsStore` mechanism as the Tous / Favoris / Suivis / Lus filter (`HFRswiftGlobalTopicListFlag`, #836), one key per account as the lead asked. An unknown, empty or mistyped stored value reads as Tous; logged out reads Tous.
- The picker « Affichage des MP » and the branch that hid the switch are removed; the switch is always shown (once the list has rows). `GeneralSettingsModel.mpListDisplay` and `MPListDisplay+App.swift` are gone.
- A change the app makes (the row of a message just sent, a notification tap) keeps Tous, else moves to the row's segment without overwriting the member's remembered choice (`chooseSegment(_:remember:)`).
- `mp_list_display` stays in the catalogue (still synced) only to seed an account's first choice.

### Persistence and migration
- `mp_list_display` written by released versions stays readable: on an account's first use, absent `mp_list_segment.<account>` seeds it once (`single` « Tout en un » is Tous, `split` « Deux listes » is MP; unknown old value reads Tous), and the seed is stored immediately so a later change of the old key (iCloud sync from another device) is ignored. Bob's first use is seeded from the old key, not from Alice's choice.
- No existing key changes type or meaning; the new key is additive and tolerant.
- Docs: ADR 0013 matrix rows, LOT-060, LOT-171, LOT-172 updated.

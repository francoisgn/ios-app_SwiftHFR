### Problem
The floating « + » button defaulted to « Réponse rapide » (`.quick`), as legacy does. The operator wants « Répondre comme le forum » (`.forum`) by default, unless the member changed it (#1016, point H).

### Cause
`SettingKey.replyButtonBehavior` (and the two reader fallbacks) defaulted to `.quick`.

### Change
- `SettingKey.replyButtonBehavior`: default `.forum`; `ReaderSettings.replyButton` and `ReaderSettingsWatch.replyButton` fallbacks follow. Doc comments, the LOT-119 and LOT-060 spec rows updated.
- **Absent vs stored `quick`**: `UserDefaultsSettingsStore.rawValue` returns `nil` for a never-set key (`defaults.object(forKey:)`), and `Setting.value(from:)` applies the default only then, so a stored `quick` or `hidden` is read as is. Nothing registers defaults, nothing writes the key at launch (`TopicsSettingsModel` writes only on a change), `LegacySettingsNormalizer` does not touch it, and the iCloud merge pushes stored values only.
- **Legacy import**: legacy's `@AppStorage(..., default: quick)` writes the key only when the member changes the picker. A migrated legacy install therefore has the key only if it was changed; one who never touched it (effectively on `quick`) gets `.forum` now. This is the intended « unless changed » reading.
- An unknown stored value now reads as `.forum` (the default), where it read `.quick` before.

### Tests
- `GeneralSettingsKeyTests`: `absentReadsAsForumAndRoundTripsLegacyValues`, `importedLegacyValueIsRead` (unknown → forum), `theLaunchNormalizerLeavesTheKeyAlone`: shown to fail with the default reverted to `.quick` (3 failures, also reproduced by the reviewer).
- `aStoredValueIsKeptWhateverTheDefault` (quick/hidden/forum): guards « stored value kept » (passes both ways by design; it fails if a future change treats a stored `quick` as unset).
- App tests (macOS CI only): `TopicsSettingsModelTests`, `ReaderDisplaySettingsTests`, and `ReaderSettingsWatchTests.theReplyButtonFallbacksAreForum` (round 1) pinning both reader fallbacks.
- Compile check green on 167f8ef; round 1 changes only a test and a doc row.

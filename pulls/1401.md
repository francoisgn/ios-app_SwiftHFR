The operator decided on 2026-11-27 (#251) to run a minimal internal TestFlight now, before the in-place update of `hfrplus.red.super`. That needs a variant of the app with its own App ID, so a beta never replaces the store app nor shares its data, and a way to archive, export and upload it with its own build counter.

### Change
- **Configuration `Beta` + shared scheme `SwiftHFR Beta`** (`project.pbxproj`: three `Beta` configurations copied from `Release`, one file reference; the scheme runs, profiles and archives in `Beta`, tests stay `Debug`). The identity is in **`App/Config/Beta.xcconfig`** (includes `Shared.xcconfig`, so `Secrets.xcconfig` applies): `hfrplus-swift.red.super`, « SwiftHFR β », team `QMG83DG7YP`, automatic signing. Same pattern as legacy's `hfrplus-legacy.red.super` (`SuperHFRplus.xcodeproj/project.pbxproj:6345,6410` @ `87fe0d1c`).

The upload prompt lists app record, scheme, version, build, commit, package and size, tester scope and API key id; the typed confirmation names the app record: `upload <bundle id> <version> (<build>)`. API key: `HFR_ASC_KEY_*`, `.p8` outside the repo (e.g. `~/.appstoreconnect/private_keys/AuthKey_<id>.p8`), unchanged.

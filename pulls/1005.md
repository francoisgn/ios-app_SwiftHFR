## Change
- **`NoelPackingModel`** (new, `@Observable @MainActor`, owned by `SeasonalThemeModel` like `crossings`): the first packing activation with animations allowed queues `Packing(year, theme)` in memory **after** the store is restored as before (a kill loses nothing). `SeasonalThemeModel.drawnTheme` = `activeTheme ?? packing.current?.theme` keeps the red accent, snow, drifts and caps drawn until the elves are done (`SwiftHFRApp.appTheme`, `SeasonalDecorations`, `SeasonalSnowCapSection`, `snowFalls` read it; the picker and the crossings keep `activeTheme`, so nothing crosses during the packing). It starts only on a clear screen (lock, sheet/alert, keyboard: rule 5) in a scene that is active itself, in one scene; ends on a tap (rule 3), when the screen stops being clear, or when its scene leaves or goes away — except in its first second (`replayWindow`), when it waits and plays again, at most twice (an alert of the same launch would otherwise take it away unseen); animations turned off before it starts drop it. Elves still waiting when the packing days end are dropped at the next activation; playing ones finish.
- **Per-scene activity** (round 1, both models): `NoelPackingLayer` and `NoelCrossingLayer` report their own scene's phase (`onChange(of: scenePhase, initial: true)` → `sceneChanged(_:active:)`); the models keep the set of active scenes. Crossing foreground time runs while any scene is active; a scene gets a crossing or the elves only while it is active; only its own scene leaving stops them. The app-wide calls in `SwiftHFRApp` are gone.
- **`NoelPackingLayout`** (pure): up to three elves, a fifth of the window high (≤ 180 pt, never taller than the band), at even fractions of the band's width with ≥ 1.25 elf widths between centres; they rise from the band's bottom edge in the first 20 % of the run, hop (amplitude easing in and out), and go down in the last 20 %.
- **`NoelPackingLayer`**: asks every 0.5 s while a packing waits (never per frame), plays 4.5 s (`NoelPackingModel.duration`, ≤ 5 s) with « Allez on remballe » in a capsule; the snow and drifts fade meanwhile. Hidden from VoiceOver, which gets « Allez on remballe » as an announcement (rule 6). No haptic (rule 4's haptic is for crossings).
- **Replay cap in time**: a cut arrival sleigh is queued again while less than `arrivalReplayWindow` (15 s) has passed since its **first** start, however many cuts; then the alert comes alone. **Debounce**: the crossing layer asks only once the band size has held 0.3 s, so a drag does not start and cut the sleigh at each size. Comment fixed to name only the resize.
- **Art**: the operator's validated `noel_elf` render, trimmed (alpha > 8 → 364 × 780) and scaled to 252 × 540 px into `Assets.xcassets/Noel/NoelElf.imageset`; job added to `tooling/art/noel-crossings/derive.swift`. No Mac in this session: the PNG was made with the same trim and a Lanczos scale in Python (PIL), which CREDITS.md and the code say; a later `derive.swift` run rewrites it with CoreGraphics resampling (same box, same size). Credited in CREDITS.md « Seasonal art ».
- Spec `docs/lots/LOT-166-seasonal-noel.md` updated (behaviour, per-scene activity, first-second replay, edge case, art, legacy counterpart).

Why no wider: no change to the scheduler's stored state or keys, nor to the alert; the packing is in memory only.

## What and why
Operator's device feedback (2026-11-16, build 75d955b3): with a composer open, pull-to-refresh is disabled (`TopicReaderModel.refresh()` returns under `suspendsPageInteractions`), yet the « Tirer vers le haut pour actualiser » hint stayed. The action is unavailable, so the hint must be too.

- `TopicReaderModel.offersPullHint` = `!suspendsPageInteractions`, the only state that suspends the refresh (docked and sheet composers both feed `openComposers`).
- `ReaderWebController.offersPullHint` toggles a `no-pull-hint` class on the page root live (`pullHintScript`); `reader.css` sets `visibility: hidden` (not removed), so the page keeps its length and the reading position does not move. No re-render.
- The same script is a user script at document start (no flash on a document loaded under a composer) and is reapplied when a document is ready (`applyDisplayState()`). The LOT-186 spec says so.

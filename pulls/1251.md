**Problem.** If you follow a `cat=prive` link from a message, the pushed reader shows the conversation without « Répondre », « Citer », « Éditer » or « Supprimer ». The same conversation opened from Messages has all four. This breaks LESSONS 7 (every entry point to a conversation behaves the same).

**Cause.** `TopicReaderView.swift:157-158` passed `composer: linked.model.isPrivateConversation ? nil : composer`. The reason given in the comment was "no composer in Messages", which stopped being true with LOT-128: `MessageReaderColumn` hands its `TopicReaderView` the composer (`MessagesRootView.swift:45-58`).

**Change.**
- The destination now passes `composer` unconditionally, and the stale comment is replaced.
- Both readers are the same `TopicReaderModel` and answer through their page's own `#repondre_form` link (`replyTarget`). No second path is added.
- Legacy shows « Répondre » whenever the page has an answer link, MP threads included (`HFRswift/Swift/MessagesView.swift:5481-5494` @ `21173e77`).
- The LOT-137 spec line that described the restriction is updated.
- The `TopicReaderModelTests` doc comment that cited the restriction is updated.
- No GAP row: this removes a SwiftHFR-only difference and restores the legacy behaviour.

**Tests** (`App/SwiftHFRTests/Reader/LinkedPrivateConversationTests.swift`, app-hosted; not run here, since Linux cannot build the app):
- `aLinkedPrivateConversationHasItsOwnReplyTarget`: a topic reader follows a `cat=prive` link. The linked reader loads the captured MP page `RA1` (with its `#repondre_form`), is a private conversation, and has a reply target on its own `cat=prive` topic. This is the model side: it already passes before the change.
- `theLinkedReaderGetsTheComposerWhateverItShows`: the view's destination hands `composer` and has no `isPrivateConversation ? nil` branch. Red before the change: the source holds that branch.

SwiftLint 0.65.1 `--strict` clean.

Device check (#893): follow an MP link from a topic. « Répondre » must show, and quote, edit and delete must work as in Messages.

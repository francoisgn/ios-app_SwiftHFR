## Problem
Fable finding 6, non-blocking, on #575 (https://github.com/ezzz/HFRnow/pull/575#issuecomment-6709646711): in `FilteredPostsView`, the `failed:` closure kept `readyToken`.
When an already-shown page crashes and its reload then fails twice, the `failed` flag is set. The "Réessayer" view only appears while `readyToken == nil`, so the user sees a blank web view and no "Réessayer".

## Change
The `failed:` closure now sets `readyToken = nil` before `failed = true`. This is the same rule `TopicReaderModel.documentDidFail` follows since #575.

## Tests
None added. `readyToken` and `failed` are private `@State` of the view, and the app has no view-test harness for them. The reader-side equivalent is covered by `aFailureOfADocumentReadyEarlierIsStillAnError`.

`swiftlint --strict` reports 0 violations. Fable said its APPROVE on #575 carries over to exactly this change.

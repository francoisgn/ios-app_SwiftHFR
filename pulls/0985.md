**Problem.** On an iPhone the default build opens every composer as the modern compact card: Réglages › Expérimental › « Composer moderne » is on by default. Legacy opens the reader's composer full screen.

The operator decided on #855 (2026-11-14, at ezzz's request): legacy's full-screen composer becomes the M4 default, with no new setting. The modern composer stays behind its switch and its code is untouched.

**Cause.** `experimental.modernComposer` defaulted to `true`. With it off, the reader showed a full-height **sheet**, not legacy's **full-screen cover** (`MessagesView.swift:5429-5443`, `coverVerticalFullScreen` @ 87fe0d1c: `modalPresentationStyle = .fullScreen`, `.coverVertical`).

**Change.**
- **Default:** `SettingKey.experimentalModernComposer` now defaults to **false**. A member who set the switch keeps their stored value.
- **Placement:** `ComposerPlacement` gets `.cover`. `reader(...)` gives:
  - modern on: docked in compact width, a sheet in regular width (as before);
  - modern off on an iPhone: `.cover` at any width;
  - iPad: `.sheet`.

  The split carries `// EXPERIMENTAL(modernComposer, #904)`.
- **Presenter:** `ReaderComposerPresenter` attaches a `.fullScreenCover(item:)` beside the sheet and the bar. One binding helper, `presented(_:)`, serves both presentations, and `LivePlacement` keeps the latest placement.
- **Unchanged:** the lists' composers (new topic, new MP) stay the full-height sheet, and the modern composer's code is untouched.
- **Texts:**
  - the option's explanation now reads « Désactivé : le composer s’ouvre en plein écran, comme l’app historique. »;
  - the ADR 0013 matrix row, AGENTS.md §7 (`experimental`) and the `EXPERIMENTAL` markers of the reply, edit and MP flows are updated.

**Deliberate differences, for the operator to confirm**
- **iPad keeps the sheet.** Legacy's cover has no idiom check (target `TARGETED_DEVICE_FAMILY = "1,2"`), so legacy is full screen on iPad too. The issue's acceptance said "iPad unchanged", so I kept the sheet. Flipping it is a one-line change in `ComposerPlacement.reader`.
- **New topic stays a full-height sheet.** That matches legacy's code (`MainWindow.swift:905-921`, `.sheet` @ 87fe0d1c), which shows nearly full height on an iPhone. The decision's wording says "full screen (reply and new topic)". If a true full-screen cover is wanted there, say so and I'll add it.
- **New MP from the Messages list:** no SwiftUI counterpart is cited at 87fe0d1c, so it keeps today's sheet.

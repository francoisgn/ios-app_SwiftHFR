LOT-057
Refs #83 (left, all waiting on Mac captures or a reader: sub-categories #285, anonymous paging and error answers #355, a bucket row's resume link / read state, bucket vs flags page membership and a bucket without a valid session #830, the account's `topicpp` reader #833)
Claim: cloud/lot-057-opus

### Problem
#356 shipped the anonymous part of LOT-057. The logged-in flag buckets (`topics/{participated,read,favorites}`) were waiting on #335, now captured (`R335a`-`R335e`, `R603f`), and were read by no client.

### Cause
No client sent the account's cookies to `rest_api.php`; `RESTBrowsingClient` is cookie-less by design.

### Change
- `RESTFlagBucketClient.topics(in:postsPerPage:)` (HFRClient): one GET of the global bucket (`R335a`-`R335c` URLs, no paging: HFR ignores it, `R335d`), redirects not followed, through an ephemeral probe seeded with the account's cookies (the `FlaggedTopicsPoll` pattern): the account is only read. Result: `RESTBrowsingResult<FavoritesPage>`, one section per category group. `postsPerPage` is the account's `topicpp` (E19); nothing reads it yet (#833).
- `RESTDocument.bucket`: every level checked (`list_type`, `page` 1, href names the bucket asked for, `results_count` = entries as a consistency check, one group per category, each row in its group's category). `flag_owntopic` 3 → `.yellow`, 1 → `.blue`, 0 → `.red` in `read` (as `R603e`) else nil, 2 → nil (redface2 only, ADR 0015 point 4). `last_post_read_id`, `last_position`, `is_read`, `is_sticky` are **not read**: no capture ties them to the flags page, so a row opens at its last page, read state unknown (#830).
- Fallback on a REST failure (not on cancellation/offline/timeout): `forum1f.php` of the same `owntopic` with `FavoritesParser`, `doNotFollow`, served-in-place check, `R70b` → `.sessionExpired` (new `RESTBrowsingError` case). An empty bucket also falls back: an anonymous or stale REST answer is not captured, and the HTML page tells "logged out" from "empty". The two sources may not list the same topics (`forum1f.php?owntopic=1` drops topics without news): the result says which one it is.
- `HFREndpoint.favorites(filter: .read)` now builds `R603e`'s URL (`config=hfr.inc&owntopic=2&new=0&nojs=0`) instead of throwing; `.all` stays refused. HFR-PROTOCOL R3 rows and `FavoritesParser` doc updated.
- Spec `docs/lots/LOT-057-rest-browsing.md` updated (behaviour, fixtures, pending capture, intentional differences). No HFRModels change.

Why no wider: the flat per-category bucket (`R335e`, `R603f`) is not needed (the global answer is whole) and is refused as an answer; sub-categories and anonymous paging remain uncaptured.

### Tests
- `RESTFlagBucketDocumentTests`: `R335a`-`R335c` against the JSON walked with `JSONSerialization` (not the decoder); the account's page size (20, 40, 100, 1); `R335d` decodes as `R335a`; flat forms refused; cross-bucket answers refused; per-field breakages each naming its field; flags per bucket; `is_sticky` not read; row without sub-category.

- `HFREndpointReadTests`: `.read` → `R603e`'s URL byte for byte.
- Shown to fail without the change: 22 mutations applied and reverted, each failing a named test (spec, Tests). `swift test` on Linux: 1962 tests green; SwiftLint clean; `check-lot-deps.py` 0 violations.

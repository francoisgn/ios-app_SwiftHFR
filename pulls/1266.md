**Problem.** These are the three divergences from `SmallStoreState` the issue names.
1. A v2 pseudo-list or reading-positions file whose shape changed was reported as `loadFailed(<decoding error>)` instead of `unsupportedVersion(2)`.
2. Writes under an empty account were accepted: `block("x", account: "")` stored a blocklist under the key `""`, and drafts likewise.
3. Positions recorded under "Alice" were not found under "alice" (the app's eraser worked around it).

**Scope.** The issue says the duplication itself is #836's. This PR fixes the behaviours in the existing stores instead of moving them onto `SmallStoreState`, a larger change better done with #836.
- File names, encoders and date strategies are unchanged.
- The v1 formats are unchanged: the pseudo-list file is now pinned by a golden test, and positions already were (`aRecordHoldsOnlyIdsAndNumbers`).
- The drafts version rule stays as it is: a newer drafts file is set aside either way.

**Change.**
- `StoredVersion.read(_:)` is the version probe of `FileSmallStorePersistence`, now shared.
  - `FilePseudoListPersistence` and `FileReadingPositionPersistence` read the version first. A newer version gives `unsupportedVersion(n)`, whatever the shape. A version below 1 gives `loadFailed`.
  - Both stores pass their own error through, and also refuse a version below 1 from any persistence.
- Empty account refused: an account whose key (`AccountKey`) is empty is refused for any write that stores something.
  - `PseudoListStore.block` and `replaceBlocklist` with pseudos throw `PseudoListError.emptyAccount`.
  - `DraftStore.save` with content and `archiveReply` throw `DraftError.emptyAccount`.
  - Emptying or removing stays possible under any key, so data stored under `""` before can still be erased.
  - A legacy blocklist filed under an empty name is rejected on its own by the importer; the other lists are imported.
  - The app's only uses of these errors are non-exhaustive: the editor's `default`, and the composer's `if case .loadFailed`.
- `ReadingPositionStore` keys by `AccountKey.make(account)` everywhere: reads, writes, `merge`, `remove` and `removeAccount`.
  - The empty-account check runs on the key, so U+200B alone is refused.
  - Files written before keep other spellings. They are merged on read (`keyedByAccount`): per topic the newest `updatedAt` wins, and on equal dates the position ahead wins, as `merge` does. Nothing is dropped. The next `advance`, `reset` or `merge` saves under the key and applies the limit.
  - `accounts()` now lists keys. That matches LOT-172's `positions.<account key>`; the sync quarantine test expectation is updated from `positions.Alice` to `positions.alice`. `SyncedListsStore` is not run by the app yet.
- Docs: LOT-090 §Accounts, LOT-061, LOT-063, LOT-172, `ReadingPositionDocument`, and the comments in `AccountDataEraser` and `SyncedListsStore+Quarantine`.

**Tests** (HFRKit, run on Linux). Each is red before the change or under its mutation (checked by the author and by the reviewer), except the golden file.
- `StoreGuardsTests`:
  - version first: `newerPseudoListVersionWithAnotherShapeIsReportedAsNewer`, `newerPositionVersionWithAnotherShapeIsReportedAsNewer`, `aVersionBelowOneIsUnreadable`, `aPositionVersionBelowOneIsUnreadable`;
  - empty account: `anEmptyAccountIsRefusedForABlocklist`, `aBlocklistUnderAnEmptyKeyCanStillBeEmptied`, `anAccountKeyEmptyOnceNormalizedIsRefusedForAPosition`, `anAccountKeyEmptyOnceNormalizedIsRefusedForAMerge`, `anEmptyAccountIsRefusedForADraft`;
  - one key per account: `positionIsFoundWhateverTheAccountCase`, `spellingsStoredBeforeAreMergedOnRead`;
  - golden file: `readsTheVersion1PseudoListFile`, which passes by design and pins the format.
- `LegacyImporterRecoveryTests.blocklistUnderAnEmptyName`.

Two existing expectations change on purpose: `ReadingPositionStoreTests.accountsAreKeptApartByTheirKey` ("User1" now finds user1's position) and `LocalStoreSyncAPITests` (`accounts()` lists `alice`).

Full `swift test`: 2197 green. SwiftLint 0.65.1 `--strict` clean. App code: two comments changed.

### Problem
Since #1295, `sub`/`sup` read `--context-100` for the floor. A sub/sup inside another one, and a sub inside a quote header (`b.s1`), did not: the header changes the font size without setting the context, and the nested one used the context over 1.2 instead of 1.44. At 100 % that computed 11 px (the floor) instead of the dev-swift size.

### Change
`reader.css` only:
- `b.s1` sets `--context-100` (and `--code-100`) to its own size at 100 % (0.85, 0.7225 in code and signature, 0.614125 in a signature code block, of the message text), one rule per existing `b.s1` size rule.
- `:is(sub, sup) :is(sub, sup)` (and its `table.code` / `table.fixed` form on `--code-100`): `max(1em / 1.2, min(context-100 / 1.44, 11px))`.

Round 1 (review r1327): a third sub/sup level gets its own rule (context / 1.728, and the code form); deeper levels are not covered (they take the third level's size). The closed blocked quote header sets `--context-100` to 0.85 of the message text, so a sub there holds the floor in a signature too.

### Tests
`ReaderTextFloorWebTests` gains a nested sup, a nested sub in a `[fixed]` block, a sub in a quote header and a sub in a code header, in both existing tests (70 %: within [min(100 %, 11), 100 %]; 100 % and 130 %: dev-swift size times the percentage), roots 17 px and 14 px.

| Element (root 17 px) | dev-swift (100 %) | before fix at 100 % | after |

Direct-PR: dev-swift CI is red; a test deadline in one helper, no product code
Claim: ext/opus-helper1

**Problem.** The `App build + tests` job has been failing on `dev-swift` since 0e0f61a, a docs-only commit. The same two tests fail on PR #309:
- `ReaderWebSecurityTests/markupCannotForgeATap`, after 102–105 s;
- `ReaderWebControllerTests/thePageRunsNoScriptAndRoutesEveryImageThroughThePolicy`, after 95–118 s.

All the other web tests pass in 1–6 s. While the suite runs in parallel, plain model tests report 70–110 s.

**Cause.** Each of the two failing tests is the first test of a serialized web suite. It starts WebKit cold while the rest of the app suite runs in parallel on the CI simulator. The `until` helper's 90 s deadline counts from the call. That cold start alone now takes 70–100 s, so the first web test of each suite times out. The suite comment already expects slow cold starts ("long deadlines").

**Change.** `ReaderWebTestSupport.until` (both overloads) now waits up to 240 s by default instead of 90 s, with a comment saying why. A passing test still returns as soon as its condition holds, so only a real failure waits the full deadline. No test asserts that a condition stays false through `until`, so nothing slows down when things pass. No product code changes.

**Not done:** splitting the web suites from the parallel run. That would be a larger change to the scheme or test plan, and it can come later if 240 s ever proves short.

**Validation.** App tests cannot run on Linux; this PR's own `App build + tests` job is the test. Both tests are expected to pass. If they still fail at 240 s, the cause is not the deadline, and the next step is the Mac.

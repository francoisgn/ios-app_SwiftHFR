### Problem
`LegacyAccountArchive.decode` read the legacy `HFR_COMPTES_KEY` archive with `requiresSecureCoding = false`, so the archive could name any class (#1205). #1202 tried secure coding with a class list and was reverted (`7b2ca13`): "decodes every field of the legacy archive" failed with `sourceUnreadable`.

### Cause (measured on macOS 27.2)
- `NSHTTPCookie` does not adopt `NSSecureCoding`: `unarchivedObject(ofClasses:from:)` with #1202's list throws `Class 'NSHTTPCookie' does not adopt it` (code 4864). No class list can include it.
- `plutil -p` of the replayed archive (`MultisManager.m:49-80` @ `87fe0d1c`): `$classes` = `NSArray`, `NSMutableDictionary`, `NSHTTPCookie`, `NSDate`; strings, numbers and data inline. Each `NSHTTPCookie` archives one object, its properties dictionary, as the unkeyed `$0` (keys `Domain`, `Created`, `Secure`, `Expires`, `Path`, `Name`, `Value`, plus `HttpOnly` when set).
- Same on the iOS 27.0 simulator (probe binaries run with `simctl spawn`): same refusal of `NSHTTPCookie`, same `$classes`, same `$0` layout. The substitute decode and the forged-`$0` refusals behave identically.

### Change
- Secure decoding with `allowedClasses` = `NSArray`, `NSDictionary`, `NSString`, `NSNumber`, `NSData`, `NSDate`, plus `LegacyArchivedCookie` (round 2: `NSURL` removed, `NSHTTPCookie` archives `CommentURL` as a string and drops `OriginURL`, measured).
- `setClass(LegacyArchivedCookie.self, forClassName: "NSHTTPCookie")`. This internal `NSSecureCoding` class reads the `$0` dictionary with an unkeyed `decodeObject()`, which inherits the unarchiver's allowed classes (checked: a forged `$0` holding another class fails the whole decode, and a non-secure class in it is never instantiated). The cookie is then rebuilt with `HTTPCookie(properties:)`. `NSHTTPCookie` itself is never instantiated from the archive.
- Round 2: `HTTPCookie(properties:)` does not check value types (a dictionary under `Path`, `Comment`, `CommentURL` or `SameSite` raises an Objective-C exception, one under `Port` crashes with SIGSEGV, the flags are read by presence; measured on macOS 27.2 for every key and 9 value types). `LegacyArchivedCookie.verdict(on:forKey:)` checks each key `NSHTTPCookie` archives against the types it archives and Apple documents (a `CommentURL` URL excluded: it raises too); a cookie with another type is skipped, an unknown key dropped.
- An unarchiver error is `sourceUnreadable`. The rest of `decode` is unchanged.
- LOT-067 spec: an Intentional differences entry (the reason and the measurements). M1 is reworded: the real-item check stays.

### Tests
- `unexpectedClass` (new): an archive whose account dictionary holds a test class outside the list → `sourceUnreadable`, and that class's `init(coder:)` never runs. **Red before the change** (no error thrown, class instantiated: 2 issues).
- `forgedCookie` (new): an archive whose `NSHTTPCookie` `$0` holds a class outside the list → `sourceUnreadable`. It passed before the change too (the real `NSHTTPCookie` rejects that dictionary). It guards the substitute's unkeyed read.
- `decode` (widened): domain, path, value, `Secure` and `HttpOnly` survive the rebuild. The fixture now sets `Secure`/`HttpOnly` only when true: Foundation reads them by presence, so `"FALSE"` counted as set.
- Round 4: `OriginURL` is dropped, not checked (never archived; Foundation reads it for a cookie without a domain); `originWithoutDomain` red at 686d895b (signal 11). 625 tests pass.
- Round 3: `StoragePartition` checked as a string; `Expires` must be a finite date (`nonFiniteExpiry`, red on f59af2a4); `mistypedProperty` tries a number too (17 keys × 2); `unknownProperty` checks the `.drop` verdict. 624 tests pass.
- Round 2: the outsider of `unexpectedClass` and `forgedCookie` adopts `NSSecureCoding`, so only the class list keeps it out; `forgedCookie` also checks it is never instantiated. Mutation: `NSObject.self` added to the list → both red (4 issues).
- `mistypedProperty` (new, 16 keys): each archived key given a dictionary → that cookie skipped, the valid one beside it kept, not secure. **Red before the fix**: the test process dies with signal 11 (`Port`), and `Secure`, `HttpOnly`, `Expires`, `Created`, `Version`, `Discard`, `Max-Age`, `OriginURL` keep the forged cookie. Mutation: the `refuse` branch ignored → same.
- `everyArchivedProperty` (new): a cookie with every property `NSHTTPCookie` archives (`Version`, `Comment`, `CommentURL`, `Port`, `Discard`, `SameSite`, `Secure`, `HttpOnly`) is kept. `unknownProperty` (new): a key it does not archive is dropped, the cookie kept.

### Problem
`MessageTitleToneTests/drawnColour(dark:)` and `rowDrawsTheTitleTone(dark:)` fail now and then in the full CI run (#931 job 133282896658, #743, #748, #761, run 42681255988), never locally.

### Cause
Not a trait leak. The one CI log with the failure detail (job 133282896658) reports the light read swatch off by **0.4101960784313725**. The expected light read colour is the secondary label at Increase Contrast over white, `(99, 99, 104.6)/255`, and 104.6/255 = 0.4101960784…: the sample was **(0, 0, 0)**. No appearance or contrast paints that read colour; a blank render does. The same test case logs `image provider … timed out while waiting for phase 6` and `building pipeline plane_color … took 3.58 seconds` just before the failure: under CI load, `ImageRenderer` handed back an image with nothing drawn, and the helper reads a transparent pixel as (0, 0, 0).

### Change
Test only. Every rendered view paints an opaque background, so `render` now checks the image's top-left pixel against that background and redoes a render that does not show it, up to three tries. Each redo prints one line, `#704 blank render redone (try N, corner r g b)`, so a slow renderer still shows in the CI log when the test passes. After three blank renders `render` returns nil, and the `#require` fails with "three blank renders, #704" (on the row: "no title drawn, #704"). The callers pass the background they painted, and the row gets a 1-point margin so the checked corner is background whatever the avatar's shape. No app change, no ledger.

The hooked test source used for the red/green runs is kept locally (`runs-704/hooked-MessageTitleToneTests.swift.txt`).

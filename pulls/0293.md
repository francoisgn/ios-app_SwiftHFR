## Problem
Any forum link (post, clipboard, universal link) must open the right screen at the right page and message. Legacy opened every `forum2.php` or `/hfr/` link as a topic (lists and profiles included), read `page=1` from links whose page the server overrides, and compared only the host (bug #106).

## Cause
Legacy has no router: each screen guessed (`Common.swift:2473-2479`, `:2693-2727`, `BookmarksPlusView.swift:143-146`). In the captures, `forum2.php?…&page=1&numreponse=M` is answered with a 301 to the page holding `M` (R25): the `page=` of such links is not the page.

## What changed (and why this wide)
- `HFRLinkRoute.route(for: URL) -> HFRLinkRoute` (pure, `HFRParsing/Links`): home, topic, private-message thread and list, topic list (category, sub-forum, page, filter), favourites, profile, search form, search results, `.external`. Shapes are only those found in the captures or legacy code; the others are `.external`.
- Page and message kept on both URL shapes; a message number leaves `page` nil (server decides); an unusable `page` value makes the link external, never page 1.
- Only `forum.hardware.fr` over http(s), no user info, no explicit port (LESSONS 37, 43).
- Spec `docs/lots/LOT-095-link-router.md`, `HFR-PROTOCOL` §6c `### LOT-095`, `CHANGELOG-LEGACY` rows 19-21, `AGENTS.md` §11 line, LESSONS 53. `docs/LOTS.md` is untouched (status lives on the issue).
- Not in this PR: clipboard text extraction, universal-link wiring, AASA (LOT-138, #127); forums missing from the catalogue stay external until #125.

## Tests (Swift Testing, `HFRParsingTests/Links`)
- `HFRLinkRouteTests`: every shape with anonymized ids, bug #106 regression on both URL shapes, refusals (bad values, views, unknown shapes).
- `HFRLinkRouteHostTests`: lookalike hosts, user info, ports, schemes.
- `HFRLinkRouteCorpusTests`: every distinct `href` of the 111 captured pages (over a thousand links) is routed or belongs to a listed page kind; all nine route kinds occur; topic links equal `HFRURL`; every corpus link on a lookalike host is external.
- `HFRLinkRouteOracleTests`: LOT-002/003 oracles (page numbers, permalink page and message, category of each permalink equals the `cat` of its quote link), 400+ and 1000+ links checked.
- Shown to fail with the rule reverted: port check, user-info check, numreponse page rule, print/quote views, unusable page silently dropped (1789, 2, 52, 3 and 8 failures).

`swift test` green (HFRParsing 389 tests), `scripts/check-lot-deps.py` clean, markdownlint clean.

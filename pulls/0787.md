**Problem.** In Favoris, VoiceOver reads every clickable category section title as « Ouvrir le forum »: the user cannot tell which category a tap opens.

**Cause.** `TopicListView.header` set `.accessibilityLabel("Ouvrir le forum")` on the title button, replacing its text.

**Change.** The label is the category name; « Ouvrir le forum » becomes the `accessibilityHint`; the button trait is added. The pair comes from a pure `TopicRowCues.sectionTitleSpeech(_:)` (next to the existing section-count speech) so the view and the test share one source. No wider.

**Tests.** `TopicRowCuesTests.sectionTitleSpeech`: label equals the category name (two names stay distinct) and hint is « Ouvrir le forum ». Without the change the function does not exist, so the test fails to compile (red). Limit (review finding 1): the test checks the helper, not the SwiftUI wiring; putting the constant label back in the view would not fail it. SwiftUI modifiers are not testable in this target, so a VoiceOver check on a Mac pass covers the wiring. Not run here: the cloud cannot build the app, CI is the first compile.

Points 1, 3 and 4 of #1398. **Point 2 (reusing a recent `valid` verdict before a gated write) is not in this PR**: the issue makes it an operator decision on a security trade-off; it needs its own `status: needs-decision` issue if wanted.

### Problem
Audit #1388 (static + Mac runtime pass): every probe (session check, MP poll, a gated write's check, login, own smileys) opened a new `HFRSession` with 2 new `URLSession`s, so a cold TCP + TLS connection. 16 transports (32 `URLSession`s) were created at launch with 4 used, and about 10 more per root build. The AQ feed was read again 3 s after every root build.

### Cause
- `HFRSession.probe(cookies:now:)` built a whole new session each call.
- `PageFetcher`, `AQClient`, `GiphyClient`, `RehostClient`, `ReaderImageFetcher`, `AnonymousAvatarLoader` and four client flows defaulted to a new `AnonymousTransport()`. `URLSessionTransport.deinit` only invalidated its no-redirect twin, never the main session it created itself.
- `QualityAlertsModel.checkAtLaunch` fetched on every root.

### Change
- **Probe connections (`SessionConnection.swift`)**: each account session owns a lazy `ProbeConnectionPool`. A probe is still a fresh `HFRSession` (no `hash_check`, generation 0, jar emptied then seeded with its cookies), but its `URLSession` + jar is taken from the pool and given back when the probe is released. The jar is emptied **before** the connection is idle again (round 1) and at check-out. Two live probes never share a connection. A connection whose exchange threw is invalidated, never recycled. The host policy is the source's. At most 2 idle connections per account. Probes do not share the account's own connection: that would need hand-made `Cookie` / `Set-Cookie` handling across redirects, so it was not guessed. The handshakes saved are intent until measured on a device.
- **`AnonymousTransport.shared`**: one cookie-less `URLSession` for every anonymous use.
- **`URLSessionTransport`**: `init()` and the internal `init(ownedSession:)` own their session and invalidate it in `deinit`. `init(session:)` leaves it to the caller.
- **AQ (`QualityAlertsLaunchFeed`)**: a memo of the last feed read, carried by `AppEnvironment.qualityAlertsFeed` (`.shared` from `make`, a new one per root when built by hand). `checkAtLaunch` counts from it at once (no wait, no request); concurrent roots share one read; a failed read is not kept; a read ending after a `keep` does not replace the newer feed. One count routine serves `checkAtLaunch` and `refreshCount`, applying the current viewer's hidden-category rule. Legacy reads the feed once per launch (`MainWindow.swift:1609` @ `87fe0d1c`).

### Tests (before → after)
Engine (`swift test`, 2256 green on Linux):

- `refreshesPollsAndAGatedWriteOpenOneProbeConnection`: 3 refreshes + 1 MP poll + 1 `addFavorite` check → **5 → 1** (seen red). Offline: loopback-restricted account.
- `aRecycledConnectionStartsWithOnlyTheNewSeed`, `probesAliveTogetherNeverShareAConnection`, `aConnectionWhoseExchangeThrewIsNotRecycled`, `theSourceSessionOpensNoProbeConnectionByItself`, `aRecycledProbeKeepsItsSeedUnderConcurrentRelease` (red with the round-1 race), the pool's limit, release and non-reusable cases, `URLSessionTransportOwnershipTests`. Each is red under its mutation.

App (Compile check green on 29cce4bb; the app tests first run when the PR is marked ready):

- `rootsOfTheAppsEnvironmentShareTheFeedAndHandBuiltOnesDoNot`, `rootsBuiltTogetherShareOneReadAndAFailedReadIsNotKept`, `aLaunchReadEndingAfterALoadKeepsTheLoadedFeed`, `aRebuiltRootAppliesTheNewViewersRuleToTheFeedAlreadyRead`.

Non-blocking round-3 details, left as follow-ups: there is no test that pins `AnonymousTransport.shared` as stored, and a second root waiting on an in-flight launch read may count from it even if a `keep` landed meanwhile (badge only, corrected when the list is shown).

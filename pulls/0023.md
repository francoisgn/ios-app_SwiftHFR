**LOT-034** — content normalization (smileys, images, links, signature, code, spoilers) into `MessageContent` (ADR 0006). Claim: `mac/w1-034-fable (2026-10-27)` (claimed by the orchestrator in #17). Spec: `docs/lots/LOT-034-content-normalization.md`.

**Problem.** The topic reader (LOT-083) needs each message body as safe, display-independent HTML plus the typed lists of images, smileys and links, so that display settings apply without re-parsing. Legacy rewrote libxml2's serialization with regexes that depend on attribute order and quoting, and inserted the result unescaped (`onclick`, `onload`, `id`s, any URL scheme) into a `WKWebView` with file access (audit C §4.2, quirks 1–3).

**Cause.** String surgery on a serialization instead of a DOM pass, and no sanitizer of record.

**What changed, and why this wide.**
- `MessageContentNormalizer` (HFRParsing): builds a new allow-listed tree (iterative walk on an explicit stack, assembled bottom-up, so nesting depth is bounded by memory, not the stack) from `MessageBlock.contentHTML` (or the `ExtractedMessageBlock.content` element) and serializes it with SwiftSoup, so every value is escaped. Elements and attributes outside the allow-list are dropped or unwrapped; `href`/`src` go through `HFRURL.absolute` (http(s) only, `https` on `*.hardware.fr`, `hfr-rehost.net` → `reho.st`); a rejected link becomes its text, a rejected image is removed. `span.signature` is split into `signatureHTML`; `div.edited` and HFR's clear trailer leave the body; smileys (standard `/icones/`, personal `/images/perso/`), images (with their wrapping link) and links fill the typed lists. Display modes (`display_images`, `display_sig`, `embedded_videos`) stay app-side; `embeds` is left to LOT-035.
- `MessageSmiley.code` doc comment (HFRModels): the code is the `alt` as served (`[:name]` for a personal smiley), the form `ForumSmiley` and `CommonSmiley` already use; no code change.
- `TopicOracle` test support gains the `html` field of the oracle.
- Docs: lot spec, HFR-PROTOCOL §6c "LOT-034" subsection, LESSONS 50, AGENTS §11 learning. Nothing else is touched: quotes (LOT-032), action links (LOT-031) and video embeds (LOT-035) read the same tree later.

**Tests** (`swift test`: HFRParsing 234 tests green, whole package green).
- `MessageContentOracleTests` — for all 358 messages of the 20 LOT-003 oracles: visible text (whitespace removed, legacy deleted every `\n`), images (`src` + wrapping link from `longdesc`), personal smileys (`src` + code from the legacy `onClick` scheme), standard smileys (`src` + `alt`), links (`href` + text), the signature cut point, no handler/`id`/`script`/`javascript:` left, `embeds` empty. The links legacy turned into iframes (`embedded_videos=yes`) are set aside explicitly and their count must equal the oracle's `div.embedvideo` count. `corpusTotals` reproduces LOT-003 RC3.9 (125 signatures, 103 messages with a personal smiley, 36 with an image), 484 links and the 2 legacy links whose href is not a URL (so a regression rejecting a class of real links is visible).
- `MessageContentNormalizerTests` — capture facts (R20 signature and smileys, R28 bare and linked images, R27 spoiler, R27b code block, whole corpus invariants); `MessageContentSanitizationTests` — the sanitization contract on inline snippets: 14 rejected link schemes (mixed case, tab/newline-obfuscated, entity-encoded, percent-encoded, `data:`, `file:`, `blob:`, `vbscript:`, user info, empty), rejected image schemes, relative and protocol-relative resolution, `hfr-rehost.net`, `on*`/`id`/`style`/unknown attributes and classes, dangerous and unknown elements, escaping, angle brackets stripped from attribute values, smiley kinds, signatures (nil when nothing survives), trailers, image links, empty input, and 10 000 nested elements normalized on a cooperative-pool thread (`deepNesting`: the process crashed on the previous head).

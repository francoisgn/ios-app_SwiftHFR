### Problem
Favoris, « Mode compact » on, sectioned by category: a tap on a section title (e.g. « Apple ») froze the app instead of showing the category's topic list.

### Cause (reproduced in a hosted test)
The tap itself works: `openCategory` writes the filter and pushes the category, which loads. The freeze comes right after, in the Favoris list that now sits under the pushed screen. `DensityHeaderMargin` (#799) moves each section header onto the compact inner margin. It measures where the header starts and pads it by the difference.
- It measured in `.named("densityList")`, a coordinate space set on the `List`. A section header is hosted apart from the list, and that name never reaches it: the value it gets is window x. Instrumented run: x = 26 at rest, then **-70** at 320 pt (-95 at 402 pt) once the list is covered, which is the push's parallax.
- So the covered list's headers took the parallax as their own misplacement, and the shift jumped from -9 to +87 pt per side. On a narrow header with the dense rows' bold title, the content no longer fits. Because the modifier measures the view it pads, the overflow moves what it measures. Log: x -70 → -70.17 → -70.33 → -70 …, shift 87 → 87.17 → …, with no end. The main thread never returns, and the test's watchdog fires: `HANG: main actor silent 20 s after 'compact 320.0: tapped'`.
- In regular density `rowSideInset` is nil, so the shift is always 0: that is why only compact froze.

### Change, and why this wide
`App/SwiftHFR/Settings/ListDensity.swift` only:
- `DensityListMargins` gives the card edge in window coordinates: the list's own global x, plus the margin, plus the safe area. `DensityHeaderMargin` measures the header in window coordinates too. Both ends move together, so a list moved as a whole (parallax, a split column) keeps its shift of -9 pt. The `densityList` coordinate space, which never worked for headers, is removed.
- The shift is capped at ±20 pt, the system's header inset and so the most a header ever has to move. A transient mismatch can no longer squeeze a header past its content, so it can never chase itself again.
- Side effect, now tested: a compact list that does not start at the window's edge (an iPad content or detail column) had its headers misplaced by the list's own x. The old code put the header at -93 pt from the card instead of 7 in the probe below. Headers there are now aligned as well.

Nothing else is touched. `openCategory`, the shared filter write and the push are correct; the test shows they work as legacy (`Favorites.swift:357` @ 87fe0d1c).

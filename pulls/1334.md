### Problem
The app said « vous » almost everywhere and « tu » in two strings. The operator decided « tu » everywhere (comment of 2026-11-19 on #1178; « Tu partout » in the triage).

### Change
Every user-facing French string under `App/SwiftHFR` moves to « tu »: pronouns, possessives (votre/vos → ton/ta/tes, « ta » only before a consonant, « ton adresse »), imperatives (« Réessayez » → « Réessaie », « Choisissez » → « Choisis », « Maintenez » → « Maintiens », …), « Voulez-vous » → « Veux-tu », « Reconnectez-vous » → « Reconnecte-toi ». Scope kept narrow:
- **Not touched**: identifiers, comments (one doc comment on `MPBackgroundCheck.legacyText` now says it moved to « tu »), HFR's own server texts (`static-charter.html`, confirmation sentences such as « Votre réponse a été postée avec succès ! » that the tests feed in as server answers), `changelog-v1.json` (generated from the legacy ledger by `tooling/docs/export-app-changelog.py`, it describes legacy fixes), the specs under `docs/` (historical records that quote the old strings).
- Done with a one-off scripted pass over non-comment lines, then every diff line read by hand.

### Numbers
- 60 app files, 207 string lines changed; 25 app test files, 48 assertion lines changed (85 files in all, 255 lines).
- `grep -rnE "\b(vous|votre|vos)\b" App/SwiftHFR --include=*.swift` returns only comments; no `-ez` imperative left outside « Allez on remballe » (an interjection) and « Nous contacter » (the team, not the reader).

### Tests
Existing app tests that assert these strings are updated (`ComposerMessages`, `AccountMessages`, `TopicFlagActions`, `PollMessages`, logged-out prompts, moderator alert, smiley picker, …). They fail without the change because they now expect « tu ». Not run here: the cloud cannot build the app; the Compile check is the arbiter.

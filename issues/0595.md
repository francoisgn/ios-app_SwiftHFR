## Analysis (read-only, sub-orch) 2026-11-07

Read from `origin/dev-swift` @ `4b1e77f`; legacy @ `2440d79`.

### SwiftHFR today: why a tap on the avatar does nothing
- **Avatar markup.** `TopicHTMLBuilder.swift:136-138` writes `<img class="avatar">` only when `avatarURL` exists. With no avatar there is nothing, and the header starts with the pseudo.
- **The avatar is inert on purpose.** LOT-087 spec, intentional difference 5: "the author menu opens from the pseudo (a button); legacy opened it from the avatar image, which stays inert here".
- **The pseudo is not tappable either.**
  - The pseudo becomes `<button class="menu-author" data-menu="avatar">` only when `showsAuthorMenus` is on (`TopicHTMLBuilder.swift:140-146`).
  - That flag is `registry.offers(.avatar)` (`TopicReaderModel+Menu.swift:43`), which needs a handler for `.profile`, `.privateMessage`, `.blocklist` or `.allowlist` (`MessageActionRegistry.swift:290-296`).
  - `TopicReaderView.installMenuActions` (`:247-266`) registers none of them. So the pseudo is a plain `<span>` and **no author menu exists at all**.
- **A blocked or failed avatar is removed.** `reader.js:16` (failed or blocked) and `:33` (tap-to-load mode) call `img.remove()` on `.avatar`, so the header loses it with no fallback.
- **The policy is already ported.** `MessageMenuPolicy.authorActions` (`MessageMenuAction.swift:231-240`) gives Profil when `profileURL`; MP when not own and `privateMessageURL`; Blacklist and Whitelist when not own and the pseudo is non-empty. This matches legacy `MessagesView.swift:205-217`.

### Legacy @ 2440d79
- **Tap targets.** `templatev2.htm:4-5`: both the avatar `div.left2` and the pseudo `div.left` call `touchHeaderMessage(this,'avatar')`.
- **Routing.** `MessagesView.swift:1525-1536` `presentPopupMenu` routes source `.avatar` to `onPopupAvatarSheetRequest` → `presentAvatarActionSheet` `:3610-3616`:
  - **With a profile URL**, it opens the **profile screen directly**, with quick actions MP / Blacklist / Whitelist (`userProfileQuickActions` `:3582-3608`; BL/WL toggles `:3652-3698` via `ObjCProfileFilterListManager`, then a reload).
  - **Without one**, it opens `MessageAvatarActionSheetView` (`:5307-5393`): an avatar preview, then Profil, MP, Whitelist, Blacklist (destructive).
- **Default avatar.**
  - Reader: CSS `--imagefile-avatar` → `avatar_male_gray_on_{light,dark}_48x48.png` (`MessagesView.swift:2411`, `style-liste.css:31,195`), with the class `noavatar` (`LinkItem.m:65-69`).
  - Sheet: the same PNG (`:5429`), or `person.crop.circle.fill`.

### Default avatar under the CSP
- **Not an `<img src>`.** `reader.js:196-200` sends every `img[src]` through policy C, and an `hfrreader:` source is not an HFR image, so it would be replaced or removed.
- **Option A, inline SVG in the header** (recommended). The builder writes a fixed `<svg class="avatar avatar-default" viewBox="0 0 32 32" aria-hidden="true">` with two shapes: a circle for the head and a rounded path for the shoulders, `fill: var(--secondary)` on a `var(--quaternary)`-style disc.
  - No request, and nothing for the CSP to allow (no script, no external reference).
  - It is original geometric art, not a likeness of anyone, and does not copy legacy's PNG.
- **Option B, `hfrreader://resource/avatar-default.svg` as a CSS `background-image`** (allowed by `img-src hfrreader:`). It needs a second case in `ReaderWebController.start` `:260-262`, which only serves `/reader.css` today. An SVG served this way cannot follow the theme colours, so A is simpler.
- **`reader.js:16,33`.** Swap the avatar for the same placeholder instead of `remove()`, so a blocked, failed or tap-mode avatar still leaves something to tap.
- **Consistency with #569.**
  - #569 proposes a **monogram** (initials on a hashed colour) for the MP list.
  - This issue asks for a **silhouette**.
  - **Operator decision needed:** one placeholder for both screens. Either the silhouette everywhere (the reader SVG and `MessageAvatarView.placeholder` built from the same path), or the monogram everywhere (the reader renders the initials as text in a `<span>`, with a palette class index computed in Swift from the same stable hash).
  - Whichever is chosen, put the shape or hash in one shared helper and record one GAP row.

# Issue #1188: [SwiftHFR] reader: a reload after the web content process dies loses the reading position and the tapped images

- State: closed
- Author: francoisgn · created 2026-11-18T20:09:40Z · updated 2026-11-19T08:13:45Z
- Labels: type: bug, priority: high, difficulty: easy, area: app, origin: audit, m4-review: quality

### Summary
As a reader far down a long page, I want the page to come back where I was when iOS killed the web content process in the background, so that I do not land back on the flag message or at the top.

### Scenario
Read far down a long page, background the app, iOS kills the WebContent process. On return the same document reloads and lands on `document.anchor` (the original flag message), or at the top without an anchor. With tap-to-load on, images already tapped are placeholders again.

### Evidence (`7a61018f`)
- `App/SwiftHFR/Reader/ReaderWebController.swift:283-294` (`contentProcessTerminated`): a ready document is loaded again with `loadPage(document)`, nothing saved.
- Same file `:251-256`: at ready, the landing is `document.anchor`, else `savedReadingTop`; `savedReadingTop` is set only in `show()` (`:144`).
- `App/SwiftHFR/Reader/Viewer/ReaderWebController+Viewer.swift:16-22`: `decisions(for:)` builds `ImageDecision` without `tapped:`.
- `App/SwiftHFRTests/.../ReaderInsetsWebTests.swift:71-85` pins the reload-once rule only.

### Fix
Keep the last `.position(post:)` the page reported for the shown document (it already passes through `handle`) and land on it after a termination reload; pass `tapped: consented.contains(text)` in `decisions(for:)`.

### Tests (fail before the fix)
`ReaderWebControllerTests.aReloadAfterProcessTerminationLandsOnTheLastReportedPost` (hosted: document with anchor A, report `.position(post: B)`, call `webViewWebContentProcessDidTerminate`, wait for ready, the topmost article is B); a second test: a tapped third-party image is loaded after the reload.

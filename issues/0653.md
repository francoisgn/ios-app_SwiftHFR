# Issue #653: [SwiftHFR] Composer (iPhone): partial-height layout with the answered message visible, full-screen toggle, legacy control row, send as an up arrow (M4)

- State: open
- Author: francoisgn · created 2026-11-08T07:05:07Z · updated 2026-11-09T15:07:24Z
- Labels: type: feature, priority: high, difficulty: difficult, area: app, status: needs-triage, beta-test finding, origin: deliberate-gap
- Source: https://github.com/ezzz/HFRnow/issues/653

### Summary
As a member replying on an iPhone, I want the reply composer to open by default on part of the screen, like the Claude app's (keyboard in the bottom third, my text and the input controls in the middle third, the message I am answering in the top third), with a control to go full screen, so that I see what I am answering while I write. Operator request, 2026-11-08.

Milestone: M4 (operator, 2026-11-08)

**This departs from the legacy layout.** It is an explicit (b) UX evolution (ROADMAP M5, AGENTS.md §4): it gets its own GAP row and spec paragraph. The legacy **controls** listed below stay a requirement.

### Legacy behaviour @ 2440d79
- **Presentation.** The composer is a sheet at the `.large` detent: almost full screen (`HFRswift/Swift/MessagesView.swift:4538-4550`). Nothing shows the message being answered. Only a quote, if any, is pre-filled in the text.
- **Layout** (`HFRswift/Swift/AnswerView.swift:184-210`): header, then metadata (recipient, subject, sub-category), then the editor, then the toolbar at the bottom.
- **Header** (`AnswerView.swift:332-370`):
  - close `xmark` on the left;
  - the title in the middle;
  - send on the right: an **up arrow** `arrow.up`, labelled "Envoyer" (`:359`, `:367`), with a spinner while posting.
- **Toolbar** (`AnswerView.swift:457-543`). One row: the edition group, a spacer, the insertion group. It becomes two rows when it does not fit (`:457-494`).
  - **Edition group, left** (`:496-515`):
    1. "Vider le texte" (`xmark.circle`, destructive);
    2. "Annuler", i.e. undo (`arrow.uturn.backward`);
    3. "Rétablir", i.e. redo (`arrow.uturn.forward`).
  - **Insertion group** (`:517-543`):
    1. Smileys (`face.smiling`);
    2. "GIF Giphy" (`g.circle`);
    3. "Insérer image" (`photo`).
  - Undo and redo keep a 200-step history (`:276-284`, `:586-605`).
- **Formatting.** Legacy has **no formatting button** in the toolbar. The BBCode actions (Gras, Italique, Souligné, Barré, Spoiler, Citation, Lien, Image, Code: `ReplyComposer.swift:59-96`) and "Fractionner la citation" are in the **text edit menu** (`AnswerView.swift:2241-2272`).

### Where this request differs from the legacy code
- **"Cancel".** In the legacy toolbar, the first button is **"Vider le texte"** (clear the text). The **undo** button carries the accessibility label "Annuler" (`AnswerView.swift:504-508`). Closing the composer is the header's `xmark`. This issue reads "cancel, back, forward" as clear, undo, redo, the legacy order. **The operator should confirm.**
- **"Formatting options".** Legacy has no formatting button: it has an edit menu. A "Format" button that opens the bar is new. SwiftHFR already has the bar (LOT-085).
- **"Only send at the top".** Legacy already had the up-arrow send at the top right. It also had a close `xmark` at the top left. Removing close from the top is new: where cancel or close goes must be decided. Swipe-down stays (UXD-15, #429).

### SwiftHFR today (origin/dev-swift @ d09a0ad8)
- **Presentation.** A plain `.sheet` with no detents, so full height (`Composer/ReaderReplyFlow.swift:38-42`). The same `ReplyComposerView` is presented from `MessageListView.swift:62`, `TopicListView.swift:75`, `AuthorActionHandlers.swift:103` and `ReaderEditFlow.swift:20`.
- **Navigation bar** (`Composer/ReplyComposerView.swift:277-299`):
  - "Annuler" (text) on the left;
  - "Envoyer" (text, not an arrow) on the right;
  - Smileys, Image (`photo.badge.plus`, #598) and GIF (`g.circle`, `Gif/GifPickerView.swift:207-208`) as `primaryAction` items, also at the top.
- **Formatting bar.** Always visible, pinned above the keyboard (`ReplyComposerView.swift:73-76`, `FormattingToolbar.swift`; #599).
- **No clear / undo / redo.** GAP-086 says "not planned".
- **No view of the message being answered.**
- **Related:** LOT-084 (#176), LOT-085 (#177), LOT-174 (#414, toolbar fixes), #592, #598, #599, #600 (smiley picker), #429 (swipe-down), GAP-085, 086, 087, 089, 090, 092.

### Scope
1. **Partial-height composer by default, on iPhone** (compact width):
   - the keyboard in the bottom third;
   - the editor and the control row in the middle third;
   - the message being answered visible in the top third, the reader page behind or a read-only excerpt (to decide in the spec).
   - A control switches to full screen and back.
   - iPad and regular width: keep the current presentation unless the spec decides otherwise.
2. **Control row at the bottom left of the input area**, in this order:
   1. clear the text ("Vider le texte", legacy order, see above);
   2. undo;
   3. redo;
   4. Smileys;
   5. GIF (Giphy);
   6. image upload;
   7. "Formatting", which opens the existing formatting bar (BBCode tags and colours).

   This brings back clear / undo / redo (GAP-086, from "not planned" to planned). The undo history must cover insertions (smileys, GIFs, images, BBCode), as legacy's does.
3. **Top:** only Send, as an **up arrow** (legacy `arrow.up`), with its spinner and disabled state. Where close / cancel lives without a top button (swipe-down, or the clear button, or a close in the expanded mode) is decided in the spec. The operator should confirm.
4. **Every composer mode** keeps its fields and rules: reply, quote, edit, new topic (subject, sub-category), new MP (recipient, subject). The #599 rule still holds: the bar must not jump when focus moves between fields.
5. **Docs:** a GAP row (b, operator) and the LOT-084 / LOT-085 spec paragraphs. Update the legacy pointer of `ReplyComposerView.swift`.

### Acceptance criteria
- [ ] On iPhone, Répondre opens the composer at partial height, with the message being answered visible above it. One control expands it to full screen and back.
- [ ] Control row order: clear, undo, redo, Smileys, GIF, image, Formatting. Formatting toggles the BBCode and colour bar.
- [ ] Undo and redo work across typing and every insertion. Both are disabled when there is nothing to undo or redo, and while sending.
- [ ] The only button at the top is Send (up arrow). Its accessible name is "Envoyer".
- [ ] Draft, swipe-down (UXD-15) and send-error behaviours are unchanged (LOT-084 tests stay green).
- [ ] Mac check on iPhone (portrait, Dynamic Type XL, compact density) and iPad; screenshots described on the PR.

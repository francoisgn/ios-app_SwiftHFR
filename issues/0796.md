### Summary
As a reader of the composer preview (LOT-152), I want the renderer's remaining differences from HFR's own preview decided or captured, so that nothing is left implicit after #742 (PR #795).

### Facts
Found while aligning the renderer with `R443a`-`R443n` (#742). None is in #742's nine facts; each is a capture-backed difference or an open question.
1. **Quote shape**: `R443h`, `R443i`, `R443l` show `table.oldquote` with `<hr size="1" />` borders, `R95d` (2026-11-02, another account) shows `table.quote` with `<br /><br />`. Same endpoint and `config`. The renderer writes the `R95d` shape; the new oracle tests map the other one (counted). Needs a decision, or a capture that says what changes it (account setting, date, forum).
2. **`[quotemsg=1,1,910001]x[/quotemsg]`** (`R443j`) is `table.oldcitation` with a `forum2.php?…#t1` link and "user a écrit :"; the renderer leaves it as text.
3. **`[email]a@x[/email]`** (`R443c`) is a `mailto:` link; the renderer leaves text (the normalizer would unwrap the link to its text anyway: the visible difference is the tags).
4. **Codes `:p:` and `:D:`** (`R443n`: `icones/smilies/p.gif`, `D.gif`) are smileys on HFR and missing from the bundled `CommonSmileyCatalog`; the oracle test adds them to its table.
5. **Anonymizer damage**: `R443c` and `R443f` carry `%redacted@…` in `request_body` where an address followed `[email]` / `[url]mailto:`, so the line is no longer decodable (the tests skip it).
6. **Corners** listed under LOT-097 "Pending capture" 11: keyword set of the syntax colours, `[i]`/`[u]`/`[strike]` like `[b]`, bare-URL terminators, nested raw blocks with special characters, bullets after a consumed break.

### Summary
As a member, I want a tap on an image hosted on a usual image host to open a viewer that **shows the preview at once and swaps in the hi-res image when it arrives**, even when the post only shows a thumbnail or a preview. The viewer should offer download, share, copy and **open in browser**, plus a full-screen mode toggled by a tap, so that I can zoom on the real image.

**M5 item.** It goes beyond legacy parity: parity with the Android app **Redface 2 (RF2)**. Its author added this viewer, with partial support for hi-res images hidden behind thumbnails, and reports that it works well (feedback received 2026-11-06). This issue holds the assessment only: no code until M5 opens.

### Gaps with RF2
1. **More hosts with a hi-res rule.** Today only `img3.super-h.fr` rewrites a thumbnail. Candidates to study:
   - the hosts already in the table (`reho.st`, `rehost.diberie.com`, `casimages.com`, `hostingpics.net`, `free.fr`, `photorapide.com`);
   - the common external hosts seen in posts (imgur, postimg and the like).

   Each rule must come from **a capture** (a thumbnail URL in a real post together with the full-size URL it leads to) or from RF2's source. It is never guessed (AGENTS.md §3.1). A rule is data in the host table, not logic.
2. **Progressive display.** Show the preview, meaning the image already loaded in the page or the thumbnail, scaled up at once. Load the hi-res image in the background and swap it in without a jump, keeping zoom and offset. LOT-109 today waits for the selected image and only falls back to the thumbnail on failure. Add a small "HD" load indicator, cancel the load when the user swipes away, and keep LOT-109's memory bound (bounded decode, pixel budget).
3. **"Ouvrir dans le navigateur"** action. It opens the **full-size page or URL** in Safari or the default browser (LOT-119 setting). Download, share and copy already exist; check their wording against RF2.
4. **Full-screen mode toggled by a tap** (chrome hidden or shown). LOT-109 chose an always-visible **Fermer** button (iPad, accessibility). Keep a visible way out, for example a tap that brings the chrome back and a VoiceOver action, and decide in D2.
5. **Pinch zoom up to the hi-res resolution.** It is only worth anything once item 2 has loaded the hi-res image. Check that the zoom ceiling follows the hi-res pixel size and not the preview's.

### Constraints and risks
- **Privacy:** hi-res downloads stay on the cookie-less client under policy C. An image whose loading the setting blocks (LOT-107) needs consent before any hi-res download. The viewer never sends the forum session.
- **Data:** the hi-res load respects "Wi-Fi only". D3: on cellular, load hi-res only on demand.
- **RF2 source:** it may be read for its host rules once its **licence** is checked. SwiftHFR is under PolyForm Noncommercial, so no code is copied without a compatible licence, and credit goes in CREDITS.md. Behaviour can always be re-implemented from captures.
- **Host fragility:** a rewrite can 404 or serve an HTML page. Then the preview stays and no error is shown (LOT-109 fallback).

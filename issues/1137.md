# Issue #1137: [SwiftHFR] Composer: new private message and new topic always open full screen (no toggle), buttons at the top

### Summary

As a member writing a **new private message** (from the Messages list: Destinataire, Sujet, text), I want the composer to open full screen, always, with no way to shrink it, so that I write with the whole screen. Partial height keeps the page behind visible and scrollable, which helps when answering something but does nothing for a new message. (Operator feedback, 2026-11-18, device screenshot with the modern composer on (Réglages › Expérimental): the new-MP card sits at partial height over the MP list, its close and send buttons are clipped at the top, and its tool row is half under the keyboard's suggestion bar.)

### Today (dev-swift)

- On an iPhone every composer opens at partial height, with a toggle to full height: reply, edit, new topic and new private message (operator, 2026-11-10; `App/SwiftHFR/Experimental/ModernComposer/ComposerHeight.swift:1-15`).
- The height comes from `ComposerHeight.shown(...)` and the toggle from `ComposerHeight.offersToggle(...)` (`App/SwiftHFR/Composer/ReplyComposerView.swift:291-300`).

### Scope

1. **The new private message composer** (the Messages list's « nouveau message », both MP and MP multiples) opens at **full height** and offers **no height toggle**. It is either open, full screen, or closed.
2. Replies to an MP or a topic, and edits, keep today's behaviour: partial height with the toggle.
3. The clipping seen on the screenshot (top buttons cut, tool row under the suggestion bar) disappears with the full height. If any of it also shows at partial height in a reply, open a separate issue: do not fix it silently here.
4. This applies with the modern composer (`EXPERIMENTAL(modernComposer, #904)`). The legacy full-screen composer is already full screen.
5. **Open question for the operator, asked on this issue:** the **new topic** composer is the same kind of composer (new content, title field). Does it get the same rule? Until answered, only the new MP changes.

### Acceptance criteria

- [ ] A test pins it: new MP → `.full` and no toggle; reply/edit → `.partial` with the toggle. The test fails on today's code.
- [ ] A device check on the next general review (#893): new MP full screen, nothing clipped, and the swipe-down/close choice unchanged.

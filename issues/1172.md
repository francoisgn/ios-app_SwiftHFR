### Summary

As a new user opening the app for the first time, I want the notification prompt to come when it means something (after I log in, or when I turn on MP notifications), so that I know why the app asks and am more likely to accept.

### Rule

"Avoid requesting permission at launch unless the data or resource is required for your app to function." and "Ideally, wait to request permission until people actually use an app feature that requires access." — [HIG › Privacy](https://developer.apple.com/design/human-interface-guidelines/privacy) (Requesting permission).

### What the app does (dev-swift @ `7a61018f`)

- `App/SwiftHFR/SwiftHFRApp.swift:104-105`: `// Notification permission at launch, as legacy …` `.task { await MPNotificationCenter().prepare() }`.
- `App/SwiftHFR/Notifications/MPNotificationCenter.swift:17-26`: `prepare()` registers the category, then calls `center.requestAuthorization(options: [.alert, .sound, .badge])`. It runs for a logged-out user, although notifications only concern the private messages of a logged-in account.
- A contextual request already exists: `Notifications/MPNotificationSettingsModel.swift:98` (`.notDetermined` → `requestAuthorization()` when a switch is turned on).

### Legacy at `87fe0d1c`

Same launch-time request: `HFRswift/Swift/HFRswiftApp.swift:27-29` (`requestNotificationAuthorization()`).

### Class

**(b) evolution, M5** (same as legacy; ported on purpose, LOT-140).

### Proposed fix and check

- Keep the category registration at launch; move `requestAuthorization` to the first successful login (or the first MP check that finds an unread message), plus the existing Réglages path.
- Check: a model test of when the request is made. Fresh install, logged out: no system prompt; after login: the prompt once.

# Issue #1397: [SwiftHFR] Images, smileys and avatars: one URLSession pair per smiley cell, no in-flight coalescing, avatars downloaded twice, no negative cache

- State: closed

### Summary
As a user, I want each image to be downloaded once over shared connections, so that the smiley picker, the reader and the MP list do not open dozens of connections or fetch the same file twice. Audit #1388, findings B5 to B8 (by reading at `dev-swift` `1685bcc`; counts derived from the code, not measured).

### Findings
1. **One transport per smiley / GIF cell.** `SmileyThumbnailView.swift:50` builds its loader per cell → `SmileyImageLoader.swift:40` → `ReaderImageFetcher.swift:27` → `AnonymousTransport.swift:21` → 2 `URLSession`s (`URLSessionTransport.swift:14-16`). First picker open: 35 catalogue cells = 70 sessions and up to 35 new TCP + TLS handshakes to the image host. No in-flight map: two cells with the same URL fetch it twice (`SmileyImageLoader.swift:69-75`). Legacy bundles the catalogue (0 requests; `SmileyImageLoader.swift:10` cites it).
2. **Each picker open refetches the reply form and the own-smileys page.** A new `SmileyPickerModel` per open (`ReplyComposerView.swift:185-192`), so its `forum == nil` / `own == nil` guards never hold: 3 opens in one composer = 3 form GETs on the account session + 3 `editprofil` page 5 GETs, each in a new probe session (`OwnSmileysFlow.swift:30-35`).
3. **Avatars are downloaded twice on a page read.** `AvatarFillingTopicPageSource` fetches each author's avatar for the cache (`AvatarStore.swift:41-64`, `:103`) while the web view fetches the same URLs through `hfrreader:` (`ReaderWebController.swift:387-424`): up to 80 image GETs for a first read of a 40-author page.
4. **No negative cache for MP-row avatars.** `MemberAvatarPrefetcher.tried` is memory-only, per `AppEnvironment` (`MemberAvatarPrefetcher.swift:79`, `:130`): a correspondent without an avatar costs 2 GETs (id lookup, profile, 1 s apart) at every launch and root rebuild; 15 such rows = 30 GETs per launch. Legacy sends none (GAP-230).
5. **Reader images are not shared between readers.** One non-persistent data store per web controller (`ReaderWebController.swift:109`), no URL cache on the transport (`AnonymousTransport.swift:36`, `URLSessionTransport.swift:52`): each reader, and each reader a link pushes, downloads the page's avatars and smileys again. Whether WebKit's memory cache holds for the custom scheme is not verified.

### Proposed fix
- One shared image fetcher (the app already builds one, `AppEnvironment.swift:64`) with an in-flight map per URL and a bounded memory cache for forum-host images.
- The picker's lists live as long as the composer.
- The scheme handler feeds the avatar store (or serves from it), instead of a second download.
- "No avatar" / "unusable" remembered for 24 h, like avatar freshness.

### Tests
Counting transport: N cells with the same URL → 1 request; second picker open → 0 request; a page read → each avatar URL once.

Refs #1388, #1375.

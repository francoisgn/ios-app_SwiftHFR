### Summary

As a member, I want the SwiftHFR **app icon on the Home Screen to show a badge** with my unread MP count, as legacy does, so I can see new messages without opening the app. (Operator feedback, 2026-11-17: no badge appears with unread MPs.)

### What dev-swift does (LOT-140, #994, merged 2026-11-17 as `c78a1a56`)

- **Permission:** `SwiftHFRApp.swift:105` calls `MPNotificationCenter().prepare()` at launch, which requests `[.alert, .sound, .badge]` (`Notifications/MPNotificationCenter.swift:17-30`). Legacy does the same at `HFRswiftApp.swift:27-29`.
- **Foreground:** `RootNavigationView.swift:59-63` sets the badge from `RootModel.appIconBadge` (`RootModel+Notifications.swift:7-10`).
  - It is `nil` until an MP list page has given a count. Then nothing is set, so the badge from the background check stays (GAP-192).
  - It is `0` when the setting `mp_badge_enabled` is off. Its default is `true` (`SettingKey.swift:78`).
- **Background:** `MPBackgroundCheck.swift:60` sets it after each `BGAppRefreshTask` check.
- **Legacy:** `MainWindow.swift:1564-1567` and `MPBackgroundService.swift:60-66` @ 87fe0d1c.

### Possible causes, to check in this order (no guessing)

1. **Build:** the device build predates `c78a1a56`. Then there is no badge code at all, and nothing to fix.
2. **iOS permission:** Réglages iOS › Notifications › SwiftHFR › « Pastilles » is off, or the prompt was refused. The app then cannot badge. Should it say so in Réglages › Notifications (`MPNotificationSettingsSection`)?
3. **App setting:** « Pastille » (`mp_badge_enabled`) is off.
4. **A real bug:**
   - `appIconBadge` stays `nil` because the count source is never filled on the path the member uses (Messages tab never opened?);
   - the background task never runs;
   - `setBadgeCount` fails silently (it only logs « Badge not set »).

### Scope

2. Fix the cause found, with a test on the count path (`appIconBadge` from the first count source).
3. If the badge permission is off, the Notifications settings section says so, with a link to the iOS settings. This already partly exists (« Réglages des notifications »); check it covers the badge.

### Acceptance criteria

- A test for the found cause, failing before the fix.

### Summary

As a member who picks the « REDFACE 3D Big » app icon, I want the Home Screen to show the icon I saw in the picker (black rim around the red face), so that the choice is not a surprise. Today the picker (Réglages, dark appearance) shows the black rim, while the Home Screen (light appearance) shows the face on a red background. Operator: **the black-rim one is the real icon**.

### Cause (not settled)

What the repo shows (`dev-swift` 64c14d4f):
- `App/SwiftHFR/Icon-RedFace3DBig.icon/icon.json` is a layered Icon Composer file whose background `fill` is an `automatic-gradient` of red (`display-p3:0.66777,0.00619,0,1`), identical to the legacy file (`SuperHFRplus/Assets/AlternativeIcons/Icon-RedFace3DBig.icon/icon.json` @ `87fe0d1c`).
- The picker previews of #809 (`Assets.xcassets/IconPreviews/IconPreview-Icon-RedFace3DBig.imageset`) differ by appearance: `default.png` red rim, `dark.png` black rim. The picker seen in dark appearance therefore shows the black rim.

What the device shows (operator, 2026-11-13): the Home Screen icon is red-rimmed, and **stays red-rimmed after switching the iPhone to dark mode**. So the light/dark split of the file does not explain it on its own. To check on the Mac and the device, in this order:
1. The Home Screen's own icon style (Home Screen › Edit › Customize: Default, Dark, Clear, Tinted): with Default the icons may stay light whatever the system appearance.
2. Whether an alternate `.icon` set with `setAlternateIconName` keeps its dark variant once compiled (`actool` output in the built app's `Assets.car`), or only the default one.
3. How the `dark.png` preview was produced in #809, and whether it matches anything the system draws for this icon.

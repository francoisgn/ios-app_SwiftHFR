# Issue #681: [SwiftHFR] iPhone Duo cover screen: no freeze when opening a category after scrolling the list (beta feedback #372, M4)

### Summary

As a reader on the folded iPhone Duo (cover screen), I want to open any forum category after scrolling the Catégories list without the app freezing, so that I never have to kill the app to keep reading.

### Legacy feedback

- Beta 4.0.4 (37), PR #372. Reported on iOS 27.2, iPhone Duo **folded** (cover screen), 100 % reproducible:
  1. tap the Catégories tab (folder icon, at the bottom of the right-hand column on the cover screen);
  2. scroll the category list (for example down to "Discussions");
  3. tap any category: the app freezes and must be killed. It happens for any category, but only once the list has been scrolled.
- **Root cause (legacy)**: the iOS 27 hang already worked around on the inner display in e1fdb57. Once a **large title** has collapsed on scroll, the next push loops forever in `UINavigationController` layout (`_observeScrollViewDidScroll` / `_updateSafeAreaInsets`). The workaround (inline titles on the tab roots) only applied in regular/regular, so the cover screen, which is compact in width, kept large titles. On this device the system chrome sits in a vertical strip on the right edge (Mac check on #372), which is the safe-area change the loop keeps recomputing.
- **Legacy fix**: 903bcb06 on #372. `PhoneDisplayPolicy` classifies the scene (inner, cover, other), and the tab roots use inline titles on **both** Duo displays. Other iPhones and the iPad keep large titles. Not yet checked on the device.

### SwiftHFR counterpart (`dev-swift`)

The same precondition is in the rewrite. It is not a confirmed bug yet, because SwiftHFR has not been run on a Duo:
- `App/SwiftHFR/Navigation/ForumListView.swift`, `ForumListView`: `.navigationTitle("Catégories")` with no display mode, so it is `.automatic`. That gives a **large title** at the root of the collapsed split in `CategoriesTabView`.
- `App/SwiftHFR/Root/RootTabsView.swift`: `CategoriesTabView` (a `NavigationSplitView` that collapses into a stack on iPhone). Selecting a row pushes `TopicsColumn`, which is exactly the "large title collapsed, then push" sequence.
- The same applies to the other tab roots with an automatic title: `App/SwiftHFR/Root/PlusView.swift` (`PlusView`, "Plus"). `TopicListView`, `MessageListView` and `TopicReaderView` are already `.inline`.
- `App/SwiftHFR/Root/RootNavigationView.swift`, `RootNavigationView.usesSidebarRoot`: iPad only. SwiftHFR has no Duo detection yet (LOT-147 #237 is in M5; the cover-screen fill was #432).

**Not fixed in a PR here.** The fix needs a Duo detection (inner and cover), or a decision to use inline titles on every iPhone, which is a visible change and needs a gap row. Both are design calls, not a small app-side fix. Options:
- (a) port legacy's `PhoneDisplayPolicy` (side safe-area strip in portrait, or "this phone once showed regular/regular") and use inline titles on the tab roots on the Duo only;
- (b) inline titles on every iPhone tab root.

### Acceptance criteria (non-regression)

- [ ] On the Duo cover screen, iOS 27.2: Catégories → scroll the list to the end → tap any category → the topic list opens, with no freeze. Repeat for 5 categories, and from the top of the list without scrolling.
- [ ] Same sequence in Favoris, Messages and Plus (scroll the list, then open an entry).
- [ ] Same sequence on the unfolded Duo (inner display), portrait and landscape.
- [ ] iPhone 18 / Pro Max and iPad: titles unchanged unless option (b) is chosen; in that case, add a gap row.
- [ ] Unit tests (Swift Testing) for any detection rule (cover, inner, other, landscape iPhone with side insets, iPad), each shown to fail without the change.

### Mac / Duo checklist (`host: mac`)

- [ ] Simulator iPhone Duo (iPhone19,4), iOS 27.2, which boots folded: Catégories → scroll → tap a category, and check there is no hang. The Duo simulator cannot unfold (see the Mac check on #372).
- [ ] Physical Duo: the same sequence folded and unfolded, plus a fold or unfold while a list is scrolled.
- [ ] If it hangs, attach a sample or spindump of the main thread (`_observeScrollViewDidScroll` / `_updateSafeAreaInsets` expected).

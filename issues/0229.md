**Inputs from LOT-068 for this lot.** LOT-068 (#93) is merged: #479, merged as af40cab. The leftovers below come from the Fable 5.1 adversarial reviews on #479 and are not blocking. They belong in the LOT-139 spec:

1. **`save` off the main actor.** `OfflineTopicStore.save` decodes the whole page's character references before the `codehex` check. That costs 89–170 ms per captured page on a Linux debug build (R22a, R28, R21), and about 0.9 s for a page with 100,000 references. Call `save` off the main actor, and record a release-build figure in the spec (LESSONS 10).
2. **Show the refusal reason.** A member who posts the text `codehex=x` makes that page unsavable for every user: the check fails closed by design. The UI should show `containsSessionToken` as the reason ("page non enregistrable : elle contient des données de session") instead of failing silently.
3. **Over-broad guard (conservative, never a bypass).** The unknown-reference guard reads the whole decoded `<input>` tag, not only its own `name=`. So `name=a&amp;b` inside the `title` of an unrelated input refuses the page. If false refusals show up, anchor the guard to the input's own `name=` attribute (`OfflinePageRecord.swift:77`).
4. **Tie-break in the topic list.** When two saved topics compare equal, the order ignores the category. Decide the display order in the spec.
5. **Legacy citation.** Next to `PageViewController.m:154`, also cite `MessagesTableViewController.m:996` @ 2440d79: it sets `currentOfflineTopic` in an initializer with no caller.

Already in place in LOT-068: pages are saved cookie-less only (any filled `hash_check`, including entity-encoded names, or any `codehex=` refuses the page); 50 pages per topic; 200 MB budget with eviction of the oldest pages; device-only cache area, never backed up (ADR 0013).

### Summary
As the maintainer, I want the Plus Bookmarks fold case of `DuoLayoutHostedTests` to stop spinning an Observation tracking feedback loop, so the suite does not stall the main actor on a cold or busy Mac (the Plus-case freezes of #1388 / #1404) and the app does not loop the same way on the Duo cover screen.

### What was measured
iPhone Duo simulator (fresh clone of the iOS 27.2 « iPhone Duo »), `-only-testing:SwiftHFRTests/DuoLayoutHostedTests`, serial, `dev-swift` `ffa9418d` and PR #1434 (test-only changes, same app code). Logs: mac/mac-mbp scratch `1201/runs2/` (2026-11-28).

- Every flood happens in **one case**: `aFoldAndAnUnfoldKeepThePlusTopicAndItsPage(entry: .bookmarks)` (`App/SwiftHFRTests/Root/DuoPlusHandoffTests.swift:14-40`). The log repeats `[Assert] Observation tracking feedback loop detected!`.
- The loop's invalidations alternate between two hosting views, about 23,400 times each in one run: the root `UIHostingView<…RootLayout…>` and `UIHostingView<TabItem.RootView>` at the cover screen's frame (466 × 678).
- Asserts per suite run, `dev-swift`:
  - 5 runs alone: 46,871 / 48,384 / 0 / 0 / 0
  - 5 runs under 4 × `yes`: 15,652 / 386 / 527 / 247 / 0
- Asserts per suite run, PR #1434:
  - 10 runs alone: 67,595 / 256 / 27,862 / 0 / 0 / 0 / 0 / 0 / 0 / 0
  - 3 runs under load: 34,184 / 6,806 / 24
- The worst runs are the first runs on a new clone. While it loops, the app process runs at about 92 % CPU and the case takes 22–144 s; it takes 1.1–1.9 s when quiet. The case still passed in every run, and so did the suite.
- The `.qualityAlerts` case and the other Plus cases show no flood. The Messages fold case (#1201) runs before it and shows none either.
- CI: the failed-step logs of the last 11 CI runs that ran this suite hold 14–256 such lines each. Those logs are truncated, so the real count is unknown there. The case passed in 4–14 s.

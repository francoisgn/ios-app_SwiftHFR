# Issue #1195: [SwiftHFR] navigation: lists keep the home page's stale logged-in state after an in-place re-login (three sources of "logged in" in one root)

### Summary
As a member whose session had expired at launch, I want the lists to see me logged in as soon as I reconnect, so that the Favoris/Suivis/Lus filter and the hidden categories come back without my pulling to refresh the Catégories list.

### Scenario
1. Launch with the current account's session expired: the home page is fetched logged out (`ForumListContent.isLoggedIn == false`).
2. Account menu › "Se reconnecter", correct password: the session is valid.
3. Every topic list still loads as logged out: the filter is forced to "Tous", the scope bar says "Connexion requise pour Favoris, Suivis et Lus…", the Apple category stays hidden.
4. This lasts until the member pulls to refresh Catégories; someone living in the Favoris tab on iPhone may never do it.
The reverse holds too: a session that expires in place keeps `isLoggedIn() == true`. `MessageListModel` and `MPStorageSyncModel` ask the session and the account row shows `AccountSessionStatus`: three sources that can disagree.

### Evidence (`7a61018f`)
- `App/SwiftHFR/Navigation/NavigationModel.swift:83-86`: `if let known = forums.loader.value?.isLoggedIn { return known }`, the session only as a fallback.
- `App/SwiftHFR/Navigation/TopicListModel.swift:288-289`: `let loggedIn = await isLoggedIn()`, `let filter = hasFilter && loggedIn ? chosenFilter : .all`.
- `App/SwiftHFR/Accounts/AccountsModel.swift:239-242, 274, 447-451`: a re-login of an existing account renews the same `HFRSession`, so the session generation does not change and `RootView` keeps its `RootModel`.
- The forum list loads only through `loadIfNeeded` (`Root/RootNavigationView.swift:40`, `Navigation/ForumListView.swift:43`) and reloads only on pull-to-refresh (`ForumListView.swift:42`).
- Existing tests pin each half: `NavigationModelTests.loggedInStateComesFromTheForumListOnceLoaded`, `AccountsModelLoginTests.reloginRenewsTheAccountsOwnSessionAndKeepsTheCurrentAccount`; none crosses them.

### Fix
One source of truth: `AccountsModel` exposes a "current session renewed" counter and the root reloads `model.forums` (then the visible lists) when it changes; or `NavigationModel.isLoggedIn()` ignores a forum page older than the last login or expiry.

### Test (fails before the fix)
`NavigationModelTests.aReloginInPlaceMakesTheListsLoggedInWithoutAManualRefresh`: scripted data source (home logged out, re-login signalled, topic list load): the request carries the chosen filter and `offersFilter == true`.

Plan:
- `AccountsModel.currentSessionChanges`: bumped when the current account's session changes in place (re-login of that account, adopted synced credentials, a check that finds it expired).
- `ForumListModel`: `sessionDidChange()` marks its page as no longer saying whether the account is signed in and reloads it; `isLoggedIn` is nil until a load started after that applies. `NavigationModel.isLoggedIn()` reads it, else the session.
- `RootNavigationView` observes the counter and calls `RootModel.currentSessionChanged()`: the forum list, then the topic lists on screen in both tabs, reload.
- Tests first: `NavigationModelTests.aReloginInPlaceMakesTheListsLoggedInWithoutAManualRefresh` (+ a failed reload falls back to the session), `AccountsModelLoginTests` for the counter.

# Issue #1430: [SwiftHFR] UX survey: a rights erasure leaves the pseudo in the database file, in earlier exports and in the shell history

### Summary
As a respondent who asks for my pseudo or my answers to be erased, I want them gone from the server when the PO says so, so that the data notice ("corriger ou effacer votre pseudo, ou vos réponses avec, y compris dans les copies d'analyse", `tooling/ux-survey/web/donnees.html:88`) is true. Today the rights commands delete the row but leave three copies behind.

Refs #635 (finding 1 of the UX-11 review). To fix before the public opening; it does not block the five-tester trial, whose data is deleted afterwards.

### What happens today
Measured on loopback at `ffa9418d` with a made-up pseudo:

1. **Database pages.** After `ux-survey pseudo --effacer <id>`, the pseudo text is still found in `reponses.db` (`grep -c -a` gives 1). SQLite does not overwrite freed pages: the base is opened without `secure_delete` (`internal/stockage/base.go:86-88`) and the rights writes (`SupprimerReponse` `internal/stockage/ecriture.go:234`, `SupprimerPseudo` `:228`, `MettreAJourDonnees` `:199`, `RemplacerPseudo`) run no `VACUUM` and no checkpoint. The residue stays until the final erasure, and until then anyone reading the file (host access, a VPS backup) finds it.
2. **Earlier exports and backups.** `exports/pseudos-*.csv`, `exports/analyse-*` and `sauvegardes/*` written before the request keep the erased data until the final erasure. The commands only print "refaire un export d'analyse" (`cmd/ux-survey/commandes.go:205-224`), and `export` never overwrites a file (`commandes.go:43`), so the stale file is the one that stays.
3. **Shell history.** `pseudo --chercher <pseudo>` takes the real pseudo as an argument (`commandes.go:148`, `:169`): through `docker compose exec` it lands in the host's shell history and process list.

### Scope
- Open the base with `PRAGMA secure_delete = ON` (or run `VACUUM` plus the truncating checkpoint after each rights write), so a deleted or corrected value does not survive in the file or in `-wal`.
- After a rights write (`--effacer`, `--effacer-pseudo`, `--effacer-question`, `--corriger`, `--limiter`), list the files of `exports/` (except `agregats-*`) and `sauvegardes/` that predate it and delete them, or refuse to report success until they are gone; say so in the README.
- `pseudo --chercher -` reads the pseudo from standard input; the README shows that form.
- Out of scope: copies outside the server (the PO's machine, recipients), already a manual step of spec §12.

### Sources

### Acceptance criteria
- A test writes a response with a pseudo and a free text, erases it with each rights command, and finds neither string in `reponses.db`, `reponses.db-wal` nor any file under the data folder (seen to fail before the change).
- A test shows that an export or a backup made before a rights write is gone (or the command fails and names it) after the write; `agregats-*` files stay.
- `pseudo --chercher -` finds a response from a pseudo given on standard input.

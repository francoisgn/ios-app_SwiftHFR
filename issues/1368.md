### Summary
As a member opening a link to a message of a multi-page private conversation (bookmark, permalink, quote link), I want the reader to know which page it is showing, so that the page counter, « next », « previous » and refresh work from that page.

### Problem
For `cat=prive`, HFR answers `forum2.php?config=hfr.inc&cat=prive&post=<post>&page=1&numreponse=<M>` **in place** (200, no `Location`) with the page that holds `M`, while the URL still says `page=1` (`R1315c`: M on page 3, the body is page 3; `R388a`: page 1). A public topic redirects instead (`R25`), and the reader relies on that redirect.

Path (at `dev-swift` 97a060bd):
- `Packages/HFRKit/Sources/HFRParsing/Links/HFRLinkRoute+Routing.swift:43-46` keeps `numreponse` (and drops `page`) for `cat=prive` links too.
- `App/SwiftHFR/Reader/TopicPageSource.swift:44-47,61-63` sends `page=1&numreponse=M`.
- `Packages/HFRKit/Sources/HFRParsing/Topic/TopicPageMetadataParser.swift:27` takes `currentPage` from the URL: 1 on page 3.
- `App/SwiftHFR/Reader/TopicReaderModel.swift:626` sets the shown target to that page 1.

Effects (on a 4-page conversation, M on page 3): the reader shows « 1 / 4 », « next » loads page 2, « previous » is disabled, a refresh reloads page 1.

### Fix direction
When the request names a message, take the current page from the pager's current page (`<b>N</b>` in the pager, present on `R1315a`/`R1315b` and on public pages), not from the URL; keep the URL rule otherwise (legacy Q18, `requestedURLIsNotClamped`). Correct the comments that say HFR redirects for every `numreponse` link: `App/SwiftHFR/Reader/TopicPageSource.swift:45`, `Packages/HFRKit/Sources/HFRNetwork/Endpoints/HFREndpoint+Topics.swift:26-27`, `App/SwiftHFR/Reader/ReaderTarget.swift:23-24`. Check legacy's handling of the same answer before choosing (`87fe0d1c`).

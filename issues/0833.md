# Issue #833: [SwiftHFR] Read the account's posts per page (`topicpp`, profile page 3) for page counts computed outside a topic page

- State: open
- Author: francoisgn · created 2026-11-11T21:34:52Z · updated 2026-11-11T21:34:52Z
- Labels: type: feature, priority: low, difficulty: easy, area: parsing, status: ready, origin: initial-port
- Source: https://github.com/ezzz/HFRnow/issues/833

### Summary

As a member whose posts-per-page setting is not 40, I want lists built from the REST API to open at the right last page, so that a flagged topic does not open mid-topic.

### Scope

- HFR's posts per page is an account setting, `topicpp`, the text input of profile page 3 (`GET /user/editprofil.php?config=hfr.inc&page=3`, `R55-p3`; HFR-PROTOCOL §7 "Posts per page", E19, R6 row).
- No source reads it today: `ProfileEditPageParserTests.swift` only checks the input exists in `R55-p3`.
- Expose it: a parser of the value (pure, `R55-p3`), and a way for the app to hold it per account (read once after login or on demand, with a stated refresh rule). The value's limits (allowed range, empty value) must come from the capture or legacy, never guessed: if `R55-p3` does not show them, list the capture needed.

### Wanted by

LOT-057 (#83, PR #831): `RESTFlagBucketClient.topics(in:postsPerPage:)` takes the account's page size to compute each REST row's page count and last page. Until this lands, an app caller has only the anonymous 40, which is wrong for accounts with another setting. Any other list built from JSON (REST) needs the same value.

### Acceptance criteria

- [ ] `topicpp` read from `R55-p3` by a tested parser; limits traced to a capture or a legacy file:line.
- [ ] The app can pass the account's value to `RESTFlagBucketClient`; spec and HFR-PROTOCOL updated.

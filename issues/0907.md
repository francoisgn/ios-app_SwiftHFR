### Script (`tooling/restore/restore_tracker.py`, Python 3, `gh api` only)

1. **Read** the archive at a given commit; build the ordered list of items (issues and PRs by number).
2. **Plan (default, dry run):** write `restore-plan.json` and a summary, without calling any write endpoint:
   - per item: the target title, body, labels, state and state reason, and comments;
   - a **number map** (old → new) and every `#N` rewrite.
3. **Apply** (`--apply --target owner/repo`, refused without an explicit `--yes-i-own-this-repo`):
   - each issue is created with a header « Originally #N by `<login>` on `<date>` (ezzz/HFRnow) »;
   - each comment is replayed with its own header;
   - labels are created from the archive's set;
   - the current state is set (closed with its reason, or open with its `status:` label);
   - a **merged PR** becomes a closed issue « PR #N → merged as `<sha>` », with the commit link in the target repo;
   - an open or closed-unmerged PR is recorded the same way, with its head SHA and bundle name.
4. **Safety:**
   - every `@login` is neutralised (`@` → `@`), so nobody is notified;
   - the rate limit is respected (pacing, retry on 403/429);
   - the run can resume: it writes `restore-state.json` after each item and skips what is done.
5. **Verify** (`--verify --target …`):
   - the counts match the archive;
   - every `merge_commit_sha` exists in the target's default branch;
   - every `Closes #N` of a merged PR maps to a closed issue;
   - every `#N` in a restored body points to the mapped number.

   Output: a red/green report.

### Test (the acceptance of this issue)

- Dry run on the full archive: the plan and the verify report on the plan, with 0 unmapped `#N` and 0 missing SHAs.
- A real `--apply` of **5 items** (2 open issues, 1 closed issue, 1 merged PR, 1 unmerged PR) into an **empty private test repository the operator creates**, then `--verify`. Screenshots or a link go on this issue.
- No run against any other repository.

### Limits (accepted)

- The restored items' author and dates are the importer's; the originals are kept in the headers.
- The event history (label changes, who claimed when) is not archived; only the final state is restored.
- Uploaded images stay linked to GitHub-hosted URLs.

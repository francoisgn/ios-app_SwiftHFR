# Issue #956: [SwiftHFR] CI: a label-triggered macOS compile-only check for draft PRs (catch compile errors before review)

### Summary

As the orchestrator, I want a fast macOS **compile-only** check of the app (build the app and its test target, run no test) that a draft PR can ask for with a label, so that compile errors no Linux session can see are caught before the adversarial review, not after it.

### Why (2026-11-16)

#953 (main-actor isolation in a test fixture), #924 (twice) and #951 each passed review and then failed to compile on the ready run, costing a review round, a fix and a new full macOS run each. Operator decision 2026-11-16: efficiency, no throttling.

### Scope

- A job in the existing CI workflow (or a small new one), triggered on `pull_request` `labeled` / `synchronize` when the PR carries a label such as `compile-check`. It runs `xcodebuild build-for-testing` for the app scheme on the same runner and Xcode as the app job, with `timeout-minutes`, and no test run.
- The label goes in `.github/labels.yml` (AGENTS §7: labels are defined there only).
- Respect CI-BUDGET: no macOS cost on a draft without the label; job timeouts; concurrency cancels an older run of the same PR.
- Document it in REVIEW-ROUNDS / ORCHESTRATION in one line: Linux-only children set the label on their draft before asking for review.

### Acceptance criteria

- [ ] A draft PR with the label gets a macOS build-for-testing result in about 10 min or less; without it, no macOS job runs on a draft.
- [ ] The job fails on a compile error and passes on `dev-swift`; evidence from one run of each is linked in the PR.
- [ ] No change to the required checks or the ready-PR jobs.

**mac/M1: LOT-146 in draft #1027 (Sonnet author, Opus review running). One product question.**

Two iPad windows with a composer open on the **same topic** share one draft (one `DraftStore`), so the last autosave wins. A reply sent from window A deletes the draft, and window B's still-open composer can write its text back at its next autosave. Legacy @ 2fe43da3 has the same single store: `ReplyDraftStore`, one app-wide UserDefaults entry keyed by topic (`HFRswift/Swift/AnswerView.swift:137-140`, `reply_active_drafts_by_topic_v1`), with no multi-window handling, so this is not a parity gap.

Options:
1. 🟢 Leave it as legacy for M4 and note it in the spec (the case needs two windows composing on one topic).
2. A per-window draft (a different key per scene): a product change, so an M5 / LOT-145 item.
3. A notice in window B when the draft changed under it.

## The Funnel client-IP check

- **What the code does** (`internal/web/ip.go:12-29`), measured: from the trusted proxy, the **last** address of `X-Forwarded-For` wins, across a comma list and across repeated header lines, so a value sent by the client in front is ignored when the proxy appends or replaces. From any other source the header is ignored.
- **What Funnel sends**: in Tailscale's published source the HTTP proxy mode **sets** (replaces) `X-Forwarded-For` with the connection's source address (tailscale v1.80.0, `ipn/ipnlocal/serve.go:817-825`, `addProxyForwardedHeaders`). That is what the code expects, and no `UX_EN_TETE_CLIENT` variable is needed. It is a secondary source for one version: the version on the VPS is proven only by the on-host test (spec §11 step 3, checklist points 3 and 4), which stays the gate.
- **If the header is missing or unreadable**: measured, the service falls back to the proxy's address. This is the safe side (nobody gains a counter) but everyone then shares one: the fourth submission gets 429, and ten wrong access-code tries by anyone lock all testers out for ten minutes. Finding 4 makes that visible in the log.

## Findings

**1. Medium (privacy, notice mismatch): a rights erasure leaves the data on the server.** → #1430
`cmd/ux-survey/commandes.go:205-224`, `internal/stockage/ecriture.go:199`, `:228`, `:234`, `internal/stockage/base.go:86-88`, `web/donnees.html:88`.
Scenario: a respondent asks for erasure; the PO runs `pseudo --effacer <id>`. Measured: the pseudo text is still in `reponses.db` afterwards (freed pages are not overwritten: no `secure_delete`, no `VACUUM`), and `exports/pseudos-*`, `exports/analyse-*` and `sauvegardes/*` made earlier keep it until the final erasure (the command only prints a reminder, and `export` never overwrites a file). Also `pseudo --chercher <pseudo>` puts the real pseudo in the host's shell history. The notice promises erasure "y compris dans les copies d'analyse".
Fix: `PRAGMA secure_delete = ON` (or `VACUUM` and checkpoint after a rights write); the rights commands delete, or refuse to succeed over, earlier exports and backups; `--chercher -` reads standard input.

**2. Low (anti-abuse): the strength of `UX_CODE_ACCES` is not enforced, and the log does not say whether access is restricted.** → #1431
`internal/contenu/config.go:42`, `internal/web/middleware.go:156-159`.
Scenario: the trial is deployed with a short code, or with the variable missing. Measured: a three-character code is accepted at startup; with an empty one the check is not installed and the startup line looks the same. The Funnel address is a public `https` name, so this code is the trial's only restriction.
Fix: refuse a non-empty code under 20 characters; `acces_restreint: true|false` in the startup line.

**3. Low (privacy, host): the relay's own logs can hold respondents' addresses.** → #1432
`web/donnees.html:49`, `docs/ux/questionnaire/verification-image.md` point 5.
Scenario: the notice says the server's technical logs hold no IP address. True for the service (measured). But the Tailscale daemon on the host logs the source address on its failure paths (tailscale v1.80.0, `ipn/ipnlocal/serve.go:418`, `:436`, `:503`), and the checklist greps its journal after successful requests only.
Fix: switch off the daemon's log upload, bound its journal's retention and grep after a failed request too; otherwise reword the notice sentence (new `UX_MENTION_MAJ`).

**4. Low (operability of the anti-abuse): a silent fallback when the proxy sends no client address.** → #1433
`internal/web/ip.go:19-29`.
Scenario and measure: see "The Funnel client-IP check". Fix: one warning line per hour at most, without any address.

## Known and accepted, re-checked, no new action

- **Many addresses**: someone with many IPv6 prefixes can fill the hourly cap (`UX_PLAFOND_HORAIRE`, 503 for the others) or add false answers up to it. Documented in spec §6; the cap bounds it and the PO watches `refus: plafond-horaire`. The pseudo is unverified by design, as the notice says.
- **Log timestamps (R14)**: each accepted POST is logged to the millisecond. With five testers, the day of `recue_le` plus the log dates each response for whoever has host access. Accepted for the trial since its data is deleted afterwards (checklist point 11).
- **Free texts are untrusted input** for the later synthesis: HTML and spreadsheet formulas are inert (see table), but when extracts go to the AI assistant they must be handled as data, never as instructions. Process note for the PO, no code change.
- **The in-memory limiter keeps 1 000 clients**; beyond, the oldest is forgotten. The stored counter per address and the hourly cap do not depend on it.

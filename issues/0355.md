### Summary

Two-line summary: LOT-057 (#83) reads the anonymous REST API on page 1 only, and treats every REST failure the same way (fallback to the HTML page), because nothing beyond `R57a`-`R57c` is captured. These anonymous GETs settle paging and the failure shapes.

### Captures (anonymous, no account, read-only GETs; `R57*` naming and FIXTURES.md rules)

1. `GET /webservices/rest_api.php?uri=forums/hardwarefr/categories/13/topics/last/&page=2`: does page 2 repeat the 5 sticky topics, and are `page` / `results_count` what page 1 says?
2. The same with `&page=1&results_per_page=50`: is the parameter honoured (the HTML list shows 50 rows per page)?
3. A page past the last one (`page=` ⌈`results_count` / 25⌉ + 1).
4. An `/api/…` href requested as is, e.g. `GET /api/forums/hardwarefr/categories/` (redface2 E1 says 404; HFR-PROTOCOL §7: not tested).
5. Error answers: an unknown category (`uri=forums/hardwarefr/categories/999/topics/last/`), an unknown topic (`…/categories/13/topics/999999999/`), and an unknown resource (`uri=forums/hardwarefr/nothing/`): status, content type, body.

Keep each answer's status, headers (`Content-Type`, any `Set-Cookie` name) and bytes in the `.meta.json`, as for `R57a`-`R57c`.

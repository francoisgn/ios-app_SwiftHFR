# Issue #1198: [SwiftHFR] tooling: the claim check, the ledger and the hygiene sweep read a PR's issue line with three different grammars

### Summary
As the orchestrator, I want one parser for the `Closes #N` / `Refs #N` line of a PR, so that a body the Issue and claim check accepts is also one the sweep closes and the ledger folds. Today a PR can pass the check and be invisible to the sweep, with no report.

### Scenario (probed in Python against the three modules)
- `LOT-012 · Closes #45`, `- Closes #77`, `**Closes #12**` and `Closed #9` pass the claim check (`linked_issues` returns the number); `hygiene.CLOSES` finds nothing, so the sweep's `close` action never closes the issue after the merge.
- For the first two bodies, and for `Fixes #123`, `ledger.issue_number` falls back to the PR number: a correct `gap-new` row `GAP-<issue>` is then refused (`tooling/docs/ledger.py:140-141`).
- `Refs #893 for the device check.` followed by `Closes #50`: the ledger takes 893 as the PR's issue, so the new row must be `GAP-893`; the claim check also requires #893 open and claimed by the same id (`scripts/issue_claims.py:128-143`).

### Evidence (`7a61018f`)
- `scripts/issue_claims.py:30`: `\b(?:close[sd]?|fix(?:e[sd])?|resolve[sd]?|refs?)\s+#(\d+)\b`, anywhere in the body.
- `tooling/roadmap/hygiene.py:82-83`: `^[ \t]*(?:closes|fixes|resolves)[ \t]+#(\d+)\b`, line start only.
- `tooling/docs/ledger.py:50`: `^[ \t]*(?:closes|refs)[ \t]+#(\d+)\b` (no `fixes`), and `:90-93` `issue_number` takes the first match, a `Refs` included.
- Each script's tests use its own regex; `scripts/tests/ledger_real_bodies.json` holds three bodies, all canonical.

### Fix
One shared parser (e.g. `tooling/common/pr_refs.py`: closing refs, `Refs`, the primary issue = the first closing ref, never a `Refs` when a `Closes` exists), imported by the three scripts. One grammar: the check rejects what the sweep cannot read, or the sweep reads what the check accepts.

### Test (fails today on five bodies)
`test_pr_refs_agree`: a table of bodies (the six above plus `Closes #50, #51`) giving the same closing set from `issue_claims.linked_issues`, `hygiene.CLOSES` and `ledger.issue_number`.

How many merged PR bodies use a variant was not counted. Rework model: Sonnet 5.5, reviewed by Opus 5.5.

### Summary
When a member turns on Réglages › Expérimental › « Chargement des images » for the first time, the choice starts at « Toujours » (the default behaviour), not at a value stored by an earlier beta (e.g. « Jamais (au toucher) »).

### Decision (operator, 2026-11-17)
Answering the open point of #902 / PR #984: « forcer toujours ». Today the option restores the stored `display_images` value when it is turned on (kept on purpose in #984: « a beta value « Jamais » comes back if the option is turned on »).

### Scope
- The first activation of the experimental option (`experimentalImageLoadingChoice` false → true, for the first time) sets the choice to « Toujours » (`ImageDisplayMode.always`).
- Later toggles keep what the member chose while the option was on: only the first activation resets.
- The code stays in `App/SwiftHFR/Experimental/ImageLoadingChoice/`, with `// EXPERIMENTAL(imageLoadingChoice, #<this issue>)` markers (AGENTS §7).
- Persistence: a member who updates from a build that stored « Jamais » sees « Toujours » at their first activation after the update. Record how « first » is remembered (a flag key, tolerant decoding).

### Acceptance criteria
- [ ] A stored `display_images = never`, then the first activation: the choice is « Toujours » and images load.
- [ ] Off, then on again after choosing « Wi-Fi uniquement »: « Wi-Fi uniquement » is kept.
- [ ] Unit tests for both, each failing without the change.

Assigned by cloud/orch. Plan:
- **Remembering "first".** A new device-only key, `experimental.imageLoadingChoice.started` (bool, default false), in the `SettingKey` catalogue and the ADR 0013 matrix. It is independent of the switch's own key, so a member who toggled the option in an earlier build still gets « Toujours » at their first activation after this update. Decoding is tolerant through `Setting.bool`: a missing or odd value reads as false.
- **Hook.** `ExperimentalSettings.set` calls `ImageLoadingChoice.didTurnOn(store:)` when `.imageLoadingChoice` turns on, behind an `// EXPERIMENTAL(imageLoadingChoice, #1003)` marker. Only the first time, it writes `display_images = always` and the flag; later activations change nothing.
- **Tests.** A stored « Jamais » followed by the first activation gives « Toujours » and images load. Off, then on again after choosing « Wi-Fi uniquement », keeps it, across a relaunch too. The key goes into the catalogue, default and scope tests.
- **Not covered.** A member whose option is already on at the update does not "activate" it, so their stored choice stays. I'll flag that on the PR for the operator.
- **Branch.** `fix/1003-image-choice-first-on`, as a draft with `compile-check`, then a Fable review.

**Open question for the operator** (from the review of #1004, kept here so it outlives the PR):

Two cases are not settled by the decision « forcer toujours ». #1004 handles both as described below, and its tests pin that behaviour.

1. **The option was on in a build since #984 (2026-11-17) with a choice made there, e.g. « Wi-Fi uniquement ».**
   - #1004 follows the persistence point: the first activation after the update, meaning off then on, gives « Toujours ».
   - The alternative is to count the first turning-off after the update as "already started" and keep the earlier choice. That would also keep a stored « Jamais ».
2. **The option is still on at the update and is never turned off and on again.** No activation happens, so the stored choice, « Jamais » included, stays.
   - The alternative is a launch-time reset when the option is on and the flag is absent.

# Issue #1391: [SwiftHFR] Session-change reloads are not coalesced: every `currentSessionChanges` bump starts its own home + lists reload

- State: open
- Author: francoisgn · created 2026-11-27T14:55:25Z · updated 2026-11-27T16:58:49Z
- Labels: type: bug, priority: low, difficulty: easy, area: app, status: ready, origin: audit, m4-review: performance
- Source: https://github.com/ezzz/HFRnow/issues/1391

### Summary
As a user, I want a burst of session changes to cost one reload, so that whatever fires `currentSessionChanges` again (the #1276 loop was one such source) can never multiply requests. Audit #1388, finding A2: the amplifier of the #1276 loop is still there after #1385.

### What happens (read at `dev-swift` `1685bcc`)
- `RootNavigationView.swift:44-47`: `.onChange(of: accounts?.currentSessionChanges) { Task { await model.currentSessionChanged(expired:) } }`: one unstructured task per bump, per window.
- `RootModel.currentSessionChanged` (`RootModel.swift:311-315`) reloads the home page, then every shown list of Catégories and Favoris (`NavigationModel.sessionDidChange`, `NavigationModel.swift:92-98`: the selection and a pushed category, each).
- Nothing limits it: N bumps = N home GETs + N × (1 to 4) list GETs, each superseding the one before (`ContentLoader.load` cancels the task in flight, so the earlier requests leave and are cancelled).

### Failing scenario and count
Device trace of #1276 (issuecomment-7218471693): 11 bumps in 2.4 s → 12 `/` + 12 `/forum1f.php`, 6 cancelled in flight. Per bump the budget is 2 requests on an iPhone showing Favoris, up to 5 with a list open in both tabs, times the number of windows on an iPad (each window has its own `RootModel`).

The bump sources today: `checkSessions` `.expired` (`AccountsModel.swift:223`), a re-login in place (`:270`), the sync take-over (`:431`).

### Proposed fix
- One reload at a time per root: a bump while a reload runs marks it dirty, and one more reload runs at the end (never one per bump).
- A floor between two session-change reloads (e.g. 2 s) as a fuse, with the last bump always honoured.
- Test (app, counting `ForumDataSource`): 10 bumps in one main-actor turn → at most 2 home loads and 2 loads per shown list.

Refs #1388, #1276, #1385.

### What the legacy patch says (`5c0f10db`, commit message and diff)
1. HFR now answers **403** to a profile request **without `md_id`**; `md_id` is set **only at login**.
2. `LoginService.swift`: the login POST now sends **the fields of the forum's own `login.php` form** (`hash_check`, `pseudo`, `password`, `cat`, `page=1`, `config=hfr.inc`, `p=1`, `sondage=0`, `owntopic=0`, `post`, `referer`, `Valider=Valider`); per the commit, with these fields `login_validation.php` also sets `md_id` (legacy « ne l'avait jamais »).
3. `MultisManager.updateCookies:` **merges** received cookies into the account's (same name, domain, path replaced; others kept) instead of replacing the list, which dropped `md_id` at each launch refresh.
4. The profile sends the account's cookies completed by the shared storage.
5. A 403 **without `md_id`** gets a new error, `reloginRequired`: « remove and re-add the account ».

Verification (ext/bybifok-opus-1, Opus 5.5; not claimed, verification only): **the legacy bug does not exist in SwiftHFR.** Legacy built `liste_sujet-1.htm?page=N`, which HFR ignores (legacy fix `a817498` in ezzz/HFRnow#3).

- **Category lists.** The builder never adds `?page=` to a list path. `ForumCatalogue.topicListPath` (`Packages/HFRKit/Sources/HFRModels/Catalogue/ForumCatalogue+TopicListPath.swift:6-9`) always builds `/forum1.php?config=hfr.inc&cat=N&page=P&subcat=&owntopic=F`, and `HFREndpoint.topicList` (`HFREndpoint+Topics.swift:8-14`) uses it. Tests: `TopicListPathTests.pageNumberIsWritten`, `HFREndpointReadTests.topicList`.
  - That exact request is what `R05a` and `R05b` captured. HFR answers 301 to `/hfr/Discussions/liste_sujet-12.htm` and `-500.htm`, and the page shows page 12 and page 500 (`TopicListParserTests.currentPageFromThePager`, `.pagerWindow`).
- **Sub-forums.** The app rewrites the path's `liste_sujet-<n>.htm`, as the legacy fix does: `SubforumPath.page(_:of:)` (`App/SwiftHFR/Navigation/SubforumPath.swift:9-12`), used by `ForumDataSource.topicList(path:page:)` (`:45-53`). Tests: `SubforumPathTests.replacesThePageOfAListPath`, `TopicListModelTests.aSubforumPagesThroughItsOwnLinkAndRefreshesTheCurrentPage`.
- **Pager links** are read from the page (`TopicListPager.linkTarget`), never rebuilt.

What is left:
- Pending capture (HFR-PROTOCOL §7b B2): the logged-in answer to `forum1.php?…&page=N` for N ≥ 2. `R08-2` only shows page 1 logged in: 200 in place, no redirect.
- Optional test: no single test ties the builder to the capture yet. A small one would assert that `HFREndpoint.topicList(category: .forum(13), page: 12).url` equals `R05a`'s requested URL (meta) and that parsing `R05a` at its final URL gives current page 12 (same for `R05b`).

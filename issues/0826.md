As the maintainer, I want the ledger and the issue status labels to stay consistent without manual label juggling, so that the docs steward stops tripping and the tracker reflects reality. ### Facts (2026-11-10/11)
- Docs consistency failed four times on a mismatch between the `### Ledger` section and the `ledger` label: #757, #759, and #795 twice. The check reads the PR only on a push, so fixing a label afterwards leaves it red.
- #747 carried `ledger` with no section. Two folds on the same day (#781, #798) came from two sessions and collided on the branch name.
- Four issues stayed `status: ready` while a PR was open on them. About ten stayed `status: claimed` with no PR for 3 to 5 days.

### Scope
1. **Ledger by section only:**
   - The Docs consistency check validates the `### Ledger` section's syntax when there is one, and no longer requires or reads the `ledger` label.
   - `tooling/docs/ledger.py fold` selects merged PRs by their section, not the label. It skips PRs already marked `ledger: done`; `done` sets that label, and no person or agent sets ledger labels by hand.
   - Migration: open PRs that carry `ledger` keep working, and the label becomes inert.
   - Update AGENTS.md §8 (the ledger bullet), `tooling/docs/README.md` and REVIEW-ROUNDS where the label is mentioned.
2. **Labels kept by `tooling/roadmap/hygiene.py --apply`:**
   - An open issue cited by an open PR (`Closes`/`Refs #N`) gets `status: claimed`.
   - An issue in `Closes #N` of a merged PR is closed with `Done in #PR (merged as <sha>)`, if still open; `Refs` issues are untouched.
   - A `status: claimed` issue with no open PR and no comment for 72 h is reported to the orchestrator, never auto-released.
   - Exactly one `status:` label per open issue.
   - Dry-run stays the default.

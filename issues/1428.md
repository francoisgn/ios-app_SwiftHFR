# Issue #1428: [SwiftHFR] Category lists opened by id (`forum1.php?cat=…`) pay a 301 on a new connection; later pages could use the served `liste_sujet-N.htm` path

- State: open
- Author: francoisgn · created 2026-11-27T23:55:43Z · updated 2026-11-27T23:55:43Z
- Labels: type: bug, priority: low, difficulty: medium, area: network, status: ready, origin: audit, m4-review: performance
- Source: https://github.com/ezzz/HFRnow/issues/1428

### Summary
As a reader, I want a page change in a category list to cost one request, so that browsing lists is as fast as the reader after #1394. Split from #1394 (item N2 of the #1388 runtime pass), so that #1394 closes on the topic pages it fixes.

### Facts
- #1388 runtime pass (issuecomment-7223560232): category lists opened by id (`forum1.php?cat=…`) pay 1 redirect. HFR closes the connection after a 301, so the hop costs a full TCP+TLS handshake (0.05–0.7 s; N3).
- `R121e` (HFR-PROTOCOL §6c, **verified**): `cat=22` page 1 answers 301 to the canonical `/hfr/reseauxpersosoho/liste_sujet-1.htm`, which serves the logged-in markup. Sub-forums already page through `liste_sujet-<n>.htm` (HFR-PROTOCOL §7b B2, `SubforumPath.page`).

### Scope
- Once a category list page has been served at its canonical `/hfr/<cat>/liste_sujet-<n>.htm` path, ask for its other pages at that path with `<n>` changed, the way #1394 does for topic pages. Keep the id form for the first open and whenever a filter is set (the filtered `forum1.php` shapes, `R603d`, have no captured canonical form).
- Never guess: what HFR serves for a canonical list page past the end is **not captured**, so the pager must stay within the known last page, or a capture must come first (`host: mac`).

### Acceptance criteria
- Engine test with a counting loopback transport: after page 1 served at `liste_sujet-1.htm`, page 2 is one request to `liste_sujet-2.htm`, not `forum1.php` plus a 301.

Refs #1394, #1388, #774.

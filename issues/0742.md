As a reader of the composer preview (LOT-152), I want the BBCode renderer to match HFR's own preview on the cases captured in #443, so that what the preview shows is what HFR renders.

### Facts
Source: `R443a`-`R443n` (PR #741), HFR-PROTOCOL §6b "BBCode preview, batch 2". Each row below contradicts a default of `docs/lots/LOT-097-bbcode-preview-renderer.md` (table, Edge cases or "Defaults for uncaptured cases").
1. **Syntax colours** (`R443e`, `R443n`): `[code]` is coloured like `[cpp]`: keywords in `span[style=color:blue]`, `//` comments in `span[style=color:green] > i` holding the line's CR, string literals not coloured. `[c]`, `[java]`, `[php]` and `[html]` are not tags. (Intentional difference 3 and pending 5.)
2. **Tags inside a raw block** (`R443j`, `R443n`):
   - `[b]` inside `[code]` is rendered (`<li><strong>x</strong></li>`).
   - `[cpp]` inside `[fixed]` drops the `[fixed]` tags and renders the code block.
   - `[code]` inside `[cpp]` renders a code table inside the cpp list item, with the inner colour spans escaped.
   - `[fixed]` inside `[code]` renders a fixed table inside the code item.
3. **Bold and quotes** (`R443i`, `R443j`): `[b][/b]` is text, not `<strong></strong>`. `[b][quote]x[/quote][/b]` and `[quote][b]x[/quote][/b]` drop the `b` tags and render the quote.
4. **Quote depth** (`R443l`): of 30 nested `[quote]`, only the two outer levels render; the inner opens and closes stay text.
5. **Smileys** (`R443a`, `R443n`):
   - Inside `[url]…[/url]` the smiley is substituted and the tag is then left as text.
   - In a bare URL the auto-link stops before `:/`, which becomes a smiley.
   - A code glued to a word is substituted.
   - `)` after `&#034;` or `&amp;` gets a space before it, so no smiley forms.
   - Overlapping `:p:pfff:` gives `:p:` and then `pfff:`.
6. **Colour** (`R443c`, `R443n`): a close in another case (`[#0055AA]x[/#0055aa]`) still renders. A colour inside a colour closes the outer span at the inner close; the inner open and the outer close stay text.
7. **Whitespace** (`R443g`, `R443n`): the start of the message is a line start, so three leading spaces give `&nbsp; `. A single leading space on a code line stays a plain space.
8. **Bullets** (`R443d`): `[list]` / `[/list]` stay text around the list; a list item ends with `\r</li>` (LF dropped).
9. **URLs** (`R443f`): HFR puts `http://` in front of `javascript:`, `tel:` and `mailto:`, and `[img]` accepts `ftp://` and page URLs. The sanitizer keeps its own rule (intentional difference 2), but the lot's notes on "HFR's answers pending" can now cite these.

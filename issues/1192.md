# Issue #1192: [SwiftHFR] messages: the list clears its local read/unread marks after a load that applied nothing

### Summary
As a member, I want a conversation I just read (or marked unread) to keep that state when a reload brings nothing, so that it does not flip back and the badge is not decremented twice (#762). The topic list already does this right; the Messages list drops the loader's answer.

### Scenario
On page 1 the member reads conversation T (`openedThreads[T]`, badge -1) or marks U unread (`markedUnread`). The next reload ends `.cancelled` without a newer load (see the unrequested-cancel finding of #775). `mine == loadCount` and `loader.error == nil`, so the code treats the page still on screen as a fresh answer: T leaves `openedThreads` and shows unread again (reopening takes a second -1 off the badge), `markedUnread` is emptied so U shows read, and `recordReadState()` sends that stale set to the notification ledger.

### Evidence (`7a61018f`)
- `App/SwiftHFR/Messages/MessageListModel.swift:339-357`: the Bool of `await loader.load { … }` is dropped; then `openedThreads = openedThreads.filter { … }`, `markedUnread.removeAll()`, `recordReadState()`.
- `App/SwiftHFR/Navigation/ContentLoader.swift:57-71`: `finish` returns false for `.failure(.cancelled)` and leaves `value` and `error` untouched.
- `App/SwiftHFR/Navigation/TopicListModel.swift:287` and `:315-316`: `let applied = await loader.load {…}` … `guard applied else { return }` ("a superseded load or a failed one changes nothing").

### Fix
`let applied = await loader.load {…}`; keep the `.notAuthenticated` branch, then `guard applied else { return }` before touching `openedThreads`, `markedUnread`, `recordReadState` and the segment advance.

### Tests (fail before the fix)
`MessageListReadStateTests.aCancelledReloadKeepsTheLocalMarks`: page 1 with T unread, `markOpened(T)`, source scripted to throw `.cancelled`, `refresh()`: `isUnread(T) == false`, the badge adjusted once, no second `ledgerSeen` call. A twin for `markedUnread`.

### Summary
As a maintainer publishing captures, I want the signature/mood redaction of #794 to fail loudly on the shapes it does not cover, so that no edge case of member markup reaches a public fixture silently.

### Facts (round-2 adversarial review of #794, APPROVE with these Low findings; no corpus page has any of these shapes)
1. **Forged boundary**: a member able to write attribute-bearing HFR tags (`<table class="messagetable">`, `<script>`, in a mood `<div class="avatar_center">` / `<td class="messCase2">`) ends the redaction and the `check` state early: `…</span><table class="messagetable"><tr><td>Secret Handle</td></tr></table><span>` keeps the text, `check` reports 0. Beyond #763's unbalanced-tag model. Fix idea: for a signature, refuse a boundary seen while its `td.messCase2` is still open (redactor and check).
2. **No boundary**: with no boundary after a signature, the redactor falls back to the depth count, and the verifier ignores comments, declarations, processing instructions and end-tag attributes while `after_personal` is set (`</span><!-- Secret Handle -->`, `</span></b title="Secret Handle">`). Fix idea: raise when no boundary follows a signature in a page; flag those non-elements while `after_personal` is set.
3. **Silent cut**: an HFR `</span>` between the block and its boundary that is not in the boundary list is deleted silently (invented: `<br/><span class="MDStatus">…</span>` after a mood with no avatar). Fix idea: raise unless the text between the chosen `</span>` and the boundary is only end tags, blanks and `<br>`.
4. **Test gaps**: no test fails when the XML exemption of the CDATA rule, the footer-table attribute restriction or the bare-`br` condition is removed.

### Acceptance
Tests first for each point; `check --corpus`, `manifest_check.py` and the tooling tests green; old vs new `anonymize` identical on the corpus.

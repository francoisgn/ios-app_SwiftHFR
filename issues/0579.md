# Issue #579: [SwiftHFR] MP list: show HFR's "[non lu]" marker (the correspondent has not read it yet)

### Summary
As a member, I want to see in my MP list which conversations my correspondent has not read yet, as the forum and the legacy app show them, so that I know whether my last message was read. Operator report after a device test, 2026-11-07, milestone M4 (parity).

### Verified
- **HFR** marks it per row with `<span class="red" title="Ce message n'a pas été lu par : <pseudos>">[non lu]</span>` before the title. It means the **other party** has not read the conversation. This state is independent of one's own unread icon (`closedbp.gif`). Sources: HFR-PROTOCOL §6b `:149`, `:297`, `:508`, captures `R13a`, `R13b`, `R13u1`, `R123a`, `R123f`. In a group MP the tooltip names every member who has not read it yet, in lower case.
- **The engine already parses it.** `PrivateMessageListParser.swift:37, 61-62` fills `PrivateMessageThread.unreadBy` and `isUnreadByOthers`, defined in `HFRModels/Lists/PrivateMessageThread.swift:10-14`.
- **The app never displays it.** `MessageRowView.swift` shows only one's own unread state (dot, semibold). The bug is display-only.
- **Legacy** showed a "non lu" capsule: `MPListView.swift:425-436` @ 2440d79, white caption on `systemGray`, 50 % opacity when the thread is viewed. GAP-111 records the capsule as not ported. This issue restores it.

### Fix
- In `MessageRowView`, when `thread.isUnreadByOthers` is true, show a small "non lu" capsule next to the title or the date, as legacy did.
  - Accessibility label: "Non lu par <pseudos>", or "Non lu par le destinataire" when `unreadBy` is empty.
  - Group MP: list the names from `unreadBy`.
- Keep it visually distinct from one's own unread state (the dot and the #570 tint). Two states can be shown at once (`R13u1`).
- Update GAP-111.
- Test: a row model with `isUnreadByOthers` shows the capsule and its label; one's own unread state alone does not.

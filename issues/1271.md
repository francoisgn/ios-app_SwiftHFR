### Summary

As the client, I want the `quote_only=1` view of a message captured as a **logged-in** reader and on a **private thread**, so that the in-app « Message cité N fois » view (#1039, PR #1268) stops resting on an anonymous public-topic capture only.

### What is known

`R126a` (HFR-PROTOCOL §6c « Batch A », #126) is anonymous, on a public topic (`cat=13`): 200 in place, the cited message's page title, no pager, only the quoting posts.

### What is not captured

1. **Logged-in request:** does fetching `quote_only=1` with the account cookies change the topic's read flag (the page the user is reading marks flags read, §7 E25), or anything else on the account? #1268 sends it through the account session; if it moves the flag, the in-app view must not.
2. **Private thread (`cat=prive`):** whether a private thread's messages carry « Message cité N fois » and what the quote view returns. `HFRQuotingLink` refuses `cat=prive` until it is captured (#1268).

### Scope

- Two read-only GETs of `mac/M1` (user2): the `R353a` `div.edited` link as a logged-in reader, with the topic's flag state before and after; a private thread message that has a count, if one exists.
- Publish the anonymized fixtures and record the result in HFR-PROTOCOL §6c (FIXTURES.md rules).

### Acceptance criteria

- The flag state before/after is stated in §6c, with the capture ids.
- The private-thread shape is captured, or its absence is stated.

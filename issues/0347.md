### Summary
Generate, on the Mac, legacy-app samples of the five on-device formats that LOT-067 (#92) must import, so that the importer is tested against what the legacy app really writes, never against hand-built plists (LESSONS 35-36).

### Scope
Run the legacy app (hfrnow @ `2440d79`, with the oracle tooling of `tooling/legacy-oracle/`, as for `samples/storage-smileys.json`, LOT-004) on **synthetic data** and export, for each format, the bytes the legacy app stores:

| # | Legacy store | Where legacy keeps it | Legacy source |
|---|---|---|---|
| 1 | `SuperFavoritesIds` | `UserDefaults` array | `Favorites.swift:114-136` |
| 2 | `CollapsedFavoriteSectionIDs` | `UserDefaults` array | `Favorites.swift` (`FavoritesCollapsedSectionsStore`) |
| 3 | `smiley_favorites_cache2` | `NSKeyedArchiver` file | `SmileyCache.m:18-35, 353-439` |
| 4 | `smileySearchHistory_v1` | JSON file | `SmileySearchService.swift:85-125` |
| 5 | `rehostImagesSwiftUI.json` | JSON file | `ReplyService.swift:1898-1911` |

For each: at least an empty, a typical and a boundary sample, for example:
- super-favourites: the same topic number in two categories;
- search history: exactly 50 entries;
- upload history: one corrupt file, since legacy rewrites it as empty.

Add the `UserDefaults` domain dump (`defaults export`) holding #1 and #2.

### Rules
- **Synthetic data only.** No real pseudo, no real topic of a member, no cookie or token. Anonymize per `docs/FIXTURES.md`; an independent reviewer checks the samples before the push (LESSONS 33-34).
- The legacy app is **not** patched beyond the oracle patch of the branch (`run-oracle.sh` refuses otherwise).
- One PR with the samples under `tooling/legacy-oracle/samples/` plus their MANIFEST rows.

# Issue #1154: [SwiftHFR] Pager « Aller à la page » alert: an out-of-range or non-numeric entry is dropped silently

### Summary

As a reader who types a page number in « Aller à la page » (topic and MP list pagers), I want a wrong entry to be corrected or refused visibly, so that the alert does not close with nothing happening.

### Rule

"Validate fields when it makes sense. For example, if the only legitimate value for a field is a string of digits, your app needs to alert people if they've entered characters other than digits." — [HIG › Text fields](https://developer.apple.com/design/human-interface-guidelines/text-fields) (Best practices).

### What the app does (dev-swift @ `7a61018f`)

- `App/SwiftHFR/Navigation/PagerPageMenu.swift:85`: `Button("Aller") { if let page = menu.page(fromEntry: entry) { onJump(.page(page)) } }`.
- `:36-39` `page(fromEntry:)` returns nil for 0, for a page above `total` and for letters (hardware keyboard, paste). The alert then closes with no move and no message. The range is only in the placeholder (`:83`), which disappears on the first digit.

### Legacy at `87fe0d1c`

`HFRswift/Swift/Common.swift:3104-3105` (`TopicPagePickerSheet`) clamps: `min(max(1, Int(trimmedInput) ?? 1), maxPage)`, and shows « Choisir une page entre 1 et N » (`:3130`). SwiftHFR is worse.

### Class

**(a) defect** (parity).

### Proposed fix and check

- Clamp to `1...total` as legacy does when the total is exact, or disable « Aller » while the entry is invalid and put the range in the alert's `message:`.
- Check: a unit test on the clamp (or on the disabled state); typing 9999 on a 12-page list goes to page 12 or cannot be submitted.

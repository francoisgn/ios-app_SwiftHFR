# Issue #1187: [SwiftHFR] reader: images still loading when a shown page is stopped are never completed when the reader comes back

- State: closed
- Author: francoisgn · created 2026-11-18T20:09:39Z · updated 2026-11-19T12:36:15Z
- Labels: type: bug, priority: high, difficulty: medium, area: app, origin: audit, m4-review: quality
- Source: https://github.com/ezzz/HFRnow/issues/1187

### Summary
As a reader, I want the pictures of a page to finish loading when I come back to it, so that leaving the reader for a moment does not turn the pending pictures into links until I tap "Actualiser".

### Scenario
Open an image-heavy page (6 images load at a time, the others wait). Before they finish, make the web view leave its window (a tab switch) and come back. The document is "ready", so it is not reloaded; the image tasks that were running or waiting were cancelled and are never asked again. Each of those images is a text link, or blank.

### Evidence (`7a61018f`)
- `App/SwiftHFR/Reader/ReaderWebController.swift:167-182` (`stopLoading`): a ready document is kept, then `for task in running.values { task.cancel() }`, `running.removeAll()`, `waiting.removeAll()`.
- Same file `:139-142`: `show` skips a document with the same token, so the ready document is never loaded again on return (`ReaderWebController+Presence.swift:35-40`: `resume()` then `show(document)`).
- `App/SwiftHFR/Reader/TopicReaderView.swift:173-178`: `onDisappear` exempts the linked reader and the image viewer only; its own comment says "stopping would turn the pending pictures into links", so the effect is known for that one cover.
- `Reader/Resources/reader.js` `load()`: an `error` on the image replaces it with a link.

### Fix
Remember in `stopLoading()` that image tasks were cut on a ready document; on return, either reload it with the reading position kept, or add a `hfrReader.retryImages()` that re-applies the decision to the cut images.

### Test (fails before the fix)
`ReaderPresenceWebTests.aShownPageStoppedWithImagesInFlightShowsThemWhenItComesBack` (hosted web view, scripted fetcher holding one image): ready, `stopLoading()`, `resume()` + `show(document)`, release the fetcher; the `img` has a loaded `hfrreader:` source and there is no `.image-link`.

Confidence: the Swift path is certain; that WebKit fires `error` on the stopped scheme task rests on the code's comment, not on a run (if it does not, the images stay blank: same defect). A device check belongs on #893.

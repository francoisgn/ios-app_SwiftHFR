# Issue #652: [SwiftHFR] Reader: a tap on a member's avatar or pseudo opens their profile with MP, Whitelist and Blacklist, as legacy (M4)

- State: open
- Author: francoisgn · created 2026-11-08T07:05:05Z · updated 2026-11-09T15:07:21Z
- Labels: type: bug, priority: high, difficulty: medium, area: app, status: needs-triage, beta-test finding, origin: parity

### Summary
As a reader, I want a tap on a member's avatar or pseudo in a topic to open that member's profile screen, with "MP", "Whitelist" and "Blacklist" on it, as the legacy app does, so that I reach the member and my lists in one tap. Operator request, 2026-11-08.

Milestone: M4 (operator, 2026-11-08)

### Legacy behaviour @ 2440d79
- **Tap targets.** `SuperHFRplus/Assets/HTML/templatev2.htm:4-5`: the avatar (`div.left2`) and the pseudo (`div.left`) both call `touchHeaderMessage(this,'avatar')`. The `oijlkajsdoihjlkjasdopopupavatar` scheme becomes `MessageWebPopupSource.avatar` (`HFRswift/Swift/Common.swift:1993-1996, 2118-2132`).
- **Profile first.** `HFRswift/Swift/MessagesView.swift:1525-1536` (`presentPopupMenu`) sends the avatar source to `presentAvatarActionSheet` (`:3610-3616`):
  - **the message has a profile link** → `openProfile(for:avatarActions:)` (`:3578-3580`) opens `UserProfileView` **directly**, in a sheet (`:4844-4849`), with quick actions;
  - **no profile link** → the fallback sheet `MessageAvatarActionSheetView` (`:4870-4887`, view `:5307`): Profil, MP, Whitelist, Blacklist.
- **Quick actions on the profile.** `userProfileQuickActions` (`MessagesView.swift:3582-3608`):
  - MP only when the post is not the user's own (`:3586`);
  - Whitelist and Blacklist only when not own and the pseudo is non-empty (`:3587`);
  - each shows its current state (`isBlacklisted` / `isWhitelisted`, `:3597-3598`).
  - The buttons are in `UserProfileView.swift:687-719`, in this order: "MP" (`message`), "Ajouter WL" / "Retirer WL" (`heart` / `heart.slash`), "Ajouter BL" / "Retirer BL" (`hand.raised` / `hand.raised.slash`, destructive when adding). They sit under the header (`:674-676`).
- **After a toggle.** `toggleProfileBlacklist` / `toggleProfileWhitelist` (`MessagesView.swift:3664-3674, 3688-3698`) close the profile, show a toast with the result and reload the page. "MP" closes the profile, then opens the MP composer (`:3646-3650`).
- The same entries and conditions are in the policy `MessagePopupMenuPolicy` (`MessagesView.swift:205-217`).

### SwiftHFR today (origin/dev-swift @ d09a0ad8)
- **Avatar and pseudo are tappable** (#595, merged in #638): `TopicHTMLBuilder.swift:141` (pseudo) and `:164` (avatar) write `data-menu="avatar"` buttons.
- **The tap opens an anchored author menu, not the profile.** `AuthorActionHandlers.swift:7-11` records this as a deliberate difference: "the entries open from an anchored menu (issue #595) where legacy jumped to the profile screen". The #595 analysis chose the menu because it read the report as asking for one. **This request reverses that choice**: profile first, as legacy.
- **The profile screen** (`Profile/UserProfileView.swift`, LOT-116, GAP-167) has "Écrire un MP" (`:111-114`) but no Whitelist or Blacklist today.
- **Whitelist and Blacklist on the profile** come with LOT-118: #209, open PR #640, which adds the list buttons to `UserProfileModel` / `UserProfileView` and the author-menu handlers.

### Scope
1. A tap on the avatar or the pseudo opens `UserProfileView` directly when the message has a profile link (legacy `:3610-3613`).
2. Without a profile link, keep the author menu (Profil, MP, Whitelist, Blacklist), as the legacy fallback sheet.
3. The profile opened from a message offers MP, Whitelist and Blacklist with legacy's conditions: not on the user's own post; lists only with a non-empty pseudo; the label shows the current state (Ajouter / Retirer).
4. After a list toggle, the reader re-renders with the new list (legacy reloaded the page) and the user gets the result (toast or announcement).
5. Update the legacy pointer of `AuthorActionHandlers.swift`, the LOT-087 / #595 difference and the GAP-064 / GAP-167 rows.

### Acceptance criteria
- [ ] Logged in, a tap on another member's avatar **or** pseudo opens their profile in one tap, with MP, Whitelist and Blacklist.
- [ ] On my own post: profile without MP / WL / BL.
- [ ] A message without a profile link still offers the author menu.
- [ ] After "Ajouter BL" or "Ajouter WL", the topic shows the member as blacklisted or whitelisted without a manual reload.
- [ ] Logged out: profile opens; MP is absent (no composer).
- [ ] Tests: routing from the avatar source to the profile, conditions of the three buttons, re-render after a toggle.

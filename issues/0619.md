### Summary

As a member of HFR, I want a native macOS version of the app, so that I can read and write on the forum from my Mac with the same features (favourites, flags, MPs, offline reading) and a Mac-like interface, instead of the website or the iPad app.

_Idea submitted by the operator on 2026-11-07. This is an M5 study for triage: nobody has claimed it and nothing is planned yet._

### Why

- Users already ask for it: the feedback study `docs/research/user-feedback-p450-510.md` (line 157, "iPad and big screens", ≈25 mentions) lists a Mac app and Mac font zoom among the requests, "Mac and Watch not delivered".
- The engine is already ready for the Mac: `Packages/HFRKit/Package.swift` declares `.iOS("27.0")` **and** `.macOS("26.0")`, and the README says the engine builds and tests on macOS. Parsing, network, client flows and storage (`HFRModels`, `HFRParsing`, `HFRClient`, `HFRStorage`…) can be reused as they are.

### What exists today (dev-swift)

- `App/SwiftHFR.xcodeproj`: one iOS target, `SUPPORTED_PLATFORMS = "iphoneos iphonesimulator"`, `SUPPORTS_MACCATALYST = NO`, `TARGETED_DEVICE_FAMILY = "1,2"`.
- About 20 files in `App/SwiftHFR/` import UIKit or wrap UIKit views (reader `ReaderWebController*`, `QuoteMenuWebView`, image viewer, video player, image upload, clipboard, avatars and smileys loaders, `OrientationPolicy`, `TextScale`, theme settings, accounts). The reader is a `WKWebView` (13 files import WebKit), which exists on macOS but is wrapped differently (`NSViewRepresentable`).
- The iPad work (LOT-146 #236 multi-window, LOT-147 #237 columns, FEAT-021 #165 keyboard shortcuts, #512 split view) is the natural base for a Mac layout.

### Options to compare

| # | Option | Effort | Mac feel | Notes |
|---|---|---|---|---|
| A | "Designed for iPad" on Apple silicon Macs (App Store checkbox) | XS | poor | No code, but iPad UI as is; a stopgap only |
| B | Mac Catalyst | M | medium | UIKit code mostly reused; menus, toolbar and windowing need work; Catalyst is not Apple's direction for new SwiftUI apps |
| C | **Native macOS target in SwiftUI** (multiplatform target or second target), sharing HFRKit and the platform-neutral views | L | good | UIKit bits move behind small platform abstractions (`#if os(macOS)`); the operator's wording ("version MacOS Swift") points here |

### What a native Mac version should offer (first ideas)

- `NavigationSplitView` with three columns: categories / topic list / reader; several windows (one topic per window or tabbed windows).
- A menu bar with the usual commands (Nouveau message, Répondre, Rafraîchir, Aller à la page, Marquer non lu…) and keyboard shortcuts shared with FEAT-021.
- Text size with ⌘+ / ⌘− (the "Mac font zoom" request), Settings window (`Settings` scene) instead of an in-app screen.
- Composer in its own window or sheet, drag and drop of images into the upload.
- MP and flag notifications through the same check flows (LOT-140 / LOT-092), plus optionally a menu bar extra with the unread MP count.
- Same accounts and Keychain storage; same polite polling rules (LESSONS 48) and cookies kept on the forum (LESSONS 30/37/56).

### Open questions for the operator

1. Option A as a quick win first, then C? Or C directly?
2. Same App Store record (universal purchase, same bundle id `hfrplus.red.super`) or a separate Mac app?
3. Priority against the M4 parity and the other M5 studies (#546, #547)?
4. Minimum macOS version (HFRKit says 26.0; the app targets iOS 27)?

## Analysis (read-only, sub-orch) 2026-11-07

Read at `origin/dev-swift` `4b1e77f`. Legacy at `2440d79`. Nothing was changed.

### 1. What legacy does @ 2440d79

**Tapping a category title in Favoris**
- `HFRswift/Swift/Favorites.swift:320-338` (`headerTitleView`): the title is a `NavigationLink` to `ForumTopicsListView(forum:, initialFlagOverride: .favorites)`. It is pushed inside the Favoris stack, so "back" returns to Favoris.
- The override is **always `.favorites`**, whatever the `vos_sujets` mode. A tap from "Drapeaux & Favoris" also opens the category on Favoris (`owntopic=3`), not on the flags.
- Legacy quirk: `MainWindow.swift:767-793`. `onAppear` applies the override, then `onChange(of: selectedFlag)` writes it to the global `HFRswiftGlobalTopicListFlag`. One header tap therefore changes the filter of every category opened afterwards.

**The filter inside a category**
- `MainWindow.swift:613-640` has a segmented `Picker` Tous / Favoris / Suivis / Lus. Without a login the three filters are disabled, with the note "Connexion requise pour Favoris, Suivis et Lus".
- The filter is persisted globally (`:268`, `:322-333`), and forced back to Tous when logged out (`:786-801`).
- The enum is `TopicListFlag` (`Common.swift:1510-1515`): `all=0, favorites=1, tracked=2, read=3`. **These raw values are not `owntopic` values.** The mapping is in `Classes/ObjCForumTopicsLoaderWorker.m:96-141`:

  | Picker | `TopicListFlag` | `owntopic` |
  |---|---|---|
  | Tous | 0 | 0 |
  | Favoris | 1 | 3 |
  | Suivis | 2 | 1 |
  | Lus | 3 | 2 |

  A port that reads the legacy key must translate it.
- On a sub-forum, `forumURLBySettingOwnTopic` (`:36-82`) only rewrites a `forum1.php` URL. For a canonical `/hfr/…` path it falls back to `forumURLWithCatID` (`:84-89`), which has an empty `subcat=`. So **legacy loses the sub-forum when a filter is on.**

**Flag kinds.** Three exist, one per non-zero `owntopic`:
- `flag1.gif` (blue): "participé", legacy "Suivis", `owntopic=1`;
- `flag0.gif` (red): read, `owntopic=2`;
- `favoris.gif` (yellow): `owntopic=3`.

These are `TopicFlag.blue`, `.red` and `.yellow` in `HFRModels`. The Favoris tab itself is `forum1f.php?owntopic=1|3` (`ObjCFavoritesLoaderWorker.m:44-48`).

### 2. What HFR exposes

**`forum1.php?…&cat=&page=&subcat=&owntopic={0..3}`** (HFR-PROTOCOL R2)
- Values: 0 all, 1 participated (flag1), 2 read (flag0), 3 favourites.
- Logged out, HFR answers a 301 and drops the filter (`R09`). An empty filter answers a `.hop` (`R08-1` "Aucun sujet auquel vous avez participé n'est connu", `R08-3` "Aucun favori n'est repertorié").
- Non-empty `owntopic=2`: captured (`R08-2`). Rows of an unfiltered logged-in list carry their flag in `sujetCase5` (`R121e`).

**HFR already does what issue 3 asks.** Each category header of the favourites page links to `/forum1.php?…&cat=<id>…&owntopic=<the page's own owntopic>`, both as the `a.cHeader` href and as the row's `ondblclick`:
- `owntopic=1` on `R10` (Drapeaux & Favoris);
- `owntopic=3` on `P03c` and `P03g` (Favoris uniquement).

`FavoritesParser` already keeps this path in `FavoriteSection.forum.path`. Following that href exactly gives "same filter as the mode" with a captured source, and fixes the legacy always-`.favorites` behaviour. That is a deliberate change, so it needs a CHANGELOG-LEGACY row.

**REST flag buckets** (`R335a`-`R335e`, HFR-PROTOCOL "Flag buckets, logged in")
- `…/categories/<cat>/topics/{participated,read,favorites}/` returns the whole bucket in one answer: paging is not served.
- Items carry `is_read`, `flag_owntopic` and `last_position`.
- They are the only captured source of a per-topic **read/unread** bit across a whole category. No `owntopic` value filters unread.

**Pending capture** (each needs a capture before any code relies on it):
- a non-empty `forum1.php?cat=<c>&owntopic=1` and `owntopic=3` (only the empty answers are captured), including whether `owntopic=1` lists favourites too, as `forum1f.php?owntopic=1` does (`R73b`);
- page 2 of a filtered list (the pager under `owntopic`);
- `forum1.php?cat=<c>&subcat=<s>&owntopic=<n>` (a filtered sub-forum);
- the pages behind `forum1f.php?owntopic=0|2`: `R11` links them, but they are not captured;
- the REST `read` bucket of a single category (HFR-PROTOCOL marks it not captured);
- `/hfr/<cat>/liste_sujet_filtre-<n>-<m>.htm`;
- what the list query's `sondage=`, `trash=` and `moderation=` do. These look like further filters, but nothing is captured: do not offer them.

### 3. What SwiftHFR has today

**Engine:** ready.
- `TopicListFilter` (`HFRModels/Lists/TopicListFilter.swift`) is `all=0, flagged=1, read=2, favorites=3`, the same values as `owntopic`.
- `HFREndpoint.topicList(category:filter:page:)`, `PageFetcher.topicList(category:filter:page:)` and `ForumCatalogue.topicListPath(categoryID:filter:)` all take it.
- `HFRLinkRoute` parses `owntopic` from a `forum1.php` link.

**App:** no filter.
- `LiveForumDataSource.topicList(category:page:)` hard-codes `filter: .all` (`App/SwiftHFR/Navigation/ForumDataSource.swift:34-37`).
- `TopicSource` (`TopicSource.swift`) is `.forum(CategoryID, title:)`, `.subforum(path:title:)`, `.flagged` or `.favorites`. It has no filter.
- `TopicListView`'s pointer comment says "no Tous / Favoris / Suivis / Lus filter" (GAP-023, "not planned", now overridden by UXD-06 → #427).

**Favourites options (LOT-124):**
- `FavoritesOptionsModel`: `mode` (`vos_sujets`), `groupedByCategory`, `autoRefresh`, `showsCollapsedSections`, folded sections and super favourites.
- `FavoritesPresentation.groups`.
- The section header (`TopicListView.swift:194-212`) is a plain `Text` with a count and a fold chevron. **It cannot be tapped.**

**`NavigationModel`:**
- one per tab: `categories` and `favorites`;
- `selectedSource` resets the topic and the reader in its `didSet`, and also writes `favorites.mode`;
- `topicList(for:)` caches one `TopicListModel` per `TopicSource`.

**How a category opens:**
- `ForumListView` uses `List(selection: $navigation.selectedSource)` with `.tag(row.source)`.
- On the iPad sidebar, `CategoriesSidebarColumn` pushes `TopicListView` with `navigationDestination(item: $navigation.selectedSource)`.
- The Favoris tab is sidebar + detail. Its `NavigationModel` has no way to push a forum list without changing `selectedSource`, and changing it would drop the reader and change the favourites mode.

### 4. Proposal

**Extend #427; do not build a second filter.**
- #427 already ports the Tous / Favoris / Suivis / Lus picker (UXD-06, option A), and issue 4 is that picker.
- Issue 3 is the legacy header link, which needs the same `TopicSource` filter.
- Both edit the same files: `TopicSource`, `ForumDataSource`, `TopicListModel`, `TopicListView` and `NavigationModel`.
- Keep #593 open with `Refs`, only for the parts with no legacy counterpart and no `owntopic` value: an **unread-only** filter and filters that combine flags. These are (b) items. If the operator still wants them, they need the REST bucket path above (LOT-057) or a client-side filter of the loaded page, which hides rows of other pages. That is the operator's call.

**Scope of the extended #427 (beyond its current list)**
1. **Filter on `TopicSource.forum`.** Add a filter to the source, or keep it in `TopicListModel` and part of the cache key.
   - `ForumDataSource.topicList(category:filter:page:)`.
   - Picker Tous / Favoris / Suivis / Lus: the legacy labels; "Suivis" is `owntopic=1`, "participé".
   - Persisted under the legacy key with the raw-value translation above, forced to Tous when logged out.
   - The empty `.hop` (`R08-1`, `R08-3`) is "Aucun sujet", not an error.
2. **Category header tap in Favoris** pushes that category inside the Favoris column, with the filter taken from the header's own `owntopic`, not legacy's fixed `.favorites`.
   - It needs a push state on `NavigationModel` that is not `selectedSource`, so the reader and the mode survive.
   - A topic opened from the pushed list uses the Favoris `selectedTopic` and reader.
3. **Sub-forums (`.subforum(path:)`)**: no filter until the `subcat` + `owntopic` capture exists. Hide the picker there, or filter the whole category as legacy does; either way say so in the spec.
4. **Whether to persist an override:** decide whether a header tap writes the global filter (the legacy quirk). Recommendation: it does not; it is a CHANGELOG-LEGACY row.
5. **Tests** (Swift Testing, app):
   - the `owntopic` sent for each picker value;
   - translation of the legacy key;
   - logged out forces Tous;
   - header with `owntopic=1` → Suivis, with `owntopic=3` → Favoris (the `R10` and `P03c` paths);
   - an empty `.hop` is an empty list;
   - the reader survives a header push.
6. **Docs:** GAP-023 → ported, GAP-020/021 per #427, the LOT-082 spec, the `TopicListView` pointer comment, CHANGELOG-LEGACY.

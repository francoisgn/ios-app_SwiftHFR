### What the code says (dev-swift)

- The message comes from `App/SwiftHFR/Navigation/TopicFlagActions.swift:85-86`, case `TopicFlagError.sessionNotConfirmed(SessionHealth)`.
- It is thrown by `TopicFlagFlow.confirm` (`Packages/HFRKit/Sources/HFRClient/Flags/TopicFlagFlow.swift:164-174`). Every flag write first runs the LOT-044 session check (`SessionRefreshFlow.refresh`, `SessionRefreshFlow.swift:41`), and refuses unless the health is `.valid`. This is the #314 guard: a cookie-less `addflag`/`delflag` gets success bytes, so the answer of the write alone proves nothing.
- `SessionHealth` (`HFRClient/Session/SessionHealth.swift`) is `.valid`, `.expired(SessionExpiry)` or `.unconfirmed(UnconfirmedSession)`. The UI maps **both** non-valid cases to « Reconnectez-vous ». For `.unconfirmed`, that advice is wrong: HFR's answer proved neither state.
- So the refresh check returned non-valid on a session that reads fine. Which case, and why, is **not known**. Do not guess (AGENTS.md §3.1). Candidates to check, without assuming any:
  - the profile-page probe answer changed or was redirected;
  - the probe jar (LOT-044 compare-and-set);
  - a timeout or an idle limit. #1009 (10 s idle, merged 2026-11-17 ~20:30 UTC) is probably not in the build used, so check the build;
  - the session store of the account.

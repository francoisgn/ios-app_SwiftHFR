# Issue #310: Shared MPStorage namespace spec with the Android app: allowlist (and super-favourites)

- State: open
- Author: francoisgn · created 2026-10-28T14:07:31Z · updated 2026-11-09T14:59:16Z
- Labels: type: docs, priority: low, difficulty: medium, area: storage, status: blocked, origin: deliberate-gap
- Source: https://github.com/ezzz/HFRnow/issues/310

### Summary
As a member who uses HFR on iOS and on Android, I want my allowlist (and later my super-favourites) to follow my HFR account across apps, so that I set them once. Operator decision 2026-10-28 (ADR 0013 draft, Q3): for now the allowlist is stored in iCloud KVS; a shared MPStorage namespace is specified and ported with the Android app's maintainers.

Scope
- Draft a namespace contract for the shared MPStorage document: name, JSON schema, size budget, merge rules, versioning. Base it on the existing namespaces (blacklist, bookmarks, `superFavs` and `lastRead` from the userscripts, #272).
- Port: once the contract is agreed, SwiftHFR reads and writes the namespace and migrates the iCloud copy into it.
- Never write a new namespace into users' documents before the contract is agreed (ADR 0013).

Blocked by
- #272: capture of a non-empty MPStorage document.
- Contact with the Android app's maintainer. This is a message outside GitHub, so it needs the operator's go (AGENTS.md §0).

Acceptance criteria
- docs/HFR-PROTOCOL.md (MPStorage) documents the contract, with a link to the other app's agreement.
- A lot row is added to docs/LOTS.md for the port.

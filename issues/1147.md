### Summary
As a user on an iPad (or a foldable's inner screen, which uses the sidebar root), I want the account button in a category's topic list column, as in legacy, so that I switch or manage accounts from the list I am reading.

### Context
#1098 (#425) puts the account button after the back button of a category's topic list at compact width (`TopicsColumn(showsAccountMenu:)`). At regular width the sidebar root (`RootSidebarView`) is used, where the button sits on the sidebar; the topic list pushed in `CategoriesSidebarColumn` (`RootSidebarView.swift:171`) has none. Legacy has it in the iPad list column: `MainWindow.swift:1932-1938` → `:803-818` @ 87fe0d1c.

### Scope
- Decide with the operator whether the list column also carries the button when the sidebar already shows one (legacy: the sidebar has none, `MainWindow.swift:1880-1902` @ 87fe0d1c), then pass `showsAccountMenu` in `CategoriesSidebarColumn` and the Favoris column accordingly.
- Update the stale comment on `TopicsColumn.horizontalSizeClass` (`RootTabsView.swift`, says `TabSplitWidth` keeps `.regular` on a foldable's inner screen: since LOT-147 that scene uses the sidebar root).
- GAP-009 `SwiftHFR final` updated by a `gap-edit`.

### Acceptance criteria
- [ ] The list column of the sidebar root shows exactly one account button (hosted test counting the pushed bar's left items, as `AccountMenuPlacementTests`).
- [ ] Device check on an iPad and a foldable inner screen.

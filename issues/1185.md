**cloud/m4q-reliab-opus: not fixed. The issue's precondition ("cite a legacy `file:line` @ `87fe0d1c` or a capture before fixing") does not hold; read at `87fe0d1c`.**

Legacy never writes a malformed entry in these four lists, and for three of them legacy's own reader already drops the whole list:
- **Smiley search history**: `HFRswift/Swift/SmileySearchService.swift:78-83`, `SmileySearchHistoryEntry` is `Codable` with non-optional `text`, `count`, `lastDate`, written with `JSONEncoder`; legacy reads it back with `try? JSONDecoder().decode([SmileySearchHistoryEntry].self, …)` (`:92-96`), all or nothing, as our port does.
- **Upload history**: `ReplyService.swift:1855-1876`: `fullURL: String` and `timeStamp: Date` are non-optional, so `JSONEncoder` cannot write a null `fullURL`.
- **Active drafts**: same shape (Codable, non-optional), so the same argument applies.
- **Smiley favourites**: the only writer, `Classes/SmileyCache.m:400-404`, sets `sCode`, `sRawUrl` and `dateAdded = [NSDate now]` on every entry (callers: `SmileyAlertView.m:106`; `ReplySmileyCatalog.swift:94`, whose arguments are non-optional Swift `String`s). An entry with a nil field would not survive legacy either: `loadDicFavorties` builds `[NSArray arrayWithObjects:sf.sRawUrl, sf.sCode, nil]` (`SmileyCache.m:381`), which a nil `sRawUrl` truncates, so `dictionaryWithObjects:forKeys:` raises on the count mismatch.

So the current all-or-nothing import matches what legacy itself could read, and no captured legacy state reaches the failing path. Making the import skip a bad entry would be defensive code for a state nobody has shown to exist (AGENTS §3 "no guessing"; ESSENTIEL "never guess").

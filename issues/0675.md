### Summary
As a reader who clears favourites with "Lu", I want the topic marked read on the forum too, so that it does not come back unread after a refresh, a relaunch or on another device.

Milestone: M4 (operator, 2026-11-08). Found by the `2440d79..2fe43da3` sweep of #655.

### Legacy @ `2fe43da3` (`legacy/duo-inner-cover`, AGENTS.md §2)
- `96336bc9` "Sync read state for favorite topics": "Lu" removes the row at once and calls `markTopicRead`, which GETs the topic's last-page URL in the session (`HFRswift/Swift/Favorites.swift:33, 44-47, 102-115`; menu entries `1145`, `1192`). At `2440d79` "Lu" was local only (GAP-034).

### Current SwiftHFR
`TopicListModel.markRead` only records `markedRead` locally (`App/SwiftHFR/Navigation/TopicListModel+RowActions.swift:28-32`); LOT-125 (#216) and GAP-034 say "Lu local only".

### Scope
- "Lu" fetches the topic's last page with the account's session (the URL legacy builds), keeping the row's "Annuler" (GAP-034 b).
- No HFR behaviour beyond the legacy code is assumed: that a last-page GET moves the flag is legacy's assumption; confirm it with a capture (before/after list) before relying on it in tests, or mark it *pending capture*.
- Update LOT-125's spec and GAP-034 through the steward (#620).

### Acceptance criteria
- After "Lu" and a list refresh, the topic is no longer unread on the forum (capture or Mac check).
- A failed fetch keeps the local state and says nothing alarming; no write is sent (a GET only).
- Tests use the loopback session (`hosts: .exactHost`).

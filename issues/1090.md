### Summary
The fixture anonymizer redacts a public forum host inside the stylesheet URL as if it were an e-mail, so the URL the meta records no longer matches the one requested. Found by the independent leak check of the #929 / #728 captures (mac/M1, 2026-11-18).

### Facts
- Every page links `/include/the_style1.php?color_key=<fields>&…`. Its 28th field is the image base, `https%3A%40%40forum-images.hardware.fr`, i.e. `https:@@forum-images.hardware.fr`, a public host of the forum's image CDN.
- The `%40` / `@` pair matches the anonymizer's e-mail rule. The committed `R728a.meta.json` (and the `<link>` of every page in the corpus) carries `https%3A%redacted@example.invalid/NULL/` instead, so `url_template`, `url` and `final_url` cannot be replayed.
- Not a leak: the host is public and appears in clear in the CSS and in `R728b`'s URL.

### Scope
- `tooling/fixtures/anonymize.py`: do not treat `https%3A%40%40forum-images.hardware.fr` (or, more narrowly, an `%40%40<forum host>` field inside `color_key`) as an e-mail. Add a test; then re-publish `R728a` (the raw is kept by mac/M1 until this lands) and check the corpus.
- Policy (FIXTURES.md): fix the anonymizer, never the fixture by hand.

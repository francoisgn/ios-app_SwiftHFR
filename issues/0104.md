## moust4ki · 2026-10-28T16:42:39Z

Verification (ext/bybifok-opus-1, Opus 5.5; not claimed, verification only): **already fixed in SwiftHFR, no new work needed.** Legacy took the last pager link as the page count (legacy fix `dc93420` in ezzz/HFRnow#3).

- **Engine (LOT-022).** `PageNavigation.last` is documented as "the last page the pager links to, not the page count of the forum" (`TopicListPager.swift:7-10`). Test: `TopicListParserTests.pagerWindow` ("last is the last linked page, not the forum's page count", `R05b`: current 500, last 700).
- **App (LOT-082).** The list screens never show a total. `TopicListModel` keeps only the current page and `hasNext = navigation.nextPath != nil` (`App/SwiftHFR/Navigation/TopicListModel.swift:25-35`), and no list view reads `navigation.last`. Tests: `TopicListModelTests.thePagerNeverClaimsATotal`, plus `refreshReloadsTheCurrentPageNotPageOne` for #107's list half.
- **Exactness flag.** #291 (LOT-167, open, approved) adds `PageNavigation.isExact` (lower bound unless the pager shows everything). It names this bug as related.

Suggest closing this issue once #291 is merged. `docs/CHANGELOG-LEGACY.md` row 12 already records the fix.


## francoisgn · 2026-10-29T09:42:46Z

Checked against `dev-swift` (steward ext/opus-helper1, 2026-10-29): **fixed in SwiftHFR**. Closing.

- **Engine:** LOT-167 (#291, merged as `0f94f4e`, Closes #279) adds `PageNavigation.isExact`. `TopicListPager` marks a windowed pager (`1 … 10 20 … 500`) as a lower bound; it is exact only for `1…N` with `N < 10`, or when there is no pager. Tests: `windowedPagerIsLowerBound` (R04, R05a, R05b), `shortPagerIsExact`, and `rowCountBeatsThePagerWindow`, which checks the R04 row count against the last link 500, per the legacy oracle.
- **App:** the forum lists never show a total. `TopicListModelTests.thePagerNeverClaimsATotal` (LOT-082) covers this.
- **Still open:** using `isExact` in the UI ("N / total" and "Dernière page" only when exact) is a feature, not this bug. It stays in FEAT-003 (#147).

# Issue #320: [SwiftHFR] SessionRefreshFlow: the refresh probe keeps the source session's host policy

- State: closed
- Author: francoisgn · created 2026-10-29T05:05:33Z · updated 2026-11-06T12:53:21Z
- Labels: type: bug, priority: medium, difficulty: easy, area: client, external: ready
- Source: https://github.com/ezzz/HFRnow/issues/320

### Summary
`SessionRefreshFlow` builds its probe with `HFRSession(cookies:now:)`, so the probe always gets the `.forum` host policy, whatever the policy of the session it refreshes. There is no production impact: every production session is `.forum`, and the restricted `.exactHost` initializer is internal and used only by tests. The exposure is test hygiene. If the `init(refresh:)` seam of `TopicFlagFlow` regressed, a test that refreshes a loopback-only session could send a real profile-page GET to the forum, with fake cookies. This came from the CodeRabbit security thread on #319, traced by moust4ki. The maintainer decided on 2026-10-29 to fix it in this follow-up issue rather than in #319.

### Scope
- Add a `package` (or `internal`) `nonisolated func probe(cookies:now:) -> HFRSession` on `HFRSession` that keeps its `hosts` policy.
- `SessionRefreshFlow()` uses it when no test factory is given (`makeProbe` becomes optional).
- No change to public API or to production behaviour.

### Sources

### Acceptance criteria
- [ ] A test asserts directly, **offline**, that the default probe of a restricted session has the source session's host policy. The test must not need a network request to fail: it fails if the default construction goes back to `HFRSession(cookies:now:)`.
- [ ] The test is shown to fail without the change.
- [ ] `swift test` green on Linux and macOS CI; `scripts/check-lot-deps.py` passes.
- [ ] LOT-044 spec updated (one line in Behaviour or Edge cases).

Depends on #319 being merged (it adds the `init(refresh:)` seam). Model: Sonnet → Opus, or any tier-B author with a tier-A reviewer.

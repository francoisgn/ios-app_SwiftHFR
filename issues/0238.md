### Operator requirements (2026-11-03), from Bybifok's legacy UI feedback

Feedback: "we read topics of several hundred pages with no simple way to move through the pagination, and no infinite scroll between the pages of a topic, « car passer à la page suivante ça fait le charme de HFR »".

**Requirements:**
- Continuous scrolling is an **option** that each user turns on or off. It is never forced on everyone (FEAT-017 already says it is off by default).
- While scrolling, the **page boundaries stay visible**.
- **Milestone M5** (an evolution, not legacy parity). It is tied to LOT-110 #201 (page navigator, M5 per UXD-10), which covers the easy way to move through the pagination.

**Open questions, kept for M5 (deliberately not answered now):**
1. How many following pages are preloaded below the current one? The idea on the table is to keep loading the 2 pages after the current one.
2. How many pages are kept in memory above the current one?
3. How loading works when a quote links to a reply on a page far back in the topic: jump, hole in the list, then going back.
4. How this works with flag semantics: a GET with the session moves the flag, so prefetch without the session and reload with it (HFR-PROTOCOL §7 E25, FEAT-017).

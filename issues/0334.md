### Capture result (mac/capture-batch, run 9, PR #400)
Corpus ids: `R95g`, `W63`, `W62` (MP thread `fixture-test-2`); the site script `forum2.js` was read for `quoter()` (not committed).
- **Selection cookie, as the site writes it**: `EcrireCookie(name, quotes, date + 1 h, '/')`: name `quotes<site>-<cat>-<post>`, value `escape()`d (`%7C<n>%7C<m>`), path `/`, **no domain** (host-only `forum.hardware.fr`). HFR prefills from the escaped form (`R95g`) as from the raw `|` form (`R47c`).
- **After a reply** HFR always answers `Set-Cookie: quoteshardwarefr-prive-<post>=deleted; expires=Thu, 01-Jan-1970 00:00:01 GMT; path=/`, **without `Domain`** (`W63` with the cookie sent, `W62` without). It clears the site's host-only cookie; it does **not** touch a cookie stored for `.hardware.fr`, which is what legacy and LOT-049 store.

Consequence for LOT-049 (#75, PR #348): HFR's header is an expired deletion, so it never creates a live host-only cookie and the "posted messages quoted again" risk in the spec does not happen; HFR does not clear the `.hardware.fr` selection either, so the client's own unselect after the post is required (as #348 does), and a message selected while the reply is in flight is not lost by HFR's doing. Facts in HFR-PROTOCOL §4 and §7.

# Issue #910: [SwiftHFR] Composer: a smiley from the picker is inserted at the end of the message, not at the cursor

### Summary

As a member writing a reply, I want a smiley picked in the smiley picker to be inserted where my cursor is, so that I can put it in the middle of my text. Operator feedback (device, 2026-11-15): whatever the cursor position, the smiley is added at the **end** of the message, which is wrong.

### Expected
- The smiley code is inserted at the caret. If text is selected, it replaces the selection.
- The caret is placed right after the inserted smiley, and focus comes back to the editor.
- The same caret rule holds for every insertion from a sheet that takes focus (smiley, GIF, image): insert at the caret, or replace a selection.
- **Formatting tags are different: they never replace a selection, they wrap it.** `[b]` + selection + `[/b]`. With no selection they are inserted at the caret, and the caret lands between the opening and the closing tag. A fix here must not turn wrapping into replacing.

### Where to look (read from `dev-swift`; the cause is not established)
- `App/SwiftHFR/Composer/ReplyComposerView.swift`:
  - `openSmileys()` (~:179) captures the caret in `rangeForSmiley = selectedRange` before presenting the sheet;
  - `insertSmiley(_:)` (:188) calls `model.insert(smiley:replacing: rangeForSmiley)`.
- Likely suspects:
  - the editor lost focus before `selectedRange` was read, so the captured range is nil or at the end;
  - the `TextEditor(selection:)` binding was not up to date;
  - `model.insert(smiley:replacing:)` falls back to the end when the range is nil.
- `ReplyTextInsertionEngine.insert(_:into:selectedUTF16Range:)` (:206) inserts at a range: check that the smiley path really reaches it with the captured range.
- Check both composers: the default one and the experimental « Composer moderne » (#903/#904), as #909 does for the picker's first tap.

### Acceptance criteria
- [ ] With the caret in the middle of a line, a picked smiley lands at the caret; with a selection, it replaces it; the caret ends right after it.
- [ ] A formatting tag applied to a selection still wraps it (text kept), at its real position, not at the end.
- [ ] Same for a smiley picked after scrolling the editor, and with the keyboard hidden before opening the picker.
- [ ] A test pins the rule. A model or engine test is red today if the captured range is lost, and a hosted test goes through the real open → pick path if feasible.

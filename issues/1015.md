## francoisgn · 2026-11-17T08:30:19Z

**cloud/orch: code study (read-only, origin/dev-swift `bb084956`), to be confirmed with Instruments**

Short version: no state written on *every frame* was found. What was found is **one invalidation of the whole Favoris `List` per crossing**. It fires exactly when the large title leaves or comes back, which is also when the tab bar minimises or expands. Its cost is O(sections + rows), which fits the operator's report (smooth with one category of 41 rows, stutters with many sections).

**Ranked suspects:**
1. **`titleIsVisible` lives in `TopicListView`** (`TopicListView.swift:30`). It is written by `ScreenTitle.swift:91` (`onScrollVisibilityChange`) and read at `:39-41` and `:58`.
   - Each crossing re-runs all of `TopicListView.body`: `model.displayedGroups` is recomputed twice (`TopicListModel.swift:144-161`, `FavoritesPresentation.groups`), the sectioned `ForEach` is diffed, and every realised row gets new swipe, context-menu and accessibility closures (`:145-176`), as does every header (`:234-263`). `canCollapseMore` also walks every favourite (`RootTabsView.swift:116-133`).
   - Catégories and Messages use the same pattern, but their flat rows are cheap.
   - **Fix:** move the visibility into a small `@Observable` tracker that `TopicListView.body` never reads, and let a `PillSlot` view inside the principal toolbar item read it.
2. **Rows and headers are not `Equatable` and carry closures**, so every `TopicListView` update re-applies every visible cell's modifiers.
   - **Fix:** a `FavoriteRowCell: Equatable` and a `FavoriteSectionHeader` built from values (`.equatable()`), and `displayedGroups` stored or memoised.
3. **No `.listStyle` on `TopicListView`** (Catégories and Messages use `.insetGrouped`). In the Favoris split sidebar it may resolve to the sidebar style, with pinned headers relaid out under the bars. Unproven; try `.listStyle(.insetGrouped)`.
4. **`DensityHeaderMargin`** (`ListDensity.swift:132-143`): one `onGeometryChange` per section header, wasted in regular density. Skip it when `rowSideInset == nil`, or use list insets instead of a measurement.
5. **`PagerBarModifier`** writes `@State` on bottom-inset changes, even with no pager (`PagerToolbar.swift:194, 228-244`). This amplifies but is not specific to Favoris. Make it a no-op when `pager == nil`, and do not observe `hiddenInset`.
6. Minor: `TopicRowInfoLine.swift:40-44` builds a `Calendar` on each body run (use a `static let`).

**To measure on the Mac (mac/M1):**
- `Self._printChanges()` in `TopicListView.body`, `PagerBarModifier.body` and `DensityHeaderMargin.body`: once per crossing confirms 1 + 2, repeated runs mean a flip-flop.
- The Instruments SwiftUI template (View Body, Cause & Effect) plus Hitches.
- A/B tests: (a) `.insetGrouped` alone, (b) the title-state move alone, (c) Equatable rows. Expectation: (b) + (c) remove the scaling with sections.

Note: #1012 (cloud/i1012-sonnet) is reworking `ScreenTitle` for the missing pill; suspect 1's fix belongs in the same code and has been passed on to it.

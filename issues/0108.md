## moust4ki · 2026-10-28T17:41:57Z

Verification (ext/bybifok-opus-1, Opus 5.5; not claimed, verification only): **already fixed in SwiftHFR; the `status: blocked` label is stale**, since LOT-083 is merged (#257, `ad071f0`). Legacy could let a cancelled topic request complete the next load and leave the topic on "Chargement…" (legacy fix `be196f8` in ezzz/HFRnow#3).

- **One task per load; a superseded or cancelled load never delivers.**
  - `TopicReaderModel.load` cancels the task in flight and bumps a generation, and `finish` drops any result whose generation is not the current one (`App/SwiftHFR/Reader/TopicReaderModel.swift:169-193`, comment "issue #108").
  - Lists do the same through `ContentLoader` (`App/SwiftHFR/Navigation/ContentLoader.swift:18-41`).
- **Shown at DOMContentLoaded, current document only.** The web view reports readiness with the document's token, and `documentDidBecomeReady(token:)` ignores an older document (`TopicReaderModel.swift:147-151`).
- **Tests with a fake page source** (`FakeTopicPages`, `ReaderGate`):
  - `TopicReaderModelTests.aSupersededLoadNeverDelivers`: page 2 held, page 3 asked, page 3 shown, token 2;
  - `.aCancelledLoadNeverDelivers`;
  - `.onlyTheCurrentDocumentCanBecomeReady`;
  - for lists: `ContentLoaderTests.aSupersededLoadCannotOverwriteTheNewerOne`, `.aCancelledLoadIsNotAnError`, `.cancelStopsTheLoadAndDropsItsResult`.

Suggest closing this issue on this evidence.

### Summary

As a reader who just replied, I want the confirmation "Votre réponse a été postée avec succès" to go away by itself after 3–5 seconds, so that it does not stay on screen. The close cross stays, so it can still be dismissed sooner. (Operator feedback, 2026-11-12.)

### Observed

After a reply is posted, the success message stays on screen until it is closed by hand with its cross.

### Expected

- The message disappears by itself after **3 to 5 s at most**. The exact value is to choose within that range; 4 s is suggested.
- The cross still closes it immediately.
- The auto-dismiss applies only to **success** confirmations. An error or an "unconfirmed" message (for example "Le forum n'a pas confirmé l'envoi…", `ComposerMessages.swift:193`) stays until it is closed, because the user must read it.
- VoiceOver: the message is announced once, and auto-dismiss never cuts the announcement short. If an accessibility setting needs the message to stay longer, follow the system's guidance.

### Scope

- Find where the reply-posted confirmation is shown in the app (composer and reader). It is not localised by that text in the code, so the success sentence may come from HFR's own answer.
- Apply the same timing to every success confirmation shown the same way, through one shared component rather than one timer per screen, in line with #836.
- Legacy behaviour at `87fe0d1c`: to check, and to cite in the PR if legacy auto-dismissed it.

### Acceptance criteria

- [ ] A success confirmation disappears by itself within 3–5 s; the cross still works.
- [ ] Error and "unconfirmed" messages do not auto-dismiss.
- [ ] A model test pins the timing with an injected clock, and fails without the change.

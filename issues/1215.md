# Issue #1215: [SwiftHFR] Theme engine: remove the dead `readerAlternate` contrast pair (the reader no longer alternates)

- State: open
- Author: francoisgn · created 2026-11-18T23:34:21Z · updated 2026-11-18T23:34:21Z
- Labels: type: chore, priority: low, difficulty: easy, area: models, status: needs-triage, origin: parity

### Summary

As a maintainer, I want the theme engine to stop validating a surface the reader no longer draws, so that theme authors are not refused for a contrast that has no effect on screen. (Follow-up of #1210, which removed the alternating message tint #568.)

### Scope

- `Packages/HFRKit/Sources/HFRModels/Theme/ThemeTokens.swift:151-211`: the `readerAlternate` derived colour (`surface` mixed with `textPrimary` at 7 % light, 16 % dark) and its four contrast rules (`textPrimary`, `textSecondary`, `link`, `accentText` on `readerAlternate`, lines 171-172).
- `Packages/HFRKit/Tests/HFRModelsTests/Theme/ThemeDefinitionTests.swift:55, 134-147` pin it.
- Docs that list it: `docs/THEMES.md` (the contrast paragraph), `docs/lots/LOT-188-theme-engine.md:37`.

Removing the rules loosens theme validation (a theme could then ship colours that only failed on that tint), so check the gallery themes against the remaining pairs first. An `HFRModels` change: merged by the core orchestrator or the maintainer.

### Acceptance criteria

- No `readerAlternate` left in code, tests or docs; the gallery themes still pass every remaining rule.

- #1210 (the removal of the tint), #568.

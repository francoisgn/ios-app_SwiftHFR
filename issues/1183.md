### Summary
As the maintainer, I want the on-disk format of drafts pinned by a golden file and decoded entry by entry, so that a later tidy-up of `DraftContext` cannot silently make every user's drafts and archived replies disappear on upgrade (ESSENTIEL persistence rule).

### Scenario
A later PR renames a label of `DraftContext`, drops the unused `page`, or changes `archivedReply`'s payload. Every test stays green (they round-trip through the same type). On the first launch after the update each user's `drafts.json` fails to decode, is moved to `.corrupt`, and all drafts and archived replies are gone without a message.

### Evidence (`7a61018f`)
- `Packages/HFRKit/Sources/HFRStorage/Drafts/DraftContext.swift:6-8`: `public enum DraftContext: Sendable, Hashable, Codable` with `case reply(topic: TopicID, page: Int)`: synthesized coding, so case and label names are the on-disk keys.
- `Packages/HFRKit/Sources/HFRStorage/Drafts/DraftStore.swift:170-171`: `} catch is DecodingError { state = quarantine(reason: "undecodable data")`: the whole file, for one entry.
- `App/SwiftHFR/Composer/ReplyPosting.swift:22`: `.reply(topic: topic, page: 1)` is the only app construction, so `page` is a dead dimension of the key.
- `Packages/HFRKit/Tests/HFRStorageTests/Drafts/DraftStoreFileTests.swift:15-29`: round trip and junk only; no literal JSON of a real draft. Other stores do pin theirs (`SmallStores/FileSmallStorePersistenceTests.swift:27`, `ReadingPositions/FileReadingPositionPersistenceTests.swift:52`).

### Fix
A golden-file test per `DraftContext` case; explicit tolerant decoding for `DraftContext` and `Draft`; decode drafts item by item so one unknown context drops one draft, not the file. Decide `page` explicitly (keep with a comment, or migrate on read).

### Test
`DraftStoreFileTests/readsTheVersion1FileOfEveryContext`: a literal v1 JSON with one draft per context reads back into the expected contexts and texts. It passes today by design: its value is to fail on any later format change. `DraftStoreFileTests/anUnknownContextDropsOneDraftNotTheFile` fails today (the file is quarantined).

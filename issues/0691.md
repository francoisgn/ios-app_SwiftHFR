### Summary
As a reader, I want a setting choosing between embedded videos (placeholder, player on tap) and plain links, so that I pick how video links show in topics; embedded is the default.

Milestone: M4 (operator, 2026-11-09, #655).

### Context
- Legacy at `2440d79` had an "Afficher les vidéos" setting (`embedded_videos`, `Root.inApp.plist`) and auto-loaded one player iframe per link.
- Legacy at `2fe43da3` (parity reference, AGENTS.md §2) removed embeds and the setting (`d645f525`): a video link is a plain link.
- SwiftHFR today: placeholder `button.video`, player on tap, no request to the provider before the tap (LOT-083, LOT-108, LOT-071 D-071-2).

### Operator decision (2026-11-09)
- A setting "Vidéos": **Intégrée** (default, current SwiftHFR placeholder + player on tap) or **Lien** (legacy `2fe43da3` behaviour, plain link).
- This is a deliberate difference from the reference (its default), recorded as such.

### Scope
- Setting in Réglages next to the reader settings; stored like the other reader settings (LOT-119 / LOT-106 conventions).
- "Lien" renders the video link as a normal link (same routing as other external links, "Navigateur par défaut" honoured).
- "Intégrée" keeps today's placeholder and player; still no provider request before the tap.
- Changing the setting applies to the next page render.

### Ledger (with the PR)
- GAP-058: legacy columns at `2fe43da3`, SwiftHFR final = setting, default embedded; `Gap`/`H.1` per the steward (deliberate difference, operator).
- CHANGELOG-LEGACY row (French): "Réglage Vidéos : intégrée (par défaut, lecture au tap) ou lien".

### Acceptance criteria
- Both modes covered by tests on the topic HTML builder (placeholder vs plain link) and the setting's default.
- No network request to a video provider in either mode before a tap (test with a loopback-only session).

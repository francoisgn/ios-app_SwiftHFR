# Issue #1006: [SwiftHFR] MP notifications: a read from a stale MP list rewrites the notification ledger (LOT-140 follow-up)

### Summary
After LOT-140 (#230, PR #994), reading or marking unread an MP from a stale MP list can replace the whole notification ledger set with the stale one. A thread can then be notified twice, or one reply can go unnotified until the next check.

### Found by
Fable 5.2 delta review of #994, head 2f461044, finding 1 (Low; present since round 1).

### Failing scenarios
- `App/SwiftHFR/Messages/MessageListModel+Notifications.swift:21`, `MessageListModel.swift:354-358`: nothing reloads the MP list when the app returns to the foreground.
  - **(a)** The app is suspended on Messages showing Z unread. A background check notifies X. The member reopens the app from its icon and reads Z. The stale set minus Z is recorded, so X leaves the ledger and is notified again.
  - **(b)** X shows as read on the stale list. The member opens X and reads its reply. `wasUnread` is false, so nothing is recorded, and a reply posted before the next check is not notified.

### Fix (to choose in the PR)
- A one-step ledger operation that removes or inserts one thread on a read or a mark unread; replace the whole set only after a list load.
- Or reload the MP list when the app returns to the foreground.

### Acceptance criteria
- [ ] A test for each scenario, failing without the fix.
- [ ] The background check and the app keep the same ledger key (`AccountKey.make`).

### Related
#230, #994, #571.

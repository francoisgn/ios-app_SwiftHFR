### Summary
The legacy parity reference moved to `legacy/duo-inner-cover` @ `2fe43da3` (operator, 2026-11-08, #655), but `tooling/legacy-oracle/run-oracle.sh` and its `hfrnow.patch` are pinned at `2440d79`: new oracles still come from the old parsers. Move the exporter to `2fe43da3` while keeping the committed `2440d79` oracles reproducible.

### Why it matters
Legacy parser code changed in `2440d79..2fe43da3`: `ParseMessagesOperation.m` (embedded video block removed, `d645f525`), `LinkItem.m`, `ObjCTopicPageWorker.m` (`ae196aa0`, `c7693a88`), `ObjCFavoritesLoaderWorker.m` (`e10bdc89`, favourite categories in forum order), `ObjCForumSearchWorker.m`. An oracle at `2440d79` may disagree with the app users run.

### Scope
- Rebase the oracle patch on `2fe43da3` (a new patch level, the script accepts both revisions).
- Re-run the oracle on the corpus and list the fixtures whose oracle changes (each change is a legacy behaviour change to map to its lot).
- Update `tooling/legacy-oracle/README.md` and AGENTS.md §2 (which says the oracle stays at `2440d79` until this issue).

### Acceptance criteria
- `run-oracle.sh` runs at `2fe43da3`; `2440d79` still reproduces the committed oracles.
- The diff of regenerated oracles is posted on this issue, each change mapped to a lot or a new issue.

# Issue #447: [SwiftHFR] App: use the iCloud-synced settings store (LOT-172 wiring)

### Summary

As a member using SwiftHFR on an iPhone and an iPad, I want the app to actually use the iCloud-synced settings store, so that the preferences LOT-172 syncs follow my Apple ID.

### Scope

LOT-172 part 1 (#446) adds `SyncedSettingsStore` (HFRStorage) and `UbiquitousKeyValueStore`; nothing in `App/` uses them yet (the app builds `UserDefaultsSettingsStore()` directly).

- Build one `SyncedSettingsStore(local: UserDefaultsSettingsStore(), cloud: UbiquitousKeyValueStore(), deviceState: FileSmallStorePersistence(fileURL: <Application Support, backed up, device-only>))` and inject it wherever a `SettingsStore` is built today.
- Start `run()` once for the process; call `synchronize()` at launch and on foreground (ADR 0013 §4).
- Surface `quotaViolations` and `deviceStateFailure` in the logs.
- Order with the legacy import (LOT-067 / LOT-158, ADR 0013 §5): device import first, then the store.
- Part 2 of LOT-172 (lists, reading positions) is wired the same way once merged.

### Depends on

- LOT-172 (#311, part 1 #446)
- LOT-160 (#250): the iCloud key-value storage entitlement (ADR 0013 §9: a developer-portal action by the maintainer)

### Acceptance criteria

- [ ] Every `SettingsStore` the app builds is the synced one; no second `UserDefaultsSettingsStore` writes synced keys behind its back.
- [ ] Two simulators (or an iPhone and an iPad) on one Apple ID see a synced setting change; a device-scoped one does not travel.
- [ ] App tests with `InMemorySyncedKeyValueStore`; `App build + tests` green.


## ezzz · 2026-11-02T19:45:35Z

Order at launch (from the #446 review): build `SyncedSettingsStore` **after** the LOT-067 legacy import; its first launch runs the initial-sync rule (device values first, then the cloud, ADR 0013 §5 step 2). If the import must run later, call `apply(SyncedStoreChange(reason: .initialSync))` right after it.

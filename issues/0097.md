# Issue #97: LOT-073: MPStorage JSON tokenizer preserving number lexemes

- State: open
- Author: francoisgn · created 2026-10-27T18:48:48Z · updated 2026-11-01T12:31:48Z
- Labels: priority: low, difficulty: medium, area: models, status: ready, type: lot, external: ready
- Source: https://github.com/ezzz/HFRnow/issues/97

### Summary

As a maintainer, I want the MPStorage JSON codec to keep number lexemes with a real tokenizer instead of the private-use marker workaround, so that other clients' numbers round-trip without a hack.

### Scope

Replace the workaround of LOT-062 (`Packages/HFRKit/Sources/HFRModels/MPStorage/JSONNumberBox.swift`: every number token boxed as a string `"<U+E000 U+E001><lexeme>"` before `JSONDecoder`, unboxed after `JSONEncoder`) by a tokenizer that preserves number lexemes natively, with the same observable behaviour. The "numbers keep their exact text" rule and its cases (`9007199254740993`, `1e17`, `-0.0`, `1.50`) are in the LOT-062 spec.

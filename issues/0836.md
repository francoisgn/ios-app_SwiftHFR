### Summary

As the maintainer, I want an end-of-M4 code review by **Fable 5.2** aimed at **duplicates only**: every behaviour coded more than once becomes one shared implementation, reused everywhere. Example: the topic list is displayed by several separate implementations; it should be one component. The goals are a lighter code base where that is relevant, and the guarantee that a requested change reaches its whole expected scope instead of one copy of it. (Operator, 2026-11-11; scope narrowed to duplicates on 2026-11-12.)

### Scope: duplicates only

App (`App/SwiftHFR`) and engine (`Packages/HFRKit`):
1. **Find the duplicates**: the same user-visible behaviour coded more than once (lists and rows, swipes, loaders and empty, error and refresh states, headers, pseudo and avatar, settings rows, navigation into a topic, menus, alerts). Find them by reading the code, not by name similarity. For each copy, give `file:line` and a short diff of how the copies differ. A difference may be a bug in one copy: that becomes a bug issue first.
2. **One canonical implementation per family**: the best existing copy or a new shared component, with every call site that must move to it and the lines saved.
3. **Scope check**: for each family, list the open issues that touch that behaviour, and say whether each would reach every copy today.
4. **Out of scope**:
   - everything that is not a duplicate (other quality findings belong to #775);
   - abstractions with a single user;
   - pure style;
   - behaviour changes without an issue.
   A refactor keeps behaviour identical, proven by the existing tests plus one test per family that pins the shared component.

### Rule: one family, one claim, one pass

The grouped-claim rule (operator, 2026-11-12) applies to every family:
- **The refactor issue of a family and every open issue that touches the same behaviour form one group.**
- Whoever claims one claims all of them, with the same `/claim <id>` on each.
- The group ships in **one PR** that does the refactor and the pending fixes on the shared component together, with one `Closes #N` per issue.
- A member that cannot be done in that pass says why and stays `Refs`. One copy is never fixed while the others are left.

Groups already known (cross-linked on each issue):
- **L, list and table rows:** #817, #825, and later #842 (themes recolour native rows, blocked by this issue so it lands once in the shared row).
- **R, reader chrome and menus:** #594, #820, #821, #641.
- **Logged-out prompts:** #824 (Favoris and topic list).

### Output, in one round

1. One comment here: the families ranked by value. One row per family: copies, canonical choice, call sites, lines saved, and the group of issues it absorbs. Each family is marked "do now" or "not worth it".
2. One refactor issue per "do now" family, linked to its group:

### Summary

As a user who turns on the experimental Recherche tab, I want it to be the system search tab (separated, at the trailing end of the tab bar), so that it behaves as search does in other iOS 27 apps.

### Rule

- "A tab bar can include a dedicated search tab at the trailing end." — [HIG › Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars) (iOS; page updated 2026-06-08), and [HIG › Search fields](https://developer.apple.com/design/human-interface-guidelines/search-fields) (search as a tab; updated 2026-06-08).
- API: [`TabRole.search`](https://developer.apple.com/documentation/swiftui/tabrole/search): "Searchable tab views will prefer to have the first tab with this role implement search."

### What the app does (dev-swift @ `7a61018f`)

`App/SwiftHFR/Root/RootTabsView.swift:34-39`: `// EXPERIMENTAL(searchTab, #896): the fifth item, left of Plus.` then `Tab(RootTab.search.title, systemImage: RootTab.search.symbol, value: RootTab.search) { SearchRootTab(…) }`, with no `role: .search`, ahead of the Plus tab (`:40`).

### Legacy at `87fe0d1c`

No counterpart: four tabs (`RootTabIdentifier`, `HFRswift/Swift/Common.swift:25-30`); `git grep -n "role: .search\|TabRole" 87fe0d1c -- HFRswift` is empty.

- Mac check: with the option on, the search tab renders as the separated trailing item and Plus keeps its place.

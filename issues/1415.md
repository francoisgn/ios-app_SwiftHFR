# Issue #1415: [SwiftHFR] Avatars downloaded twice on a page read; forum images not shared between readers

- State: open
- Author: francoisgn · created 2026-11-27T22:17:25Z · updated 2026-11-27T22:17:25Z
- Labels: type: bug, priority: low, difficulty: medium, area: app, status: needs-triage, origin: audit, m4-review: performance
- Source: https://github.com/ezzz/HFRnow/issues/1415

### Summary
As a user, I want each avatar and forum image downloaded once per page read and shared between readers, so that a first read of a 40-author page does not cost up to 80 image GETs. Remainder of #1397 (findings 3 and 5 of audit #1388), left by PR #1405 (`Refs #1397`).

### Scope
1. **Avatars twice (finding 3).** `AvatarFillingTopicPageSource` fetches each author's avatar for the cache (`AvatarStore.swift`, `offer`), while the reader's web view fetches the same URLs through `hfrreader:` (`ReaderWebController.swift`). The scheme handler should feed the avatar store, or serve from it, instead of a second download. The Mac runtime pass confirmed it (11 of 40 requests on a page open, #1397 comment 7223567819).
2. **Cache across readers (finding 5).** #1405 removes the per-reader `URLSession` and merges identical GETs in flight (`CoalescingTransport`), but nothing is kept once an exchange ends: each reader, and each reader a link pushes, still downloads the page's avatars and smileys again. Proposed: a bounded memory cache for forum-host images (policy C unchanged, cookie-less client kept), and check whether WebKit's memory cache already holds for the custom scheme before adding one.

### Acceptance criteria
- A page read fetches each avatar URL once (counting loopback transport, `hosts: .exactHost`; never forum.hardware.fr).
- A second reader on the same thread fetches no avatar or smiley the first one loaded.
- The image policy and the cookie-less image client (LOT-083) are unchanged.

Refs #1397, #1388, #1405.

# Issue #501: [SwiftHFR] Quote selection: match a selection that spans formatting tags in QuoteSelectionFormatter

### Summary

As a member quoting part of a message, I want a selection that crosses a formatting tag (`Hello world` over `Hello [b]world[/b]`) to be found, so that the quote is narrowed or bolded as for any other selection instead of left whole.

**Optional improvement, not a parity gap.** The maintainer (francoisgn) considers the current behaviour **at parity with legacy**: legacy searched the contiguous BBCode source too, and when the selection is not found the prefill stays unchanged (or, for one block without bold, is narrowed to the selection text). Nothing wrong is posted: the user gets the whole quote and can trim it. Milestone **M5** (UX evolutions, [ROADMAP](https://github.com/ezzz/HFRnow/blob/dev-swift/docs/ROADMAP.md)): no GitHub milestone named M5 exists on this repository, so it is recorded here.

### Scope

`Packages/HFRKit/Sources/HFRClient/Quote/QuoteSelectionFormatter.swift` (LOT-049, merged in #485 as 2cfa0a3):

- Match the trimmed selection against the block's **visible** text (BBCode tags removed), case-insensitive, and map the match back to source offsets.
- Several blocks: choose the block whose visible text holds the selection, even across a tag.
- Bolding a match that crosses a tag boundary must not write crossed tags (`[b]Hello [b]world[/b][/b]`-style or `[b]Hello [i]wor[/b]ld[/i]`): decide and document one rule (e.g. wrap the smallest balanced range, or bold each tag-free segment).
- Open points to settle in the design, from the rendered message vs BBCode gap: smileys (`[:…]`, `:o`), links (`[url=…]label[/url]`), `[img]`, nested quotes, whitespace and line breaks the renderer collapses.
- Out of scope: the composer UI (LOT-086), the multi-quote cookie (LOT-042).

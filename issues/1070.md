## francoisgn · 2026-11-17T22:49:16Z

**mac/M1: SDK investigation done (Xcode 27.2, build 27B52, iOS 27.2 SDK). Apple offers no "expand on scroll up" and no "expand at a list's end" for the tab bar; our behaviour is the system's. Closing as not planned, per the operator's decision (22:40 Paris, above).**

- **The four behaviours.** `TabBarMinimizeBehavior` has exactly `.automatic`, `.onScrollDown`, `.onScrollUp` and `.never` (`SwiftUI.swiftinterface:11349-11368`; UIKit `UITabBarController.h:32-46`).
  - Apple's docs for `.onScrollDown`: "Minimize the tab bar when downwards scrolling starts."
  - None of the four expands the bar at the bottom of a list, or when the scroll reverses mid-list.
  - The UIKit header comment on `OnScrollDown` (l.39) says "expands when scrolling back up". The HIG below is more precise and matches the device.
- **HIG, Tab bars:** "A person can exit the minimized state by tapping a tab or scrolling to the top of the view." That is what Catégories, Favoris, Messages and Réglages do.
- **"Restore on reversal" exists for the navigation bar only.** iOS 27 adds `toolbarMinimizationBehavior` and `toolbarMinimizationRestoration(_:for:)` (`UIBarMinimization.h:13-81`, `SwiftUI.swiftinterface:13995-14055`). Its default "restores when the user reverses scroll direction", but: "Currently, only navigationBar supports customizing the restoration behavior". It does not apply to the tab bar.
- **No public way to expand the bar.** `tabViewBottomAccessoryPlacement` and UIKit's `UITabAccessory` environment can only be read. `UITabBarController` offers only `tabBarHidden`, which hides the bar rather than expanding it.
- **The tracked scroll view.** With none set, UIKit picks one by heuristic (`UIViewController.h:308-321`), and SwiftUI exposes no setter. It already tracks each tab's list: the bar minimises on scroll down and comes back at the top on all four tabs, so it is not tracking the wrong view.
- **App and legacy.** `RootTabsView.swift:50` applies `.tabBarMinimizeBehavior(minimizesTabBarOnScroll ? .onScrollDown : .never)`. Legacy @ 87fe0d1c does the same (`MainWindow.swift:1803, 2786-2788`).

Nothing to change. The only remaining way would be the custom layer the operator excluded, and there is no public API to force the bar open anyway.

# Issue #1413: [SwiftHFR] Account sync: two devices holding the same accounts in a different order rewrite the copy at every reconcile

- State: open
- Author: francoisgn · created 2026-11-27T19:36:34Z · updated 2026-11-27T19:36:34Z
- Labels: type: bug, priority: low, difficulty: easy, area: storage, status: ready, origin: audit, m4-review: performance
- Source: https://github.com/ezzz/HFRnow/issues/1413

### Summary
As a user with the account sync on and two devices whose account lists are in a different order, I want a reconcile that changes nothing to write nothing, so that the iCloud Keychain item is not rewritten at every foreground on both devices.

### What happens
`AccountSyncMerge` keeps **this device's** order for the merged entries (`AccountSyncMerge.swift`, "local order first, new accounts appended"; LOT-173 spec "Merge": "The local order is kept"). Two devices holding the same accounts in a different order therefore each compute an envelope that differs from the item only by the order, and write it: 8 item writes in 4 rounds of reconciles in a probe, same on `dev-swift` before #1406.

Found by the Fable adversarial review of #1406 (round 2, finding 5), out of that PR's scope (#1390 is about cookie-expiry refreshes).

### Proposed fix
The copy's entries keep the copy's order (new keys appended); the device-only book keeps this device's order. Test (Linux, `HFRStorageTests`): two devices with `[x, y]` and `[y, x]`, repeated reconciles → `itemWritten == false` after the first.

### Acceptance
- A reconcile between devices that hold the same accounts in a different order writes nothing to the synchronizable item.
- Each device keeps its own order.

Refs #1390, #1406.

### Summary

As a contributor, I want `ForumSessionCheckTests` to pass reliably on the iOS simulator CI, so that unrelated PRs are not blocked by a red `App build + tests` job.

### Observed

Two failures in two days on PRs that do not touch `App/` or the code under test (both tests use `ScriptedRefresher`, never `SessionRefreshFlow`); a rerun of the failed job passed the first time:

- #356 (LOT-057, HFRKit REST only), run 41232795746: `ForumSessionCheckTests/loginSavedWhileACheckWritesBackWinsOverItsCookies()` failed at its 60 s `.timeLimit`.
- #364 (#320, HFRKit session probe), run 41323654034: `ForumSessionCheckTests.loginDuringARecheckWinsOverItsResult()` failed.

Both tests drive a re-check and a login concurrently through gates (`CheckGate`, `beforePersistWrite`) under `.timeLimit(.minutes(1))` (`App/SwiftHFRTests/Accounts/ForumSessionCheckTests.swift:184-232`).

### Scope

Find why they can hang or fail on a loaded simulator runner (a gate never entered, an ordering the test assumes, the time limit itself) and make them deterministic. Not a guess: reproduce first (e.g. repeated runs of the suite on the simulator), then fix the test or the model.

### Acceptance criteria

- [ ] Root cause stated on this issue with evidence (a reproduction or a trace).
- [ ] Both tests deterministic; the suite passes N repeated runs on the simulator (N stated).
- [ ] `App build + tests` green.

# Issue #83: LOT-057: REST browsing client

- State: open

### Summary

As a reader, I want categories, topic lists and my flag buckets loaded from HFR's JSON API when it answers, with the HTML pages as fallback, so that lists load reliably and stay complete.

### Scope

A read-only HFRClient (ADR 0008) over `GET /webservices/rest_api.php?uri=<path>[&page=N&results_per_page=M]` (builder `HFREndpoint.rest`, LOT-041): categories, sub-categories, last topics of a category, one topic, and the flag buckets (`participated`, `read`, `favorites`). The JSON is decoded into the existing LOT-010 list models (DTOs stay internal). When REST fails or lacks a field, the client falls back to the HTML pages and the LOT-021/022/024 parsers. It reads with the account's session cookies and writes none back. Never `/posts/` (always 500). REST writes (POST/PUT) are out of scope.

- Module: HFRClient · Difficulty: medium · Priority: medium
- Audit source: redface2 E1 (`docs/research/redface2-comparison.md:289`; its `PH:`/`ADR-003:` citations point outside this repository)
- Legacy sources: none. The legacy app never called the REST API (no `rest_api` in francoisgn/hfrnow at `2440d79` nor in `origin/master`), so there is no legacy oracle for the JSON part. Facts come from HFR-PROTOCOL §7 (REST API row: JSON, hrefs `https://forum.hardware.fr/api/…`, 25 per page for topics, 20 categories) and redface2 E1 (`/api/…` hrefs 404 and are rewritten to `rest_api.php?uri=…`; `total_pages` = ceil(posts count / per page); `last_position` is an offset). The HTML fallback follows the LOT-021, LOT-022 and LOT-024 specs.
- Spec: `docs/lots/LOT-057-*.md`

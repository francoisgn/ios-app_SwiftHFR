# Issue #571: [SwiftHFR] Notification ledger: detect a new reply in an already-unread MP (LOT-091 follow-up)

### Summary
For LOT-140 (#230) to notify each MP conversation that receives news, the ledger must remember, for each unread thread, its `repliesCount` and its `lastPost` date. A conversation is then news again when either value grows. Today the ledger keeps only `unreadThreads: Set<Int>`, so a reply in an already-unread thread is not news.

### Scope
- `HFRStorage`, `NotificationLedger` and `NotificationSummary`, the MP part only:
  - keep a per-thread watermark: topic number, `repliesCount` and `lastPost` date;
  - change `diff` so it returns threads that are newly unread or that moved forward;
  - record the baseline silently on the first check.
- Migrate the existing ledger files: when an older record has no watermark, the first check sets the baseline.
- Tests: newly unread; a thread that is still unread and moved forward; read and then unread again; no change, so no news.

### Blocked by
The capture issue (MP list before and after one reply) must land first. It shows which row fields change, so nothing is guessed.

### Model
Sonnet 5.5 writes it and Opus 5.5 reviews it. Milestone M4. LOT-140 depends on it.

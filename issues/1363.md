### Summary
As a member opening someone's profile in SwiftHFR, I want the profile sheet to load, so that I can read it. Since 2026-11-26 HFR refuses profile pages to anonymous requests (403), and SwiftHFR fetches profiles without cookies on purpose (LOT-116), so every profile now fails.

- `GET /hfr/profil-<id>.htm` with no cookie: **403**, Apache's default page (230 bytes), as on #1349.
- The same URL with a logged-in kit session (`user1`, cookies `md_id`, `md_passs`, `md_user` from `login_validation.php`): **200**, 7.4 KB, a real profile page.
- Legacy fixed it on `master` in `bb58131d` (2026-11-26, #1349): `UserProfileService` sends the main account's cookies on the request (`httpShouldHandleCookies = false`), refuses to send with no account (`loginRequired`), maps 401/403 to `accessDenied` (`HFRswift/Swift/UserProfileService.swift:14-50` @ `bb58131d`).
- SwiftHFR: `App/SwiftHFR/Profile/UserProfileSource.swift:24` calls `fetcher.profile(memberID:as: .anonymous)` (LOT-116 differences 1-2, #124: the parser was only verified on logged-out pages).

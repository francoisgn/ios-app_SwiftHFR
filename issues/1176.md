### Summary

As a user adding an account from « Comptes », I want the login form to open inside the same sheet, so that closing it brings me back where I expect and I never have two sheets stacked.

### Rule

"Display only one sheet at a time from the main interface. When people close a sheet, they expect to return to the parent view or window. If closing a sheet takes people back to another sheet, they can lose track of where they are in your app. If something people do within a sheet results in another sheet appearing, close the first sheet before displaying the new one." — [HIG › Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets) (Best practices; page updated 2026-03-24).

### What the app does (dev-swift @ `7a61018f`)

- Comptes is a sheet: `App/SwiftHFR/Accounts/AccountMenuButton.swift:58-59` (`.sheet(isPresented: $showsAccounts) { AccountsView() }`), also `Reader/TopicReaderView.swift:134`.
- Inside it, `App/SwiftHFR/Accounts/AccountsView.swift:55-57`: `.sheet(item: $loginTarget) { target in LoginView(target: target, accounts: accounts) }`: « Ajouter un compte » or « Se reconnecter » stacks a second sheet.
- The one-sheet path exists in the same file: `AccountMenuButton.swift:61-62` opens `LoginView` directly from the main interface.

### Legacy at `87fe0d1c`

`AddAccountView` is a single sheet from the main views (`HFRswift/Swift/MainWindow.swift:240`, `:903`, `Favorites.swift:875`, `MPListView.swift:703`). There is no manage-accounts sheet (new, GAP-163), so legacy never stacks.

### Class

**(a) defect** (SwiftHFR-only), low.

### Proposed fix and check

- Push the login form inside the Comptes sheet's `NavigationStack` (`navigationDestination(item:)`) instead of a second sheet.
- Mac check: Comptes › Ajouter un compte shows one sheet with a back button; cancelling returns to the account list in the same sheet.

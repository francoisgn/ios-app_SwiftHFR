# Issue #1431: [SwiftHFR] UX survey: refuse to start with a weak UX_CODE_ACCES and log whether access is restricted

- State: open
- Author: francoisgn · created 2026-11-28T04:58:48Z · updated 2026-11-28T04:58:48Z
- Labels: type: chore, priority: medium, difficulty: trivial, status: ready, area: tooling, origin: deliberate-gap
- Source: https://github.com/ezzz/HFRnow/issues/1431

### Summary
As the PO running the five-tester trial, I want the service to refuse a short access code and to tell me at startup whether access is restricted, so that a typo or an empty variable cannot open the trial to everyone. The access code is the only thing that restricts the trial: the Funnel address is a public `https` name.

Refs #635 (finding 2 of the UX-11 review).

### What happens today
- `UX_CODE_ACCES` is read without any check (`tooling/ux-survey/internal/contenu/config.go:42`). Measured on loopback at `ffa9418d`: the service starts with a three-character code and accepts it. The "20 random characters at least" rule exists only in the README, the spec §6 and `deploy/ux-survey.env.exemple`.
- With an empty value the access check is simply not installed (`internal/web/middleware.go:156-159`) and the startup line (`cmd/ux-survey/main.go`, "démarrage") does not say so: a trial deployed with the variable missing looks the same in the log as a restricted one.

### Scope
- `ChargerConfig` fails when `UX_CODE_ACCES` is set and shorter than 20 characters (message without the value).
- The startup log line carries `acces_restreint: true|false`, never the code.
- README and spec §10 say the service refuses a shorter code.
- Optional, same change: the PO checklist of `docs/ux/questionnaire/verification-image.md` (point 8) asks to read that line after `up`.

### Acceptance criteria
- A config test: a 19-character code is refused, a 20-character one accepted, an empty one accepted (seen to fail before the change).
- A test or the CI image job reads `acces_restreint` in the startup line, and no log line holds the code.
- `go vet ./... && go test -race ./...` green.

### Summary

As a member on iPad, I want the Bookmarks list to highlight and close the bookmark that really shows beside it, and the column to empty as soon as I delete that bookmark, so the screen never points at the wrong message. Follow-up of LOT-132 (#222, merged in #1102 as `fd1a98c`): the three Low / Detail points of Fable's round 3 (comment on #1102), left out to keep the approved head.

### Scope

1. **Selection set by a pushed open** (Low). `App/SwiftHFR/MPStorage/BookmarksView.swift` (`open(_:)`) calls `model.didOpen` also when the row is pushed on the Plus stack (no detail column). Since #1102 the selection is the window's (`BookmarkSelection` in `RootModel`). Scenario: iPad, open A beside the list, narrow to compact, open B (pushed), widen. B is highlighted while the detail column shows A, and deleting B closes A. Fix: record the selection only in the `if let openInDetail` branch; add a model or hosted test.
2. **Detail closed after the forum exchange** (Low). `BookmarksModel.delete` returns only when `MPStorageSyncModel.edit` has finished the forum read and write, so on a slow network the deleted bookmark stays open beside a list that no longer shows it. Fix: close the detail once the local edit is shown (for example a callback or a state change before `syncOnce()`); add a gated test (`GatedBookmarks`, `ReadGate`).
3. **LOT-130 spec and test** (Detail). #1102 changed `MPStorageSyncModel.edit`: the device copy is shown right after the local edit, before the forum exchange, and `afterSync`'s "before" is still the document shown when the call began. `docs/lots/LOT-130-mpstorage-sync.md` (lines ~69-72) does not say so. No test pins the "before". Fix: one spec sentence, and a test that fails when `afterSync` gets the post-edit document.

### Contract summary
- Create: `POST /api/addAlerte.php`, form-urlencoded, UTF-8. Answer body: `1` OK, `-1` insert failed, `-2` unknown AQ, `-3` missing parameter, `-4` duplicate.
- **Silent refusals:**
  - 403 with an empty body when the IP is blacklisted or `post_url` does not start with `https://forum.hardware.fr`;
  - 200 with an empty body for the 60 s anti-flood (3 or more new AQs from one IP). The server then **deletes those AQs and bans the IP**.
  - So the app sends one create at a time and never retries.
- Duplicate keys: (`alerte_qualitay_id`, `pseudo`) and (`pseudo`, `post_url`), case-insensitive. The app must always send one stable permalink form.
- Adding to an existing AQ: `alerte_qualitay_id=<id>`.
- Limits: `nom`, `topic_titre`, `post_url` ≤512; `pseudo` ≤128; `commentaire` ≤1024.
- Optional `from` client identifier.
- RSS parameters: `entries`, `minimal_votes`, `enable_smilies`.
- The server stores a hashed IP under a published key (reversible for IPv4) and e-mails its operator on each create. Mention this in the LOT-071 / N1 notice.

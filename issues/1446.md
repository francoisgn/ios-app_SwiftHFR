# Issue #1446: [SwiftHFR] Tests: root hosted tests watch their "nothing happened" checks instead of sleeping a fixed delay

### Summary
As the maintainer, I want the root hosted tests' "nothing happened" checks to watch for the unwanted state over a bounded window after an end-state wait, instead of sleeping a fixed delay and checking once, so they fail the moment the regression shows and cannot pass by checking too early or turn red because the Mac is slow.

### Background
PR #1434 (#1201) found this class in the Duo fold tests and fixed it there. The fix has two parts:
- Wait for the end state of what the step started, with `settle`: a rebuilt split laid out, no stack in a push or a pop, no list load in flight.
- Then watch the negative check with the shared helper `staysAway(_:for:_:)` in `App/SwiftHFRTests/Root/DuoLayoutTests.swift`. It runs a layout pass each poll for 500 ms by default and fails the moment the unwanted state holds.

Fable's review of #1434 measured why a single check is not enough. A bring-back that lands 0, 100 or 300 ms after the end state passed an end-state wait followed by one check, and failed the 500 ms sleeps.

### Scope
These are negative checks made once, after a fixed delay (from the inventory in #1434):
- `App/SwiftHFRTests/Root/CoverScreenThumbActionsTests.swift:194`: 500 ms before "no bottom-bar item" on the cover screen's root lists.
- `App/SwiftHFRTests/Root/AppIconBadgeHostedTests.swift:107`, `:109`, `:144`: 100–300 ms before "no new badge".
- `App/SwiftHFRTests/Root/TabSplitWidthTests.swift:116`: 500 ms before "no detail column beside the list".

For each one:
- Name the end state the step reaches and wait for it.
- Then use the shared helper. Move `staysAway` to shared test support if a second suite needs it (these suites are not `DuoLayoutHostedTests`).
- Keep a window at least as long as the old delay. The point is to watch for the regression the whole time, not to wait less.

Not in scope: the layout-settling delays before a measurement (`CoverScreenThumbActionsTests:230`, `RegularWidthListStyleTests:100/153`), the deliberate `SidebarDetailHostedTests:143`, and the poll intervals.

### Acceptance criteria
- No fixed `Task.sleep` before a negative check remains at the places above.
- For each place, a mutation that brings the unwanted state back 0, 100 and 300 ms after the step is red, and the suite is green with the mutation off. The run is on the simulator the suite targets.
- SwiftLint passes.

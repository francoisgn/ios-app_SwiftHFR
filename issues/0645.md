# Issue #645: [SwiftHFR] Reader "…" menu: page items come before Rechercher and Hors ligne, not last

### Summary
As a reader, I want the page items at the end of the top "…" menu, after Rechercher and Hors ligne, as #583 and legacy have them, so that the menu reads like the legacy one.

Refs #583 (found in its Mac check; build `cb3da9ce` = `origin/dev-swift`, which contains #583 and #590).

### Observed
iPhone 18 Pro (iOS 27.0, portrait and landscape) and iPad Pro 13" (iOS 27.0, landscape, regular width), logged in, a 511-page topic. The top "…" menu lists, top to bottom, in light, dark, Increase Contrast, XL and AX3 alike:

1. Filtrer les posts
2. (separator) Première page, Aller à la page…, Page 509, Page 510, Dernière page, Dernier post
3. (separator) Enregistrer cette page hors ligne, Rechercher dans le sujet

### Expected
#583's own check list: "Rechercher, Hors ligne, Filtrer, then the page items", a separator before the page items. Legacy (`MessagesView.swift:4692-4725` @ 2440d79): Sondage, Rechercher, a divider, then `pageChoiceMenuItems()`. So the page items close the menu.

### Likely cause
The overflow is built from four `.secondaryAction` items: Filtrer and the page group are in `TopicReaderView`'s `.toolbar`, while Rechercher (`ReaderSearchFlow`) and Hors ligne (`ReaderOfflineSave`) are added by modifiers applied before that `.toolbar`. The system orders them in its own way, so declaration order inside one `.toolbar` is not enough. Not verified in code beyond this reading.

### Acceptance
- Top "…" order on iPhone and iPad: Rechercher, Hors ligne, Filtrer, separator, page items (or the order the operator picks, written in LOT-186).
- A test or a Mac check pins the order.

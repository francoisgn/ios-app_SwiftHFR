# Issue #1422: [SwiftHFR] A reader, profile or category load in flight at a lock ends timedOut on return (#1404 follow-up)

### Summary
As a member who locks the phone while a topic, a profile or the categories are loading, I want that load to be asked again when I come back, so that I do not find « Le forum ne répond pas » left by a request iOS froze. #1414 (#1404) does this for the topic lists (Favoris, flags, categories' topic lists) and the MP list only.

### Scope
A load in flight when the window goes to the background is frozen by iOS once the phone locks and ends `URLError.timedOut` 25–56 s later (device pass of #1388, Favoris). #1414 stops such a load and asks for it again on return (`SceneAwareListLoad`, `ContentLoader.suspend()`, `\.sceneIsAway` set by `SceneAwayTracking` above the root), for `TopicListModel` and `MessageListModel` only. Not covered, same exposure:
- the reader's page loads (`TopicReaderModel`, its own task, not `ContentLoader`; mind LOT-137: a covered reader must not cancel on `onDisappear`);
- the profile (`UserProfileModel.onAppear` / `reload`);
- the categories' forum list (`ForumListModel`, loaded by the root's `.task` and `ForumListView`);
- the Plus lists that load on appearance (`BookmarksView`, `OfflineTopicsView`, quality alerts).

Decide per screen: stop and ask again on return (as #1414), or let it run and retry once on return after a `timedOut` / connection-lost failure that spanned the background. Read-only loads only; writes are never re-sent (LOT-048).

### Acceptance criteria
- For each screen above, a hosted test: a load in flight when the window goes to the background leaves no error on return and is asked again once (red first).
- No request sent while the window is away.
- Device check on #893: lock during a topic page load and during a profile load, unlock: the page or profile shows.

Found by the review of #1414 (Fable, r1414 finding 4). Refs #1404, #1388, #774.

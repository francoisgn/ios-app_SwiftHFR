## moust4ki · 2026-10-28T16:42:41Z

Verification (ext/bybifok-opus-1, Opus 5.5; not claimed, verification only): **engine half fixed. App half fixed for permalinks, but one link shape still opens page 1; that part belongs to #227 (LOT-137).**

**Fixed.**
- **Engine (LOT-095).** `HFRLinkRoute` keeps page and message on both URL shapes. For `forum2.php?…&page=1&numreponse=M` it sets `page` to nil and keeps `numreponse`, which `HFREndpoint.topicPage(topic:page:numreponse:)` sends so HFR redirects to the message's page (R25). Tests in `HFRLinkRouteTests`: "Canonical topic URLs keep category, page and message", "forum2.php keeps category, page and message", `messageLinkKeepsNumreponseAndAnchor`, `badPageWithNumreponse`. Recorded in `docs/CHANGELOG-LEGACY.md` row 20.
- **Reader (LOT-083).** `ReaderTarget(link:)` (`App/SwiftHFR/Reader/ReaderTarget.swift:42-60`, used by `TopicReaderModel.action(forLink:)`) keeps page and `#t` anchor for `forum2.php?…&page=N#tM` and canonical `…-sujet_<post>_<page>.htm#tM`. That covers the quote headers of `R21` (`…pizza-maison-sujet_28563_1.htm#t2666682`). Tests: `ReaderTargetTests.aForum2LinkKeepsTopicPageAndPost`, `.aCanonicalLinkKeepsPageAndPost`.

**Still open.**
- **Message links in the reader.** `ReaderTarget(link:)` reads `page=` directly (`ReaderTarget.swift:46-48`) and has no `numreponse`, so a link carrying `numreponse=M` opens page 1:
  - `forum2.php?…&page=1&numreponse=M` with no fragment opens at the top;
  - a legacy bookmark (`Bookmark.m:17`: `…&numreponse=<n>#t<n>`, no `page`) opens page 1 with an anchor that is not on it.
  
  This is the router/ReaderTarget disagreement already written up for LOT-137 (#227 comment, `docs/lots/LOT-095-link-router.md`): build `ReaderTarget` from `HFRLinkRoute`.
- **AQ and bookmarks screens** do not exist in the app yet.

Suggest keeping this issue open, blocked on #227, and adding a `ReaderTargetTests` case for `/forum2.php?cat=13&post=28563&page=1&numreponse=2666649` in that lot. That test would fail today.

### Summary

As a user who runs « Filtrer les posts », and above all as a VoiceOver or Switch Control user, I want the result message (« Aucun post n'a été trouvé ») to stay until I dismiss it and its buttons to be easy to hit, so that I do not miss the outcome of the run.

### Rule

- "Minimize use of time-boxed interface elements. Views and controls that auto-dismiss on a timer can be problematic for people who need longer to process information, and for people who use assistive technologies that require more time to traverse the interface. Prefer dismissing views with an explicit action." — [HIG › Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility) (Cognitive; page updated 2025-06-09).
- "Inform VoiceOver when visible content or layout changes occur." — [HIG › VoiceOver](https://developer.apple.com/design/human-interface-guidelines/voiceover).
- "As a general rule, a button needs a hit region of at least 44x44 pt" — [HIG › Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons) (Best practices; updated 2025-12-16); minimum control size on iOS 28×28 pt (Accessibility › Mobility).

### What the app does (dev-swift @ `7a61018f`)

- `App/SwiftHFR/FilteredPosts/FilteredPostsView.swift:78-82`: `.task(id: model.statusMessage) { … try? await Task.sleep(for: .seconds(3)); … model.dismissStatus() }`. The message is the outcome of the run (`FilteredPostsModel.swift:132`, `:159`). This timer is not `Common/ConfirmationAutoDismiss.swift`, the shared component of #864 that skips the timer under VoiceOver (`:18`, `:27`), and the model posts no `AccessibilityNotification`.
- `FilteredPostsView.swift:68,70`: `Button("Annuler") { … }.font(.footnote.weight(.semibold))` and `Button("OK") { … }.font(.footnote.weight(.semibold))`: no button style, frame or `contentShape`, so the hit region is the footnote text box.

### Proposed fix and check

- Route the status through `ConfirmationAutoDismiss` (or keep it until « OK » at least while VoiceOver runs) and post an `AccessibilityNotification.Announcement` when the status is set; #864 already decided the rule for success confirmations.
- Give both buttons a standard bordered style (`.buttonStyle(.glass)`, `.controlSize(.small)`) or a 44 pt minimum frame with `contentShape`.
- Check: a model test with a VoiceOver stub (status survives, announcement posted). Mac check: Accessibility Inspector hit area of both buttons; a filter run with no match under VoiceOver.

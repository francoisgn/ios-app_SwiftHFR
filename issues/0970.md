### Summary

As a tester, I want a tap on « Version » in Réglages (and in À propos) to copy the app's build details to the clipboard, so that I can paste them in a bug report and we know exactly which build, OS and device it is.

### Today

- `SettingsView.swift:172` and `AboutView.swift:24` show `LabeledContent("Version", value: AppVersion.current.display)`; the values come from `CFBundleShortVersionString` and `CFBundleVersion` (`AboutModel.swift:9-12`). A tap does nothing.
- No build records which commit it came from: the operator could not tell whether their Xcode build included cd049542 (2026-11-16).

### Wanted (operator, 2026-11-16)

A tap on the Version row copies one line or a short block, with no account, pseudo or other personal data:
- app version and build (`CFBundleShortVersionString` (`CFBundleVersion`));
- **the git commit** the app was built from: a short sha, plus `-dirty` if the tree had local changes. Inject it at build time (a build-phase script writing an Info.plist key, e.g. `HFRGitCommit`), and show `?` when it is absent (CI unsigned builds, a tarball);
- the OS (`UIDevice.systemName` + `systemVersion`);
- the device model code (`utsname.machine`, e.g. `iPhone18,2`; the simulator's `SIMULATOR_MODEL_IDENTIFIER`).

Then a short confirmation (« Copié », and a VoiceOver announcement). The row also shows the commit, e.g. « 1.0 (42) · cd04954 ».

### Acceptance criteria

- [ ] A tap copies the text, in a stable format: `SwiftHFR <version> (<build>) · <commit> · <OS> · <model>`.
- [ ] A test of the formatter covers a missing key, a missing commit and a simulator model.
- [ ] The build script works for a local Xcode build and an unsigned CI build, never fails the build, and reads only `git rev-parse` (nothing secret). No new dependency.

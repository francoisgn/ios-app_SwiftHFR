### Summary
As a member removing several favourites in a row, I want each write to cost one request like legacy, so that a batch of writes is not doubled by session checks; but the check before a write exists for safety (#314, #1200). Split from #1398, point 2 (#1388 audit).

### Facts (#1398, audit #1388)
- Every gated write runs a fresh session check first (`TopicFlagFlow.swift:181-202`, `PollVoteFlow.swift:102`): add a favourite = 1 check + 1 write; removing 5 favourites = 10 requests. Legacy: 1 request per write.
- The check is deliberate: HFR answers a cookie-less `addflag` with the logged-in success bytes (#314, AGENTS.md learning 2026-10-28), so a write without a check can report a success that did nothing.

### Decision needed (operator)
Reuse a `valid` verdict for a short window (for example 60 s), keyed on the account's login generation, so a burst of writes after one check sends no further check; or keep one check per write. Code only after the decision.

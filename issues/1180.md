### Summary

As a user tapping a formatting button with something in the clipboard, I want the question to offer named choices and a real « Annuler », so that I can back out of the tap and Esc on a keyboard inserts nothing.

### Rule

- "Use an action sheet — not an alert — to offer choices related to an intentional action." and "In informational alerts only, you can use "OK" for acceptance, avoiding "Yes" and "No." Always use "Cancel" to title a button that cancels the alert's action." — [HIG › Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts) (page updated 2024-02-02).
- "Provide alternative ways to cancel an alert when it makes sense." — same page.

### What the app does (dev-swift @ `7a61018f`)

- `App/SwiftHFR/Composer/ReplyComposerView.swift:105-109`: `.alert("Utiliser le presse-papiers ?" …)`.
- `:348-361`: `.link` → « Non » (`role: .cancel`) / « Oui »; `.linkChoice` → « Sans le presse-papiers » (`role: .cancel`) / « Oui [url=XXX] » / « Oui [url]XXX[/url] »; `.formatting` → « Sans le presse-papiers » (`role: .cancel`) / « Insérer ».
- The cancel-role button is not a cancel: it calls `formatting.declinePending(pending)` (`Composer/ComposerFormattingModel.swift:114-121`), which applies the tag without the clipboard. No button backs out of the tap, and the system's cancel gestures (Esc, ⌘.) trigger the cancel-role button, so they insert the tag.

- Check: a model test that the cancel path leaves the text unchanged. Mac check: Esc on a hardware keyboard inserts nothing.

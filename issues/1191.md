# Issue #1191: [SwiftHFR] app: a cancellation nobody asked for has one rule in the reader (retry once, then an error) and none elsewhere: blank Messages, endless profile and AQ spinners, a silent filter

- State: closed

- Labels: type: bug, priority: high, difficulty: easy, area: app, origin: audit, m4-review: quality
- Source: https://github.com/ezzz/HFRnow/issues/1191

### Summary
As a member, I want a request that ends "cancelled" without anyone cancelling it to be retried or reported everywhere, as the reader does since #566, so that no screen is left blank or spinning. Today each screen treats `.cancelled` as "the user went away", whoever cancelled.

### Scenario
The transport answers `.cancelled` while our task was not cancelled (the #566 case: `URLSessionTransport.map` turns any `URLError.cancelled` into `.cancelled`, `Packages/HFRKit/Sources/HFRNetwork/Transport/URLSessionTransport.swift:166-171`).
- First load of the Messages list: empty list, no message, no "Réessayer".
- First load of a profile: "Chargement du profil…" for ever.
- Alertes Qualitay: "Chargement…" for ever on a first load started by "Réessayer" or "Actualiser".
- Post filter: the banner vanishes with no result and no message.

### Evidence (`7a61018f`)
- The reader's rule: `App/SwiftHFR/Reader/TopicReaderModel.swift:547-550` and `:619-621` (retry once, then an error; "never a screen left waiting").
- `App/SwiftHFR/Navigation/ContentLoader.swift:66-67`: `.failure(.cancelled)` clears `isLoading` and sets neither value nor error; `App/SwiftHFR/Profile/UserProfileView.swift` and `App/SwiftHFR/Messages/MessageListView.swift` have no state for "no value, no error, not loading".
- `App/SwiftHFR/FilteredPosts/FilteredPostsModel.swift:229-230`: `if case .network(.cancelled) = error { return .success(nil) }`, then `:125-130` returns on `guard let batch`.
- `App/SwiftHFR/QualityAlerts/QualityAlertsModel.swift:166-171`: sets `isLoading = false` and returns with `hasLoaded` false; `QualityAlertsView.swift:75` shows `ProgressView` while `!model.hasLoaded`.

### Fix
One rule, shared with the reader: `.cancelled` means "stopped" only when the run was really cancelled (`Task.isCancelled` or a generation change); otherwise retry once, then show the generic failure. Put it in `ContentLoader.load` and reuse it in the filter and the AQ list.

### Tests (fail before the fix)
- `ContentLoaderTests.aCancellationNobodyAskedForIsRetriedOnce`: the operation throws `.cancelled` once, then returns a value.
- `FilteredPostsModelTests.aCancellationNobodyAskedForIsAFailure`; `QualityAlertsModelTests.aCancellationNobodyAskedForEndsTheLoad` (`hasLoaded && failure != nil`).

How often the transport cancels unasked outside the reader is not measured. Related: #108 (a cancelled request must never complete the next load), #566.

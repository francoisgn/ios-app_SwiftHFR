### Summary
As a reader, I want an SVG image posted in a message to open in the image viewer, so that tapping it does not show an empty or failed viewer.

Milestone: M4 (operator, 2026-11-08). Found by the `2440d79..2fe43da3` sweep of #655.

### Legacy @ `2fe43da3`
`9f15513d` "Add default browser and SVG photo support": the viewer detects SVG (`image/svg+xml` MIME type or content, `HFRswift/Swift/MessagesView.swift:6717-6730`) and renders it in a web view instead of the bitmap path (`6600-6680`, `6736-6820`).

### Current SwiftHFR
`ImagePolicy` lists `svg` as an image extension (`App/SwiftHFR/Reader/ImagePolicy.swift:39`), but the viewer decodes with `CGImageSource` only (`App/SwiftHFR/Reader/Viewer/ImageViewerServices+Live.swift:35-55`), which cannot decode SVG.

### Scope
- Detect SVG in the viewer and render it without running script (same isolation as the reader: no JavaScript, image policy C, cookie-less fetch, LOT-083 / LOT-109).
- Save/share: keep what legacy offers for SVG.

### Acceptance criteria
- An SVG served as `image/svg+xml` opens and zooms; a script inside an SVG never runs (test with a synthetic SVG).
- Bitmap images unchanged.

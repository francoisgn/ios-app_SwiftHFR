# Issue #338: [SwiftHFR] After M4: return to a standard contribution and PR process, remove the M1–M4 delegation scaffolding

- State: open
- Author: francoisgn · created 2026-10-29T13:15:49Z · updated 2026-11-09T15:00:03Z
- Labels: type: chore, priority: low, difficulty: medium, area: docs, status: blocked, origin: infra
- Source: https://github.com/ezzz/HFRnow/issues/338

### Summary

As the maintainer, once the final version ships (M4: LOT-165 App Store submission accepted), I want contributions to follow a **standard open-source process**: issues, PRs, GitHub reviews and one CONTRIBUTING guide. The scaffolding built for M1–M4 goes away. It was there to delegate under tight control while tokens were short: per-person rules for moust4ki (Bybifok) and Ezzz, claims typed by hand, steward sessions, bot-routed adversarial reviews. Its job is done, and it makes the repository harder to contribute to.

### When

After LOT-165 (#255) is done. The Fable audit of outside contributors' work (#326) and the parity gate LOT-164 (#254) happen before it. This is the last item after M4 on the board #324.

### Scope

**1. Decide first, in an ADR.** A decision not in an ADR is not a decision (AGENTS.md). The ADR updates or supersedes ADR 0011 (contribution model and feature intake). It sets:
- who may merge;
- what review a PR needs: GitHub required reviewers or CODEOWNERS, versus the model-routing matrix of AGENTS.md §6;
- whether claims stay, and in which form (GitHub assignees, or the `issue-claims.yml` workflow once it runs from the default branch);
- what remains of the AI-agent rules: generic rules for any agent, with no named person.

**2. Then remove or rewrite the temporary parts.** This list is a starting point; re-check it against the repository when the issue starts.

| Where | What was added for M1–M4 | Target |
|---|---|---|
| `AGENTS.md` §8 | Bybifok's 10-open-PR exception (#331), the 5-PR limit per contributor id, the "merge as soon as green" policy with merges by the core or the maintainer, `Direct-PR:` break-glass, `Claim:` line in every PR | the ADR's merge and review rules, no named person |
| `AGENTS.md` §0, §5, §6 | manual `/claim` / `/release`, orchestrator claiming for sessions, the reviewer-model matrix as a merge gate | the ADR's rules |
| `docs/agents/EXTERNAL-AGENTS.md` | the whole brief for contributors' agents: queues, `REVIEW WANTED`, `CLAIM REQUEST`, the cross-contributor review of §7, the open-PR limit | merged into `CONTRIBUTING.md`, or deleted |
| `docs/agents/ORCHESTRATION.md` | the steward, labels and claims set by hand "until the workflows run from master", the manual unblock procedure, the milestone boards #166 and #324 | kept only if workflows still cannot do it, otherwise deleted |
| `docs/agents/REVIEW-ROUNDS.md` | the bot-round handling written for token-limited sessions (CodeRabbit pauses, operator-posted bot commands) | the parts that still apply go into `CONTRIBUTING.md` |
| `README.md` | the "spare AI quota? give your agent this line" section that points to EXTERNAL-AGENTS | a normal "Contributing" section pointing to `CONTRIBUTING.md` |
| `.github/labels.yml` | `external: ready`, `direct-pr`, the per-person credit label `moust4ki aka bybifok finding`, and `status: claimed` if claims go | removed, or replaced by standard labels (`good first issue`, `help wanted`); credits stay in `CREDITS.md` |
| `.github/pull_request_template.md` | `Claim:` / `Direct-PR:` lines | the ADR's PR template |
| `docs/research/bybifok-proposals.md` §9 | the prompt for one contributor's agent | removed; the proposals stay as research |
| Issues | the steward-state and restart-plan comments on #166, the boards #166 and #324, the capture backlog #337, the post-capture reviews #328–#330 | closed with a final summary |

**3. Keep:**
- credits to contributors (`CREDITS.md`, FEAT credits in `docs/FEATURES.md`);
- the security rules (SECURITY.md, gitleaks, push protection);
- the HFR "no guessing / fixtures anonymized" rules;
- the module boundaries.

These are project rules, not delegation scaffolding.

### Acceptance criteria

- [ ] An ADR (Accepted) records the post-v1 contribution model and supersedes the M1–M4 rules it replaces.
- [ ] No document in the repository names moust4ki/Bybifok or Ezzz in a rule; credits remain.
- [ ] `CONTRIBUTING.md` is the single entry point for contributors, human or agent. `AGENTS.md` keeps only generic agent rules and points to it.
- [ ] The labels, the PR template and the README match the ADR. `scripts/configure-repo.sh` (run by the maintainer) matches the new review and merge settings.
- [ ] The tracking issues above are closed, each with a summary.
- [ ] Docs consistency CI is green, with no broken links to removed files or anchors.

**BLOCKED — decisions needed** (spec: https://github.com/ezzz/HFRnow/pull/703, `docs/lots/LOT-067-legacy-import.md`, head `1729b4f`)

Every legacy store is traced at the reference `2fe43da3`; no new capture is needed for the small stores (#347 samples cover them). The port stops on three decisions, each with a proposed default in the spec:

- **D1 — Drafts (contradicts ADR 0013 §5).** `composerDraftText` is not persisted at `2fe43da3` (`@State`, `MessagesView.swift:3081`, `MainWindow.swift:312`). The Swift composer keeps `reply_active_drafts_by_topic_v1` (one active draft per topic, ≤ 50) and `reply_drafts_by_topic_v1` (≤ 3 archived drafts per topic), keyed `post-<topic number>` with no category or page (`AnswerView.swift:102-272`, `MessagesView.swift:3245-3262`); the ObjC `brouillon` key still exists (`AddMessageViewController.m:69, 483`). Proposal: `brouillon` → `.legacyGlobal`; active drafts → new `DraftContext.legacyTopic(number:)` offered by the composer when a topic with that number opens; archived drafts not imported (left in place) + GAP row. Needs an ADR 0013 §5 amendment.
- **D2 — Super-favourites without category.** `SuperFavoritesIds` holds topic numbers only (`Favorites.swift:132-157`); `SuperFavoritesStore` needs a `TopicID`. Proposal: a pending device-only list resolved by the app against each favourites-list load, in every category where the number appears (legacy matched the number alone).
- **D3 — Account of the global items** (super-favourites, smiley favourites, drafts): the legacy main account (last `MAIN`, `MultisManager.m:168-176`); with no legacy account, the first account that logs in.

Mac check (not blocking the decisions): **M1**, decode a real legacy `HFR_COMPTES_KEY` archive and measure whether `NSHTTPCookie` decodes under secure coding (spec "Pending capture / Mac checks").

## francoisgn · 2026-11-09T20:49:20Z

**Operator decisions on LOT-067 (2026-11-09 ~21:10 UTC, relayed by cloud/orch)**

- **D1 drafts**:
  - active Swift drafts (`reply_active_drafts_by_topic_v1`) are imported into a **temporary device-only pending list** keyed by topic number, not into a new permanent `DraftContext` case;
  - an entry is resolved when a topic with that number is opened (the app then knows its `TopicID`): it becomes an ordinary reply draft of that topic, so the composer needs no legacy logic;
  - entries expire after 30 days, like LOT-063 drafts;
  - archived drafts are not imported: they stay in `UserDefaults`, get a GAP row (`b·operator`) through the PR's `### Ledger`, and are never deleted;
  - ObjC `brouillon` goes to `.legacyGlobal`.
- **D2 super-favourites**: as proposed (pending numbers, resolved at each favourites-list load in every category where the number appears, dropped after 90 days or when super-favourites are emptied), **through the same pending mechanism as D1**: one resolver, one test suite, one thing to remove later.
- **D3**: the global items go to the legacy main account (the last `MAIN`); with no legacy account, they stay pending and go to the first account that logs in, once.
- **ADR 0013 §5 amendment**: `composerDraftText` was never persisted; record D1–D3 and the shared pending mechanism.
- **Retirement**: a separate issue to remove the legacy import code (and the pending lists) in a later version, once the in-place update has shipped for long enough.

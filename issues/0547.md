### Summary

As a member of HFR, I want to see my unread private messages and the topics I follow on my Home Screen, my Lock Screen and in Control Center, and to get back into them in one tap, so that I can follow the forum without opening the app just to check.

_This is an M5 study (UX evolutions, after M4 parity). The sub-orchestrator `ext/francoisgn-suborch-1` did the research read-only on `dev-swift`, and read the HIG live on 2026-11-07. The issue is for triage: nobody has claimed it and nothing is planned yet. The operator received HTML mockups built with fake data only. The companion study for the Dynamic Island and Live Activities is #546; its MP answer, a notification plus a widget, is P1 here._

### Context and constraints

**What the engine already offers:**
- **MP count.** `MPUnreadPoll.unreadCount() -> Int?` (`Packages/HFRKit/Sources/HFRClient/MPPoll/MPUnreadPoll.swift:22,55`) makes one `GET /` in a probe session and never writes cookies back. A `nil` result means "no information" and must never be shown as 0.
- **MPs and flags together.** `CheckUpdatesFlow.check() -> UpdateSummary` (`HFRClient/Updates/CheckUpdatesFlow.swift:11-21,61`) makes at most two GETs and never moves a flag. It returns separate outcomes for the MPs and for the flagged topics.
- **Topic rows.** A `TopicSummary` row has the title, `lastPost`, `flag` and `readState` (`HFRModels/Lists/TopicSummary.swift:14-39`), but **no per-topic unread count**. A widget can show "nouveau", not "12 nouveaux".
- **Ledger.** `NotificationLedgerStore` handles throttling and the already-notified state for each account.
- **Reading positions.** `ReadingPositionStore` has no title (`ReadingPositionRecord.swift:6-8`).
- **Search.** `GlobalSearchFlow` needs the session's token, so a widget can only open the search, not run it.
- **Links.** `HFRLinkRoute.route(for:)` already maps forum URLs to `.topic`, `.privateMessageThread`, `.privateMessageList`, `.favorites` and `.search`. Plain forum URLs are enough as widget destinations, with no new URL scheme.

**What the app is missing today:**
- There is no `onOpenURL` (`App/SwiftHFR/SwiftHFRApp.swift:26-45`); FEAT-020 is only proposed.
- There is no BGTask, no App Group, no entitlements file and no `WidgetCenter` anywhere in `App/`. ADR 0013 also notes the missing App Group.
- The stores live in the app's own `applicationSupportDirectory`.
- LOT-140 (#230) is ready but not built, and LOT-141 (#231) and LOT-143 (#233) are blocked.

**Constraints:**
1. **Extension target.** The widget extension is a new target in its own folder (ADR 0012, line 27). It needs the maintainer's Mac and team signing.
2. **App Group.** The app and the extension share data through a new `WidgetSnapshot` small store in `HFRStorage`, written by the app into the group container. It needs file protection `completeUntilFirstUserAuthentication`, or Lock Screen widgets read nothing while locked.
3. **Keychain and network.** The extension **never reads the Keychain and never touches the network**. No keychain sharing is needed, and no cookie ever reaches the extension.
4. **Refresh budget (live docs).** A widget gets about 40–70 reloads a day, at least about 5 minutes apart. Reloads requested while the app is in the foreground, or by an app intent, are free. The app and the BGTask therefore fetch the data, write the snapshot and call `WidgetCenter.reloadTimelines`. The widget's own timeline is `.never`, with a relative "vérifié à" time.
5. **No backend.** Without one there are no pushes, so the data is only as fresh as the last check by the app, LOT-140 or LOT-141. Every widget shows when that check happened.
6. **Cookies stay on the forum** (LESSONS 30/37/56), and polling stays polite (LESSONS 48).
7. **Multi-account.** Snapshots are keyed by `AccountKey`, and each widget can be set to one account (`AppIntentConfiguration`).
8. **Privacy when locked.** MP senders and subjects, topic titles and the member's own pseudo get `.privacySensitive()`. The system redacts control values when the device is locked.

**P1 — Messages privés**
- **States:**
  - ok;
  - no information, shown as "—", never 0;
  - logged out: "Connectez-vous pour voir vos messages privés";
  - expired.
- **Taps:**
  - the widget opens the MP list;
  - a medium row opens its thread.
- **HIG:**
  - dynamic information;
  - show when the data was last updated;
  - deep links;
  - vibrant and accented rendering modes;
  - Lock Screen widgets give useful information, they are not a launcher.

**P2 — À suivre**

- **Unread mark:** a "nouveau" dot, because no per-topic count exists.

**P3 — "Vérifier HFR" control**
- **What it is:** a control button, not a toggle, showing "2 MP · 14:05".
- **What it does:** runs the LOT-141 intent (`CheckUpdatesFlow` plus the ledger), then reloads P1 and P2.
- **Rate limit:** `markCheckedIfDue`.
- **Where it runs:** in the app's process, never in the extension (open question 2).
```
Control Center (2×1)        Lock Screen / Action button
┌────────────────────────┐   ╭───╮
│ ⟳  Vérifier HFR        │   │ ⟳ │  (locked: symbol only)
│    2 MP · 14:05        │   ╰───╯
└────────────────────────┘
```

**P4 — Reprendre la lecture**
- **Data:** a new list of recent topics (title, `TopicID`, page, `updatedAt`) that the reader writes into the snapshot. No network.
- **Tap:** opens the reader at the saved position.
- **Overlap:** FEAT-001, "resume last reading".
```
┌───────────────────┐
│ 📖 Reprendre      │
│ [Topic unique]    │
│ Exemple           │
│ page 42 · il y a 2 h │
└───────────────────┘
```

**P5 — Rechercher**
- **What it is:** a control plus an App Shortcut "Rechercher sur HFR" with one optional parameter.
- **What it does:** opens the app on its search screen with the terms filled in. The search itself needs the session's token.
- **Why not a Lock Screen widget:** the HIG says widgets should not be "an additional way for people to launch into your app".
```
Control Center (1×1)   Siri / Spotlight
┌──────┐               « Rechercher sur HFR » → [ termes ] → app, Rechercher
│  🔍  │
└──────┘
```

**P6 — StandBy and Smart Stack.** This is a set of acceptance criteria for W1 and W2, not a lot:
- removable backgrounds (`containerBackground`);
- large text that survives the StandBy night-mode red tint;
- `TimelineEntryRelevance` raised when MPs are new. Whether the iOS Smart Stack honours it must be measured on a device.

Dropped: a separate "Derniers MP" widget (folded into P1 medium) and a Smart Stack widget (folded into P6).

### Open questions for the operator

1. Should counts ("2 MP", "À suivre · 3") stay visible on a locked Lock Screen? The alternative is to redact everything with the Data Protection capability, but then the widget gets no runtime while the phone is locked.
2. Should the P3 control run the check in the app's process (an App Intent in the app target), or open the app? An extension never holds cookies.
3. Multi-account: should widgets follow the current account, or be configurable per account? A per-account setting shows the member's pseudo in the widget configuration.
4. Should W0 ship with LOT-140, so the first BGTask also feeds the widget, or strictly after M4 parity?
5. App Group identifier and signing: this is a new capability on the App ID (`hfrplus.red.super`, FEAT-020 Q-1). Only the maintainer can set it up.

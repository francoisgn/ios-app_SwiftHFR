### Summary
As a user of a strong gallery theme, I want destructive buttons in list rows to stay legible, so that I can read « Effacer… » rows as clearly as the rest of the list. Under Noël abusé, the system red of a `role: .destructive` row button measures 3.75:1 on the theme's row `surface` (#0B3A22), under the 4.5:1 that THEMES.md §3 requires. Before #842 the row sat on the system card, at 4.99:1.

### Context
#842 (PR #1118) themes native list rows and moved row error text to `ThemedErrorStyle`. A round-3 attempt to apply that style to destructive row buttons was reverted (Fable round 4 on #1118):
- `PollCreationSheet`'s remove-answer button is `.buttonStyle(.plain)`, so the role's red never reached its glyph, and the change turned it red under Legacy.
- An explicit `foregroundStyle` may stop `.disabled` from dimming a row, under Legacy too.
- No rendered test covered it.

### Scope
- A `themedDestructive()` modifier in `App/SwiftHFR/Common/ThemedList.swift`:
  - it returns `content` untouched under Legacy;
  - under a theme it applies `errorText` (`AccessibleColors.errorText`, already checked by the `errorText/surface` and `errorText/selection` rules), dimmed when `isEnabled` is false.
- Apply it to the destructive buttons that are rows of a themed list: `AccountDeletionView` (« Effacer les données de … », « Effacer les données restantes de … ») and `AccountsView` (« Effacer les comptes enregistrés »). Do not apply it to `.plain` buttons, alerts, dialogs, swipe actions or toolbars.
- Update THEMES.md §3 (the sentence on row error text).

### Acceptance criteria
- [ ] Rendered tests in `ThemedListTests`, each seen red without the change:
  - under Legacy, a destructive row button's pixels are equal with and without the modifier, enabled and disabled;
  - under the test theme, its label is #FF827A in dark, and it is dimmed when disabled.
- [ ] Legacy is pixel-identical (the LOT-188 and #842 tests stay green).

### Summary
As a reader of my private messages, I want each one-to-one row to show the correspondent's **avatar by default**, with the initials disc only when the member has no avatar, so that I recognise who wrote at a glance (operator device feedback, 2026-11-10).

### Today (dev-swift `fddb6a37`)
- `App/SwiftHFR/Messages/MessageAvatarView.swift`: avatar from the avatar cache, else the monogram (initials). The cache is filled only by `AvatarStore` from the pages read (GAP-230, #569/#578), so a correspondent whose thread or posts were never opened since the install shows initials even when they have an avatar.
- The legacy app's avatar files sit in the same folder (`Caches/cache/avatars`) under another name: `MD5(lowercased pseudo)` (`HFRswift/Swift/MPListView.swift:911-917` @ `87fe0d1c`), while `AvatarCache` names files by the hex of the lowercased pseudo (`Packages/HFRKit/Sources/HFRStorage/Caches/AvatarCache.swift:62-70`). After the update to SwiftHFR, every avatar the legacy app had cached is ignored.

### Scope
1. **Now (cloud):** when `AvatarCache` has no entry for a pseudo, read the legacy file `MD5(lowercased pseudo)` in the same area (read-only, same checks: regular file, no symlink, size cap, decodes as an image), and adopt it into the SwiftHFR name. Tests on both names.
2. **Now (cloud):** the row passes the right pseudo (one-to-one: the interlocutor, never the account's own pseudo; groups keep their icon); a test per case.
3. **After capture #716:** for a one-to-one row with no cached avatar, fetch the correspondent's profile through the captured `profilebdd.php` route, read its avatar with `UserProfileParser`, and store it with `AvatarStore`'s rules (cookie-less, forum image host only, 256 KiB cap, 24 h): rate-limited, only for visible rows, never with the session.
4. The monogram stays the fallback when the member has no avatar or a fetch fails.

### Acceptance criteria
- An MP row whose correspondent has an avatar shows it, on a fresh install (item 3) and right after the update from legacy (item 1); initials only when there is none.
- No session cookie sent for an avatar or a profile; no more than the visible rows fetched.
- Swift Testing tests for 1, 2, 4 shown to fail without the change; a Mac check on device.

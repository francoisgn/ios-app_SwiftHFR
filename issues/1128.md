As a user reading Réglages › Expérimental, I want each option's description set a little further below its title, and the « MP multiples → dark topic » option to work like the others (description plus the ⓘ button), so that the page is easier to read and consistent. - **(A) The description sticks to the title.**
  - `DescribedFeatureRow` stacks the switch and its description with `VStack(spacing: 2)` (`App/SwiftHFR/Experimental/MPDarkTopic/DescribedFeatureRow.swift:11`).
  - `ExperimentalFeatureRow` uses `spacing: 6` (`App/SwiftHFR/Experimental/ExperimentalSettingsView.swift:95`).
  - The two rows of the same page therefore differ, and both read as cramped.
- **(B) « MP multiples → dark topic » has no ⓘ.**
  - It is the only `showsExplanationUnderSwitch` option (`ExperimentalSettingsView.swift:59-63`), by the operator's choice of 2026-11-17 (#1014).
  - The operator now wants the ⓘ on it too, like the other options. This replaces the 2026-11-17 decision.

### Scope

1. **(A) One spacing.** Use a single spacing constant between a switch's title and its description, shared by every Réglages row that shows a description under its control. Start with the Expérimental rows, then any other settings row built the same way (grep for the pattern). The value must be clearly larger than today's 2–6 pt. Pick it from the system `Form` look, as Settings.app does for a footnote under a row, and state it in the PR.
2. **(B)** « MP multiples → dark topic » shows the ⓘ like the other options of the page.
   - If its long description stays permanently under the switch, the ⓘ is redundant: the simplest path is to make it a plain `ExperimentalFeatureRow` (description behind the ⓘ, as the others).
   - Then `showsExplanationUnderSwitch` and `DescribedFeatureRow` have no user left and are removed, together with their `EXPERIMENTAL(mpDarkTopic, #1014)` markers. The marker on the option itself stays.
   - The PR states the choice.
3. VoiceOver is unchanged: the explanation stays the switch's hint.

### Summary

As a reader, I want to make the text smaller or bigger with a slider and choose a dense display, so that lists and topics show as much as the legacy Favoris list or Gmail's dense list instead of looking zoomed in.

Operator decision 2026-10-28: the renders shown so far look zoomed in and very big. There MUST be a text-size slider whose range goes below the current default, and a density option (compact rows). Respect Dynamic Type: the slider is an in-app offset on top of it; accessibility sizes still work.

### Scope

- **One app-wide type scale.** Every screen (sidebar / Catégories, topic lists, favourites and flags, MP list, settings, reader) takes its sizes from one scale: system text styles × the in-app percentage `text_size_percent` (70–130 %, step 5, stored by LOT-119 (#210), PR #292). No fixed point size outside the scale.
- **Reader:** the same percentage drives `reader.css` (`html` font size on top of `-apple-system-body`), live, without reloading the page. The text-size part of LOT-106 (#197) moves here; LOT-106 keeps layout, signatures and swipe.
- **Density:** `compact_mode` (LOT-119) switches lists to compact rows: smaller insets and row spacing, title on one or two lines, one meta line (author · replies · date), smaller flag / unread markers. References: Gmail dense list, legacy Favoris list (legacy `Common.swift:228` `compact_mode`, `compactListSectionSpacing` `:309`).
- **Default:** check the default (100 %, regular density) against the legacy app on the same device: row height and lines per screen in the Favoris and topic lists within ±10 % of legacy (screenshots of both on the PR, no real pseudo or topic title in them: use the anonymized fixtures or blur).
- **Dynamic Type:** the in-app percentage multiplies the system size; AX sizes still grow the text; the slider never stops large accessibility sizes from applying. `@ScaledMetric` for icon and spacing sizes.
- Legacy `text_size_scale` (100/110/120/130, `Common.swift:265-293`) is already migrated by LOT-119.

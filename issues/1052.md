# Issue #1052: [Legacy 4.0.x] Security: img3 upload API key hard-coded in the public repo — remove from git, renew on Chevereto, synchronised release

- State: open
- Author: ezzz · created 2026-11-17T20:19:53Z · updated 2026-11-18T05:02:25Z
- Labels: type: security, priority: high, difficulty: easy, area: app, host: mac, status: needs-decision
- Source: https://github.com/ezzz/HFRnow/issues/1052

### Summary

The legacy app (`HFRswift`, 4.0.x) has the `img3.super-h.fr` (Chevereto) upload API key **hard-coded in a public repository**: `HFRswift/Swift/ReplyService.swift:2003` (`defaultAPIKey`, used to build `https://img3.super-h.fr/api/1/upload/?key=…`). It must stop being published in git, and the key must be **renewed** on the Chevereto admin of img3, in step with the app releases.

_Operator decision, 2026-11-17: **high priority**. The key is deliberately not copied in this issue._

### Facts

- The key is in `origin/master` since commit `9e949246` (2026-02-18, "Reply: add img3 upload flow and legacy rehost options"). It is in **only that file** on `master`, and in no file of `dev-swift`.
- It is therefore in the public git history, in every clone and fork, and in every 4.0.x binary shipped on the App Store / TestFlight (a string in the binary). Removing it from the current code is not enough: **the key must be considered leaked and revoked**.
- Anyone holding it can upload to img3 in the app's name (abuse, illegal content, storage and bandwidth on super-h.fr) and, depending on question 3 of #1050, perhaps act on the images uploaded with it.
- SwiftHFR already does it right: ADR 0007 (`docs/adr/0007-third-party-api-keys.md`), git-ignored `App/Config/Secrets.xcconfig` (template `Secrets.xcconfig.example`), read through `Info.plist`, Actions secrets `REHOST_BASE_URL` / `REHOST_API_KEY` for CI and release (#471, PR #537). A build with no key hides the upload button.

### The synchronisation problem

Revoking the key on img3 **breaks upload in every installed version that embeds it**. So the order matters:

1. **Legacy code**: read the key the SwiftHFR way (git-ignored `.xcconfig` → `Info.plist`, Actions secret for the release build); delete `defaultAPIKey` from the source; with no key, hide the upload button instead of failing. Check no other secret is hard-coded in `HFRswift/` (a quick scan found none, to be confirmed).
2. **New key**: create it on the Chevereto admin of img3 (with the super-h.fr admin if it is not us), as a key tied to a dedicated account rather than the public guest key if Chevereto allows it (helps with #1050 and with abuse tracking). Put it only in the local `Secrets.xcconfig` and in the Actions secrets, for both the legacy and the SwiftHFR builds.
3. **Release** a legacy version (4.0.x) with the new key; SwiftHFR TestFlight builds use the same secret.
4. **Revoke the old key** on img3. When: right away (upload breaks on not-updated versions until they update; acceptable?) or after a short grace period once most users have the update (the old key keeps working for anyone who copied it). To decide by the operator; given the key is public, a short delay is preferable.
5. In the app, an upload refused with "Invalid API key" (code 100, capture `U02`) should say "mettez l'app à jour" rather than a generic error.

### Git history

- Rewriting history (`git filter-repo`) does not un-leak a key already public, and it would break every fork, open PR and worktree. **Recommended: revoke and do not rewrite.** To confirm with the operator.
- Add a secret scan to CI / pre-commit (e.g. GitHub secret scanning and push protection on the repo, which is free for public repositories) so it does not happen again.

### Acceptance criteria

- [ ] No API key in any tracked file of `master` or `dev-swift`; legacy reads it from a git-ignored config, documented in its README / ADR 0007 is cited.
- [ ] A new key exists on img3, stored only in the local config and the Actions secrets; legacy and SwiftHFR release builds upload with it (checked on device).
- [ ] A legacy release with the new key is out; the old key is revoked on img3 at the date the operator chose, and an upload with it answers "Invalid API key".
- [ ] The app explains an invalid-key refusal ("mettez l'app à jour").
- [ ] GitHub secret scanning / push protection enabled, or a CI secret scan added.
- [ ] Decision on history rewrite recorded here.

## francoisgn · 2026-10-28T14:18:22Z

Scope addition from ADR 0013 §7 (operator decision 2026-10-28, Q14), recorded in the LOT-130 row of `docs/LOTS.md` rather than as a new lot:

- At login or first sync, look for the account's storage thread (the LOT-038 scan, read-only). **Found → sync is on** for that account (the member already chose it in another client; reading costs nothing).
- **Not found → ask at the first bookmark or blacklist write**, because creating the thread is a write to the forum (a private message to `MultiMP`). Until the user answers, the list stays device-only; declining is remembered per account; the setting can be turned on later in Settings.
- On a successful remote read the local blacklist is **merged** (LOT-062 three-way), never replaced as legacy did (`MPStorage.m:202-215`); a failed sync never undoes a local edit.
- The legacy app-wide `mpstorage_active` becomes a per-HFR-account record `mpstorage.<account key>` = `{state, decidedAt}` (`unasked` / `on` / `declined` / `off`) in iCloud KVS (LOT-172, #311; ADR 0013 §7, operator 2026-10-28): sync runs for an account only when its record is `on`, one account's choice never applies to another; the legacy key is read once by the import (`true` → every imported account `on`, `false` → `unasked`) and never written again. (Edited 2026-10-29 to match ADR 0013 §7, PR #313 review F1.)

Blacklist and bookmarks stay in MPStorage; nothing of them goes to iCloud (ADR 0013, alternatives rejected).

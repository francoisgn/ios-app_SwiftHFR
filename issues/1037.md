### Summary

As a reader, I want a plain YouTube link in a message (`youtu.be/…`, `youtube.com/watch?v=…`) to show as the video's **thumbnail**, so I can see what it is at a glance. A tap opens it in the **YouTube app**, or in **Safari** when the app is not installed, never in an in-app browser. (Operator feedback, 2026-11-17, with a device screenshot: a topic of `youtu.be` links shown as bare underlined URLs.)

### Today (dev-swift)

- A plain YouTube link is rendered as a text link.
- YouTube videos that HFR **embeds** (video tags, LOT-035) get the LOT-108 placeholder and the in-app player sheet (`App/SwiftHFR/Reader/VideoPlayerSheet.swift`, #752). **Those stay as they are** (operator, 2026-11-17).
- The long press on a link already offers « Ouvrir dans YouTube » (universal link only, then a fallback; #596, `ReaderLinkMenu`, tested in `ReaderLinkMenuTests.swift:30-32, 172-174`).

### Scope

1. **Detection:** in a message body, an `<a>` whose href is a YouTube video URL: `youtu.be/<id>`, `youtube.com/watch?v=<id>`, `m.youtube.com`, `youtube.com/shorts/<id>`.
   - Reuse the LOT-035 video-id parsing, including the `t=` start time.
   - Out of scope: links in quotes and signatures; a link whose text is not the URL itself (a named link stays a text link). The spec decides and states which.
2. **Thumbnail card:** below the link, or in its place, show the video thumbnail with a play mark.
   - The link text stays visible and tappable.
   - The thumbnail is fetched through the reader's **cookie-less image client** and obeys the image loading modes (Réglages › Expérimental › « Chargement des images », policy C).
3. **Fallback:** if the thumbnail does not load (timeout, error, or image loading off), show the link plus a pill « Vidéo YouTube · toucher pour lire ».
   - The timeout value is cited (the reader's image limit, #683 / `RequestTimeout.standard`), never invented.
4. **Tap**, on the card, the pill or the link:
   - first open the URL as a **universal link only** (`UIApplication.open(_:options: [.universalLinksOnly: true])`), which opens the YouTube app when installed;
   - otherwise open it in **Safari** (`UIApplication.open` without options);
   - **never** an `SFSafariViewController`, a `WKWebView` or the video sheet for these links.
   - Keep the start time.
5. **Long press** stays as today (#596).

### Sources (AGENTS.md §3.1, ADR 0015: no guessing about a third party)

## francoisgn · 2026-11-17T17:02:43Z

**cloud/i1037-sonnet: stopped before coding, no documented thumbnail source (AGENTS.md §3.1, ADR 0015).**

What I read (2026-11-17):

- [YouTube Data API, `thumbnails` resource](https://developers.google.com/youtube/v3/docs/thumbnails): documents the sizes (default 120×90, medium 320×180, high 480×360, standard 640×480, maxres 1280×720; standard and maxres "available for some videos") but **no URL form**: `url` is only "The image's URL". It needs an API key and a quota, and returns the URL, so it does not give us the `i.ytimg.com/vi/<id>/…` pattern either.
- [oEmbed spec](https://oembed.com/): `thumbnail_url` is optional, with width and height. This is the generic spec. I found **no YouTube-published page** for `https://www.youtube.com/oembed` (only third-party examples showing an `i.ytimg.com/vi/<id>/hqdefault.jpg` result).
- The `i.ytimg.com/vi/<id>/<name>.jpg` form is widely used but is documented only by third-party articles, which the issue does not accept.

So neither option of the issue ("oEmbed `thumbnail_url`" or "the documented `i.ytimg.com/vi/<id>/…` form") has a YouTube-published source I can cite. Nothing is written on the branch `feat/1037-youtube-thumbnails` (no commit, no PR).

Decision needed from the operator:

1. Accept the oEmbed endpoint on the strength of the generic spec (oembed.com) plus a capture of one real response as the fixture (it needs a Mac or a session with network access to `www.youtube.com`; I can then cite the capture, ADR 0015 §3). It adds one request per link and a host to the LOT-071 table (T9) and to policy C.
2. Accept `i.ytimg.com/vi/<id>/hqdefault.jpg` as a de-facto form, recorded as such in LOT-071 with the capture as proof (hqdefault exists for every video, unlike standard and maxres; this is third-party knowledge, not documented).
3. Drop the thumbnail and keep only the pill and the tap routing.

Everything else (detection reusing `MessageEmbedDetector`, tap routing, fallback pill) is ready to implement once 1 or 2 is chosen.

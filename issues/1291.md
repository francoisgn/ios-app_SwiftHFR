### Summary
Two minor limits of the shared PR-reference parser (`tooling/common/pr_refs.py`, #1198 / PR #1289) were left after the review cap was reached. Neither affects any of the 567 PR bodies on ezzz/HFRnow today.

### Scope
1. A ref that follows `.` mid-line still opens a sentence. `Not done. Closes #12 (later).` and `We tried it. Fixes #12, partly.` both give closing `[12]`. The rule is kept on purpose so that #303, #259 and #257 still read. Pin it with a table case in `scripts/tests/test_pr_refs.py` and state the limit in the module docstring.
2. `Refs LOT-118, Refs #209:` (as in #638) no longer yields #209, because `Refs LOT-\d+` does not count as a preceding reference. A PR written this way would not get its issue marked claimed by the sweep. Fix: let a `Refs LOT-\d+` count as a preceding ref, with a table case.

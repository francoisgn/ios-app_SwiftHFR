## francoisgn · 2026-11-11T15:20:35Z

**Operator, 2026-11-11: settled, and this is a deliberate gap.** Legacy shows no signature in MPs, consistent with HFR sending no `span.signature` on MP pages (see the investigation above). The operator wants the MP reader as close as possible to a topic: a public topic and a multi-member MP are both threads, so MPs show signatures too.

**Proposed design (no new request in the first step):**
1. **Signature cache per member**, filled from the topic pages the user reads, where HFR does send `span.signature`. This is the same pattern as the avatar cache (GAP-230, `AvatarStore`, #747/#790). When « Afficher les signatures » is on, an MP message shows its author's cached signature, with the same separator as topics (#755/#806).
2. **No cached signature:** nothing is shown, as today. A profile lookup, as #790 does for avatars, could fill it later, but it needs the profile signature capture **#124** first: never guess the markup.
3. A cached signature is shown as a snapshot, so it may be older than the member's current one. Use the same freshness and size limits as the avatar cache, purge it with the account data (LOT-157), and keep it local only.

### Summary

As a reader, I want a rehosted image posted as a **thumbnail (`.th.`) or medium (`.md.`)** rendition to show at **full resolution**, both **inline in the topic** and when I **save, copy or share it from a long press**, so that a screenshot posted small stays readable without opening the viewer. (Operator feedback, 2026-11-17.)

### Today (dev-swift)

- `ImageHostTable.fullSizeURL(for:)` (`Packages/HFRKit/Sources/HFRNetwork/ImageHosts/ImageHostTable.swift:64`) removes `.th.` and `.md.` from `img3.super-h.fr` file names (rule at `:20`, #917, merged in #923). It also rewrites `reho.st` `/thumb/` and `rehost.diberie.com` `/Picture/Get/t/`.
- Its only caller is the viewer: `App/SwiftHFR/Reader/Viewer/ImageGallery.swift:50`.
- **Inline:** the reader renders the URL the member posted, so the `.th.`/`.md.` file is the one shown in the page.
- **Long press:** in `App/SwiftHFR/Reader/ReaderWebController+LinkMenu.swift`, « Ouvrir l'image » goes through the viewer (full size). « Enregistrer dans Photos » (`saveImage`) and « Copier le lien » act on the link URL as posted, so they save or copy the small rendition.
- In the viewer, check what « Partager », « Enregistrer » and « Copier le lien » use (`ImageViewerView.swift:58-65`): the bytes shown are full size since #923, but the copied link may still be the posted one.

### Scope

1. **Inline:** the reader fetches and shows `fullSizeURL(for:)` for an image whose host rule has a thumbnail rewrite. This covers the `img3.super-h.fr` `.th.`/`.md.` markers asked here; the existing `reho.st` and `diberie` rewrites follow the same path unless the spec gives a reason to keep them out. Display size is unchanged: same layout width and the same max-size rules as today, only the source is sharper.
2. **Long press on an image link:** « Enregistrer dans Photos » saves the full-size file. Copy and share use the full-size URL.
3. **Viewer:** the share sheet, save and « Copier le lien » use the full-size file and URL.
4. **Fallback:** if the full-size fetch fails (the host answers 404 or a non-image for the rewritten URL), fall back to the posted URL, so no image disappears.
5. **Image loading modes** (Réglages › Expérimental › « Chargement des images », policy C): the full-size fetch obeys them like any reader image. The cookie-less client and the private-host block always apply.

### Intentional difference from legacy

Legacy shows the posted rendition inline and in its save action (`Common.swift` `saveImageToPhotoLibrary` :2584-2605 @ 2fe43da3). This is a **deliberate gap** decided by the operator: the member's choice of a light rendition no longer limits what the reader sees. The cost is more data per page on topics full of thumbnails. The spec states it in a `### Ledger` `gap-new` or `gap-edit` row.
